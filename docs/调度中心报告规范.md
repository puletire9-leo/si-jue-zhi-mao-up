# 调度中心 V2 — 报告驱动工作流

> 核心原则: **agent不生成报告 = 任务不算完成**
> 主模型(Claude)只读报告审查，不读原始输出

---

## 怎么用（SOP）

### 1. 写任务提示词

```bash
cat > .dispatch/tasks/my-task.txt << 'EOF'
修复前端bug: ElMessage 导入错误
编辑文件: frontend/src/modules/product-line-selection/index.vue
将 ElMessage 从第二个 <script> 块移到 <script setup>
EOF
```

### 2. 启动任务

```bash
cd /mnt/f/项目/调度中心
dc launch run --agent opencode "修复前端bug: ..." -d /path/to/project
```

引擎会自动在prompt末尾追加报告模板指令。

### 3. 等待完成

```bash
dc watch              # 实时看板
dc status show <id>   # 查单个任务
```

### 4. 读报告（关键步骤）

```bash
dc report <id>        # 查看报告内容
# 或直接读文件:
cat .dispatch/reports/<task_id>.md
```

报告示例:
```markdown
# 任务完成报告
| 字段 | 值 |
|------|-----|
| 状态 | 成功 |

## 修改清单
| 文件 | 操作 | 内容摘要 |
|------|------|----------|
| index.vue | edit | 修复ElMessage导入 |

## 给主模型的建议
已确认修改正确，可进入下一步
```

### 5. 判断

| status | 含义 | 主模型操作 |
|--------|------|-----------|
| `reported` | agent完成并生成报告 ✅ | 读报告，审查修改 |
| `no_report` | agent执行完但没写报告 ⚠️ | 查原始输出，判断是否需要重跑 |
| `failed` | agent异常退出 ❌ | 查error信息，修复后重试 |

---

## 报告格式规范

agent收到的报告模板（引擎自动注入）：

```
⚠️ 任务完成后必须创建: .dispatch/reports/{task_id}.md

# 任务完成报告
| 字段 | 值 |
|------|-----|
| 任务ID | {task_id} |
| 状态 | 成功 / 部分完成 / 失败 |

## 修改清单
| 文件 | 操作 | 内容摘要 |
|------|------|----------|
| (列出修改的文件) | edit/write/delete | (一句话) |

## 验证
- 期望修改: N 个文件
- 实际修改: N 个文件
- 自检通过: yes/no

## 给主模型的建议
(一句话)
```

## 引擎自动解析

引擎从报告中提取:
- `report_status` — "成功"/"部分完成"/"失败"
- `report_summary` — "给主模型的建议"内容
- `report_files` — 修改清单中的文件列表

这些数据通过 API 可查询，前端 Dashboard 自动展示。

---

## 任务状态变化

```
QUEUED → RUNNING → (agent写报告文件) → REPORTED
                  → (agent没写报告)   → NO_REPORT
                  → (agent异常退出)   → FAILED
```

`REPORTED` 是新的"正常完成"状态。
