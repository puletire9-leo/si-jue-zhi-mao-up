# 备份功能

## 概述

系统内置数据库全量备份功能，支持**本地备份**和**腾讯云 COS 备份**两种方式。使用 `mysqldump` 导出 + `gzip` 压缩，备份记录存入 `backup_records` 表。

## 备份范围

备份**当前连接的整个 MySQL 数据库**，包含表结构、数据、存储过程、触发器、事件。

配置来源（`backend/app/config.py`）：
- `MYSQL_HOST`：默认 `mysql`
- `MYSQL_PORT`：3306
- `MYSQL_DATABASE`：默认 `sijuelishi`
- `MYSQL_USER` / `MYSQL_PASSWORD`：数据库账号密码

> 开发环境通过 `backend/.env` 覆盖为 `sijuelishi_dev`。生产环境使用 `sijuelishi`。

## 备份流程

### 1. mysqldump 导出

文件：`backend/app/services/backup_service.py` → `_execute_backup()`

```
mysqldump --host={host} --port={port} --user={user} --password={pass}
          --single-transaction --quick --lock-tables=false
          --routines --triggers --events {database}
          --result-file={temp_file}
```

关键参数：
- `--single-transaction`：InnoDB 一致性快照，不阻塞写入
- `--routines --triggers --events`：导出存储过程、触发器、事件
- `--lock-tables=false`：不锁表

### 2. gzip 压缩

原始 SQL 通过 Python `gzip` 模块压缩，删除未压缩的临时文件。

### 3. 文件名规则

```
{数据库名}_full_{YYYYMMDD_HHMMSS}.sql.gz
```
示例：`sijuelishi_full_20260515_160545.sql.gz`

### 4. 存储

- **本地备份**：文件保存到 `BACKUP_DIR`（默认 `/app/backup`，开发环境：`backend/backup/`）
- **COS 备份**：本地备份完成后，上传到腾讯云 COS（路径：`backups/{timestamp}_{md5}.sql.gz`）

### 5. 记录入库

备份完成后向 `backup_records` 表写入一条记录。

## API 端点

全部位于 `backend/app/api/v1/system_config.py`（标记为已弃用，待迁移到 Java 后端）。

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/api/v1/system-config/backup/start` | 启动备份 | `config:write` |
| GET | `/api/v1/system-config/backup/records` | 获取备份记录（分页） | `config:read` |
| GET | `/api/v1/system-config/backup/expired` | 获取过期备份（>3天） | `config:read` |
| GET | `/api/v1/system-config/backup/download/{id}` | 获取下载链接（仅COS） | `config:read` |
| DELETE | `/api/v1/system-config/backup/{id}` | 删除备份记录+文件 | `config:write` |

### 启动备份

```
POST /api/v1/system-config/backup/start
Body: { "backup_type": "local" | "cos" }
Response: { code: 200, data: { name, size, status, storage_location, ... } }
```

**注意**：备份是**同步**执行的——API 会阻塞直到 mysqldump 完成。大数据库可能超时。

### 下载

- **COS 备份**：返回一个预签名 URL（7 天有效），前端通过 `window.open(url)` 下载
- **本地备份**：返回错误 "本地备份文件不支持直接下载URL"

## 数据库表：backup_records

```sql
CREATE TABLE backup_records (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,           -- 备份文件名
    type VARCHAR(50) DEFAULT 'full',      -- 备份类型（始终为 full）
    size DECIMAL(10,2) NOT NULL,          -- 文件大小（MB）
    status VARCHAR(50) DEFAULT 'success', -- success / failed / running
    storage_location VARCHAR(50) DEFAULT 'local', -- local / cos
    cos_object_key VARCHAR(255),          -- COS 对象键
    cos_url TEXT,                         -- COS 访问 URL
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## 前端界面

文件：`frontend/src/views/Settings/index.vue`，"备份设置"标签页。

### 界面组成

1. **备份方式选择**：单选按钮（本地备份 / 腾讯云备份）
2. **立即备份按钮**：仅管理员可用，调用 `systemConfigApi.startBackup()`
3. **进度条**：显示 0% → 100%（因为是同步备份，只有 0 和 100 两个状态）
4. **配置信息展示**：备份类型、数据库、环境、保留期（3天）、本地/COS路径、自动备份时间
5. **最近备份记录**：表格展示，支持下载（COS）和删除
6. **过期备份**：超过 3 天的记录，可手动删除

### API 调用

文件：`frontend/src/api/systemConfig.ts`

```typescript
startBackup(backupType: 'local' | 'cos')  → POST /backup/start
getBackupRecords(params)                  → GET  /backup/records
getExpiredBackups()                       → GET  /backup/expired
downloadBackup(id)                        → GET  /backup/download/{id}
deleteBackup(id)                          → DELETE /backup/{id}
```

## 定时任务

**当前没有自动备份定时任务。** 前端展示的"每天凌晨 2:30"自动备份仅是硬编码文案，后端未实现。

相关但未启用的定时清理函数：
- `cleanup_service.cleanup_old_backups()`：删除超过 30 天的本地备份（保留最新 10 个）

## 已知问题

1. **`BACKUP_REMOVE_AFTER_COS_UPLOAD` 未定义**：`backup_service.py` 第 122 行引用了此配置，但 `config.py` 里没有定义，会导致 COS 备份时 AttributeError。

2. **本地备份无法下载**：API 对本地存储的备份返回错误，前端 `handleDownload` 对本地备份会失败。

3. **同步备份阻塞**：大数据库备份时，API 响应可能超过 uvicorn 的 300 秒超时。

4. **进度条不实时**：前端进度条只有 0% 和 100%，没有中间进度。

5. **无自动过期清理**：超过 3 天的备份被标记为 "expired" 但不会自动删除。

6. **前端显示路径与实际不一致**：前端计算的路径和后端 `BACKUP_DIR` 不是同一个值。

## 手动执行备份

绕过前端 API，直接在 Docker 容器内执行：

```bash
# 备份生产数据库
docker exec prod-mysql sh -c "mysqldump -usijue -psijue123456 --single-transaction sijuelishi | gzip > /tmp/sijuelishi_full_$(date +%Y%m%d_%H%M%S).sql.gz"

# 备份开发数据库
docker exec dev-mysql sh -c "mysqldump -usijue -psijue123456 --single-transaction sijuelishi_dev | gzip > /tmp/sijuelishi_dev_full_$(date +%Y%m%d_%H%M%S).sql.gz"

# 复制到宿主机
docker cp prod-mysql:/tmp/sijuelishi_full_*.sql.gz backend/database/backup/
docker cp dev-mysql:/tmp/sijuelishi_dev_full_*.sql.gz backend/database/backup/

# 重新导入开发数据库
docker cp backend/database/backup/sijuelishi_full_*.sql.gz dev-mysql:/tmp/
docker exec dev-mysql sh -c "zcat /tmp/sijuelishi_full_*.sql.gz | mysql -usijue -psijue123456 sijuelishi_dev"
```
