# 选品Agent系统 - 详细报告

## 一、计划目标（选品Agent设计初衷）

选品Agent的设计目标是构建一个**11节点智能分析图**，用于跨境电商产品的自动化选品决策。

### 核心目标

1. **数据驱动的选品决策** - 通过聚合数据源进行多维度分析
2. **两阶段分析模式** - 初筛（快速评分）+ 深度分析（全面评估）
3. **11节点能力分析图** - 覆盖语义理解、竞争格局、生命周期、利润推算、差异化、风险、卖家画像、跨品线、最终裁决等全方位分析
4. **实时流式反馈** - 通过SSE实时推送分析进度
5. **定时自动化** - 自动执行月度/季度任务

### 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    选品Agent系统                          │
├─────────────────────────────────────────────────────────┤
│ 前端：Vue3 + TypeScript + Element Plus                   │
│   ├─ SSE实时进度                                        │
│   └─ 分析结果卡片                                       │
├─────────────────────────────────────────────────────────┤
│ Python后端：FastAPI + LangGraph + Celery                │
│   ├─ 11节点分析图                                       │
│   ├─ 双阶段模式（初筛+深度）                            │
│   ├─ L1/L2双层评分                                      │
│   ├─ 定时任务调度                                       │
│   └─ 外部集成（Java/卖家数据）                          │
├─────────────────────────────────────────────────────────┤
│ Java后端：Spring Boot + MyBatis-Plus                    │
│   ├─ 聚合数据API                                        │
│   ├─ 分析结果回写                                       │
│   └─ 品类基线管理                                       │
├─────────────────────────────────────────────────────────┤
│ 数据层：MySQL + Redis + SQLite                          │
│   ├─ 原始数据存储                                       │
│   ├─ 决策快照存储                                       │
│   └─ 缓存优化                                           │
└─────────────────────────────────────────────────────────┘
```

### 核心工作流

```
前端触发 → SSE建立连接
    ↓
Data Fetch → 拉取Java聚合数据
    ↓
初筛（能力1-4）→ 快速评分
    ↓ (score≥60 或 STRONGLY_RECOMMEND)
深度分析（能力5-10）→ 完整评估
    ↓
回写Java → SSE通知完成
```

#### 2. 双阶段分析模式

- **初筛图**（能力1-4）：快速评分
  - semantic_understanding → competition_analysis → lifecycle_judgment → profit_estimation
  
- **深度图**（能力5-10）：完整分析
  - risk_radar → seller_profiling → cross_line_discovery → burst_signal_detection → final_verdict
  
- **条件路由**：
  - margin ≥ 30% → differentiation_full（3个方案）
  - margin < 30% → differentiation_quick（1个建议）

#### 3. 智能评分系统

- **L1评分**（6维通用）：opportunity_scorer
  - 需求/市场容量（0-25）
  - 盈利能力（0-20）
  - 竞争格局（0-20）
  - 差异化空间（0-15）
  - 时机窗口（0-10）
  - 风险惩罚（-10）

- **L2评分**（8维品类专属）：l2_scorer
  - 规模、体量、利润、情感、装饰、裂变、文化、市场

- **百分位评分**：percentile_scorer
- **机会分类**：opportunity_classifier
- **品类健康度**：category_health

## 五、代码审查建议

### 建议优化项

1. **httpx客户端生命周期管理**
   - 添加atexit注册或FastAPI shutdown事件
   - 避免ResourceWarning

2. **测试mock隔离**
   - 使用scope="module" fixture
   - 避免污染其他测试模块

3. **卖家数据类型确认**
   - 确认Java API返回品类级聚合还是卖家级明细
   - 根据实际情况调整转换逻辑

### 性能优化建议

1. **并发控制**
   - MAX_CONCURRENT_SUBS环境变量控制并发数
   - 避免过度并发导致资源耗尽

2. **缓存优化**
   - 品类基线数据缓存
   - 卖家画像数据缓存

3. **数据库优化**
   - SQLite WAL模式
   - 决策快照定期清理
