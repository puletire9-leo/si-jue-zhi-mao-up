> 总览见 [八爪鱼功能实现总览](八爪鱼功能实现总览.md)。

## 1. 背景与目标

「榜单采集榜单数据三国」(US/UK/DE) 的新品数据，过去是**人工**从八爪鱼下载文件 → 上传系统 → 初筛 → 调卖家精灵 API。

本功能把**前半段自动化**：

```
云端每周定时爬取八爪鱼  →  入库(按周存,上周自动删)  →  自动初筛存表  →  前端确认无误  →  调卖家精灵(现有流程)
└────────────── 新增(止于初筛) ──────────────┘                    └─── 复用现有,人工触发 ───┘
```

**关键边界**：自动流水线**止于初筛**。卖家精灵 API（消耗额度）仍由人在前端确认后手动触发，额度花费始终受人工把关。

## 3. 架构决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 后端归属 | 全放 Java `sjzm-product` 模块，不新增微服务 | 下游(初筛/卖家精灵/清洗层/评分)全在 sjzm-product，核心价值是进程内复用；周级低频任务无独立伸缩需求 |
| 采集触发 | 我们主动 启动云任务 + 轮询 + 拉取 | 最稳，不依赖八爪鱼端是否配了定时 |
| 初筛产出 | 复用现有 `asin_import_tasks` + `asin_import_results` | execute→卖家精灵 流程已读它，零改造对接 |
| 调度 | Java `@Scheduled`（非 Python Celery） | Python 端无 beat 调度器、prod 无 beat 容器；Java 单实例 @Scheduled 最省事 |

模块路径：`com.sjzm.product.modules.bazhuayu`（遵守模块化铁律，自动被 `scanBasePackages` 扫描）。

## 4. 数据流与组件

```
BazhuayuScheduledService.runCollection(mp)
  │
  ├─ scoringService.getCurrentWeekTag()           # ISO 周 如 2026-W26
  ├─ 删非本周数据 (rawMapper)                       # 「上周自动删」
  │
  └─ 逐站点 collectAndScreen(mp, taskId, weekTag):
       ├─ BazhuayuClient.startExtraction(taskId)        # POST /cloudextraction/start → lotNo
       ├─ BazhuayuClient.waitForExtraction(taskId)      # 轮询 statuses/v2 到 Finished
       ├─ createStreamingTask(mp, "BAZHUAYU_AUTO")      # 建 RUNNING 任务 + 流式上下文
       └─ BazhuayuClient.drainNotExported(taskId, page -> {       # notexported 游标增量,不堆全量
              ├─ 整形周表实体 → Db.saveBatch(pageEntities) → 丢弃(释放 raw_json)
              ├─ filterPageAndAppend(ctx, 轻量行)         # 复用 filterRows 分桶,逐页落 results
              └─ markExported(taskId)                     # 成功后标记,游标前移,下次跳过
          }, drainMaxRows)
       └─ finishStreamingTask(ctx)                       # 回填计数, status=READY
                                  │
            前端确认页 ──────────┘
              └─ POST /api/v1/asin-import/execute?taskId=  # 现有流程,调卖家精灵
```

> **增量获取(notexported+markexported)**：八爪鱼 `/data/all` 含 192 万历史累积，改用 `/data/notexported` 只取未导出新数据，处理成功后 `markexported` 标记。内存恒定（每轮 1000 条），天然增量。详见 §12。文件上传路径(小数据)仍走 `filterRowsAndCreateTask` 单事务，不变。

## 5. 数据库

```sql
-- java-backend/sql/create_bazhuayu_weekly_raw.sql
CREATE TABLE bazhuayu_weekly_raw (
  id BIGINT PK,          marketplace VARCHAR(10),  asin VARCHAR(20),
  price VARCHAR(50),     reviews VARCHAR(50),       title VARCHAR(1000),
  raw_json JSON,         week_tag VARCHAR(10),      lot_no VARCHAR(40),
  scraped_at DATETIME,
  UNIQUE KEY uk_mp_asin_week (marketplace, asin, week_tag)
) CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- charset/collation 与 `competitor_products` 一致(避免 collation 混用坑)。
- **「上周自动删」**：每次采集开始 `DELETE WHERE week_tag <> 当前周`，只留最新周；同周重跑靠唯一键幂等。
- `raw_json` 留痕：核对八爪鱼真实字段名用。

## 10. 注意事项

- **额度**：卖家精灵不自动触发，需人工确认；八爪鱼云采集额度由「我们启动」消耗，prod cron 每周一次。
- **凭证**：八爪鱼账号有效期至 2027-03-19，密码进 secrets 不进 git。
- **调度单点**：`@Scheduled` 在 java-product 单实例运行；将来多实例需加分布式锁。
- **限流**：客户端翻页间 sleep 2s（沿用卖家精灵 `BATCH_API_DELAY_MS`），避免八爪鱼 429（文档要求 ≤20 次/秒）。
- **僵尸任务**：`AsinImportService` 启动时把残留 RUNNING 任务标 ERROR（容器重启场景），自动任务同样受益。

## 12. 大数据量 + 增量获取（实测 192 万累积 / 单批 30 万）

连真实 API 探查的发现（美国任务）：
- `/data/all` 的 `total = 1,924,957`（192 万）是 `executedTimes=6` 次采集的**历史累积**，八爪鱼云端从不自动清空。
- `/data/all` 实测按最新数据优先返回。人工点击“导入DB”且开放接口没有 `lotNo` 时，后端先用 `statuses/v2.currentTotalExtractCount` 锁定本批次 N，再只读取 `/data/all` 前 N 行；读满 N 立即停止，少于 N 则拒绝，绝不继续扫历史累计部分。
- 任务状态 `currentTotalExtractCount = 305,811` 才是本批次（~30 万），云端 `nextExecuteTime` 每日 10:00 自采。
- 字段名实测全命中（`ASIN`/`标题`/`价格`/`review数量`），另有 `类目名称`/`排行`/`任务源网址`（初筛用不到）。
- 价格空缺约 28%（新品预售未定价），初筛保留现状：空价跳过价格判断、当 PASS。

### 增量方案：notexported + markexported（游标式）

不用 `/data/all`（会拉 192 万历史），改用未导出游标：

```
drainNotExported(taskId, pageHandler, maxRows):
  while 未达上限:
    page = GET /data/notexported?taskId=&size=1000   # 最旧的未导出 N 条(FIFO)
    if page 空: break
    pageHandler(page)        # 写周表 saveBatch 即丢 + filterPageAndAppend 初筛
    POST /data/markexported  # 成功后才标记，游标前移，下次跳过这批
    if page 不足整页: break
    sleep 2s
```

- **内存恒定**：每轮只 1000 条，已导出的下次不返回，**无需 192 万去重大 Set**。
- **at-least-once**：先处理落库成功、再 markexported；处理失败不标记，下次重试，靠库内唯一键 `uk_mp_asin_week` + `skip_asins` 幂等去重。
- **不再 startExtraction/waitForExtraction**：云端自带定时采集，我们只取未导出增量（`start/wait` 方法保留备用）。

### 首次 192 万积压

`BAZHUAYU_DRAIN_MAX_ROWS`（dev 默认 5000，prod 100000，0=不限）防失控。两种处理：
- **方案 X（默认）**：drain 跑完历史（耗时数小时，受 1000/页 + 2s 限速），数据完整。首次先小 `maxRows` 验证链路，再放量。
- **方案 Y（清积压）**：`POST /api/v1/modules/bazhuayu/mark-all-exported?marketplace=US` 把历史全标记已导出（不入库），从下一个采集批次起正常增量。**丢弃历史换最快进入稳态**。

> ⚠️ `markexported` **不可逆**：标记后该批 `notexported` 不再返回。首次操作务必先小批验证。

### cron 与云端定时

八爪鱼云端在客户端里设了**周日 + 周二**定时自采；本系统 cron 设**周一 + 周三 06:00**（prod），即云端采完的次日早上去查 `notexported` 有没有新批次，有就 drain 入库初筛，没有就空跑不报错。本系统**不控制云端启动**（不 startExtraction / 不 waitForExtraction），只做增量拉取。需调整节奏就改 `BAZHUAYU_CRON`（6 段式，须错开云端采集时段）。
