# 精铺测品二批转正模型

## 1. 模型目的

这个模型不是只看首批能不能赚钱，而是判断一批测品 SKU 是否能通过“首批测品 + 命中 SKU 补第二批”的方式实现整体正利润。

核心问题：

> 每月测一批 SKU 时，首批备货会产生测品成本。只有一部分 SKU 能出单并进入第二批。我们要判断这些出单 SKU 的首批利润和第二批利润，能不能覆盖没有跑出来的 SKU 以及二批后仍被淘汰 SKU 的损失。

因此，真正的盈亏平衡不是：

```text
首批卖完是否赚钱
```

而是：

```text
首批出单 SKU + 二批转正 SKU 的利润
- 首批淘汰 SKU 的损失
- 二批后淘汰 SKU 的损失
- 固定成本分摊
>= 0
```

## 2. 业务定义

### 2.1 首批测品

每月上新或运营一批测品 SKU，每个 SKU 先备一个较小的首批库存。

首批的作用主要是：

```text
验证市场需求
验证图片、标题、价格、广告、平台流量是否能跑通
筛选值得继续补货的 SKU
```

首批本身通常很难覆盖完整经营成本，所以不能只用首批利润判断项目是否成立。

### 2.2 二批转正

首批中能够出单、达到补货条件的 SKU，会再备第二批货。

二批的作用是：

```text
放大已经验证过的 SKU
让命中 SKU 贡献主要利润
覆盖未命中 SKU 的淘汰损失
覆盖团队、广告、软件、仓储等固定成本
```

如果二批能正常卖完或达到稳定销售状态，这类 SKU 才算真正转正。

### 2.3 淘汰 SKU

淘汰 SKU 分两类：

```text
首批淘汰 SKU：首批没有跑出来，没有达到补货标准。
二批后淘汰 SKU：首批跑出来并补了第二批，但第二批表现不达标，最终仍要清货或停止补货。
```

这两类 SKU 都需要计入亏损。

## 3. 核心变量

| 变量 | 含义 |
|---|---|
| N | 每月测品 SKU 数 |
| Q1 | 每个 SKU 首批备货数量 |
| Q2 | 进入二批后，每个 SKU 第二批备货数量 |
| R1 | 首批出单率，也就是进入二批的 SKU 比例 |
| R2 | 二批转正率，也就是进入二批后最终跑出来的 SKU 比例 |
| M | 单件真实贡献利润 |
| L1 | 首批淘汰 SKU 的单件淘汰损失 |
| L2 | 二批后淘汰 SKU 的单件淘汰损失 |
| F | 每月固定成本分摊 |

## 4. 单件真实贡献利润 M

单件真实贡献利润不是售价减采购价，而是扣完所有变动成本后的利润。

建议计算口径：

```text
M = 售价
  - 商品采购成本
  - 头程物流
  - 平台佣金
  - 支付手续费
  - 尾程/履约费用
  - 包装耗材
  - 广告成本分摊
  - 退款退货损失分摊
  - 税费
  - 汇损
```

如果不同 SKU 利润差异较大，可以先用平均单件贡献利润，也可以按品类分层计算。

## 5. 单件淘汰损失 L

淘汰损失不是简单的采购成本，而是库存清理后的真实损失。

建议计算口径：

```text
L = 商品采购成本
  + 头程物流
  + 入仓/贴标/处理费
  + 仓储费
  + 清仓折价损失
  + 销毁/移除/退仓费用
  - 清仓回收金额
```

如果首批淘汰和二批淘汰的处理方式不同，应该拆成：

```text
L1 = 首批淘汰单件损失
L2 = 二批淘汰单件损失
```

## 6. 简化版模型

适合在数据还不完整时快速判断。

假设：

```text
1. 进入二批的 SKU 都能把首批和二批卖完
2. 没进入二批的 SKU 按首批库存全部淘汰
3. 暂时不单独计算二批后淘汰
```

净利润公式：

```text
净利润 = N * R1 * (Q1 + Q2) * M
       - N * (1 - R1) * Q1 * L1
       - F
```

盈亏平衡条件：

```text
N * R1 * (Q1 + Q2) * M
- N * (1 - R1) * Q1 * L1
- F
>= 0
```

最低首批出单率：

```text
R1 >= (Q1 * L1 + F / N) / ((Q1 + Q2) * M + Q1 * L1)
```

这个公式用于回答：

```text
在首批备货 Q1、二批备货 Q2、单件利润 M、淘汰损失 L1 固定时，
最低需要多少首批出单率，整批测品才能不亏钱。
```

## 7. 二阶段真实模型

更接近实际经营，需要同时考虑：

```text
首批没有跑出来的 SKU
进入二批但二批后仍被淘汰的 SKU
真正二批转正并持续赚钱的 SKU
```

SKU 数量拆分：

```text
首批进入二批 SKU 数 = N * R1
首批淘汰 SKU 数 = N * (1 - R1)
二批转正 SKU 数 = N * R1 * R2
二批后淘汰 SKU 数 = N * R1 * (1 - R2)
```

净利润公式：

```text
净利润 =
  N * R1 * R2 * (Q1 + Q2) * M
- N * (1 - R1) * Q1 * L1
- N * R1 * (1 - R2) * Q2 * L2
- F
```

盈亏平衡条件：

```text
N * R1 * R2 * (Q1 + Q2) * M
- N * (1 - R1) * Q1 * L1
- N * R1 * (1 - R2) * Q2 * L2
- F
>= 0
```

这个版本更适合最终落地，因为它承认一个现实：

```text
首批出单不等于真正成功。
首批出单只能说明这个 SKU 值得进入二批验证。
二批转正之后，才说明这个 SKU 具备稳定利润价值。
```

## 8. 不同首批备货数量如何影响盈亏平衡

首批备货数量 Q1 会同时放大两件事：

```text
1. 命中 SKU 的首批利润空间
2. 未命中 SKU 的库存淘汰损失
```

所以 Q1 不是越少越好，也不是越多越好。

当 Q1 太少：

```text
单个命中 SKU 的利润太薄
二批还没开始前，首批几乎覆盖不了测品成本
对二批转正率要求更高
```

当 Q1 太多：

```text
未命中 SKU 的淘汰损失快速放大
要求更高的首批出单率
资金占用更大
清货压力更大
```

所以要用模型比较不同 Q1 下的最低出单率，而不是凭感觉决定首批备货数量。

## 10. 后续需要收集的数据

### 10.1 测品规模数据

| 数据 | 用途 |
|---|---|
| 每月实际上架/运营测品 SKU 数 N | 确定整批测品规模 |
| 每个 SKU 首批备货数量 Q1 | 比较不同首批备货方案 |
| 每个 SKU 第二批备货数量 Q2 | 计算二批利润能力 |
| 首批观察周期 | 定义多久内判断是否出单 |
| 二批观察周期 | 定义多久内判断是否转正 |

### 10.2 出单和转正数据

| 数据 | 用途 |
|---|---|
| 首批有出单 SKU 数 | 计算首批出单率 R1 |
| 达到补货标准 SKU 数 | 更准确地计算进入二批比例 |
| 进入二批 SKU 数 | 验证实际 R1 |
| 二批卖完 SKU 数 | 计算二批转正率 R2 |
| 二批后仍被淘汰 SKU 数 | 计算二批淘汰损失 |
| 每个 SKU 首批销量 | 判断首批是否真的跑出来 |
| 每个 SKU 二批销量 | 判断二批是否转正 |

建议先明确“出单 SKU”的标准，例如：

```text
标准 A：首批有 1 单就算出单
标准 B：首批卖出达到 30% 才算出单
标准 C：首批在 30 天内卖完才算进入二批
标准 D：首批日均销量达到指定阈值才算进入二批
```

不同标准会让 R1 差异很大，必须统一口径。

| 平台佣金 | 计算真实贡献利润 |
| 支付手续费 | 计算真实贡献利润 |
| 尾程/履约费用 | 计算真实贡献利润 |
| 包装耗材成本 | 计算真实贡献利润 |
| 广告花费 | 计算广告成本分摊 |
| 退款退货率 | 计算退款损失 |
| 折扣/优惠券成本 | 计算真实成交利润 |
| 税费 | 计算真实利润 |
| 汇率和汇损 | 跨境业务必须计入 |

### 10.4 淘汰损失数据

| 数据 | 用途 |
|---|---|
| 首批淘汰 SKU 剩余库存 | 计算首批淘汰件数 |
| 二批淘汰 SKU 剩余库存 | 计算二批淘汰件数 |
| 清仓售价 | 计算回收金额 |
| 清仓周期 | 判断资金占用和仓储成本 |
| 仓储费 | 计算淘汰损失 |
| 移除/退仓/销毁费用 | 计算淘汰损失 |
| 清仓平台费用 | 计算真实回收金额 |
| 最终回收金额 | 计算净损失 |

### 10.5 固定成本数据

| 数据 | 用途 |
|---|---|
| 团队人工成本 | 计算每月固定成本 F |
| 软件订阅成本 | 计算每月固定成本 F |
| 办公/管理成本 | 计算每月固定成本 F |
| 拍摄/修图/内容成本 | 可按 SKU 或月份分摊 |
| 样品/测试成本 | 可按 SKU 分摊 |
| 店铺固定费用 | 计算每月固定成本 F |

固定成本可以先按月分摊：

```text
F = 当月团队成本 + 软件成本 + 店铺固定成本 + 内容成本 + 其他固定费用
```

也可以折算到单个 SKU：

```text
单 SKU 固定成本 = F / N
```

## 11. 最终要看的几个指标

| 指标 | 含义 |
|---|---|
| 最低首批出单率 R1 | 首批至少要跑出多少 SKU，整批测品才可能不亏 |
| 最低二批转正率 R2 | 进入二批后至少要有多少 SKU 真正跑出来 |
| 单 SKU 盈亏平衡利润 | 每个成功 SKU 需要贡献多少利润 |
| 最大可承受淘汰率 | 最多可以淘汰多少 SKU 仍不亏 |
| 不同 Q1 下的净利润 | 比较首批备货 10、15、20、25、30 件哪个更合理 |
| 资金占用峰值 | 首批和二批合计需要占用多少现金 |

## 12. 分散补货/滚动补货更新计划

实际经营中，二批补货通常不是整批 SKU 同时发生，而是某个 SKU 卖完或接近卖完后单独补货。

因此，模型需要从：

```text
整批 SKU 统一首批 + 统一二批
```

升级为：

```text
单 SKU 生命周期记录 + 月度 cohort 汇总
```

### 12.1 为什么不能只按整批算

如果所有 SKU 都等到同一天统一补二批，公式会很简单，但这不符合真实运营。

真实情况通常是：

```text
SKU A 第 7 天卖完，马上补货
SKU B 第 15 天卖完，单独补货
SKU C 第 30 天才卖完，再决定是否补货
SKU D 一直不动，进入清货/淘汰
```

所以补货是分散的，利润也是分散产生的。

但经营复盘仍然需要一个统一口径，因此不能只看单个 SKU，也不能只看某一天补了几件货。

推荐口径：

```text
补货动作按 SKU 单独记录
经营结果按上架月份汇总
```

### 12.2 单 SKU 生命周期

每个 SKU 单独记录完整生命周期。

建议字段：

| 字段 | 含义 |
|---|---|
| SKU | 商品编码 |
| 上架日期 | SKU 开始销售的日期 |
| 首批入库日期 | 首批库存可售日期 |
| 首批数量 Q1 | 首批备货数量 |
| 首单日期 | 第一次出单日期 |
| 首批卖完日期 | 首批库存售罄日期 |
| 首批售罄天数 | 从可售到首批卖完用了几天 |
| 是否触发补货 | 是否进入下一批 |
| 第 2 批补货日期 | 下单补货日期 |
| 第 2 批到货日期 | 二批可售日期 |
| 第 2 批数量 Q2 | 二批补货数量 |
| 第 2 批卖完日期 | 二批是否卖完以及何时卖完 |
| 当前剩余库存 | 当前未售出的库存 |
| 当前累计销量 | 截止统计日总销量 |
| 当前累计利润 | 已实现利润 |
| 当前库存风险 | 如果现在淘汰，预计损失多少 |
| 当前状态 | 未出单/首批验证/已补货/转正/淘汰 |

### 12.3 时间窗口

分散补货后，需要用统一的观察周期来比较不同 SKU。

建议观察窗口：

| 时间窗口 | 用途 |
|---|---|
| 7 天 | 判断是否有快速出单信号 |
| 14 天 | 判断是否有初步市场反馈 |
| 30 天 | 判断首批是否值得补货 |
| 60 天 | 判断补货后是否继续放量 |
| 90 天 | 判断本月测品 cohort 是否整体转正 |
| 120 天 | 做最终清货和淘汰结算 |

推荐主口径：

```text
按上架月份作为 cohort，观察 90 天。
```

例如：

```text
7 月上架 120 个 SKU
不管它们分别在第几天补货
都归为 7 月测品 cohort
然后统计这 120 个 SKU 在上架后 90 天内的累计表现
```

### 12.4 滚动补货触发规则

补货不建议只等卖完再补，因为可能造成断货。

推荐用可售天数触发补货：

```text
可售天数 = 当前可售库存 / 最近 N 天日均销量
```

触发条件：

```text
如果 可售天数 <= 补货到货周期 + 安全库存天数
则触发补货
```

示例：

```text
当前库存 = 3 件
最近 7 天日均销量 = 1 件
可售天数 = 3 天

如果补货到货周期 = 15 天
安全库存天数 = 3 天
则补货触发线 = 18 天

因为 3 天 <= 18 天
所以应该立即补货，甚至已经偏晚。
```

### 12.5 分散补货下的净利润计算

分散补货后，不再强行假设只有固定 Q1 和 Q2。

应改为按每个 SKU 的实际累计批次计算：

```text
SKU 累计净利润 =
  SKU 累计已售件数 * 单件贡献利润
- SKU 当前淘汰风险库存 * 单件淘汰损失
- SKU 分摊固定成本
```

整个月度 cohort 的净利润：

```text
cohort 净利润 =
  所有 SKU 累计已售件数 * 单件贡献利润
- 所有 SKU 当前风险库存 * 单件淘汰损失
- 该 cohort 分摊固定成本
```

如果要拆得更细：

```text
cohort 净利润 =
  首批已售利润
+ 补货批次已售利润
- 首批淘汰损失
- 补货后淘汰损失
- 固定成本
```

### 12.6 分散补货后的盈亏平衡口径

分散补货后，盈亏平衡不再只问：

```text
首批 + 二批能不能赚钱
```

而是问：

```text
在 90 天或 120 天内，
这一批上架 SKU 的累计销售利润，
能不能覆盖所有未跑出来 SKU 的淘汰损失和固定成本。
```

建议保留两个口径：

| 口径 | 用途 |
|---|---|
| 90 天经营口径 | 判断这批测品是否值得继续放大 |
| 120 天结算口径 | 判断这批测品最终是否真实盈利 |

90 天口径更适合运营决策，120 天口径更适合财务复盘。

### 12.7 需要新增收集的数据

为了支持滚动补货，需要新增这些数据：

| 数据 | 用途 |
|---|---|
| SKU 上架日期 | 归属到哪个月度 cohort |
| 每批次补货日期 | 记录补货节奏 |
| 每批次到货日期 | 判断断货和补货周期 |
| 每批次补货数量 | 计算实际库存投入 |
| 每日销量 | 计算日均销量和可售天数 |
| 每日库存 | 判断何时触发补货 |
| 首单日期 | 计算首单速度 |
| 首批卖完日期 | 判断首批验证速度 |
| 每次断货天数 | 判断损失的销售机会 |
| 每个 SKU 当前状态 | 判断转正、观察、淘汰 |

### 12.8 后续落地步骤

第一步，先建立单 SKU 生命周期表：

```text
每个 SKU 一行，记录上架、首批、补货、销量、库存、状态。
```

第二步，建立补货流水表：

```text
一个 SKU 可以有多行补货记录，每一次补货单独记录数量、日期、成本、到货时间。
```

第三步，建立月度 cohort 汇总表：

```text
按上架月份汇总所有 SKU 的 30 天、60 天、90 天、120 天表现。
```

第四步，再计算不同首批备货数量下的盈亏平衡：

```text
比较 Q1 = 10、15、20、25、30 时，
在真实滚动补货规则下，
各自需要多少首批出单率、补货成功率和二批转正率。
```

第五步，形成补货决策规则：

```text
什么时候补
补多少
什么时候停止补
什么时候清货淘汰
```

## 13. 经营结论

这个模型的核心不是追求所有 SKU 都赚钱，而是判断：

```text
少数跑出来的 SKU，能不能覆盖多数没跑出来 SKU 的成本。
```

精铺测品的关键不是首批利润，而是：

```text
首批负责筛选
二批负责验证
转正 SKU 负责覆盖淘汰 SKU
```

因此，真正需要优化的是：

```text
1. 降低首批备货 Q1，减少测错成本
2. 提高首批出单率 R1，减少首批淘汰
3. 提高二批转正率 R2，避免二次误判
4. 提高单件贡献利润 M
5. 降低淘汰损失 L1 和 L2
6. 控制固定成本 F
```

最终目标：

```text
找到不同首批备货数量下，最低需要多少首批出单率和二批转正率，
才能让“首批测品 + 二批转正”整体实现正利润。
```
