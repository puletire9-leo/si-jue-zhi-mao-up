# 页面展示问题诊断与改造要求

> 给实现页面的 AI 使用。当前 `selection-display-system` 原型方向不够满意，主要问题不是页面数量，而是展示范式偏离了本项目现有前端和选品业务。请按本文重新理解和改造。

## 一、核心结论

当前原型最大的问题：

```text
它把选品系统做成了“指标表格后台”，但我们的选品观看更需要“图片主导 + 重点信息密集展示 + 快速动作”。
```

选品不是财务报表。用户第一眼要先看到商品长什么样，再同时看到：

- ASIN
- 标题
- 店铺
- 类目
- 月销量
- 销量等级 A/B/C/D
- BSR
- 价格
- 上架时间 / 上架天数
- 入库时间 / 批次
- 方法卡命中
- 是否来自优质店铺 / 郑总 / 自有优质店
- 是否已被我选中 / 被谁选中
- 一键打开 Amazon
- 以图识图
- 加入候选池 / 观察

当前原型太多页面是“表格 + 指标卡”，图片只是小占位，甚至没有真实商品图片区域。这会导致选品判断很慢，也不符合我们现有系统习惯。

## 二、它现在做得可以保留的地方

当前原型不是完全不能用，以下可以保留：

| 可保留点 | 说明 |
|---|---|
| 页面拆分 | 今日工作台、新品雷达、新品起量榜、方法卡结果、店铺画像、店铺上新流、类目机会榜、候选池这些页面方向是对的 |
| 顶部筛选条 | marketplace、时间、方法卡、类目、店铺搜索这些筛选方向是对的 |
| 类目机会榜 | 类目本来就适合表格，当前表格方向可以保留 |
| 店铺画像摘要 | 店铺 A/B/C/D、ABC/D 结构、基线定位这些摘要块可以保留 |
| 候选池状态流 | 候选池用状态看板/列表是合理的 |
| 信息密集目标 | 它试图做密集后台，而不是营销页，这点是对的 |

但所有“商品展示型页面”必须改成图片主导。

## 三、当前原型主要问题

### 1. 商品图片被弱化

当前很多页面使用：

```html
<div class="thumb-placeholder"></div>
<div class="img-placeholder"></div>
```

这不符合选品场景。商品图片是判断形态、材质、款式、差异化、是否可做的第一信息。

必须改成：

```text
真实 imageUrl 图片 + 失败占位 + 图片区域足够大
```

建议商品卡图片尺寸：

```text
卡片视图：160-220px 宽，高度稳定
表格视图：64-88px 缩略图
店铺上新流：96-120px 缩略图
```

### 2. 太表格化，缺少“商品卡片流”

当前 `新品雷达`、`新品起量榜`、`方法卡结果中心` 都主要是表格。

但我们现有系统已经有商品卡片组件：

```text
frontend/src/components/UniversalCard/index.vue
```

它已经支持：

- 商品图片
- ASIN
- 标题
- 店铺
- 类目
- 价格
- 销量 badge
- 等级 badge
- 上架时间
- 入库时间
- 一键打开
- 以图识图
- 选中此产品
- 多人选中状态

所以新增页面不能完全另起炉灶。应该复用或参考 `UniversalCard`。

### 3. 没有遵循当前项目技术栈

当前原型是静态 HTML，并引入：

```html
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser..."></script>
```

但项目实际技术栈是：

```text
Vue 3 + TypeScript + Element Plus + Vite + 模块 manifest
```

要求：

- 不要引入 Tailwind CDN。
- 不要写静态 HTML 页面。
- 不要写原生 DOM 操作脚本。
- 新页面必须做成 `frontend/src/modules/{module}/index.vue`。
- API 必须走 `frontend/src/utils/request.ts`。
- 表格/分页/弹窗/筛选控件优先用 Element Plus。

### 4. 颜色风格偏离当前系统

当前原型使用一套深色/Claude 风格：

```text
暗色背景 #1b1b19
卡片 #2c2c2b
Poppins
自定义 brand #d97757
```

但当前项目已有 Element Plus 管理后台风格和 `UniversalCard` 视觉。不要把页面做成独立暗色 app。

建议：

- 沿用当前系统背景、卡片、按钮和间距。
- 可以使用橙色作为强调，但不要整体重做设计系统。
- 页面应像现有系统的一部分，而不是另一个产品。

### 5. 信息字段仍然不够选品

当前表格虽然有 ASIN、标题、店铺、销量、BSR、价格，但缺了很多关键判断信息：

| 缺失字段 | 为什么重要 |
|---|---|
| `imageUrl` | 选品第一判断依据 |
| `productUrl` | 一键打开 Amazon |
| `similarUrl` | 以图识图/相似商品 |
| `parentAsin` | 去重/变体判断 |
| `variantCount` | 判断是否变体污染 |
| `availableDate` | 上架时间 |
| `listingDays` | 新品判断核心 |
| `createdAt` / `createdWeek` | 入库时间，不等于上架时间 |
| `batchDate` | 郑总/店铺数据批次 |
| `nodeLabelPath` | 完整榜单类目路径 |
| `bsrId` / `nodeId` | 可跳类目/品线 |
| `fulfillment` | M03/FBM 判断 |
| `weightG` | 轻小件判断 |
| `sellerId` | 店铺画像/店铺链接 |
| `selectedByUsers` | 多人协同选品 |
| `filterReasons` | 方法卡命中原因 |

### 6. 没体现“上架时间 vs 入库时间”的差异

我们现有 `UniversalCard` 已经特别处理：

```text
上架 Amazon(available_date) + 实时天数
入库时间(created_at)
```

这非常重要。一个商品可能上架很久，只是今天才被我们抓进来。当前原型没有把这个差异突出出来。

所有新品页面必须同时展示：

```text
上架：2026-07-01 · 6 天
入库：2026-07-07
```

### 7. 方法卡展示太浅

当前只是显示 M01/M02/M03 tag，但没有展示：

- 为什么命中
- 命中哪个条件
- 是否多卡重叠
- 当前方法卡是否默认应用
- 方法卡规则摘要
- 方法卡结果和普通筛选结果的区别

方法卡结果中心必须显示“命中原因”，否则用户不知道为什么这个商品值得看。

### 8. 店铺页面没有充分利用“店铺画像证据层”

店铺页面不能只是商品表和 A/B/C/D 饼图。我们的店铺画像系统已经有：

- A 层利润来源
- A+B 强候选池
- A+B+C 稳定盘
- D 测品池
- top A 类目
- top ABC 类目
- top D 类目
- D 与 ABC 类目重合
- 店铺基线相似度
- profileAdvice

这些应该成为店铺页面第一屏的核心解释。

### 9. 候选池缺少“证据来源”

候选池不是普通收藏夹。每个候选都要知道为什么进来：

```text
来自：新品起量榜
证据：M01 命中 + 上架 12 天 + units 87 + 郑总相似店出现 + 类目机会高
```

当前原型的候选池状态流可以保留，但商品项需要展示证据链。

## 四、当前项目真实前端上下文

### 2. 模块注册方式

新增页面不要改死路由，新增模块：

```text
frontend/src/modules/{module-name}/manifest.ts
frontend/src/modules/{module-name}/index.vue
```

manifest 示例：

```ts
import type { ModuleManifest } from '@/modules/types'

export default {
  id: 'new-product-radar',
  name: '新品雷达',
  icon: 'Star',
  menuGroup: '选品中心',
  menuOrder: 11,
  route: {
    path: 'new-product-radar',
    name: 'NewProductRadar',
    component: () => import('./index.vue'),
    meta: { title: '新品雷达', keepAlive: true }
  }
} satisfies ModuleManifest
```

### 3. 现有商品卡片

参考：

```text
frontend/src/components/UniversalCard/index.vue
```

它已经有选品卡片需要的大量能力。新增商品展示页应该优先复用：

```vue
<UniversalCard
  v-for="product in products"
  :key="product.id || product.asin"
  :product="product"
  mode="selection"
  :selected="selectedAsins.includes(product.asin)"
  :is-selected-by-me="mySelections.has(product.asin)"
  :selected-by-users="selectionUsersMap[product.asin] || []"
  @click="handleCardClick"
  @select="handleSelect"
  @toggle-select="handleToggleSelect"
  @view="handleView"
  @delete="handleDelete"
  @image-search="handleImageSearch"
/>
```

如果觉得 `UniversalCard` 信息还不够，可以新增一个专门的增强卡：

```text
SelectionProductCard.vue
```

但它必须继承当前卡片的信息结构，而不是重新做一个只显示 3 个字段的卡片。

## 五、页面改造方向

## 1. 今日选品工作台

### 当前问题

太像指标 dashboard，商品信息太少。每日工作台不仅要看数字，还要直接看到“今天最值得点开的商品”。

### 改造要求

保留顶部指标，但下面必须加入图片商品区：

```text
顶部：今日新增 / 本周新增 / 方法卡命中 / 优质店上新 / 待复查 / 候选池

主体：
左：今日重点新品 6-12 张商品卡
中：方法卡新增命中 6-12 张商品卡
右：待复查 / 候选池动态列表
底部：优质店铺上新横向商品流
```

每张商品卡至少显示：

```text
图片、ASIN、标题、店铺、units、BSR、价格、上架天数、方法卡、加入候选
```

## 2. 新品雷达

### 当前问题

当前是表格为主，图片只是 50px 占位。新品雷达应该像“商品流”，不是 Excel 表。

### 改造要求

默认视图改为：

```text
左侧筛选栏 / 顶部筛选条
中间：图片商品卡瀑布/网格
右侧：Top 类目、Top 店铺、A/B/C/D 分布
```

支持视图切换：

```text
卡片视图 / 表格视图
```

默认必须是卡片视图。

商品卡重点：

- 大图
- 销量 badge
- A/B/C/D badge
- 上架天数 badge
- 方法卡 tag
- 店铺名
- 类目路径
- 一键打开 / 以图识图 / 加入候选

## 3. 新品起量榜

### 当前问题

起量榜可以有表格，但图片太小，且缺少“为什么起量”的解释。

### 改造要求

做成“榜单式商品卡 + 紧凑表格”的混合：

```text
前 20 个用横向大商品行：
图片 96px + 标题/ASIN + 店铺/类目 + units/BSR/价格/天数 + 证据标签 + 动作

后续可用表格。
```

必须增加解释标签：

```text
短账龄
销量达 B
BSR 优秀
M01 命中
多卡重叠
优质店铺
```

## 4. 方法卡结果中心

### 当前问题

方法卡结果中心做成了普通表格，右侧规则说明还可以，但商品展示缺少图片主导和命中解释。

### 改造要求

布局建议：

```text
顶部：方法卡 Tabs + 站点/批次/类目筛选
左侧：方法卡规则与当前命中统计
右侧：商品卡片网格，支持切换表格
```

每个商品必须展示：

```text
命中方法卡
命中原因 filterReasons
基础数据：units / listingDays / bsr / price / weightG / fulfillment
商品图
店铺
类目
动作
```

不要只显示 M01 tag，必须解释为什么 M01。

## 5. 店铺画像

### 当前问题

店铺画像比其他页好，但商品列表还是表格重，店铺“样貌”没有通过商品图表达出来。

### 改造要求

单店详情页第一屏要分三层：

```text
1. 店铺结构指标：productCount、A/B/C/D、ABC、D、top A/ABC/D 类目、基线相似
2. 店铺样貌商品墙：A 层代表商品、ABC 稳定盘代表商品、D 测品代表商品
3. 明细表格：可筛选所有商品
```

店铺画像列表可继续表格，但单店详情必须有商品图片墙。

### 店铺样貌商品墙

建议模块：

```text
A 利润层代表商品：6 个
ABC 稳定盘代表商品：8 个
D 测品池代表商品：8 个
```

这样才能回答：

```text
这家店到底长什么样？
它卖什么？
它靠什么赚钱？
它在测什么？
```

## 6. 店铺上新流

### 当前问题

这个页面方向接近正确，但右侧商品仍然信息偏少，图片不够突出。

### 改造要求

保留左店铺列表 + 右商品流结构。

右侧商品必须是横向图片商品卡：

```text
图片 120px
标题/ASIN
units / salesTier / BSR / price
上架天数 / 入库批次
方法卡命中
类目路径
一键打开 / 以图识图 / 加入候选
```

左侧店铺卡应显示：

```text
店铺名
市场
总商品数
本批次新增
A/B/C/D 小条
top ABC 类目
是否郑总/自有/方法卡高命中基线
```

## 7. 类目机会榜

### 当前问题

类目页表格方向可以保留，但缺少“点进类目后看商品”的连接。

### 改造要求

类目机会榜本身可以是表格。

但点击类目后必须打开：

```text
类目机会详情抽屉 / 品线详情页
```

里面要展示：

- 类目代表商品图
- A 商品
- 起量新品
- 方法卡命中商品
- 优质店铺
- 郑总/自有店铺覆盖

否则类目机会榜只有指标，不能指导选品。

## 8. 选品候选池

### 当前问题

状态流可以，但候选商品缺少图片和证据链。

### 改造要求

候选池卡片必须展示：

```text
图片
ASIN / 标题
当前状态
来源页面
证据标签
关键数据快照
负责人
下次复查时间
备注
```

候选商品不是普通收藏，必须保存“为什么进入候选”。

证据示例：

```text
来自：新品起量榜
证据：M01 命中 / 上架 12 天 / units 87 / BSR 4213 / 郑总相似店出现 / Home & Kitchen 类目机会高
```

## 六、推荐商品卡信息结构

新增或复用一个增强商品卡：

```text
SelectionProductCard.vue
```

### 卡片布局

```text
┌──────────────────────────┐
│ 图片                     │
│ 左上：A/B/C/D            │
│ 右上：units              │
│ 左下：上架天数           │
│ 右下：方法卡 M01/M03     │
├──────────────────────────┤
│ ASIN + 复制              │
│ 标题，两行截断           │
│ 店铺名 / 类目            │
│ units / BSR / price      │
│ 上架日期 / 入库日期      │
│ 证据标签                 │
│ [打开] [以图识图] [候选] │
└──────────────────────────┘
```

### 必填字段

```text
imageUrl
asin
title / productTitle
sellerName / storeName
units / salesVolume
salesTier
bsr
price
listingDays
availableDate
createdAt / createdWeek / batchDate
nodeLabelPath / category
methodHits
filterReasons
productUrl
similarUrl
variantCount
```

### 视图模式

所有商品页建议支持：

```text
卡片视图：默认，用来看货
表格视图：用于批量比较和排序
```

## 七、给实现 AI 的明确要求

请不要继续按当前静态 HTML 原型直接实现。

必须按以下原则重做：

1. 商品展示页面默认使用图片卡片视图。
2. 表格只能作为辅助视图，不是默认视图。
3. 必须复用或参考 `UniversalCard`。
4. 必须用 Vue 3 + Element Plus，不要 Tailwind CDN。
5. 必须接真实 API，不要写死假数据。
6. 每个商品卡必须显示图片、ASIN、标题、店铺、类目、销量、BSR、价格、上架天数、方法卡、动作。
7. 新品页面必须区分上架时间和入库时间。
8. 店铺页面必须有商品图片墙，不能只有表格。
9. 方法卡页面必须展示命中原因。
10. 候选池必须展示证据链。

## 八、推荐第一轮修改顺序

不要一次重做所有页面。先改最影响体验的 4 个：

```text
1. 新品雷达：改成图片商品卡默认视图
2. 新品起量榜：改成榜单式大商品行
3. 方法卡结果中心：改成规则侧栏 + 商品卡片网格 + 命中原因
4. 店铺画像详情：增加 A/ABC/D 商品图片墙
```

第二轮再改：

```text
5. 店铺上新流：增强右侧商品卡
6. 候选池：增加图片和证据链
7. 今日工作台：加入重点商品卡区域
8. 类目机会榜：增加类目详情抽屉和代表商品
```

## 九、最终判断标准

改完后用户应该能做到：

```text
不用点详情，只看一屏，就知道：
这个商品长什么样；
为什么值得看；
来自哪个店铺/类目/方法卡；
销量和时间是否靠谱；
下一步是打开、以图识图、观察，还是加入候选。
```

如果页面只能看到数字和表格，而不能快速形成“这个货能不能做”的直觉，就还没有达到要求。
