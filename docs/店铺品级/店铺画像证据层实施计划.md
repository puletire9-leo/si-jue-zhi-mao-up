# 店铺画像证据层实施计划

> 目标：把“每一家店铺都能被结构化分析”沉淀为系统能力，后续前端可以进入单店详情页，直接理解一家店的商品结构、利润锚点、稳定盘、测品池、方法卡命中和类目方向。

## 一、当前结论

店铺分析不应该只放在方法卡消费层，也不应该只停留在商品基础特征层。后续商品数据处理、市场基线、店铺画像、商品族证据统一归入 `analysis-baseline 数据分析基线层`，方法卡和前端只消费这一层产出的证据。

最终分层建议：

```text
L0 原始数据层
↓
L1 数据底座层：原始数据 / 清洗数据 / 字典 / 归档
↓
L2 analysis-baseline 数据分析基线层：商品基础特征 / 市场基线 / 店铺画像证据 / 商品族证据
↓
L3 店铺定位消费层：方法卡 / 店铺基线 / 店铺评级 / 前端展示
```

其中店铺方向新增的核心是：

```text
analysis-baseline.shop-profile-evidence 店铺画像证据子模块
```

这一层类似选品方法里的“证据加工层”，但分析对象从单品变成店铺。它不单独脱离 `analysis-baseline`，而是作为其中一个子模块，与商品基础特征、市场销量基线、商品族证据并列。

## 二、为什么要新增店铺画像证据层

方法卡回答的是：

```text
这家店有多少商品命中某个合格标准？
```

店铺画像回答的是：

```text
这家店到底是什么结构？
它靠什么赚钱？
稳定盘在哪里？
测品池有多大？
类目是否集中？
是不是精铺测品飞轮？
```

这两个问题不同，所以不能把店铺画像全部塞进方法卡。

店铺画像证据层只产出事实和结构，不直接决定最终评级。最终“是否值得盯”“是否学习”“是否进入选品池”，由消费层根据业务目标决定。

2026-07-07 追加结论：后续不只要分析单店，还要能快速定位“这家店像谁、适合学什么”。因此 L3 需要明确增加一层“店铺基线库”和“店铺定位消费层”：

```text
店铺画像证据层：回答这家店是什么结构
店铺基线库：保存郑总基线、自有优质店基线、方法卡高命中店基线
店铺定位消费层：回答这家店像哪个基线、哪里像、哪里不像、值得学什么
```

同时，店铺画像证据也可以反哺单品选品。后续某些选品方法卡不再只看当前 ASIN 的即时销量，而会消费“商品族是否被多家优质店铺验证过”。例如一个爆款种子 30 天销量 50+，且相似商品在郑总相似店、自有优质相似店或方法卡高命中店中反复出现，那么一个刚上架 2 天暂无销量的相似 ASIN，也可能被“爆款多店验证法”提前圈出。

对应总卡见：

```text
docs/选品方法库/2_数据加工/analysis-baseline_数据分析基线层.md
```

### 6. 精铺画像原型已验证

已形成核心解释：

```text
A：利润答案
A+B：确定性盈利 / 强候选池
A+B+C：店铺稳定经营画像和主打法
D：测品池 / 未起量池，需要叠加时间判断
```

对精铺型店铺，重点不是只看 A 多不多，而是看：

- C 是否足够厚
- D 是否足够多
- A+B 是否能覆盖试错
- D 是否围绕 ABC/A 已验证方向继续测
- 老 D 是否过多

## 四、目标系统能力

### 1. 店铺列表页

用于筛选和比较店铺。

核心字段：

| 字段 | 含义 |
|---|---|
| marketplace | 国家 |
| sellerName | 店铺名 |
| productCount | 不含变体商品数 |
| A/B/C/D/UNKNOWN | 销量等级数量 |
| aRatio | A 占比 |
| abCount / abRatio | A+B 强候选池 |
| abcCount / abcRatio | A+B+C 稳定盘 |
| dCount / dRatio | D 测品池 |
| topACategory | A 层主类目 |
| topABCCategory | ABC 主打法类目 |
| topDCategory | D 测品类目 |
| methodHitCount | 当前方法卡命中数 |
| profileType | 店铺结构标签 |
| latestBatchDate | 数据批次 |

### 2. 单店详情页

用于理解一家店。

建议模块：

| 模块 | 作用 |
|---|---|
| 店铺总览 | 商品数、A/B/C/D、ABC、D 占比 |
| 销量等级分布 | 看利润锚点、稳定盘、测品池 |
| A/B/C/D 商品明细 | 每个等级有哪些商品、ASIN、链接、榜单类目 |
| 榜单类目结构 | A、ABC、D 的 top 类目 |
| 上架时间 × 销量等级 | 区分新测品和老失败品 |
| 方法卡命中 | 这家店在 M01/M03/未来方法卡中产出多少合格品 |
| 原始商品列表 | 可搜索、筛选、排序 |

### 3. 方法卡店铺排名页

用于回答：

```text
按某张方法卡标准，哪些店铺持续产出合格品？
```

这页可以消费店铺画像层，但主排序仍由方法卡命中数决定。

### 4. 店铺画像页

用于回答：

```text
这家店是否是成熟精铺？
它的利润方向和测品方向是什么？
值得我学习哪一部分？
```

这页主排序可以按：

- ABC 厚度
- A+B 健康度
- D 测品规模
- D 与 ABC 类目重合度
- 老 D 风险
- 方法卡命中数

### 5. 店铺基线库

用于把已经验证过的优质店铺集合沉淀成可复用参照物。

第一批建议基线：

| 基线 | 含义 | 用途 |
|---|---|---|
| 郑总 UK/DE 基线 | 已验证的精铺样本 | 寻找郑总相似结构店铺 |
| 自有优质商品相似店基线 | 我们自有商品跑出来的优质方向对应店铺 | 寻找可复制竞品店 |
| 方法卡高命中店基线 | 在 M01/M03/未来方法卡中持续产出合格品的店铺 | 寻找稳定新品来源 |
| 类目专项基线 | 某个类目内表现好的店铺集合 | 做垂类扩展和专项学习 |

基线不是一条固定规则，而是一组已验证店铺的画像统计结果。后续新增一家店时，可以和某个基线对比，快速判断它是否值得盯。

### 6. 店铺定位消费层

用于回答：

```text
这家店像不像郑总？
这家店像不像我们的自有优质店？
它哪里像，哪里不像？
它值得学习的是 A 层利润方向、ABC 稳定盘，还是 D 层测品方向？
```

定位层不应只输出一个分数，而要输出解释：

| 维度 | 解释 |
|---|---|
| ABC 稳定盘相似度 | 判断店铺主打法是否接近基线 |
| A 层利润类目相似度 | 判断最终跑出来的赚钱方向是否接近 |
| D 测品池相似度 | 判断测品规模和铺货动作是否接近 |
| D 与 ABC 类目重合度 | 判断测品是否围绕已验证方向继续铺 |
| 方法卡命中相似度 | 判断合格新品产出能力是否接近 |
| 老 D 风险差异 | 判断是否存在大量长期未起量商品 |

推荐前端解释示例：

```text
这家店接近郑总 UK 精铺基线：
- ABC 稳定盘接近
- D 测品池偏小，持续铺货动作弱一些
- A 层利润类目集中在 xxx
- D 层测品类目和 ABC 重合度高，不像乱铺
- M01 命中数中等，但 C 层较厚，适合继续观察
```

## 五、数据模型建议

后续商品数据处理统一归到 `analysis-baseline`，而不是散落在方法卡、店铺分析和前端页面里。

建议子模块：

| 子模块 | 职责 | 当前状态 |
|---|---|---|
| product-feature | 商品基础特征 | 已有 `ProductFeatureProcessor` |
| market-baseline | 市场销量基线 / M04 新品分级 | 已有 `SalesBaselineService`、`CategoryAgeTierBaselineService` |

## 十、验收标准

### 数据口径验收

- 店铺商品数默认不含变体。
- 卖家精灵请求使用 `variation=Y`。
- 列表商品数与亚马逊店铺页口径一致，而不是含变体子 ASIN 数。

### 后端验收

- 任意店铺能返回 A/B/C/D 分布。
- 任意店铺能返回每个等级的商品明细。
- 店铺列表支持国家、批次、店铺名筛选。
- 聚合结果与离线 Excel 可对上。

### 前端验收

- 用户能从店铺列表进入单店详情。
- 用户能看到这家店 A/B/C/D 各有多少商品。
- 用户能点开 A/B/C/D 查看 ASIN、链接、榜单类目。
- 用户能判断这家店的利润锚点、稳定盘和测品池。

### 业务验收

- 能回答“这家店靠什么赚钱？”
- 能回答“这家店稳定盘在哪里？”
- 能回答“这家店是否大量测品？”
- 能回答“这家店值得学习哪些类目/打法？”
- 能回答“这家店像不像郑总？”
- 能回答“这家店像不像我们的自有优质店？”
- 能回答“这家店和基线相比，优势和缺口在哪里？”
- 能和方法卡命中数并列使用，而不是互相替代。

## 十一、最终定位

店铺画像证据层不是方法卡，也不是最终评级。

它是店铺分析的中间证据层：

```text
商品数据 → analysis-baseline → 店铺画像证据 / 商品族证据 → 方法卡排名 / 店铺详情 / 人工决策
```

只有这样，后续系统才能同时支持：

- 按方法卡找店铺
- 按店铺结构理解店铺
- 按单店详情学习打法
- 按郑总/自有优质店基线快速定位相似店铺
- 按优质店铺共同验证过的商品族反哺单品选品方法
- 按历史批次观察店铺变化
