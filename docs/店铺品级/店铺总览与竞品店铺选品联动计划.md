# 店铺总览与竞品店铺选品联动计划

## 背景

当前系统已经形成两条相邻但还没有完全打通的链路：

```text
选品中心 / 竞品店铺：
读取旧选品数据源，主要按商品列表查看。

店铺总览 / 店铺全集画像：
读取 shop_products，按店铺画像、三维结构、请求中心抓取快照查看。
```

问题在于：用户想研究“某一家竞品店铺具体有哪些商品值得看”时，不应该先跳到选品中心的旧“竞品店铺”商品池。正确入口应该是：

```text
店铺总览 -> 店铺列表 -> 单店画像 -> 店铺商品数据详情
```

也就是说，“竞品店铺选品”不再是一个孤立的选品中心页面，而应成为店铺画像里的商品下钻视图。

## 总原则

1. **店铺维度入口归店铺总览**

   凡是先选店铺、再看该店商品，都从店铺总览进入。

2. **商品维度入口归选品中心**

   凡是先看商品、再判断商品能不能做，仍在选品中心和方法卡页。

3. **店铺全集商品数据源统一为 `shop_products`**

   店铺总览里的商品详情不再读取旧 `competitor_products_clean/reference` 口径，而读取：

   ```text
   GET /api/v1/modules/shop-collection/{marketplace}/{sellerName}/products
   ```

4. **旧竞品店铺页保留但降级**

   旧 `reference-products` 可暂时保留为历史导入/旧竞品商品池视图，但不再作为“研究某个店铺”的主入口。

## 目标链路

### 1. 店铺总览列表

页面：店铺总览 / 店铺全集画像

数据源：

```text
GET /api/v1/modules/shop-collection/selection-shops
```

展示字段：

- 店铺名
- 市场
- 最新批次 / 快照
- 商品数
- M01 命中数
- 新品 ABC 数
- 好品倾向数
- 强注意 / 需复核数
- 三维店铺类型
- top 类目

点击店铺行后进入单店详情。

### 2. 单店画像详情

页面：店铺总览 / 单店画像

数据源：

```text
GET /api/v1/modules/shop-collection/{marketplace}/{sellerName}/insight
```

展示结构：

```text
单店画像
├─ 总览：店铺类型、商品数、M01、新 ABC、老 D、平均销量、平均上架天数
├─ 三维矩阵：销量 × 时间、销量 × 注意/倾向、时间 × 注意/倾向
├─ 类目结构：A/B/C/D top 类目、好品倾向 top 类目、强注意/需复核类目
├─ 商品数据详情：按三维条件筛商品
├─ 商品墙：图片主导，按 A/B/C/D 或新品/好品倾向分区
└─ 历史对比：不同快照新增、消失、升级、降级
```

### 3. 店铺商品数据详情

这是旧“竞品店铺选品”的主要迁移目标。

数据源：

```text
GET /api/v1/modules/shop-collection/{marketplace}/{sellerName}/products
```

筛选条件：

- `salesTier`：A/B/C/D/UNKNOWN
- `ageBucket`：NEW/GROWING/MATURE/OLD/UNKNOWN
- `attentionLevel`：GOOD_TENDENCY/NEUTRAL/ATTENTION_REVIEW/ATTENTION_STRONG/UNKNOWN
- `m01Only`：只看 M01 命中
- `category`：类目
- `keyword`：标题关键词

展示字段：

- 图片
- ASIN
- 商品标题
- 30 天销量 / units
- 销量层
- 时间层
- M01 是否命中
- 注意/倾向层
- 类目路径
- 上架时间 / listing_days
- 价格、评分、评论数、BSR
- 亚马逊链接

点击商品后可以继续跳转到已有商品详情组件或选品详情页，但数据来源必须标记为：

```text
source = shop_products
marketplace
sellerName
sourceRunId
asin
```

## 前端调整建议

### 1. 店铺总览新增详情页或详情抽屉 Tab

当前 `frontend/src/modules/shop-collection-shops/index.vue` 已经有列表和单店抽屉基础。下一步建议把抽屉升级为明确的 Tab：

```text
Tab 1：画像总览
Tab 2：商品数据
Tab 3：商品墙
Tab 4：历史对比
Tab 5：抓取快照
```

其中“商品数据”就是迁移后的竞品店铺选品视图。

### 2. 旧竞品店铺入口改名或加提示

**注意实现现状**：`reference-products` 模块的 `manifest.ts` 的 `component` 直接指向
`@/views/AllSelection/index.vue`，也就是它和“全站选品”很可能共用同一个视图组件。所以：

- 改名（`竞品店铺` -> `历史竞品商品池`）只需改 `reference-products/manifest.ts` 的 `name / meta.title`，成本低；
- 加“顶部提示”必须**按当前路由名判断**（如 `route.name === 'ReferenceProducts'`）才显示，
  否则会污染 AllSelection 的其它入口。不要无条件在 AllSelection 视图里加提示。

建议顶部提示文案：

```text
这里展示历史导入/旧竞品商品数据。按店铺研究商品，请进入「店铺总览 -> 店铺全集画像」。
```

避免用户误以为这里就是最新的店铺全集。

### 3. 从选品中心跳店铺

选品中心如果某个商品带有 `sellerName / marketplace`，应提供“查看店铺画像”按钮：

```text
跳转到：店铺总览 / 店铺全集画像
参数：marketplace + sellerName
动作：自动打开对应店铺详情
```

如果该店铺还没有抓取全集，则提示：

```text
该店铺尚未抓取全集，可加入候选池或创建请求中心任务。
```

## 后端现状

已具备：

- `selection-shops`：店铺列表与筛选。
- `insight`：单店画像。
- `products`：单店商品明细三维筛选。
- `product-wall`：商品墙。
- `snapshots`：快照列表。
- `compare`：快照对比。

当前不需要为了这次前端联动新增表。

### 后端已知缺口与约束（审查补充）

1. **`ShopProfileProduct` 缺 `ageBucket` 字段**

   `products` 接口目前只在 `attachProductLabel` 里补了 `attentionLevel / attentionReason / labelMeaning`，
   SQL 的 `age_bucket` 是查询内计算列，没有出现在 select 字段里。要让“商品数据”表展示时间层，
   需要后端 select 补 `age_bucket AS ageBucket` 并让 `ShopProfileProduct` 带上该字段（本次实现已补齐）。

2. **注意/倾向层筛选有 20000 候选上限**

   注意层不是落库字段，必须逐商品按 `categoryLeaf + nodeLabelPath` 精确打标签。
   实现走的是“先 SQL 下推销量层/时间层/M01/关键词/类目，再在候选集内 Java 侧过滤+分页”。
   当候选商品超过 20000 会抛异常，要求先缩窄其它维度。前端在“商品数据”Tab 选注意层筛超大店时，
   必须捕获该错误并提示用户先按销量层/时间层/关键词收窄，不能让报错直接弹给用户。

3. **`selection-shops` 列表三维字段是请求时计算**

   列表页的“新品 ABC / 好品倾向 / 强注意 / 三维类型”由 `enrichSummary3d` 批量查
   `selectTierAgeCategoryCellsBatchFromShopProducts` 再逐 cell 分类得到，不落库。
   默认 100 家店时是一次大聚合 + 全量 Java 分类。店多或类目碎时需评估是否加商品级标签缓存表
   （见“还差的能力”第 3 条），当前规模先接受请求时计算。

可能需要补充的后端增强：

1. 商品详情适配接口

   如果现有商品详情组件强依赖 `competitor_products_clean` 字段，可新增轻量适配接口：

   ```text
   GET /api/v1/modules/shop-collection/{marketplace}/{sellerName}/products/{asin}
   ```

   但优先建议前端复用 `products` 列表返回字段和已有详情组件。

2. 跳转定位接口

   如果前端需要从选品中心跳店铺并自动定位快照，可复用：

   ```text
   GET /api/v1/modules/shop-collection/{marketplace}/{sellerName}/snapshots
   ```

   默认取最新成功快照即可。

3. 未抓取店铺判断（统一信号）

   `insight` 在无成功快照时会抛 `IllegalArgumentException`，前端若直接调 `insight` 会当成错误弹窗。
   统一约定：**跨页面跳转判断“该店有没有抓过全集”，一律先调 `snapshots`**：

   ```text
   snapshots 返回空数组 -> 该店尚未抓取全集 -> 显示引导：可加入候选池或创建请求中心任务
   snapshots 非空       -> 取最新成功快照 sourceRunId -> 再调 insight / products
   ```

   不要用 `insight` 抛异常来判断未抓取，避免前端吞异常或误报。对应引导文案：

   ```text
   该店铺尚未抓取全集，可加入候选池或创建请求中心任务。
   ```

## 下一阶段实现顺序

### 阶段 A：前端联动收口（已完成）

> **提示**：当前 `shop-collection-shops` 抽屉是平铺结构（画像总览 + 商品明细同屏）。
> “增加详情 Tab”不是接一个接口，而是一次结构性重构，需拆成三小步做：

1. [x] 抽屉 Tab 化：用 `el-tabs` 分出 画像总览 / 商品数据 / 商品墙 / 历史对比 / 抓取快照，各 Tab 懒加载。
2. [x] 内容迁移：把现有平铺的画像/商品明细/商品墙/对比分别搬进对应 Tab，避免重复请求。
3. [x] 把“商品数据”Tab 接到 `shopCollectionApi.shopProducts`，支持三维筛选、分页、图片、ASIN 链接。
4. [x] 商品行支持打开商品详情或亚马逊链接；时间层列用后端补齐的 `ageBucket` 字段（并补 `listingDays` 上架天数列）。
5. [x] 注意层筛选要捕获后端 20000 上限异常，提示先按销量层/时间层/关键词收窄。
6. [x] 旧竞品店铺页按路由名加提示或改名：`reference-products` 改名「历史竞品商品池」，`AllSelection` 按 `route.name==='ReferenceProducts'` 显示降级提示。

### 阶段 B：跨页面跳转（基本完成，待浏览器实跑）

1. [x] 从店铺列表点击进入单店详情。
2. [x] 从选品中心商品行点击“查看店铺画像”：`ProductDetailDialog` 在商品带 `storeName+marketplace` 时显示按钮，跳转带 `tab=products`。
   - `SelectionDetail` 的商品对象不带 marketplace 字段，无法可靠跳转，暂未加（其店铺链接是外部亚马逊链接）。
   - 已补标准市场码归一化，只允许跳转 `UK / DE / US`，避免把中文国家或小写国家直接传给后端。
3. [x] 从候选池、观察池、精品池跳到对应店铺画像（已存在，核对路由名 `module-shop-collection-shops-ShopCollectionShops` 一致）。
4. [x] 路由 query 统一，店铺画像页 `onMounted` 支持：

   ```text
   marketplace
   sellerName
   sourceRunId（可选）
   tab=products / overview / wall / compare / snapshots
   ```

5. [x] 同一路由内 query 变化已支持响应：从一个商品详情跳另一个店铺时，店铺全集画像页会重新打开目标店铺；只切换 `marketplace` 时会刷新列表。

> 待办：跨页跳转仅核对路由名与参数，未在浏览器实跑体验，尤其 `ProductDetailDialog` 新按钮与未抓全集引导。

### 阶段 C：商品详情复用

> **前置盘点**：现有选品中心详情组件大概率吃 `competitor_products_clean` 字段结构，
> 而 `ShopProfileProduct` 的字段名（salesTier / nodeLabelPath / categoryLeaf / units / availableDate...）未必对齐。
> 阶段 C 动手前必须先做**字段映射盘点**：列出详情组件所需字段 -> `ShopProfileProduct` 对应字段 -> 缺口。
> 若缺口大到组件改造不划算，再启用被列为“可选”的 `GET /products/{asin}` 适配接口。

0. 字段映射盘点：详情组件所需字段 vs `ShopProfileProduct`，确认能否直接复用。
1. 统一商品卡片字段适配：`competitor_products_clean` 与 `shop_products` 共用展示组件。
2. 在商品详情里显示来源：

   ```text
   来源：店铺全集 / 新品榜 / 历史竞品商品池
   ```

3. 商品详情内展示店铺画像摘要：

   ```text
   该商品来自哪家店，该店是什么三维类型，M01 命中多少，新 ABC 多少。
   ```

### 阶段 D：方法卡与店铺画像互相反哺

1. M01/M03/Mxx 命中统一进入方法卡命中缓存。
2. 店铺画像商品详情可以按任意方法卡命中过滤。
3. 选品中心可以读取店铺画像证据，显示“来自优质画像店铺”。
4. 后续 M06 多店验证法消费店铺画像与商品族证据。

## 还差的能力

1. M03/Mxx 方法卡命中还没有统一进入店铺画像筛选。
2. 注意/倾向规则还没有配置化和版本化。
3. 商品级标签还没有缓存表，大批量筛选时仍是请求时计算。
4. 精品店铺周期复抓后的市场洞察还没展开。
5. 多店同品/相似品分析还没接入店铺总览。
6. 阶段 C 未做：商品详情组件与 `ShopProfileProduct` 的字段映射盘点与展示组件复用。
7. 阶段 B 跨页跳转已接线，但未在浏览器实跑验证体验。

> 已收口：店铺总览与选品中心的跳转参数规范（阶段 B）、旧竞品店铺页与新店铺商品详情的职责分离（阶段 A）。
> 已修复：静态 `/reference-products` 标题、同页 query 跳转响应、商品详情跳转市场码归一化、`listingDays` 前端类型。

## 关键结论

下一步不是再新增一个孤立页面，而是把入口理顺：

```text
店铺相关：全部归店铺总览。
商品相关：全部归选品中心。
从店铺看商品：店铺总览里的商品数据详情。
从商品看店铺：选品中心跳回店铺画像。
```

这样“总览 -> 分析 -> 店铺详情 -> 店铺商品数据详情”才是一条完整链路。
