# 商品基础销量分级

这是商品基础特征处理层的辅助字段，不是方法卡片本身，也不直接决定商品是否合格。

## 分级规则

| 月销量 units | 基础销量分级 |
|-------------|--------------|
| >= 100 | A |
| 50-99 | B |
| 15-49 | C |
| 0-14 | D |
| 空值 | UNKNOWN |

## 定位

商品销量分级用于后续分析和决策，属于“数据处理层”的通用基础特征。

方法卡片属于“消费层”，可以引用这个基础特征，但每张方法卡必须保持独立筛选逻辑。例如未来可以有一张新方法卡专门消费 `sales_tier IN ('A', 'B')`，但 `sales_tier` 本身不等于方法卡命中。

## 店铺模型里的用法

建立店铺模型时，不能把 A/B/C/D 简单理解成“好/坏”。销量等级更像商品生命周期里的阶段信号：

- A 级：已经被市场验证过的利润锚点，代表店铺“最终靠什么赚钱”。
- B 级：强候选利润品，通常已经具备稳定销量，但还未达到 A 级强度。
- C 级：稳定小单或潜力池，是判断店铺主打法和可复制方向的重要样本。
- D 级：未起量商品，可能是新品/测品，也可能是长期失败品，必须叠加时间判断。
- UNKNOWN：数据缺失，不能直接用于正负判断。

因此：

| 观察口径 | 适合回答的问题 | 不适合回答的问题 |
|---------|---------------|----------------|
| A | 这家店最终跑出来的利润方向是什么 | 这家店完整打法是什么 |
| A+B | 这家店的确定性盈利/强候选池在哪里 | 这家店的测品能力如何 |
| A+B+C | 这家店较稳定的经营画像和主打法 | 哪些新品刚开始测试 |
| D | 这家店的测品池规模、铺货方向、未起量库存 | 不能不看时间就判定垃圾 |

这类分布是店铺分析的辅助证据；真正的店铺命中数仍由选择的独立方法卡片计算。

## 店铺商品数量口径

店铺维度默认采用“不含变体”的父体商品口径。

原因：

- 亚马逊店铺页面显示的总商品数，本质上是不含变体的父体商品数量。
- 店铺画像要回答的是“这家店铺有多少独立商品方向、这些方向分布在哪些销量层级”，而不是颜色、尺寸、套装等子变体数量。
- 卖家精灵含变体数据会把同一父体下多个子 ASIN 重复计入，容易放大商品数、销量分布和店铺规模。

因此后续店铺筛选、店铺画像、销量分级、店铺品级统计默认使用：

```text
SellerSprite competitor-lookup
variation=Y
```

即不含变体口径。只有在专门研究变体策略、子 ASIN 表现、颜色/尺寸/套装结构时，才使用 `variation=N` 抓取含变体数据。

## 精铺店铺模型里的解释

对精铺型卖家，销量分级分布不应按“精品店”逻辑解读。

精品店倾向于：

```text
SKU 少，A/B 占比高，单品吃透
```

精铺店更接近：

```text
大量 D 测品
部分 D 升 C
少量 C/B 升 A
A+B 的利润覆盖 D 的试错亏损
下一批继续复制
```

所以判断一家精铺店是否值得学习，重点不是只看 A 多不多，而是看：

- D 是否足够多：说明是否有持续测品动作。
- C 是否足够厚：说明测品是否能沉淀出稳定小单池。
- A+B 是否健康：说明利润端是否能覆盖试错成本。
- D 的类目方向是否和 ABC/A 有重叠：说明测品是否围绕可验证方向，而不是乱铺。
- 老 D 是否过多：如果 D 商品上架时间很久仍未起量，应视为低效库存或失败品。

## 必须叠加时间维度

D 级不能直接等于失败品，也不能直接等于新品。必须叠加上架时间：

| 组合 | 解释 |
|------|------|
| 新 D | 正常测品，还不能判死 |
| 老 D | 长期未起量，倾向失败品/低效品 |
| 新 C | 有潜力，值得继续观察 |
| 老 C | 稳定小单，可能是长尾利润品 |
| B | 稳定强候选利润品 |
| A | 已验证核心利润品 |

后续店铺品级分析模型应增加二维视图：

```text
销量等级 × 上架时间分层
```

这能区分“测品池”与“死品池”，也能判断一家店是否有持续把 D/C 推升到 B/A 的能力。
