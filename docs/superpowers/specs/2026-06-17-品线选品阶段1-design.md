# 品线选品 · 阶段1 设计文档

> 日期：2026-06-17
> 范围：品线排序 + 人工选品（纯 SQL，无 AI）
> 状态：设计已评审，待实现

## 背景与目标

把"品线选品"模块理顺成清晰的两阶段。本次只做**阶段1**：用郑总店铺数据当"品线盘子"为竞品品线排序，人工从竞品表选品入库。AI 选品（阶段2）只在文档末尾锚定方向，不实现。

核心定位（来自 `docs/选品算法/重要思想.md`）：
- `deng_zong_shop`（郑总）= 学方法论的**排序盘子**
- `competitor_products`（竞品）= 实际**选品池**
- 算法是"排序器"不是"守门员"，决策权永远在人

## 1. 整体架构与阶段边界

```
阶段1 品线排序 + 人工选品  ← 本次设计&实现（纯 SQL，无 AI）
  ① 品线树：竞品全量(L1→L2)，按郑总盘子排序
  ② 点开一条线 → 竞品商品列表 + 基础筛选
  ③ 人工勾选 → 加入选品库 / 导出
        │
        ▼ （人自己挑出好品线，隐式衔接，不在本阶段产出）
阶段2 AI 选品 agent  ← 未来演进，仅锚定方向（见第 5 节）
```

阶段1 **不做什么**：
- ❌ 不调任何 AI / 大模型 / SSE
- ❌ 不碰 `product_line_guidance` / `analysis_batches` / `product_line_elements`（阶段2 的表）
- ❌ 不动 `selection-agent-v2` 和已废弃的 8011 分析页
- ❌ 不产出"已确认品线"状态（人后续自己挑）

阶段1 **做什么**：重写品线树排序契约 + 竞品商品列表 + 基础筛选 + 选品入库；**含禁止类目硬排除**（19 类，纯规则，属阶段1 范畴）。

## 2. 后端契约重定义

阶段1 只需**两个端点**，职责单一。按"Controller 只校验路由 → Service 写逻辑 → Mapper 查数据"分层，修掉现在 `ProductLineController` 直接注入 Mapper 的违规。

### 端点 1：品线排序树

```
GET /api/v1/product-line/tree?marketplace=UK&month=202605
```

| 维度 | 规则 |
|------|------|
| 树主体 | `competitor_products` 全量（该 marketplace+month），L1=bsr_id → L2=node_id |
| 禁止类目 | 19 类黑名单（存 `api_config`）在 SQL 层排除（见第 4 节） |
| 郑总盘子 | `deng_zong_shop` 自己的**最新 batch_date**（与竞品 month 解耦） |
| L1 排序 | 郑总验证线（郑总数 ≥ `MIN_ZENG=3`）在前，按郑总商品数降序；其余按竞品数降序 |
| L2 排序 | 每个 L1 内：郑总数降序 → 竞品数降序 |
| 标记 | 每个 L1/L2 带 `isZheng`、`zhengCount`、`count` |

返回结构：
```json
{
  "marketplace": "UK", "month": "202605",
  "zhengBatchDate": "20260617",
  "productLines": [
    { "bsrId": "...", "bsrName": "...", "count": 320, "zhengCount": 45, "isZheng": true,
      "subCategories": [
        { "nodeId": "...", "nodeName": "...", "count": 88, "zhengCount": 12, "isZheng": true }
      ] }
  ]
}
```

### 端点 2：某品线下的竞品商品列表

```
GET /api/v1/product-line/products?marketplace=UK&month=202605
    &bsrId=...&nodeId=...
    &priceMin=&priceMax=&ratingMin=&bsrMax=&weekTag=
    &page=1&pageSize=50&sortBy=units
```

- 数据源 `competitor_products`，**和树同一个 month**（口径对齐）
- 父体去重（`groupByParent`），保留表现最好的 1 条
- 禁止类目同样排除
- 返回 `{ list, total, page, pageSize }`

### 阶段1 不调用（代码保留给阶段2）

`/aggregated-data`、`/analysis-results`、`/guidance`、`/elements`、`/model/*`、`getDengZongShopList`。郑总从"可浏览的数据模式"降级为"只参与排序的盘子"。

### 郑总批次统一规则（已写入 `java-backend/CLAUDE.md` 铁律 #8）

郑总盘子批次解析全系统只走 `DengZongShopService.getMaxBatchDate(marketplace)`，未传则 `resolveBatchDate` 回退最新批次。郑总聚合**只按 `marketplace + batch_date`，禁止再 AND `month`**（`batch_date` 已唯一标识快照，叠加独立 `MAX(month)` 会误杀跨月行）。竞品表按业务 `month` 过滤——两条线各自单一真相源。

落地：`/tree` 的 `selectZhengNodeCounts` / `selectZhengBsrIdsOrdered` 去掉 `month` 参数；`zhengBatchDate` 与 `/deng-zong-shop/max-batch-date` 同源同值；前端不再自拼批次。

## 4. 禁止类目排除机制 + 边界处理

### 禁止类目排除

19 类禁止类目是亚马逊一级大类名。竞品表层级在 `node_label_path`（冒号分隔）。

- **匹配方式**：按 L1 段精确匹配 —— 取 `node_label_path` 第一段（`split(':')[0]`）落在黑名单则排除。禁止类目本就是一级大类，精确匹配最干净，避免全路径包含的误伤。
- **执行顺序**：禁止类目是**行级过滤，先于聚合**。即先按 `node_label_path` 第一段剔除黑名单商品行，剩余行再按 `bsr_id`(L1)/`node_id`(L2) 聚合成树。`node_label_path` 仅用于禁止类目判断，树的分层维度仍是 `bsr_id`/`node_id`。
- **存储**：黑名单存 `api_config` 表（`config_key='forbidden_categories'`，值为 JSON 数组），不硬编码。Service 启动加载 + 缓存。
- **应用位置**：`/tree` 和 `/products` 两端点 Service 层统一过滤。

### 边界处理（对齐"数据不完美是常态"）

| 场景 | 处理 |
|------|------|
| 郑总无任何批次（`getMaxBatchDate` 返回 null） | 树正常出（竞品全量），所有线 `isZheng=false`/`zhengCount=0`，只按竞品数降序，不报错 |
| 某竞品月份无数据 | `/tree` 返回空 `productLines`，前端提示"该月份暂无竞品数据" |
| 某条线下竞品商品为空 | `/products` 返回空列表，前端提示"该品线暂无商品" |
| `node_label_path` 为空/格式异常 | 归入"未分类"或跳过，不进树主干，记 warn 日志 |
| 黑名单配置缺失/解析失败 | 降级为"不排除"（宁可多显示，不挡整棵树）+ warn 日志 |

## 5. 阶段2 未来演进（仅锚定，不实现）

```
阶段2 = 统一为一个"选品 agent"（hermesagent 改造，Hermes 当 runtime）
  能力构成：
    - 配方提取    ← selection-agent-v2 已有（preprocess + DeepSeek），改造成 agent 工具
    - 品线评分    ← 旧 LangGraph 遗产（机会分6维/CR3/生命周期/Go-NoGo），重写为工具
    - 竞品商品推荐 ← 新增缺口（把"望远镜"变"地图"）
  对接设计：
    → docs/选品算法/    （L1硬筛→L2软评分→L3深度分析、百分位基线、品类专属权重、反馈闭环）
    → docs/ai结合分析/  （六层方法论、9嵌入点、Agent架构）
  底层原则（docs/选品算法/重要思想.md）：
    算法是排序器非守门员 · 红海也测品 · "好"是相对的 · 竞品是望远镜 · 决策权在人
  衔接：阶段1 产出"郑总排序的竞品品线树 + 人工选品"，人挑出好品线后，
       阶段2 agent 对选定品线做评分+推荐
```

现状关键事实（供阶段2 规划参考）：
- 旧 `selection-agent/`（11 节点 LangGraph + SSE）已删除，仅存 git 历史；前端 `productLineAnalysis.ts` 调的 `/selection/analyze` 后端已不存在（悬空），8011 现仅为只读 JSON 服务。
- `selection-agent-v2` 当前不是 agent，是借 Hermes 壳的"ETL + 单步 DeepSeek 批处理脚本"，只读郑总数据；Hermes 框架与选品业务零耦合，可作 runtime 复用。

**重点保的两个回归**（本次理顺的核心价值）：
1. **口径一致**：树和商品列表用同一 month，杜绝"树里有、点进去没货"。
2. **批次统一**：郑总盘子只按 batch_date，去掉 month 后跨月行不被误杀。
