# 选品算法 — 系统集成与工作流设计

> 01-05文档定义了选品算法"是什么"。本文档定义"怎么串联"——算法如何嵌入现有系统、用户每天怎么用、新旧评分如何过渡。

---

## 一、现有系统全景

### 1.1 现有页面结构

系统已有完整的选品展示层，选品算法需要**嵌入**而非替换：

| 页面/组件 | 现有能力 | 选品算法新增 |
|----------|---------|------------|
| **AllSelection**（全选品页） | Tab切换（新品榜/竞品/郑总/全部）、列表+卡片、导入导出 | 新增"选品评分"排序、"选品等级"筛选 |
| **SelectionQueryForm** | 分类/等级/国家/筛选模式/日期/排序 | 新增 `selection_grade` 筛选、选品评分排序选项 |
| **UniversalCard** | 展示grade(S/A/B/C/D)、filterMode、时效标签 | 新增 `selection_grade`（S1/S2/S3/X）标签、8维雷达图缩略 |
| **ScoringConfigPanel** | 4维评分配置（listing_age/sales_volume/bsr_rank/price） | 新增8维选品评分配置面板 |
| **ProductDetailDialog** | 商品详情弹窗 | 新增"AI分析报告"Tab（竞品格局/趋势/蓝海匹配） |

### 1.2 现有评分体系

当前系统已有 **4维评分**（ScoringService）：

| 维度 | 权重 | 数据库字段 |
|------|------|-----------|
| listing_age | 可配 | `listing_days` |
| sales_volume | 可配 | `units` |
| bsr_rank | 可配 | `bsr` |
| price | 可配 | `price` |

等级：S(≥90) / A(≥80) / B(≥65) / C(≥50) / D(<50)

**关键问题**：选品算法的8维评分与现有4维评分是什么关系？

### 1.3 现有时间维度

当前系统以 `week_tag`（如 "2026-W23"）标识数据批次，前端有"本周/往期"筛选。

选品算法以 `month`（如 "2026-05"）为全局控制器。

**关键问题**：`week_tag` 和 `month` 如何共存？

## 二、新旧评分的关系

### 2.1 两套评分并存，各有职责

| 维度 | 4维评分（现有） | 8维选品评分（新增） |
|------|---------------|-------------------|
| 职责 | 评估商品"当前表现" | 评估商品"是否值得开" |
| 视角 | 回看（过去表现好不好） | 前看（未来值不值得做） |
| 等级 | S/A/B/C/D | S1/S2/S3/X |
| 使用者 | 运营日常看数据 | 选品决策时判断 |
| 字段 | `score` / `grade` | `selection_score` / `selection_grade` |

**不替换，不冲突**。一个商品可以"表现好但不值得开"（S级 + X级），也可以"表现一般但值得试"（C级 + S2级）。

### 2.2 前端展示方式

```
┌─────────────────────────────────────────┐
│  [UniversalCard 商品卡片]                │
│                                         │
│  标题: Motivational Wall Art            │
│  类目: Home & Kitchen > Wall Art        │
│                                         │
│  ┌─ 表现评分 ─┐  ┌─ 选品评分 ─┐        │
│  │  等级: A    │  │  等级: S1  │        │
│  │  分数: 82   │  │  分数: 88  │        │
│  └────────────┘  └────────────┘        │
│                                         │
│  售价: £7.99  月销: 45  BSR: 12.3万     │
│  利润: £70.36  重量: 85g                │
│                                         │
│  [查看详情]  [AI分析]                    │
└─────────────────────────────────────────┘
```

- 表现评分（4维）：小标签，辅助参考
- 选品评分（8维）：大标签，决策主依据
- AI分析按钮：仅S1/S2级商品显示

## 三、时间维度设计

### 3.1 week_tag 与 month 的共存

| 字段 | 用途 | 更新频率 | 前端展示 |
|------|------|---------|---------|
| `week_tag` | 数据批次标识（哪周导入的） | 每周 | "本周/往期"筛选（已有） |
| `month` | 选品分析的时间基准（哪个月的数据） | 每月 | 月份选择器（商品树新增） |

**关系**：
- 一个月 ≈ 4个 week_tag
- 选品评分以 `month` 为粒度更新（每月重新评分）
- 表现评分以 `week_tag` 为粒度更新（每周重新评分）

### 3.2 月份选择器与Tab的关系

```
全选品页（AllSelection）
├─ Tab: 新品榜 / 竞品 / 郑总 / 全部  ← 已有
├─ 月份选择器: [2026-05 ▼]           ← 新增（控制selection_score基准月）
├─ 本周/往期: [本周] [往期] [全部]    ← 已有（控制week_tag）
└─ 筛选: 分类 / 表现等级 / 选品等级   ← 新增选品等级筛选
```

月份选择器影响：
- 选品评分/等级（以该月数据计算）
- 蓝海指数（以该月数据聚合）
- 趋势分析（以该月为终点回看）

## 四、每日选品工作流

邓总开品模型定义了"每日循环"。系统如何支持这个节奏？

### 4.1 工作流时间线

```
08:00  数据自动导入（卖家精灵API → competitor_products）
       │
       ▼
08:05  硬筛选自动执行（CompetitorFilterService → filter_mode）
       │
       ▼
08:10  选品评分自动计算（8维评分 → selection_score / selection_grade）
       │  ├─ 硬维度SQL计算（毫秒）
       │  ├─ 软维度向量传播（秒级）
       │  └─ 汇总写回（秒级）
       │
       ▼
08:30  用户打开系统
       │
       ├─→ 看"今日新品报告"
       │   ├─ 新进入S1的商品（重点关注）
       │   ├─ 新进入S2的商品（值得关注）
       │   └─ 蓝海信号变化（本周 vs 上周）
       │
       ├─→ 浏览商品树
       │   ├─ 按品类浏览，看各品类的选品等级分布
       │   ├─ 蓝海品类高亮显示
       │   └─ 切换月份对比不同时期的评分
       │
       ├─→ 对S1商品点击"AI分析"
       │   ├─ 查看竞品格局分析报告
       │   ├─ 查看跨月趋势分析
       │   └─ 查看蓝海匹配度
       │
       └─→ 做决策
           ├─ LAUNCH → 标记为"待开品"，进入开品流程
           ├─ CONDITIONAL → 标记为"待确认"，记录条件
           ├─ WATCH → 标记为"观察"，下周再看
           └─ ABANDON → 标记为"放弃"，记录原因
       │
       ▼
每周   蓝海信号自动扫描（Celery Beat，每周一凌晨）
每月   品类级LLM评估更新（Celery Beat，每月1日）
每月   决策反馈闭环（人工review，调整权重）
```

### 4.3 决策操作流

用户在商品卡片或详情页做决策时：

```
商品详情
    │
    ├─ 8维评分雷达图
    ├─ AI分析报告（如有）
    ├─ 同品类TOP10对比
    │
    ▼ 用户点击"做决策"
    │
    ├─→ [开品] → 弹窗记录：
    │     ├─ 开品理由（选填）
    │     ├─ 裂变方向（图案/尺寸/场景）
    │     ├─ 目标售价
    │     └─ 首批SKU数
    │
    ├─→ [有条件开品] → 弹窗记录：
    │     └─ 待确认条件（如"找到MOQ<100的供应商"）
    │
    ├─→ [观察] → 自动加入观察池，下周提醒
    │
    └─→ [放弃] → 弹窗记录：
          └─ 放弃原因（竞争太激烈/利润不够/...）
```

## 五、数据库全景

### 5.1 表关系

```
competitor_products（核心表）
│  唯一键: (marketplace, asin, month)
│  表现评分: score / grade（4维，每周更新）
│  选品评分: selection_score / selection_grade（8维，每月更新）
│  筛选状态: filter_mode / filter_reasons
│
├─→ product_ai_labels（AI标签表，新增）
│     存储种子标注和传播结果
│     关联: (asin, marketplace, month)
│
├─→ product_analysis（分析报告表，新增）
│     存储Agent深度分析报告
│     关联: (target_asin, marketplace, month)
│
├─→ selection_decisions（决策记录表，新增）
│     存储用户决策（LAUNCH/CONDITIONAL/WATCH/ABANDON）
│     关联: (asin, marketplace, month)
│
├─→ scoring_config（评分配置表，已有）
│     4维表现评分配置
│     扩展: 新增8维选品评分配置
│
└─→ filter_config（筛选配置表，已有）
      硬筛选阈值配置
      扩展: 新增禁止类目黑名单
```

### 5.2 新增表设计

#### selection_decisions（决策记录表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| asin | VARCHAR | 关联competitor_products |
| marketplace | VARCHAR | 站点 |
| month | VARCHAR | 决策基准月 |
| decision_status | VARCHAR | LAUNCH / CONDITIONAL / WATCH / ABANDON |
| decision_score | DECIMAL | 5维决策评分（0-10） |
| reasons | JSON | 决策理由/条件/原因 |
| decided_by | INT | 决策人 |
| decided_at | DATETIME | 决策时间 |
| actual_result | VARCHAR | 实际结果（反馈闭环时填写） |
| actual_result_at | DATETIME | 验证时间 |

#### filter_config 扩展

| 新增配置项 | 默认值 | 说明 |
|-----------|-------|------|
| banned_categories | JSON数组 | 19个禁止类目 |
| selection_price_min | 5.99 | 选品价格下限 |
| selection_price_max | 16.99 | 选品价格上限 |
| selection_sales_min | 100 | 选品月销下限 |

## 六、选品算法与Pipeline的关系

### 6.1 选品算法是一个"默认管道"

`AI 选品 Agent — 实施方案.md` 设计了完整的Pipeline执行器（管道化选品）。

选品算法（01-05文档）可以理解为 **一个具体的、预设好的管道**：

```
邓总选品法（默认管道）
├─ Step 1: 硬筛选（禁止类目+重量+价格+销量+去重）
├─ Step 2: 8维评分（4硬+4软）
├─ Step 3: Agent深度分析（竞品+趋势+蓝海）
├─ Step 4: 5维决策评分
└─ Step 5: 决策（开品/条件/观察/放弃）
```

### 6.2 管道化的未来

当Pipeline执行器实现后，用户可以：

| 操作 | 说明 |
|------|------|
| 使用默认管道 | "邓总选品法"，一键执行全流程 |
| Fork管道 | 复制默认管道，修改权重/阈值/步骤 |
| 自建管道 | 从零开始，选择自己需要的步骤和工具 |
| 分享管道 | 好的选品方法全员共享 |

### 6.3 工具层的复用

无论哪个管道，底层都调用同一套工具：

| 工具 | 来源 | 用途 |
|------|------|------|
| filter_products | 01 §3.1 | 硬筛选 |
| score_products | 01 §3.2 | 8维评分 |
| analyze_competition | 03 §二 | 竞品格局 |
| analyze_product_trend | 03 §三 | 跨月趋势 |
| discover_blue_ocean | 03 §四 → [09升级](./09-蓝海发现算法升级.md) | 蓝海发现（10维雷达+品类分型+测品推荐） |
| analyze_seller | 05 §2.1 → [10卖家画像](./10-卖家行为画像.md) | 卖家行为画像（聪明卖家+跟品节奏） |
| cross_marketplace | 05 §2.2 → [13跨站套利](./13-跨站点套利发现.md) | 跨站套利发现（品类对比+ASIN空白+利润差） |
| detect_explosion | 05 §2.3 → [12爆发信号](./12-新品爆发信号检测.md) | 新品爆发检测（速度+密度+跟品+质量） |

**管道是可配置的编排层，工具是固定的能力层。**
