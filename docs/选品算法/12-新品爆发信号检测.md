# 选品算法 — 新品爆发信号检测

> 选品的核心竞争力是**"比别人早"**。
> 08文档解决"好不好"，01文档解决"做不做"，本文档解决**"快不快"**。
> 当前系统只看跨月趋势（03文档§三），最有价值的**月内变化信号**完全未覆盖。

---

## 一、问题诊断：当前为什么看不到"爆发"

### 1.1 时间盲区

| 维度 | 当前覆盖 | 缺失 |
|------|---------|------|
| **跨月趋势** | ✅ 03文档§三：线性回归销量斜率、BSR均值变化 | — |
| **月内变化** | ❌ | bsrCv/bsrCr/unitsGr/ratingsCv 字段已有，但未被任何算法使用 |
| **月内变化信号** | ❌ | 邓总三级信号体系（紧急/重要/一般）完全未实现 |

### 1.2 被浪费的字段

competitor_products 表中已有月内变化字段，但**零算法使用**：

| 字段 | 含义 | 爆发信号价值 |
|------|------|-----------|
| `bsrCv` | BSR月内变化值 | 负值大 = BSR骤降 = 排名飞升 |
| `bsrCr` | BSR月内变化率 | -80% = BSR跌了80% = 爆发 |
| `unitsGr` | 销量月内增长率 | +200% = 销量3倍增长 |
| `ratingsCv` | 评论月内变化值 | +50 = 30天内新增50条评论 = 自然流量验证 |
| `ratingsRate` | 评论增长率 | +100% = 评论翻倍 |
| `listingDays` | 上架天数 | ≤30天 = 极新品，配合其他信号 = 爆发候选 |

> **关键发现**：这5个字段是卖家精灵提供的**月内快照**，等于每月一次的"体检报告"。当前系统只看了"体检结果"（当前BSR、当前销量），没看"变化趋势"（BSR在降、销量在涨）。

### 1.3 邓总三级信号体系的缺口

邓总开品模型定义了信号优先级，当前系统覆盖情况：

| 级别 | 邓总定义 | 当前覆盖 | 本文档方案 |
|------|---------|---------|-----------|
| 🔴 紧急 | 郑总+3个竞品同时上同一类产品 | ❌ 未覆盖 | §四 密度信号 + 10文档跟品联动 |
| 🟡 重要 | BSR新品榜出现多个同类产品 | ❌ 未覆盖 | §四 品类密度突增信号 |
| 🟢 一般 | 单个竞品上了新品 | ⚠️ 仅listing_days筛选 | §三 单品速度信号 |

## 二、设计思路：4类信号 × 3级紧急度

### 2.1 信号分类框架

```
                    检测对象
                    ┌──────────────┐
                    │  单个产品     │ → 速度信号（§三）
                    │  整个品类     │ → 密度信号（§四）
                    │  卖家行为     │ → 跟品信号（§五）→ 联动10文档
                    │  产品质量     │ → 质量信号（§六）
                    └──────────────┘
                    
每个信号输出紧急度等级：
  🔴 立即行动（今天决策）
  🟡 重点关注（本周决策）
  🟢 持续观察（本月跟踪）
```

### 2.2 与现有文档体系的关系

```
09 蓝海雷达（品类级） → "这个品类有没有机会"（静态）
10 卖家画像（卖家级） → "谁在做，做得好不好"（静态）
12 爆发信号（时间级） → "现在正在发生什么"（动态）← 本文档

08 品类评分 + 12 爆发信号 = 既好又快的产品优先
01 决策模型 + 12 爆发信号 = 紧急信号提升决策等级
```

## 三、速度信号 — 单品爆发检测

> 核心问题：**这个新品正在起飞吗？**

### 3.1 BSR骤降信号

BSR排名下降 = 卖得好。月内BSR骤降是最强的爆发信号。

| 信号强度 | 条件 | 含义 |
|---------|------|------|
| 🔴 极强 | `bsrCr ≤ -80%` AND `listingDays ≤ 30` | 30天内BSR跌了80%+，火箭式起飞 |
| 🔴 强 | `bsrCr ≤ -60%` AND `listingDays ≤ 60` | 60天内BSR跌了60%+，快速起量 |
| 🟡 中 | `bsrCr ≤ -40%` AND `listingDays ≤ 90` | 90天内BSR跌了40%+，稳步增长 |
| 🟢 弱 | `bsrCr < 0` AND `bsrCv ≤ -5000` | BSR在改善，但幅度一般 |

**注意**：BSR变化需结合绝对值看。BSR从100万降到20万（-80%）不如从5万降到1万（-80%）有意义。

```
BSR骤降综合分 = |bsrCr| × BSR质量系数

BSR质量系数：
  bsr < 10,000  → ×2.0（进入大类前1万，极强）
  bsr < 50,000  → ×1.5（前5万，强）
  bsr < 100,000 → ×1.0（前10万，一般）
  bsr ≥ 100,000 → ×0.5（10万以外，信号弱）
```

### 3.2 销量增速信号

`unitsGr` 直接反映月内销量变化。

| 信号强度 | 条件 | 含义 |
|---------|------|------|
| 🔴 极强 | `unitsGr ≥ 200%` AND `listingDays ≤ 30` | 30天内销量翻3倍 |
| 🔴 强 | `unitsGr ≥ 100%` AND `listingDays ≤ 60` | 60天内销量翻倍 |
| 🟡 中 | `unitsGr ≥ 50%` AND `listingDays ≤ 90` | 90天内销量增长50%+ |
| 🟢 弱 | `unitsGr > 0` | 正增长但幅度一般 |

**异常过滤**：`unitsGr` 极端值（如 +10000%）可能是首月仅1-2单的噪音，需加绝对值门槛：

```
有效增速 = unitsGr ≥ 50% AND units ≥ 10
// 排除"1单→100单"的虚假增速
```

### 3.3 评论增速信号

评论增长 = 真实买家在增加，是自然流量的间接验证。

| 信号强度 | 条件 | 含义 |
|---------|------|------|
| 🔴 强 | `ratingsCv ≥ 30` AND `listingDays ≤ 60` | 60天内新增30+评论，爆品特征 |
| 🟡 中 | `ratingsCv ≥ 15` AND `listingDays ≤ 90` | 90天内新增15+评论 |
| 🟢 弱 | `ratingsCv ≥ 5` AND `listingDays ≤ 90` | 有自然评论积累 |

### 3.4 单品爆发综合分

将3类速度信号融合为一个分数：

```
爆发分 = 0.45 × BSR骤降分（归一化）
       + 0.35 × 销量增速分（归一化）
       + 0.20 × 评论增速分（归一化）

归一化：各信号按 0-100 百分位映射

紧急度判定：
  爆发分 ≥ 80 → 🔴 立即行动
  爆发分 ≥ 50 → 🟡 重点关注
  爆发分 ≥ 30 → 🟢 持续观察
  爆发分 < 30 → 无信号
```

### 3.5 检测SQL

```sql
-- 新品爆发候选（listingDays ≤ 90）
SELECT 
    asin, title, price, marketplace,
    bsr, bsrCv, bsrCr,
    units, unitsGr,
    ratings, ratingsCv, ratingsRate,
    listingDays, availableDate,
    sellerName, brand
FROM competitor_products
WHERE month = #{currentMonth}
  AND marketplace = #{mp}
  AND listingDays <= 90
  AND bsrCr < 0              -- BSR在改善
  AND unitsGr > 0            -- 销量在增长
ORDER BY 
    ABS(bsrCr) * (CASE WHEN bsr < 50000 THEN 1.5 WHEN bsr < 100000 THEN 1.0 ELSE 0.5 END) DESC
LIMIT 50;
```

## 四、密度信号 — 品类热度突变检测

> 核心问题：**这个品类最近是不是突然热起来了？**

### 4.1 新品密度突增

某个品类短期内新品数量暴增 = 赛道正在爆发。

```sql
-- 品类月度新品数统计
SELECT 
    SUBSTRING_INDEX(nodeLabelPath, ':', -1) AS category,
    COUNT(*) AS new_product_count,
    AVG(ABS(bsrCr)) AS avg_bsr_improvement,
    AVG(unitsGr) AS avg_units_growth
FROM competitor_products
WHERE month = #{currentMonth}
  AND marketplace = #{mp}
  AND listingDays <= 30       -- 30天内的新品
GROUP BY category
HAVING new_product_count >= 5  -- 至少5个新品
ORDER BY new_product_count DESC;
```

**突增判定**：

| 信号强度 | 条件 | 含义 |
|---------|------|------|
| 🔴 赛道爆发 | 本月新品数 ≥ 上月×3 AND 品类均BSR改善 | 多人同时涌入 = 有肉吃 |
| 🟡 赛道升温 | 本月新品数 ≥ 上月×2 AND 均销量增长 | 关注度在上升 |
| 🟢 正常活跃 | 本月新品数 > 上月 | 正常波动 |

> **与09蓝海雷达的联动**：密度突增信号应反哺09的 D1新品活跃度维度。当检测到🔴赛道爆发时，该品类的D1分应上调。

### 4.2 多卖家同步进入

同一品类中，多个不同卖家同时上架新品 = 强烈的赛道信号。

```sql
-- 品类内新品卖家分散度
SELECT 
    category,
    COUNT(DISTINCT sellerName) AS unique_sellers,
    COUNT(*) AS new_products,
    COUNT(DISTINCT sellerName) / COUNT(*) AS seller_diversity
FROM new_products_by_category
WHERE listingDays <= 30
GROUP BY category;
```

| 信号强度 | 条件 | 含义 |
|---------|------|------|
| 🔴 | 30天内≥5个不同卖家上新品 AND seller_diversity > 0.7 | 多家同时发现机会 |
| 🟡 | 30天内≥3个不同卖家上新品 | 有一定关注度 |
| 🟢 | 30天内≥2个不同卖家上新品 | 初步关注 |

> **与10文档联动**：如果同步进入的卖家中包含S/A级聪明卖家（10文档§三），信号等级自动提升一级。

### 4.3 郑总店铺同步上新（🔴紧急信号）

邓总三级信号体系中最紧急的一级：郑总多家店铺同时上同一类产品。

```sql
-- 郑总店铺品类集中度（需seller_profiles表，10文档）
SELECT 
    category,
    COUNT(DISTINCT sellerName) AS zheng_shops,
    COUNT(*) AS new_products,
    MIN(listingDays) AS freshest
FROM competitor_products cp
JOIN seller_profiles sp ON cp.sellerName = sp.shop_name
WHERE sp.is_zheng_shop = TRUE
  AND cp.month = #{currentMonth}
  AND cp.listingDays <= 30
GROUP BY category
HAVING zheng_shops >= 3;     -- 3家以上郑总店铺同时上
```

| 郑总店铺数 | 紧急度 | 行动建议 |
|-----------|--------|---------|
| ≥5家 | 🔴🔴 极紧急 | 郑总内部验证过的品，立即跟进 |
| 3-4家 | 🔴 紧急 | 当天决策，小批量测品 |
| 2家 | 🟡 关注 | 本周评估 |
| 1家 | 🟢 观察 | 纳入常规评估 |

## 五、跟品信号 — 谁在跟进（联动10文档）

> 核心问题：**爆发产品背后，有没有聪明卖家在跟？**

本节直接复用10文档§五产品级跟品节奏分析，新增**时间维度增强**：

### 5.1 跟品速度

```
跟品速度 = 第2个卖家的listingDays - 首发的listingDays

| 跟品速度 | 含义 |
|---------|------|
| ≤ 7天 | 极快跟进 = 信号已传播，竞争激烈 |
| 7-30天 | 正常跟进 = 还有窗口期 |
| 30-90天 | 慢跟进 = 窗口期充足 |
| > 90天或无人跟 | 冷门或先发优势强 |
```

### 5.2 跟品质量

```
跟品质量 = 跟进卖家的聪明卖家等级（10文档）

| 跟进者质量 | 信号增强 |
|-----------|---------|
| S级卖家跟进 | 信号等级 +1（如🟡→🔴） |
| A级卖家跟进 | 维持原等级 |
| B/C级卖家跟进 | 信号等级 -1 |
| 无人跟进 | 保持🟢观察 |
```

> **与10文档的完整联动**：10文档提供"谁在做"，12文档提供"正在发生什么"。两者组合 = "聪明卖家正在快速进入这个品类" = 最强跟品信号。

## 六、质量信号 — 新品质量过滤

> 核心问题：**这个新品是真的好，还是刷单/偶然？**

### 6.1 信号可信度过滤

不是所有BSR骤降都是爆发，需要质量验证：

| 验证维度 | 可信条件 | 不可信条件 |
|---------|---------|-----------|
| **BSR vs 销量一致性** | BSR改善 AND units增长 | BSR改善但units不变 = 可能刷单 |
| **评论增速 vs 销量** | ratingsCv > 0 AND unitsGr > 0 | units增长但零评论 = 可能广告推 |
| **价格稳定性** | 月内价格波动 < 15% | 大幅降价冲量 = 不可持续 |
| **卖家历史** | 卖家过去新品成功率 > 40% | 卖家历史成功率 < 20% = 偶然 |

### 6.2 新品质量评分

```
新品质量分 = 0.4 × 信号一致性分
           + 0.3 × 卖家能力分（10文档聪明卖家得分）
           + 0.3 × 品类契合分（08文档品类评分）

过滤规则：
  质量分 < 30 → 信号不可信，降级或忽略
  质量分 ≥ 30 → 信号有效，维持原等级
```

### 6.3 假爆发识别

| 假爆发模式 | 特征 | 处理 |
|-----------|------|------|
| **刷单冲排名** | BSR骤降但ratingsCv=0，unitsGr异常高 | 标记为可疑，降低信号等级 |
| **大促冲量** | price骤降 > 30%，配合units暴增 | 标注"促销驱动"，观察大促后表现 |
| **单日出单** | units极高但listingDays=1-3 | 数据不稳定，等7天后再评估 |
| **BSR波动** | bsrCv大但bsr绝对值仍>20万 | 低基数噪音，信号无效 |

### 7.2 与01决策模型的对接

爆发信号影响决策等级提升：

| 原决策等级 | 爆发信号 | 调整后 |
|-----------|---------|-------|
| S2（推荐开品） | 🔴 立即行动 | **S1（优先开品）** |
| S3（可开品） | 🔴 立即行动 | **S2（推荐开品）** |

## 八、数据模型

### 8.1 explosion_signals 表

```sql
CREATE TABLE explosion_signals (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    marketplace VARCHAR(10) NOT NULL,
    month VARCHAR(10) NOT NULL,
    week_number INT,                     -- ISO周数
    
    -- 信号对象
    signal_type ENUM('product', 'category') NOT NULL,
    asin VARCHAR(20),                    -- product级信号时填写
    category VARCHAR(200),               -- category级信号时填写
    
    -- 信号内容
    signal_name VARCHAR(100) NOT NULL,    -- 如 'BSR骤降', '品类密度突增'
    signal_value DECIMAL(10,2),           -- 原始值（如 -85.5）
    signal_score DECIMAL(5,2),            -- 归一化分（0-100）
    urgency ENUM('critical', 'important', 'watch') NOT NULL,
    
    -- 质量验证
    quality_score DECIMAL(5,2),           -- 信号可信度（0-100）
    is_verified BOOLEAN DEFAULT FALSE,
    false_positive_reason VARCHAR(200),   -- 如 '刷单嫌疑', '大促冲量'
    
    -- 联动信息
    related_seller_grade VARCHAR(5),      -- 10文档聪明卖家等级
    related_blue_ocean_d1 DECIMAL(5,2),   -- 09文档D1新品活跃度
    related_category_score DECIMAL(5,2),  -- 08文档品类评分
    
    -- 决策影响
    original_grade VARCHAR(5),            -- 信号前决策等级
    adjusted_grade VARCHAR(5),            -- 信号后决策等级
    
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_urgency (urgency),
    INDEX idx_marketplace_month (marketplace, month),
    INDEX idx_signal_type (signal_type)
);
```

### 8.2 检测频率

| 检测类型 | 建议频率 | 数据来源 |
|---------|---------|---------|
| 单品速度信号 | 每次数据导入（每月） | bsrCv/bsrCr/unitsGr/ratingsCv |
| 品类密度信号 | 每次数据导入（每月） | 新品数量统计 |
| 郑总同步上新 | 每次数据导入（每月） | 10文档seller_profiles |
| 跟品速度信号 | 每次数据导入（每月） | 跨月数据对比 |

> **当前数据频率限制**：卖家精灵数据按月导入，所以爆发信号最快也是月度检测。未来如果接入日频数据源，可升级为周度/日度检测。

## 十、核心结论

1. **当前系统有时间盲区** — bsrCv/bsrCr/unitsGr/ratingsCv 五个"月内变化"字段已有但零算法使用，最大的信号浪费
2. **4类信号互补** — 速度（单品起飞）、密度（赛道爆发）、跟品（聪明卖家跟进）、质量（过滤假信号），缺一不可
3. **3级紧急度驱动行动** — 🔴立即/🟡本周/🟢本月，不是所有信号都需要当天决策
4. **邓总三级信号体系可实现** — 🔴郑总多店同步（§四.3）、🟡品类密度突增（§四.1）、🟢单品爆发（§三），从概念到算法
5. **Phase 1 零依赖可上线** — 单品速度信号只需4个已有字段，是最快的ROI
6. **爆发信号提升决策等级** — S2+🔴→S1，"又好又快"的产品优先
7. **红海也测品原则适用** — 即使蓝海指数低，🔴爆发信号仍应触发测品推荐
