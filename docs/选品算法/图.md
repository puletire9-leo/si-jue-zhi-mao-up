## 1. 品线分级体系定义

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        三级分级体系                                       │
│                                                                         │
│  L1 品线（Product Line）                                                 │
│  ├─ 字段：bsr_id（如 "beauty", "pet-supplies", "toys-uk"）              │
│  ├─ 含义：亚马逊 Best Seller 根目录大类                                   │
│  └─ 示例：Beauty / Home & Garden / Pet Supplies / Toys                  │
│        ↓                                                                 │
│  L2 小类（Sub-Category）                                                  │
│  ├─ 字段：node_id（如 2909187031）+ node_label_path 最后段                │
│  ├─ 含义：最细粒度的叶子类目                                              │
│  └─ 示例：Nail Tips / False Nails / Training Clickers                   │
│        ↓                                                                 │
│  L3 商品（Product）                                                       │
│  ├─ 字段：asin（如 B0F3J71BB1）                                          │
│  ├─ 含义：具体ASIN商品                                                   │
│  └─ 示例：96PCS Stick on Nails...                                       │
│                                                                         │
│  实例（Nail Tips）：                                                      │
│  L1 "beauty"                                                             │
│    └── L2 nodeId=2909187031 "Nail Tips"                                  │
│          └── L3 ASIN="B0F3J71BB1" "96PCS Stick on Nails..."             │
└─────────────────────────────────────────────────────────────────────────┘
```

### 与商品树的关系

| 商品树维度 | 对应品线层级 | DB字段 |
|-----------|------------|--------|
| 分类树第1段 | L1 品线 | `bsr_id` |
| 分类树最后段 | L2 小类名称 | `node_label_path` 最后一段 |
| 分类树完整路径 | L2 小类路径 | `node_label_path` |
| 叶子节点产品 | L3 商品 | `asin` |

## 3. 数据存储设计

### 3.1 product_line_guidance 表（品线指导记录）

```sql
CREATE TABLE product_line_guidance (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    batch_id        VARCHAR(32)  NOT NULL COMMENT '批次号（时间戳生成）',
    marketplace     VARCHAR(8)   NOT NULL COMMENT '站点 UK/DE/US',
    month           VARCHAR(8)   NOT NULL COMMENT '数据月份 202606',

    -- 品线定位
    bsr_id          VARCHAR(64)  NOT NULL COMMENT 'L1品线ID（如 beauty）',
    node_id         BIGINT       NOT NULL COMMENT 'L2小类nodeId',
    node_name       VARCHAR(128) NOT NULL COMMENT 'L2小类名称',
    node_full_path  VARCHAR(512) DEFAULT NULL COMMENT '完整类目路径',

    -- 聚合指标（Java计算）
    product_count   INT          DEFAULT 0 COMMENT '商品数',
    total_units     INT          DEFAULT 0 COMMENT '总销量',
    total_revenue   DECIMAL(12,2) DEFAULT 0 COMMENT '总营收(£)',
    avg_price       DECIMAL(8,2) DEFAULT 0 COMMENT '均价',
    price_min       DECIMAL(8,2) DEFAULT 0 COMMENT '最低价',
    price_max       DECIMAL(8,2) DEFAULT 0 COMMENT '最高价',
    avg_bsr         INT          DEFAULT 0 COMMENT '平均BSR',
    avg_rating      DECIMAL(3,1) DEFAULT 0 COMMENT '平均评分',
    avg_ratings     INT          DEFAULT 0 COMMENT '平均评论数',
    units_growth_rate DECIMAL(8,2) DEFAULT 0 COMMENT '销量增速%',
    bsr_change_rate DECIMAL(8,2) DEFAULT 0 COMMENT 'BSR变化率%',
    top_brands      VARCHAR(512) DEFAULT NULL COMMENT '头部品牌JSON数组',
    store_names     VARCHAR(512) DEFAULT NULL COMMENT '店铺名JSON数组',
    best_seller_count INT         DEFAULT 0 COMMENT 'BestSeller数量',
    amazon_choice_count INT       DEFAULT 0 COMMENT 'AmazonChoice数量',

    -- Agent分析产出（Agent回写）
    recommend_level  VARCHAR(32)  DEFAULT NULL COMMENT '推荐等级',
    opportunity_score TINYINT     DEFAULT NULL COMMENT '机会分0-100',
    analysis_report TEXT         DEFAULT NULL COMMENT '分析报告JSON',
    confidence      DECIMAL(3,2) DEFAULT NULL COMMENT 'Agent置信度',
    agent_version   VARCHAR(32)  DEFAULT NULL COMMENT 'Agent版本号',

    -- 元数据
    analyzed_at     DATETIME     DEFAULT NULL COMMENT 'Agent分析时间',
    created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_batch_node (batch_id, bsr_id, node_id),
    INDEX idx_bsr_id (bsr_id),
    INDEX idx_recommend_level (recommend_level),
    INDEX idx_opportunity_score (opportunity_score)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='品线指导记录（郑总店铺分析结果）';
```

## 4. 完整数据流（v2.1 三项目解耦架构）

```
  时间轴 →

  T1: 郑总店铺定时上新
  ┌──────────┐
  │ 脚本同步  │ ──→ deng_zong_shop 表写入新批次数据
  │ Sellersprite│    （~29个店铺, ~6991商品）
  └──────────┘

  T2: 用户在品线分析页面点击 [开始分析]
  ┌──────────────────────────────────────────────────────┐
  │  Vue前端 :5173                                       │
  │  ① POST /api/product-line/aggregate → Java聚合       │
  │  ② Java 从 deng_zong_shop 聚合 → 写入batch表        │
  │  ③ Java 返回 batchId (如 "20260609-001")            │
  │  ④ 前端拿到batchId，调Agent分析接口                 │
  └──────────────────────┬───────────────────────────────┘
                       │  batchId
                       ▼
  T3: Agent 分析（前端直连，Java不参与）
  ┌──────────────────────────────────────────────────────┐
  │  选品Agent :8001  ← 前端SSE长连接建立               │
  │  ① data_fetch: GET /aggregated-data?batchId=xxx     │
  │     → 从Java拉取聚合数据                          │
  │  ② 遍历每个小类 → 8能力LLM推理                    │
  │  ③ SSE实时推送每步进度给前端                       │
  │     “正在分析Nail Tips... 能力3完成...”              │
  │  ④ 分析完成 → POST /results 回写Java              │
  └──────────────────────┬───────────────────────────────┘
                       │  分析结果 JSON
                       ▼
  T4: Java 写入结果（被动接收，不主动调度）
  ┌──────────────────────────────────────────────────────┐
  │  Java后端 :8080                                      │
  │  ① POST /results → 写入 product_line_guidance 表   │
  │  ② Java不知道是谁发的，只负责存储+提供查询          │
  └──────────────────────────────────────────────────────┘

  T5: 用户查看结果
  ┌──────────────────────────────────────────────────────┐
  │  Vue前端 :5173                                       │
  │  ① 分析完成通知                                     │
  │  ② GET /guidance → 拉取结果卡片展示                  │
  │  ③ 品线卡片列表（推荐等级 + 机会分 + 行动指令）    │
  └──────────────────────────────────────────────────────┘
```

> **关键区别**：T2-T3 之间，Java 完全不参与。前端是唯一的调度者，Agent 通过前端触发。
> Java 在 T2 只负责“聚合+存”，在 T4 只负责“接收+存”，中间分析过程 Java 不知情。

## 5. 三项目职责分工矩阵

| 能力模块 | 项目A: Java :8080 | 项目B: Agent :8001 | 项目C: Vue :5173 |
|---------|---------------------|----------------------|---------------------|
| **数据采集** | Sellersprite API同步、JSON解析、入库 | — | — |
| **品线聚合** | SQL GROUP BY → 写入batch表 | — | 触发聚合接口 |
| **分析调度** | **不参与** | **不参与（被动触发）** | **唯一调度者** |
| **L2软维度评分** | — | LLM理解语义 → 打分 | — |
| **L3深度分析** | — | 8能力节点推理 | — |
| **实时进度** | — | SSE推送每步进度 | 接收并展示进度条 |
| **结果存储** | POST /results 被动接收存储 | POST回写Java | — |
| **结果展示** | GET /guidance 提供查询 | — | 品线卡片列表+筛选 |
| **消息推送** | 飞书/企微Webhook | — | — |
| **反馈闭环** | 记录验证结果 | 读取并校准 | 展示反馈统计 |

> **核心原则**：Java 不知道 Agent 存在；Agent 不知道前端存在；前端是唯一的编排者。
> 如果未来要加定时触发（不用前端），只需加一个 cron 服务调 Agent 接口，不改 Java 也不改 Agent。

## 附录：关键设计决策记录

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 为什么L2/L3交给Agent？ | 分离关注点 | Java擅长数据处理，Agent擅长语义推理；解耦后双方独立迭代 |
| 为什么不把Agent嵌进Java进程？ | 独立部署 | Agent可能用Python/不同硬件/GPU；失败不影响Java主服务 |
| 为什么品线以deng_zong_shop为源头？ | 数据质量 | 郑总29店6991商品是已验证的成功案例，比competitor_products更聚焦 |
| 为什么先推小类不推ASIN？ | 渐进式 | 小类级决策足够指导方向；ASIN级推送后续迭代 |
| 为什么保留01文档的L1硬筛选？ | 效率 | 规则过滤不需要AI，SQL最快最稳 |
| 为什么Agent通过HTTP而非消息队列？ | 简单 | 同步REST便于调试；后续可升级为异步队列 |
