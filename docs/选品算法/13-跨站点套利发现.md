# 选品算法 — 跨站点套利发现

> UK和DE当前是**隔离分析**的。但郑总有6家店铺同时做UK+DE，同一产品跨站点表现差异巨大。
> 本文档从"单站点选品"升级到**"跨站点套利发现"**——找到信息差带来的机会窗口。

---

## 一、问题诊断：隔离分析的信息盲区

### 1.1 数据现状

竞品数据以 `(marketplace, asin, month)` 为唯一键，UK和DE完全独立分析。

但实际上：

|------|-----|-----|--------|

| 品类成熟度 | 品类A可能饱和 | 品类A可能刚起步 | 时间差套利 |
| 价格水平 | 同类均价£8 | 同类均价€10 | 利润差套利 |

## 二、设计思路：3层套利发现

```
第1层：品类级对比（§三）  → "哪个品类在两站发展阶段不同"
第2层：产品级对比（§四）  → "哪个具体产品存在跨站机会"
第3层：价格/利润对比（§五）→ "同一产品哪个站更赚钱"

每一层输出：
  - 机会类型：UK→DE（UK验证过了，DE可做）/ DE→UK / 双向
  - 窗口期判断：先发优势还剩多久
  - 与现有文档的联动建议
```

## 三、品类级对比 — 发展阶段差异发现

> 核心问题：**同一品类在UK和DE处于不同的发展阶段吗？**

### 3.1 品类成熟度对比

对每个品类，分别统计UK和DE的核心指标，找出差异：

```sql
-- 品类级跨站对比
SELECT 
    SUBSTRING_INDEX(nodeLabelPath, ':', -1) AS category,
    marketplace,
    COUNT(*) AS product_count,
    AVG(price) AS avg_price,
    AVG(units) AS avg_units,
    AVG(bsr) AS avg_bsr,
    SUM(CASE WHEN listingDays <= 90 THEN 1 ELSE 0 END) / COUNT(*) AS new_ratio,
    AVG(ABS(COALESCE(bsrCr, 0))) AS avg_bsr_change,
    AVG(ratings) AS avg_ratings
FROM competitor_products
WHERE month = #{currentMonth}
GROUP BY category, marketplace;
```

### 3.2 发展阶段判定

| 对比维度 | UK领先DE | DE领先UK | 选品含义 |
|---------|---------|---------|---------|
| **新品占比** | UK新品率 > DE×1.5 | DE新品率 > UK×1.5 | 领先站=创新源头，落后站=跟进市场 |
| **BSR改善幅度** | UK均bsrCr更负 | DE均bsrCr更负 | 领先站=市场正在增长 |
| **产品数量** | UK产品数 > DE×2 | DE产品数 > UK×2 | 领先站=已饱和，落后站=仍有空间 |
| **均价差异** | UK均价(换汇后) > DE×1.2 | DE均价(换汇后) > UK×1.2 | 高价站=利润更好 |

### 3.3 品类套利信号

```
品类套利评分 = 0.35 × 发展阶段差异分
             + 0.35 × 竞争强度差异分
             + 0.30 × 利润空间差异分

发展阶段差异分：
  |新品占比差| 归一化到 0-100
  领先站新品占比高 = "创新源头已验证，落后站可跟进"

竞争强度差异分：
  落后站产品数少 AND 均评论少 = 竞争弱 = 进入容易
  归一化到 0-100

利润空间差异分：
  |换汇后均价差| / 高价站均价 × 100
  差价大 = 套利空间大
```

### 3.4 汇率换算

跨站价格对比需要统一货币：

| 参数 | UK (£) | DE (€) |
|------|--------|--------|
| 到CNY汇率 | 8.54 | 7.5 |
| 互相换算 | £1 = €(7.5/8.54) ≈ €0.878 | €1 = £(8.54/7.5) ≈ £1.139 |

```
统一比较价(CNY) = UK价格 × 8.54  或  DE价格 × 7.5
// 用CNY作为中间货币进行跨站价格对比
```

### 3.5 品类套利信号矩阵

| 信号类型 | 条件 | 行动建议 |
|---------|------|---------|
| **UK验证→DE跟进** | UK新品率高+BSR好，DE同品类产品少+新品少 | DE市场布局该品类 |
| **DE验证→UK跟进** | DE新品率高+BSR好，UK同品类空白 | UK市场抢先布局 |
| **双向成熟** | 两站产品数都多+新品率都低 | 红海，需差异化切入（→11文档） |
| **双向蓝海** | 两站产品数都少+新品率都高 | 新兴品类，双站同时布局 |

> **与09蓝海雷达的联动**：跨站对比结果应作为09文档D1新品活跃度维度的补充信号。UK的D1高分品类如果在DE还是空白 → DE的该品类机会分应上调。

## 四、产品级对比 — ASIN跨站机会发现

> 核心问题：**具体哪个产品在另一站有套利机会？**

### 4.1 同ASIN跨站存在性检测

```sql
-- 找出只在一个站点存在的ASIN（表现好的）
SELECT 
    uk.asin, uk.title, uk.price AS uk_price, uk.bsr AS uk_bsr, 
    uk.units AS uk_units, uk.listingDays AS uk_age,
    de.asin AS de_exists,
    de.price AS de_price, de.bsr AS de_bsr, de.units AS de_units
FROM competitor_products uk
LEFT JOIN competitor_products de 
    ON uk.asin = de.asin 
    AND de.marketplace = 'DE' 
    AND de.month = uk.month
WHERE uk.marketplace = 'UK'
  AND uk.month = #{currentMonth}
  AND uk.bsr < 50000            -- UK表现好
  AND uk.listingDays <= 180     -- 相对新的品
ORDER BY de_exists IS NULL DESC, uk.units DESC;
-- de_exists IS NULL = UK有但DE没有 = DE套利机会
```

### 4.2 产品套利分类

| 情况 | 条件 | 套利方向 | 信号强度 |
|------|------|---------|---------|
| **UK爆品，DE空白** | UK BSR<5万, units>30, DE无此ASIN | UK→DE | 🔴 强 |
| **DE爆品，UK空白** | DE BSR<5万, units>30, UK无此ASIN | DE→UK | 🔴 强 |
| **两站都有，UK表现更好** | 同ASIN, UK units > DE×2 | 分析UK优势因素 | 🟡 中 |
| **两站都有，DE表现更好** | 同ASIN, DE units > UK×2 | 分析DE优势因素 | 🟡 中 |
| **两站都有，表现接近** | 同ASIN, units差异<30% | 无套利空间 | 🟢 弱 |

### 4.3 跨站上新时间差

检测同一卖家在两个站点的上新时间差：

```sql
-- 同一卖家跨站上新时间差
SELECT 
    uk.sellerName,
    uk.asin, uk.title,
    uk.availableDate AS uk_date,
    de.availableDate AS de_date,
    (uk.availableDate - de.availableDate) / 86400000 AS day_diff
FROM competitor_products uk
JOIN competitor_products de 
    ON uk.asin = de.asin 
    AND uk.sellerName = de.sellerName
    AND de.marketplace = 'DE'
WHERE uk.marketplace = 'UK'
  AND uk.listingDays <= 180
ORDER BY ABS(day_diff) ASC;
```

| 时间差 | 含义 | 行动建议 |
|--------|------|---------|
| DE先上≤30天 | DE首发，UK尚未上 | 观察UK是否跟进 |
| UK先上≤30天 | UK首发，DE尚未上 | DE跟进窗口 |
| 两站同步上(±7天) | 卖家双站同时布局 | 该品跨站验证强 |
| 间隔>90天 | 单站试水后缓慢扩展 | 正常节奏 |

### 4.4 跨站店铺联动（联动10文档）

结合10文档的聪明卖家评分：

```
如果 S/A级聪明卖家在UK上新了品X：
  → 检查品X在DE是否存在
  → 如果DE不存在 → 🔴 UK验证过的品，DE套利窗口
  → 如果DE已有但表现差 → 🟡 分析差异原因（价格？Listing？配送？）

如果 郑总某店铺在DE的品Y表现好：
  → 检查品Y在UK是否存在
  → 如果UK不存在 → 🔴 郑总内部验证过的品，UK抢先布局
```

## 五、价格/利润跨站对比

> 核心问题：**同一产品在UK和DE哪个更赚钱？**

### 5.1 同ASIN利润对比

利用08文档§10.2的精确利润计算算法，对同ASIN在两站分别计算利润：

```
UK利润 = UK_price - UK佣金(15%) - UK_VAT(20%) - UK_FBA - 成本 - UK头程
DE利润 = DE_price - DE佣金(15%) - DE_VAT(20%) - DE_FBA - 成本 - DE头程

// 统一换算为CNY对比
UK利润(CNY) = UK利润 × 8.54
DE利润(CNY) = DE利润 × 7.5
```

| 对比结果 | 条件 | 建议 |
|---------|------|------|
| UK利润 > DE×1.3 | 换算后UK利润显著更高 | 优先做UK站 |
| DE利润 > UK×1.3 | 换算后DE利润显著更高 | 优先做DE站 |
| 利润接近(差异<30%) | 两站利润差异小 | 两站都做，分散风险 |
| 一站亏损一站盈利 | UK利润<0, DE利润>0 | 只做盈利站 |

### 5.2 FBA配送费跨站对比

同一尺寸/重量的产品，UK和DE的FBA配送费不同：

| 产品特征 | UK FBA (£) | DE FBA (€) | UK FBA (CNY) | DE FBA (CNY) |
|---------|-----------|-----------|-------------|-------------|
| 轻型信封 ≤60g | £1.52 | €1.92 | ¥12.98 | ¥14.40 |
| 标准信封 ≤210g | £1.73 | €2.12 | ¥14.77 | ¥15.90 |
| 小包裹 ≤150g | £2.67 | €3.04 | ¥22.80 | ¥22.80 |
| 小包裹 ≤400g | £2.70 | €3.25 | ¥23.06 | ¥24.38 |

> DE的FBA配送费普遍高于UK（约高10-15%），但DE售价也通常更高，需要综合计算。参考 [配送费.md](../郑总公司分析/配送费.md)

### 5.3 品类价格带对比

```sql
-- 品类级价格带跨站对比
SELECT 
    SUBSTRING_INDEX(nodeLabelPath, ':', -1) AS category,
    marketplace,
    COUNT(*) AS count,
    MIN(price) AS min_price,
    PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY price) AS p25,
    PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY price) AS median_price,
    PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY price) AS p75,
    MAX(price) AS max_price
FROM competitor_products
WHERE month = #{currentMonth}
GROUP BY category, marketplace;
```

> **与11文档的联动**：11文档定义了UK站的4档固定价格带（£4.99-5.99/£5.99-7.99/£7.99-9.99/£9.99-16.99）。跨站对比时，DE需要对应的价格带定义（€5.99-6.99/€6.99-8.99/€8.99-11.99/€11.99-18.99），按汇率换算保持等价。

## 六、跨站套利综合评分

### 6.1 套利机会评分

将品类级、产品级、利润级信号融合为综合套利评分：

```
套利评分 = 0.35 × 品类阶段差异分（§三）
         + 0.40 × 产品空白分（§四）
         + 0.25 × 利润差异分（§五）

紧急度判定：
  套利评分 ≥ 75 → 🔴 立即布局（窗口期有限）
  套利评分 ≥ 50 → 🟡 重点关注（本周评估）
  套利评分 ≥ 30 → 🟢 持续观察（月度跟踪）
```

### 6.2 窗口期判断

套利机会不会永远存在，需要评估窗口期：

| 因素 | 窗口期短（≤30天） | 窗口期中（30-90天） | 窗口期长（>90天） |
|------|------------------|-------------------|-----------------|
| **竞品跟进速度** | 已有3+卖家在跟进 | 1-2个卖家跟进 | 尚无人跟进 |
| **品类热度** | 12文档检测到🔴爆发 | 12文档检测到🟡关注 | 12文档无信号 |
| **季节性** | 距离旺季<30天 | 距离旺季30-90天 | 无季节性/距离远 |

```
窗口期评分 = 0.4 × 竞品跟进速度分
           + 0.3 × 品类热度分（12文档联动）
           + 0.3 × 季节性分

窗口期短 → 加速决策，今天评估明天上架
窗口期中 → 正常流程，本周内完成评估
窗口期长 → 可以从容准备，优化Listing质量
```

## 七、数据模型

### 7.1 cross_marketplace_signals 表

```sql
CREATE TABLE cross_marketplace_signals (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    month VARCHAR(10) NOT NULL,
    
    -- 信号层级
    signal_level ENUM('category', 'product', 'profit') NOT NULL,
    
    -- 品类级信号
    category VARCHAR(200),
    
    -- 产品级信号
    asin VARCHAR(20),
    title VARCHAR(500),
    
    -- 套利方向
    source_marketplace VARCHAR(10) NOT NULL,    -- 已验证的站点
    target_marketplace VARCHAR(10) NOT NULL,    -- 机会站点
    
    -- 核心数据
    source_bsr INT,
    source_units INT,
    source_price DECIMAL(10,2),
    source_profit DECIMAL(10,2),
    target_exists BOOLEAN DEFAULT FALSE,
    target_price DECIMAL(10,2),
    target_avg_bsr INT,
    target_competitor_count INT,
    
    -- 评分
    arbitrage_score DECIMAL(5,2) NOT NULL,     -- 套利评分 0-100
    urgency ENUM('critical', 'important', 'watch') NOT NULL,
    window_days INT,                            -- 估算窗口期（天）
    
    -- 联动信息
    related_explosion_signal VARCHAR(200),      -- 12文档爆发信号
    related_seller_grade VARCHAR(5),            -- 10文档聪明卖家等级
    related_blue_ocean_score DECIMAL(5,2),      -- 09文档蓝海评分
    
    -- 跨站店铺验证
    dual_shop_count INT DEFAULT 0,              -- 同时做两站的店铺数
    zheng_shop_in_source BOOLEAN DEFAULT FALSE, -- 郑总在源站有此品
    zheng_shop_in_target BOOLEAN DEFAULT FALSE, -- 郑总在目标站有此品
    
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_urgency (urgency),
    INDEX idx_level (signal_level),
    INDEX idx_month (month)
);
```

## 十、核心结论

1. **UK和DE隔离分析是信息浪费** — 6家店铺同时做两站，跨站数据是天然的套利信号
2. **3层套利发现互补** — 品类级（发展阶段差异）、产品级（ASIN空白）、利润级（同一产品利润差），层层聚焦
3. **UK→DE和DE→UK双向都有机会** — 不是单向套利，需要按品类具体分析
4. **窗口期是核心变量** — 套利机会不会永远存在，需联动12文档爆发信号判断紧迫度
5. **郑总跨站店铺是最强验证** — 郑总在源站卖得好的品，在目标站有套利机会 = 内部验证过的信息差
6. **汇率换算是基础** — UK(£×8.54) vs DE(€×7.5)，所有跨站对比必须统一货币
7. **Phase 1 零依赖可上线** — 一条JOIN SQL即可发现产品空白，最快ROI
