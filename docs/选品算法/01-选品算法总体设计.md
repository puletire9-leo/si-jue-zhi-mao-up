# 选品算法 — 总体设计

> 基于邓总店铺开品模型提炼，结合系统现有数据与AI能力，构建三层选品决策架构。

---

## 一、选品逻辑来源

### 1.1 邓总店铺模式（学什么）

29家店铺、6991条商品的数据揭示了郑总团队的选品方法论：

| 模式 | 数据证据 | 选品启示 |
|------|---------|---------|
| **轻小件为主** | 主力品类Wall Art/Card/Fidget Toy均<100g | 物流成本是核心约束 |
| **低客单价高频** | 主力价格带£5-10（占60%+） | 冲动消费型产品 |
| **礼品+装饰双驱动** | Wall Art 997条、Card 352条、Mug 292条 | 情绪价值是选品灵魂 |
| **图案裂变** | 同品类动辄几十上百SKU | 一个爆款图案可裂变为20+SKU |
| **快速跟新** | 多家店铺近90天新品>30% | 速度>完美，10天内上架 |

### 1.2 开品模型（怎么学）

邓总店铺提炼出完整的工作流：

```
每日新品发现 → 快速筛选 → 竞品分析 → 利润核算 → 选品决策 → 开品执行
```

6步流程中有两个关键评分体系：
- **8维评分模型**（100分制）：用于产品筛选阶段的快速打分
- **5维决策评分**（10分制）：用于最终开品决策

## 三、三层决策架构

### 总览

```
┌─────────────────────────────────────────────────────────┐
│ 第1层：硬筛选（规则引擎，毫秒级）                         │
│ 职责：排除不合格商品，产出候选池                           │
│ 技术：Java CompetitorFilterService（已有）                │
│ 留存率：约20-30%                                         │
├─────────────────────────────────────────────────────────┤
│ 第2层：AI软评分（向量+LLM+SQL，秒级）                     │
│ 职责：对候选池商品进行8维选品评分                           │
│ 技术：SQL硬维度 + CLIP向量传播 + LLM视觉增强              │
│ 产出：selection_score(0-100) + selection_grade           │
├─────────────────────────────────────────────────────────┤
│ 第3层：Agent深度分析（按需触发，分钟级）                    │
│ 职责：竞品格局、趋势判断、蓝海发现、决策建议               │
│ 技术：Python Agent + LLM + 结构化报告                    │
│ 触发：用户点击"AI分析" 或 定时批量（Celery Beat）          │
└─────────────────────────────────────────────────────────┘
```

### 3.1 第1层：硬筛选

**目标**：快速排除明确不合格的商品。

#### 筛选漏斗

```
全量商品
  │
  ├─ 排除禁止类目（19个：数字/电子/大型/媒体/特殊资质）
  │
  ├─ 排除重量超标（>300g）
  │
  ├─ 排除价格超区间（<€5.99 或 >€16.99）
  │
  ├─ 排除月销不达标（按站点差异化，见[07文档](./07-动态基线与相对评分.md)）
  │  └─ UK ≥ 10 / DE ≥ 8 / US ≥ 50（父体聚合）
  │
  ├─ 去重（同一父体只保留表现最好的1条）
  │
  └─ 输出：候选池（MODE1/MODE2标记）
```

#### 禁止类目清单

**数字/虚拟类**：Apps & Games、Digital Music、Kindle Store、Prime Video、Software、Gift Cards

**电子类**：Electronics & Photo、Computers & Accessories、Amazon Devices & Accessories

**大型/重型**：Large Appliances、Lighting

**媒体类**：Books、CDs & Vinyl、DVD & Blu-ray

**特殊资质**：Grocery、Musical Instruments & DJ、Amazon Renewed、New Finds、PC & Video Games

#### 与现有系统的关系

现有 `CompetitorFilterService` 已实现 MODE1/MODE2/FAIL 三级筛选。需要：
- 新增禁止类目黑名单（配置化，存 `api_config` 表）
- 调整 `FilterConfigService` 中的价格/月销阈值对齐开品模型标准
- MODE1 = 全通过（候选池A级），MODE2 = 部分通过（候选池B级），FAIL = 排除

### 3.2 第2层：AI软评分

**目标**：对候选池商品进行8维选品评分，产出 `selection_score`。

> **[已确认决策]** 评分采用**百分位相对评分**替代绝对阈值（详见[07-动态基线与相对评分.md](./07-动态基线与相对评分.md)）。
> 商品与同(站点×品类)的其他商品比较，而非与固定数字比较。
> 品类基线使用**第2级品类**（约40个子类目），每月随数据自动更新。
> 最终得分 = 8维百分位加权分 × **品类健康度系数**(0.6-1.2)。
> 选品等级命名采用 **S1/S2/S3/X**（与现有表现评分S/A/B/C/D并存，互不冲突）。
> 8维权重先采用邓总开品模型原始权重，Phase 5通过反馈闭环校准。
> **品类专属权重**：不同品类原型使用不同权重（详见[08-品类专属评分模型.md](./08-品类专属评分模型.md)），
> 替代统一权重，解决“用装饰品标准评功能品”的系统性偏差。
> **注意**：下表“基础(邓总)权重”是未映射品类的回退方案，已映射品类使用08文档专属权重。

#### 8维评分模型

总分100分，由邓总店铺开品模型定义：

| 维度 | 权重 | 类型 | 数据来源 |
|------|------|------|---------|
| 轻小件指数 | 15% | 硬维度 | `weight_g` 直接计算 |
| 体积成本指数 | 15% | 硬维度 | `fba` / `price` 计算 |
| 利润指数 | 20% | 硬维度 | `profit` / `price` 计算 |
| 情绪价值指数 | 15% | 软维度 | CLIP向量传播 + LLM视觉 |
| 装饰价值指数 | 10% | 软维度 | CLIP向量传播 + LLM视觉 |
| 裂变能力指数 | 10% | 软维度 | CLIP向量传播 + LLM视觉 |
| 欧洲文化匹配度 | 5% | 软维度 | CLIP向量传播 + LLM视觉 |
| 市场容量指数 | 10% | 硬维度 | `units` 直接计算 |

**硬维度（60%权重）**：SQL直接计算，零AI成本，毫秒级。

**软维度（40%权重）**：向量传播+LLM增强，是AI发挥价值的核心区域。

**8维总计100%**：硬维度60% + 软维度40%。

#### 各维度评分标准

> **[已确认决策]** 以下绝对阈值仅作为参考基准。实际评分采用百分位排名（见07文档）。
> 其中**轻小件**和**体积成本**保留绝对值（物理/成本约束），**利润**和**市场容量**改为百分位。

**轻小件指数（15分）** — 保留绝对值（重量是物理约束）

| 重量 | 得分 |
|------|------|
| ≤100g | 15 |
| 100-150g | 13 |
| 150-300g | 10 |
| 300-500g | 5 |
| >500g | 0 |

**体积成本指数（15分）**

| FBA占比（配送费/售价） | 得分 |
|---------------------|------|
| ≤15% | 15 |
| 15-25% | 12 |
| 25-35% | 8 |
| >35% | 0 |

**利润指数（20分）** — 改为百分位（各品类利润率基线不同，见07文档）

**市场容量指数（10分）** — 改为百分位（各品类月销基线差4-5倍，见07文档）

**情绪价值/装饰价值/裂变能力/欧洲文化匹配度** — 见 [02-AI驱动选品评分.md](./02-AI驱动选品评分.md)

#### 总分与等级

```
8维加权分 = 0.15×轻小件 + 0.15×体积成本 + 0.20×利润
          + 0.15×情绪价值 + 0.10×装饰价值 + 0.10×裂变能力
          + 0.05×文化匹配 + 0.10×市场容量

// 以上为基础权重(60%硬+40%软=100%)
// 已映射品类使用08文档专属权重替代（硬软比例因品类而异）

selection_score = 8维加权分 × 品类健康度系数
```

> **[已确认决策]** 品类健康度系数已采纳（0.6-1.2）。蓝海品类加分，红海品类减分。详见07文档§五。

| 总分区间 | 选品等级 | 含义 |
|---------|---------|------|
| ≥85 | S1 | 强烈推荐开品 |
| 70-84 | S2 | 推荐，可进入 |
| 55-69 | S3 | 可观察 |
| <55 | X | 不推荐 |

#### 结果回写

评分结果写回 `competitor_products` 表新增字段，参与商品树排序和前端展示。

### 3.3 第3层：Agent深度分析

**目标**：对高分候选商品进行深度竞品分析、趋势判断和决策建议。

#### 触发方式

| 触发方式 | 场景 | 频率 |
|---------|------|------|
| 用户点击"AI分析" | 单品深度分析 | 实时 |
| Celery定时任务 | 每日凌晨批量分析S1/S2新品 | 每日 |
| 蓝海发现任务 | 自动扫描全品类寻找蓝海信号 | 每周 |

#### 三大分析工具

**工具1：竞品格局分析**

输入一个类目路径，聚合查询同类目TOP20商品，计算：
- 头部集中度（TOP10销量占比）
- 评论门槛（TOP10平均评论数）
- 新品机会（1年内新品占比）
- 中国品牌占比
- 价格分布与空白点

LLM解读数据，输出进入难度判断和切入建议。

**工具2：跨月趋势分析**

利用 `competitor_products` 的 `(marketplace, asin, month)` 多月份数据：
- 销量变化趋势与加速度
- BSR走势（健康上升 vs 打价格战）
- 价格变化（是否在被卷）
- 生命周期阶段判断

LLM综合判断产品处于上升期/稳定期/下降期。

**工具3：蓝海信号发现**

按 `node_label_path` 聚合全品类，计算蓝海指数：
- 新品占比高 + 商品总数少 = 新兴赛道
- 多店铺同时上新 = 需求验证
- BSR表现好 + 卖家分散 = 未固化市场

LLM对TOP10蓝海品类进行深度解读和匹配度分析。

#### 分析报告结构

```json
{
  "asin": "B0XXX",
  "summary": "一句话概述",
  "competition": {
    "entry_difficulty": "easy/medium/hard",
    "concentration_risk": "low/medium/high",
    "review_barrier": 500,
    "price_gap": "£8-12区间空白",
    "recommendation": "enter/observe/avoid"
  },
  "trend": {
    "phase": "rising/stable/declining",
    "sales_momentum": "accelerating/stable/slowing",
    "price_war_risk": "low/medium/high"
  },
  "ai_score_breakdown": {
    "硬维度总分": 52,
    "软维度总分": 28,
    "selection_score": 80,
    "selection_grade": "S2"
  },
  "risks": ["风险1", "风险2"],
  "entry_strategy": "切入建议",
  "confidence": 0.85
}
```

## 四、与现有系统的对接

### 4.1 数据流全景

```
卖家精灵API
    │
    ▼ 每日数据导入
competitor_products 表
    │
    ├─→ CompetitorFilterService（已有）
    │   └─→ filter_mode = MODE1/MODE2/FAIL
    │
    ├─→ AI软评分（新增）
    │   ├─→ SQL计算硬维度（55%）
    │   ├─→ 向量传播软维度（40%）
    │   └─→ 写回 selection_score / selection_grade
    │
    ├─→ 商品树页面（新增）
    │   └─→ 按评分等级筛选、排序、浏览
    │
    └─→ Agent深度分析（新增）
        └─→ product_analysis 表（分析报告）
```

### 4.2 现有系统能力复用

| 现有模块 | 用途 | 选品算法新用途 |
|---------|------|--------------|
| `CompetitorFilterService` | MODE1/MODE2筛选 | 第1层硬筛选（已有，需调阈值） |
| `FilterConfigService` | 筛选配置管理 | 新增禁止类目配置项 |
| `ScoringService` + `scoring_engine` | 4维评分 | 扩展或替换为8维选品评分 |
| `CompetitorProductMapper` | 多维查询 | 新增品类聚合查询、蓝海指数查询 |
| CLIP + Qdrant | 以图搜图 | 向量传播选品标签（核心新增） |
| 混元大模型视觉 | 素材库图片分析 | 商品图片→选品软维度评分 |
| Celery | 异步任务 | 新增选品评分定时任务 |

| 字段 | 类型 | 说明 |

## 六、决策评分表（开品模型最终决策）

在第2层8维评分之后，对S1/S2级商品执行第3层5维决策评分：

| 决策维度 | 权重 | 10分标准 | 7分标准 | 4分标准 | 1分标准 |
|---------|------|---------|--------|--------|--------|
| 利润率 | 30% | ≥25% | 20-25% | 15-20% | <15% |
| 市场容量 | 25% | ≥3000/月 | 1000-3000 | 500-1000 | <500 |
| 竞争强度 | 20% | 评论<500 | 500-2000 | — | >2000 |
| 裂变空间 | 15% | 20+SKU | 10-20 | — | <10 |
| 差异化机会 | 10% | 明显 | 一般 | — | 很难 |

| 综合得分 | 决策 |
|---------|------|
| ≥8分 | 立即开品 |
| 6-8分 | 有条件开品（需找到差异化点） |
| 4-6分 | 观察，暂不开品 |
| <4分 | 放弃 |

## 七、季节性维度

选品需考虑时间因素，不同月份关注不同品类：

| 标签 | 旺季月份 | 典型品类 | 系统实现 |
|------|---------|---------|---------|
| 圣诞旺季 | 10-12月 | Ornaments, Gift Wrap, Cards | `month`字段筛选 |
| 情人节 | 1-2月 | Love-themed decor, Jewelry | `month`字段筛选 |
| 复活节 | 3-4月 | Easter decor, Spring items | `month`字段筛选 |
| 毕业季 | 5-7月 | Graduation cards, Signs | `month`字段筛选 |
| 全年稳定 | 全年 | Birthday Cards, Keyrings | 无季节性 |

系统已有 `month` 字段作为全局控制器（商品树月份选择器），季节性分析可直接通过跨月数据对比实现。
