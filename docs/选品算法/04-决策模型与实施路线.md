# 选品决策模型与实施路线

> 本文档定义从评分到决策的完整链路，以及分阶段实施路线。

> **[已确认决策]**
> - 选品评分采用百分位相对评分（07文档），本档的决策评分同步对齐
> - 选品等级命名 S1/S2/S3/X，与现有表现评分S/A/B/C/D并存
> - 8维权重先采用邓总模型，Phase 5反馈闭环再调
> - 品类健康度系数已采纳，影响最终选品得分

---

## 一、决策链路全景

```
competitor_products（6991+条）
    │
    ▼ 第1层：硬筛选
候选池（~1500-2000条，MODE1+MODE2）
    │
    ▼ 第2层：AI软评分（8维，100分）
分级商品（S1 ~50条 / S2 ~200条 / S3 ~500条 / X 其余）
    │
    ▼ 第3层：Agent深度分析（仅S1+S2）
决策报告（竞品格局 + 趋势 + 蓝海匹配）
    │
    ▼ 第4层：5维决策评分（10分制）
最终决策（开品 / 有条件开品 / 观察 / 放弃）
```

---

## 二、8维评分 → 决策评分的转换

第2层的8维评分解决"这个产品好不好"。

第4层的5维决策评分解决"我们要不要做"。

两者关系：

| 8维评分维度 | 对决策评分的影响 |
|-----------|----------------|
| 轻小件指数(15%) | 影响"竞争强度"（轻小件=易物流=低门槛） |
| 体积成本指数(15%) | 影响"利润率"（FBA占比低=利润高） |
| 利润指数(20%) | 直接决定"利润率" |
| 情绪价值(15%) | 影响"差异化机会"（情绪产品容易差异化） |
| 装饰价值(10%) | 影响"裂变空间"（装饰品容易换图案） |
| 裂变能力(10%) | 直接决定"裂变空间" |
| 文化匹配(5%) | 影响"市场容量"（匹配度高=有效市场大） |
| 市场容量(10%) | 直接决定"市场容量" |

## 三、5维决策评分模型

来自邓总店铺开品模型，适配系统数据：

> **[已确认决策]** 决策评分中的“利润率”和“市场容量”也采用百分位（与07文档对齐），
> 避免绝对阈值在不同站点/品类下的系统性偏差。

### 3.1 利润率（权重30%）

> 采用百分位（同站点×品类内比较）

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 10分 | 利润率在同品类TOP10% | `profit/price` ≥ 品类p90 |
| 7分 | 利润率在同品类TOP25% | `profit/price` ≥ 品类p75 |
| 4分 | 利润率在同品类TOP50% | `profit/price` ≥ 品类p50 |
| 1分 | 利润率在同品类后50% | `profit/price` < 品类p50 |

### 3.2 市场容量（权重25%）

> 采用百分位（同站点×品类内比较，避免UK/US/DE体量差异）

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 10分 | 月销在同品类TOP10% | `units` ≥ 品类p90 |
| 7分 | 月销在同品类TOP25% | `units` ≥ 品类p75 |
| 4分 | 月销在同品类TOP50% | `units` ≥ 品类p50 |
| 1分 | 月销在同品类后50% | `units` < 品类p50 |

### 3.3 竞争强度（权重20%）

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 10分 | 低竞争 | 竞品格局分析输出 `entry_difficulty = easy` |
| 7分 | 中等竞争 | `entry_difficulty = medium` |
| 4分 | 高竞争 | `entry_difficulty = hard` |
| 1分 | 红海 | TOP10均评论>5000 且 品牌集中 |

如无竞品格局分析数据，用简化规则：
- `ratings < 500` → 10分
- `ratings 500-2000` → 7分
- `ratings > 2000` → 4分

### 3.4 裂变空间（权重15%）

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 10分 | 可裂变20+ SKU | AI软评分 `fission_score ≥ 8` |
| 7分 | 可裂变10-20 SKU | `fission_score` 在 6-8 |
| 4分 | 可裂变5-10 SKU | `fission_score` 在 4-6 |
| 1分 | 不可裂变 | `fission_score < 4` |

### 3.5 差异化机会（权重10%）

| 得分 | 标准 | 数据来源 |
|------|------|---------|
| 10分 | 明显差异化空间 | Agent分析发现价格空白（→[11文档](./11-竞品差异化分析.md)）或评论痛点 |
| 7分 | 一般差异化 | `emotion_score ≥ 7` 或 `decoration_score ≥ 7` |
| 4分 | 难以差异化 | 软维度均<6 |
| 1分 | 无法差异化 | 纯标品，无情绪/装饰属性 |

### 3.6 综合决策

```
决策得分 = 0.30×利润率 + 0.25×市场容量 + 0.20×竞争强度 + 0.15×裂变空间 + 0.10×差异化机会
```

| 决策得分 | 决策 | 系统状态 |
|---------|------|--------|
| ≥8 | 立即开品 | `decision_status = 'LAUNCH'` |
| 6-8 | 有条件开品 | `decision_status = 'CONDITIONAL'` |
| 4-6 | 观察 | `decision_status = 'WATCH'` |
| <4 | 放弃 | `decision_status = 'ABANDON'` |

### 3.7 深度分析信号对决策的调整

> 以下信号来自10-13文档的深度分析，在5维决策评分之后叠加调整。

**等级提升规则**（来自[12-新品爆发信号](./12-新品爆发信号检测.md)）：

| 原始等级 | 爆发信号 | 调整后 | 理由 |
|---------|---------|---------|------|
| S2 | 🔴紧急（爆发分≥80） | → **S1** | 正在爆发的产品不能等 |
| S3 | 🔴紧急 | → **S2** | 趋势足够强，提升关注级别 |
| S2 | 🟡重点（爆发分≥50） | 不变，但加注“重点关注”标签 | |

**决策加分规则**（来自[13-跨站点套利](./13-跨站点套利发现.md)）：

| 套利信号 | 调整 | 理由 |
|---------|------|------|
| 跨站套利评分≥70 | 决策得分 +1.0 | 信息差套利机会，竞争更小 |
| 跨站套利评分≥50 | 决策得分 +0.5 | |

**差异化加分**（来自[11-竞品差异化](./11-竞品差异化分析.md)）：

| 差异化信号 | 调整 | 理由 |
|---------|------|------|
| 发现明确价格带空白（≥20%产品数缺口） | 差异化机会维度直接给10分 | 有明确切入角度 |
| 发现≥2个可切入维度 | 决策得分 +0.5 | 多维度差异化更稳健 |

## 四、决策状态机

```
            ┌──────────────────────┐
            │ 候选池（MODE1/MODE2） │
            └──────────┬───────────┘
                       │ 8维评分
                       ▼
              ┌────────────────┐
              │ S1/S2/S3/X分级  │
              └───┬──┬──┬──┬───┘
                  │  │  │  │
          S1/S2   │  │  │  │  X
                  │  │  │  │
                  │  │  │  └──→ ABANDON（直接放弃）
                  │  │  │
                  │  │  └────→ WATCH（仅S3，观察等数据完善后再评）
                  │  │
          Agent深度分析
                  │  │
                  │  └──────→ 5维决策评分
                  │
                  ▼
         ┌──── LAUNCH ────→ 进入终稿池/开品流程
         ├──── CONDITIONAL ─→ 记录待确认条件，人工审批后可开品
         └──── ABANDON ────→ 标记放弃原因，存档
```

## 五、与"商品树"页面的关系

商品树页面是选品算法的**展示层**：

| 商品树功能 | 选品算法提供 |
|-----------|------------|
| 品类层级浏览 | `node_label_path` 解析为树结构 |
| 评分排序 | `selection_score` 降序 |
| 等级筛选 | `selection_grade`（S1/S2/S3/X） |
| 决策状态标签 | `decision_status`（LAUNCH/CONDITIONAL/WATCH） |
| AI分析报告查看 | `product_analysis` 关联查询 |
| 蓝海品类高亮 | 蓝海指数 > 阈值的品类特殊标记 |
| 月份切换 | `month` 字段作为全局筛选条件 |

## 七、关键设计决策

### 7.1 为什么不做"全量AI分析"

- 6991条商品 × LLM逐条分析 = 成本高、速度慢、意义不大
- 选品的本质是"从海量中找少量"，不需要每条都精确
- 向量传播用200条种子覆盖60-80%商品，性价比最优
- 只有S1/S2（~250条）才值得深度分析

### 7.2 为什么品类是分析单位

- 同一品类的商品选品特征高度相似
- 品类级分析减少LLM调用（20-50次 vs 6991次）
- 品类画像可跨月对比，发现趋势变化
- 蓝海信号天然按品类聚合

### 7.3 为什么保留规则兜底

- 向量传播不可能覆盖100%商品
- 新数据导入时，传播结果尚未更新
- 规则兜底确保所有商品都有基础评分
- 规则评分的置信度（0.3）低于AI标注（0.7+），排序时自然靠后
