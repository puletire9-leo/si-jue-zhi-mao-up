## 三、10维机会雷达（品类级信号）

### 3.1 维度定义

每个维度 0-100 分（百分位归一化），越高越好。

| # | 维度 | 数据来源字段 | 计算逻辑 | 高分含义 |
|---|------|-------------|---------|---------|
| D1 | **新品活跃度** | listingDays | 新品(≤90天)占比 | 很多人在尝试进入 |
| D2 | **新品成功率** | listingDays + bsr + units | 新品中BSR<10万的比例 | 新品进入后能活下来 |
| D3 | **评论壁垒（反向）** | ratings, ratingsCv | TOP10均评论数的倒数归一化 | 评论门槛低，新品容易追赶 |
| D4 | **品牌分散度** | brand | unique_brands / total | 没有品牌垄断 |
| D5 | **卖家分散度** | sellerName | unique_sellers / total | 没有卖家垄断 |
| D6 | **利润空间** | profit, price | 品类均利润率(profit/price) | 有利润可赚 |
| D7 | **需求强度** | units, bsr | 品类均月销量的百分位 | 市场需求真实存在 |
| D8 | **价格战风险（反向）** | price + listingDays | 新品均价/老品均价的比值 | 新品不需要降价才能卖 |
| D9 | **Listing质量差距** | rating, ratingsRate, video, ebc | 品类头部低质Listing比例 | 现有卖家运营水平低，有超越空间 |
| D10 | **标签势能** | bestSeller, amazonChoice, newRelease | 品类中有标签的产品比例 | 品类受亚马逊算法青睐 |

### 3.2 维度分组

10个维度分为3组，对应选品的3个核心问题：

```
┌─────────────────────────────────────────────────┐
│  第一组：能不能进？（进入壁垒）                    │
│  D3 评论壁垒  D4 品牌分散度  D5 卖家分散度        │
├─────────────────────────────────────────────────┤
│  第二组：值不值得进？（机会质量）                   │
│  D1 新品活跃度  D2 新品成功率  D7 需求强度         │
│  D10 标签势能                                    │
├─────────────────────────────────────────────────┤
│  第三组：进去能不能赚？（盈利可行性）               │
│  D6 利润空间  D8 价格战风险  D9 Listing质量差距     │
└─────────────────────────────────────────────────┘
```

### 3.3 各维度计算逻辑

**D1 新品活跃度**
- 统计：品类中 listing_days ≤ 90 的商品数 / 品类总商品数
- 含义：高=很多人在进入，赛道活跃
- 注意：单独看高不一定是好事（可能是扎堆），需要结合D2

**D2 新品成功率**（V2新增核心维度）
- 统计：品类新品(listing_days ≤ 90)中 BSR < 100000 的比例
- 含义：高=新品进入后能活，低=很多人试但很少人成（伪蓝海识别器）
- 关键判断：D1高 + D2低 = "很多人试但成功率低"，需要警惕

**D3 评论壁垒**（V2新增核心维度）
- 统计：品类TOP10商品的平均ratings数
- 归一化：1 / (1 + avg_top10_ratings / 1000)
- 含义：高=评论门槛低（TOP10也才几百评论），低=评论壁垒高（TOP10均5000+评论）
- 关键判断：<30分 = 高壁垒红海，进入困难

**D4 品牌分散度**（V2新增）
- 统计：unique_brands / total_products
- 含义：高=50个产品50个品牌（极度分散），低=50个产品只有3个品牌（垄断）
- 与V1的区别：V1只看卖家分散度，品牌集中度是独立信号

**D5 卖家分散度**（V1保留）
- 统计：unique_sellers / total_products
- 含义：同V1

**D6 利润空间**（V2新增核心维度）
- 统计：AVG(profit) / AVG(price) — 品类利润率
- 含义：高=利润空间大，低=利润薄
- 关键判断：<30%利润率 = 扣除广告后可能亏损

**D7 需求强度**（V2新增）
- 统计：品类均月销量的百分位排名（相对所有品类）
- 含义：高=市场需求大，低=需求小
- 注意：需求小不一定是坏事（小众蓝海），但需求大+低壁垒=绝佳机会

**D8 价格战风险**（V2新增）
- 统计：新品(listing_days≤90)均价 / 老品(listing_days>365)均价
- 含义：>0.9=新品不需要降价，<0.7=新品被迫降价30%以上才能卖
- 关键判断：<0.7 = 该品类靠低价竞争，利润不可持续

**D9 Listing质量差距**（V2新增）
- 统计：品类TOP20中满足以下条件的比例——rating<4.0 OR ratings_rate<2% OR video IS NULL OR ebc IS NULL
- 含义：高=现有卖家运营水平低，做好就能超越（"软蓝海"）
- 关键判断：>60% = 大量低质Listing，运营优势明显

**D10 标签势能**（V2新增）
- 统计：品类中 bestSeller='Y' OR amazonChoice='Y' OR newRelease='Y' 的商品比例
- 含义：高=品类整体势能高，被亚马逊算法青睐
- 选品意义：有标签的品类说明亚马逊认为该品类有需求

## 四、品类机会分型

根据10维雷达数据，将每个品类归入4种机会类型：

### 4.1 分型规则

| 类型 | 标记 | 判定条件 | 行动建议 |
|------|------|---------|---------|
| **蓝海机会** | 🌊 | D3≥60 AND D4≥50 AND D6≥50 AND D7≥40 | 优先投入，批量选品 |
| **红海有缝** | 🔥 | D3<60 但 D9≥50 OR D8≥70（有Listing差距或价格空间） | 精准切入，测品2-3个 |
| **小众精品** | 💎 | D7<40 但 D6≥70 AND D2≥50（需求小但利润高、成功率高） | 少量测品，验证需求 |
| **观望区** | ⏳ | D2<30 AND D3<30（成功率低+壁垒高） | 暂不投入，下月再看 |

### 4.2 分型逻辑说明

```
不是"蓝海 or 不做"的二分法！

每个品类都会得到分型，每个分型都有对应的行动建议。
即使"观望区"也不是"不做"，而是"下个月数据更新后再评估"。

红海有缝是最体现"尝试优先"思想的分型——
壁垒高但有缝隙（Listing差距大 or 有价格空间），值得小批量试。
```

### 4.3 与08品类原型的协同

品类原型（DA/FH/FP/TN/PE/PS）影响分型的权重偏好：

| 原型 | 更关注维度 | 原因 |
|------|-----------|------|
| DA 装饰艺术 | D9 Listing质量 > D3 评论壁垒 | 装饰品靠视觉差异化，运营差距比评论更重要 |
| FH 功能家居 | D6 利润 > D7 需求 | 功能品利润稳定，需求已验证 |
| FP 时尚个人 | D1 新品活跃度 > D8 价格战 | 时尚变化快，新品本身有机会 |
| TN 趋势潮流 | D2 新品成功率 > D10 标签势能 | 趋势品成功率是关键，不追热度 |
| PE 派对活动 | D7 需求 > D9 Listing质量 | 刚需品类，需求确认比质量差距重要 |
| PS 纸品文具 | D6 利润 > D4 品牌分散 | 文具利润薄，利润空间是第一门槛 |

## 五、产品级测品推荐（V2核心新增）

### 5.1 设计目标

每个品类（包括红海）输出2-5个"值得测品"的具体ASIN推荐。

### 5.2 测品候选筛选逻辑

从品类内所有商品中，按以下条件筛选测品候选：

**基础门槛**（硬排除，仅过滤明显不可做的）：
- filter_mode != 'FAIL'
- weight_g < 1000（轻小件）
- price 在品类均价的 0.5x-2x 范围内

**机会评分**（排序依据，取TOP5）：

| 信号 | 加分条件 | 理由 |
|------|---------|------|
| 新品快速起量 | listing_days ≤ 90 AND bsr < 50000 | 证明新品可以快速做到好排名 |
| 低评论高销量 | ratings < 50 AND units > 品类中位数 | 不需要大量评论也能卖，我们也能做到 |
| 高利润 | profit > 品类75百分位 | 利润空间大 |
| 运营差距大 | rating < 4.0 OR video IS NULL | 我们做好运营就能超越 |
| 价格带空白 | 所在价格区间(±20%)商品数 < 品类中位数的30% | 竞争少的价格带 |
| 变体少 | variations ≤ 3 | 变体竞争不激烈 |

### 5.3 测品推荐输出格式

```
品类：Wall Art（UK站 / 2026-06）
分型：🌊 蓝海机会
雷达：D1=72 D2=65 D3=78 D4=82 D5=90 D6=68 D7=55 D8=85 D9=70 D10=45

推荐测品：
┌─────┬──────────┬───────┬──────┬──────┬──────────────────┐
│ ASIN │ 上架天数  │ 月销  │ 利润£ │ 评论数 │ 推荐理由            │
├─────┼──────────┼───────┼──────┼──────┼──────────────────┤
│ A001 │ 45天     │ 120   │ £85  │ 12   │ 新品快速起量+低评论  │
│ A002 │ 180天    │ 200   │ £92  │ 350  │ 高利润+价格带空白    │
│ A003 │ 30天     │ 80    │ £78  │ 5    │ 超新品+极少评论     │
└─────┴──────────┴───────┴──────┴──────┴──────────────────┘

切入角度：
- 价格带£8-12竞争较少（该区间仅占品类15%）
- 头部TOP5中3个没有做视频，Listing质量差距大
- 建议：从差异化设计切入，首月目标50单
```

### 5.4 与08品类原型的联动

测品推荐的评分权重受品类原型影响：

- **DA型**：更看重"运营差距大"（装饰品靠视觉）
- **FH型**：更看重"高利润"（功能品利润是核心）
- **FP型**：更看重"新品快速起量"（时尚品速度是核心）
- **PE型**：更看重"价格带空白"（派对品找到空白价位）

## 六、SQL聚合查询设计

### 6.1 品类级10维聚合

```sql
SELECT
  -- 品类标识
  SUBSTRING_INDEX(SUBSTRING_INDEX(node_label_path, ':', 3), ':', -1) AS category,

  -- D1 新品活跃度
  AVG(CASE WHEN listing_days <= 90 THEN 1.0 ELSE 0.0 END) AS new_ratio,

  -- D2 新品成功率
  AVG(CASE WHEN listing_days <= 90 AND bsr < 100000 THEN 1.0 ELSE 0.0 END)
    / NULLIF(SUM(CASE WHEN listing_days <= 90 THEN 1 ELSE 0 END), 0) AS new_success_rate,

  -- D3 评论壁垒（需要子查询取TOP10，此处简化为全品类）
  AVG(ratings) AS avg_ratings,
  AVG(CASE WHEN ratings < 100 THEN 1.0 ELSE 0.0 END) AS low_review_ratio,

  -- D4 品牌分散度
  COUNT(DISTINCT brand) AS unique_brands,

  -- D5 卖家分散度
  COUNT(DISTINCT seller_name) AS unique_sellers,

  -- D6 利润空间
  AVG(profit) AS avg_profit,
  AVG(price) AS avg_price,
  AVG(profit / NULLIF(price, 0)) AS avg_profit_rate,

  -- D7 需求强度
  AVG(units) AS avg_units,
  SUM(units) AS total_units,

  -- D8 价格战风险
  AVG(CASE WHEN listing_days <= 90 THEN price END) AS new_avg_price,
  AVG(CASE WHEN listing_days > 365 THEN price END) AS old_avg_price,

  -- D9 Listing质量差距
  AVG(CASE WHEN rating < 4.0 OR video IS NULL OR ebc IS NULL
           THEN 1.0 ELSE 0.0 END) AS low_quality_ratio,

  -- D10 标签势能
  AVG(CASE WHEN best_seller = 'Y' OR amazon_choice = 'Y'
                OR new_release = 'Y' THEN 1.0 ELSE 0.0 END) AS tag_ratio,

  -- 基础统计
  COUNT(*) AS total,
  COUNT(DISTINCT seller_name) / NULLIF(COUNT(*), 0) AS seller_diversity,
  COUNT(DISTINCT brand) / NULLIF(COUNT(*), 0) AS brand_diversity

FROM competitor_products
WHERE marketplace = #{mp} AND month = #{month}
  AND filter_mode != 'FAIL'
GROUP BY category
HAVING total >= 5
```

### 6.2 产品级测品推荐查询

```sql
SELECT
  asin, title, price, profit, units, bsr, ratings, rating,
  listing_days, seller_name, brand, weight_g, variations,
  video, ebc, best_seller, amazon_choice, new_release,
  node_label_path
FROM competitor_products
WHERE marketplace = #{mp} AND month = #{month}
  AND filter_mode != 'FAIL'
  AND node_label_path LIKE CONCAT(#{category}, '%')
  AND weight_g < 1000
  AND price BETWEEN #{price_low} AND #{price_high}
ORDER BY
  -- 综合排序：新品快速起量 + 低评论高销量 + 高利润 + 运营差距
  (CASE WHEN listing_days <= 90 AND bsr < 50000 THEN 3 ELSE 0 END)
  + (CASE WHEN ratings < 50 AND units > #{median_units} THEN 2 ELSE 0 END)
  + (CASE WHEN profit > #{p75_profit} THEN 2 ELSE 0 END)
  + (CASE WHEN rating < 4.0 OR video IS NULL THEN 1 ELSE 0 END)
  DESC,
  profit DESC
LIMIT 5
```

## 九、执行流程

### 9.1 定时执行（每月初）

```
数据导入完成
    │
    ▼
品类级SQL聚合（1次查询，返回所有品类×10维数据）
    │
    ▼
Python计算：百分位归一化 + 品类分型
    │
    ▼
产品级测品推荐查询（每个品类1次，取TOP5 ASIN）
    │
    ▼
写入 blue_ocean_snapshots 表
    │
    ▼
LLM解读（分批，每批10个品类）→ 更新 llm_summary
    │
    ▼
前端商品树刷新品类标记
```

### 9.2 按需执行（用户触发）

在商品树页面点击某个品类节点 → 实时计算该品类的机会卡 + 测品推荐。
