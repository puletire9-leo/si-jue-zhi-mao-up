### 1.2 卖家精灵设计要点

| 特征 | 说明 |
|------|------|
| **单一入口** | 只有一个"更多筛选"按钮，点击打开右侧抽屉 |
| **排序置顶** | 排序字段+方式放在抽屉最顶部，视觉优先级最高 |
| **三列布局** | 价格 / 销量与上架 / 其他筛选，三列并排，信息密度高 |
| **预设快捷按钮** | 上架天数用按钮组（30/60/90/180/360天+自定义），不用输入框 |
| **单位内联** | 货币符号(£/$/€)、单位(g)紧跟输入框右侧 |
| **帮助图标** | 每个字段旁有 `?` 图标，hover 显示说明 |
| **预设管理** | 底部"我的筛选"区域，星标=默认，+更新=保存当前，...=更多操作 |
| **底部固定** | 重置+确认筛选按钮固定在抽屉底部 |
| **无分散筛选** | 页面顶部没有额外的筛选栏，所有筛选集中在抽屉内（注：本项目**不照搬**此点，站点/大类仍留主栏，见修复 1） |

### 2.2 核心问题清单

#### 问题 1：筛选入口分散（严重）

| 位置 | 筛选能力 | 问题 |
|------|---------|------|
| SelectionQueryForm 紧凑模式 | 国家/卖家/搜索 | 与 unified-filter-bar 重复 |
| SelectionQueryForm 筛选对话框 | 国家/来源/大类/等级/时效/排序 | 与 FilterDrawer 重复，且已废弃但未删除 |
| unified-filter-bar | 站点/大类/更多筛选按钮/chips | 与 SelectionQueryForm 重复 |
| FilterDrawer | 卖家/排序/区间/预设 | 主要筛选入口，但与其他组件有重叠 |

**根因**：SelectionQueryForm 是通用组件，AllSelection 页面又自建了一套筛选体系，两者没有整合。

#### 问题 2：排序逻辑重复（中等）

| 位置 | 排序字段 | 排序方式 |
|------|---------|---------|
| SelectionQueryForm 传统模式 | 销量/BSR/价格/上架时间/创建时间 | 降序/升序 |
| SelectionQueryForm 筛选对话框 | 评分/销量/BSR/价格/上架时间/创建时间 | 降序/升序 |
| FilterDrawer | 评分/销量/BSR/价格/上架时间/创建时间 | 降序/升序 |

排序出现在 **3 个地方**，字段列表不完全一致（传统模式缺"评分"），用户困惑。

#### 问题 3：draft/committed 双状态同步问题（中等）

当前 AllSelection 使用 draft（草稿）+ committed（已提交）双状态模式：
- `draft`：抽屉内的临时状态
- `committed`：已确认的筛选条件
- `rangeFilter`：区间筛选的独立状态

**问题**：
1. `rangeFilter` 与 `draft.range` 是**两个独立对象**，同步逻辑复杂
2. `committed.category` 是数组，`SelectionQueryForm.formData.category` 是字符串，需要转换
3. `syncCommittedToForm()` 只同步部分字段，遗漏 `sortField`/`sortOrder` 到 SelectionQueryForm
4. 预设加载时（`handlePresetApply`）需要同时更新 committed、rangeFilter、draft 三处，容易遗漏

#### 问题 4：视觉风格不统一（中等）

| 组件 | 背景色 | 边框 | 圆角 | 间距 |
|------|--------|------|------|------|
| SelectionQueryForm | 透明 | 无 | 无 | 16px |
| unified-filter-bar | #fff | 1px solid #ebeef5 | 8px | 10px 14px |
| FilterDrawer | 透明（抽屉默认） | 无 | 无 | 20px |
| RangeFilterPanel | $bg-body (#f5f0eb) | 1px solid $border-color | 10px | 16px 20px |

RangeFilterPanel 用了项目的 Amber Classic 风格变量，但其他组件用硬编码颜色。

#### 问题 5：SelectionQueryForm 过于臃肿（中等）

- 文件行数：1266 行（含样式）
- 两种模式（紧凑/传统）+ 筛选对话框 + 多项搜索对话框 = 4 种 UI 形态
- 内部维护 18 个字段的 formData
- 同时承担"搜索"和"筛选"两种职责

#### 问题 6：字段映射混乱（轻微）

```ts
// FILTER_TO_API_KEY 映射表
const FILTER_TO_API_KEY: Record<string, string> = {
  country: "marketplace",      // 前端 country → 后端 marketplace
  dataFilterMode: "filterMode", // 前端 dataFilterMode → 后端 filterMode
  productTitle: "title",        // 前端 productTitle → 后端 title
  storeName: "sellerName",      // 前端 storeName → 后端 sellerName
  sortField: "sortBy",          // 前端 sortField → 后端 sortBy
};

// SORT_VALUE_MAP 映射表
const SORT_VALUE_MAP: Record<string, string> = {
  salesVolume: "units",         // 前端 salesVolume → 后端 units
  listingDate: "listingDays",   // 前端 listingDate → 后端 listingDays
};
```

前端字段名与后端 API 字段名存在差异，需要两处映射表转换，容易出错。

## 三、重构方案

### 3.1 目标架构

```
AllSelection/index.vue（核心页面）
├── SearchBar（新组件：搜索栏）
│   ├── 搜索类型选择器 + 搜索输入框 + 搜索按钮
│   ├── 以图搜图按钮
│   └── 更多筛选按钮（区间/维度类筛选入口）
│
├── unified-filter-bar（主栏：高频维度，保留）
│   ├── 站点选择器（US/UK/DE）
│   └── 大类榜单选择器（多选）
│
├── FilterChipsBar（新组件：已选条件标签栏）
│   └── 显示所有已生效的筛选条件，可单个删除或清除全部
│
├── FilterDrawer（优化：筛选抽屉，承载区间/维度类筛选）
│   ├── 排序区（顶部）
│   ├── 区间与维度区（三列布局）
│   │   ├── 入库批次（周）← 唯一时效筛选（已删数据时效 isCurrent）
│   │   ├── 价格 / 销量与上架 / 其他筛选
│   │   └── 配送方式 / 评分等级
│   ├── 我的筛选（预设管理）
│   └── 底部：重置 + 确认筛选
│
└── 产品列表 + 分页
```

### 3.2 组件职责重新划分

| 组件 | 职责 | 状态 |
|------|------|------|
| **SearchBar** | 仅负责搜索（ASIN/标题/店铺/关键词） | 新建，替代 SelectionQueryForm 的搜索部分 |
| **FilterDrawer** | 唯一筛选入口，包含所有筛选条件 | 优化现有组件 |
| **FilterChipsBar** | 显示已选筛选条件 | 从 AllSelection 内联代码抽取 |
| **SelectionQueryForm** | 降级为纯搜索组件或废弃 | 待决策 |
| **RangeFilterPanel** | 区间筛选面板（嵌入抽屉） | 保持，优化样式 |
| **FilterPresetSelector** | 预设管理（嵌入抽屉） | 保持 |
| **QualifyRuleFilter** | 灵活合格规则（新品榜用） | 保持，按需启用 |

### 3.3 详细修复建议

#### 修复 1：统一筛选入口（优先级：高）

**目标**：页面只有一个"次级"筛选入口（"更多筛选"按钮），区间/维度类筛选集中在抽屉内；**站点、大类两个高频维度保留在主栏**，不进抽屉。

> ⚠️ 决策修正（2026-06-19）：站点/大类**不**移入抽屉。卖家精灵把所有筛选塞进抽屉的做法不适用于本项目——站点和大类是高频切换维度，放在主栏可见、可直接操作，体验更好。"单一入口"原则仅适用于区间与维度类的低频筛选。

**具体操作**：
1. 站点/大类选择器**保留在主栏** `unified-filter-bar`，不移入 FilterDrawer
2. 删除 SelectionQueryForm 的筛选对话框代码（`filterDialogVisible` 相关）
3. SelectionQueryForm 只保留搜索功能（搜索类型+输入框+按钮+以图搜图+重置）
4. "更多筛选"按钮放在主栏右侧，打开抽屉承载区间/维度类筛选

**修改文件**：
- `frontend/src/views/AllSelection/index.vue`
- `frontend/src/components/SelectionQueryForm/index.vue`

#### 修复 2：排序逻辑统一（优先级：高）

**目标**：排序只在 FilterDrawer 顶部出现一次。

**具体操作**：
1. 删除 SelectionQueryForm 传统模式中的排序选择器
2. 删除 SelectionQueryForm 筛选对话框中的排序选择器
3. FilterDrawer 顶部的排序区作为唯一排序入口
4. 排序字段统一为：评分/销量/BSR/价格/上架时间/创建时间

**修改文件**：
- `frontend/src/components/SelectionQueryForm/index.vue`
- `frontend/src/views/AllSelection/index.vue`

#### 修复 3：简化状态管理（优先级：高）

**目标**：用单一 `filterState` 对象替代 draft/committed/rangeFilter 三套状态。

**当前状态**：
```ts
// 三套独立状态
const rangeFilter = ref<RangeFilterValue>({...})
const draft = reactive({ country, sellerSelect, category, isCurrent, sortField, sortOrder, range })
const committed = reactive({ country, sellerSelect, category, isCurrent, sortField, sortOrder })
```

**目标状态**：
```ts
// 单一状态 + 草稿拷贝
interface FilterState {
  marketplace: string
  sellerName: string
  category: string[]
  sortField: string
  sortOrder: "desc" | "asc"
  range: RangeFilterValue
}

const activeFilters = ref<FilterState>({...})  // 已生效的筛选
const draftFilters = ref<FilterState>({...})   // 抽屉内的草稿
```

**具体操作**：
1. 定义统一的 `FilterState` 接口
2. 打开抽屉时：`draftFilters = clone(activeFilters)`
3. 确认筛选时：`activeFilters = clone(draftFilters)` + 触发查询
4. 重置时：`draftFilters = defaultFilterState`
5. 删除 `rangeFilter`、`draft`、`committed` 三个变量

**修改文件**：
- `frontend/src/views/AllSelection/index.vue`
- `frontend/src/types/filter.ts`（新建）

#### 修复 4：统一视觉风格（优先级：中）

**目标**：所有筛选组件使用统一的 Amber Classic 风格变量。

**具体操作**：
1. SelectionQueryForm 的样式改用 `$bg-body`、`$border-color`、`$radius-lg` 等变量
2. unified-filter-bar 的硬编码颜色改为变量
3. FilterDrawer 的内容区背景色统一
4. 所有筛选组件的间距统一为 `$space-lg`（16px）

**修改文件**：
- `frontend/src/components/SelectionQueryForm/index.vue`
- `frontend/src/views/AllSelection/index.vue`
- `frontend/src/components/FilterDrawer/index.vue`

#### 修复 5：字段映射统一（优先级：中）

**目标**：前端字段名与后端 API 字段名保持一致，消除映射表。

**方案 A（推荐）**：前端字段名改为与后端一致
```ts
// 前端直接使用后端字段名
interface FilterState {
  marketplace: string      // 原 country
  sellerName: string       // 原 storeName
  sortBy: string           // 原 sortField
  sortOrder: string
  title: string            // 原 productTitle
  filterMode: string       // 原 dataFilterMode
  unitsMin/Max: number
  listingDaysMin/Max: number
  priceMin/Max: number
  bsrMax: number
  weightMax: number
  maxVariantCount: number
  fulfillment: string[]
  grade: string[]
  createdWeeks: string[]
}
```

**方案 B**：保留前端字段名，但将映射逻辑抽取为独立函数
```ts
// frontend/src/utils/filterMapper.ts
export function mapFilterToApi(filters: FilterState): CompetitorListParams {
  return {
    marketplace: filters.marketplace,
    sellerName: filters.sellerName,
    sortBy: SORT_FIELD_MAP[filters.sortBy] || filters.sortBy,
    // ...
  }
}
```

**修改文件**：
- `frontend/src/types/filter.ts`（新建）
- `frontend/src/utils/filterMapper.ts`（新建）
- `frontend/src/views/AllSelection/index.vue`

#### 修复 6：SelectionQueryForm 瘦身（优先级：中）

**目标**：将 SelectionQueryForm 拆分为两个独立组件。

**拆分方案**：
```
SelectionQueryForm/          ← 保留，但只负责搜索
├── index.vue                ← 搜索栏（搜索类型+输入框+按钮）
├── types.ts                 ← 搜索相关类型

SearchBar/                   ← 新建（可选，如果 SelectionQueryForm 足够简单）
├── index.vue
```

或者更激进的方案：
```
SearchBar/                   ← 新建，替代 SelectionQueryForm
── index.vue                ← 搜索类型+输入框+按钮+以图搜图+重置+更多筛选
├── types.ts
```

**修改文件**：
- `frontend/src/components/SelectionQueryForm/index.vue`（大幅删减）
- 或新建 `frontend/src/components/SearchBar/index.vue`

### 7.1 统一 FilterState 类型定义

```ts
// frontend/src/types/filter.ts
import type { RangeFilterValue } from "@/components/RangeFilterPanel/index.vue";
import type { QualifyRule } from "@/api/competitor";

export interface FilterState {
  // 基础筛选
  marketplace: string;           // 站点：US/UK/DE
  sellerName: string;            // 卖家名称
  category: string[];            // 大类榜单（多选）
  // 注：数据时效 isCurrent 已删除——与入库批次（range.createdWeeks）功能重合，统一用入库批次

  // 排序
  sortBy: string;                // 排序字段：score/units/bsr/price/listingDays/createdAt
  sortOrder: "desc" | "asc";    // 排序方式

  // 区间筛选
  range: RangeFilterValue;

  // 合格规则（新品榜用）
  qualifyRules: QualifyRule[];
}

export function createDefaultFilterState(marketplace = "UK"): FilterState {
  return {
    marketplace,
    sellerName: "",
    category: [],
    sortBy: "score",
    sortOrder: "desc",
    range: {
      priceMin: null,
      priceMax: null,
      unitsMin: null,
      unitsMax: null,
      listingDaysMin: null,
      listingDaysMax: null,
      bsrMax: null,
      weightMax: null,
      variantCountMax: null,
      fulfillment: [],
      createdWeeks: [],
      category: [],
      grade: [],
      listingPreset: null,
    },
    qualifyRules: [],
  };
}

export function cloneFilterState(state: FilterState): FilterState {
  return {
    ...state,
    category: [...state.category],
    range: {
      ...state.range,
      fulfillment: [...state.range.fulfillment],
      createdWeeks: [...state.range.createdWeeks],
      category: [...state.range.category],
      grade: [...state.range.grade],
    },
    qualifyRules: state.qualifyRules.map(r => ({
      conditions: r.conditions.map(c => ({ ...c })),
    })),
  };
}
```

### 7.2 简化后的 AllSelection 状态管理

```ts
// frontend/src/views/AllSelection/index.vue（节选）
import { ref, onMounted } from "vue";
import { createDefaultFilterState, cloneFilterState } from "@/types/filter";
import type { FilterState } from "@/types/filter";

// 单一状态
const activeFilters = ref<FilterState>(createDefaultFilterState("UK"));
const draftFilters = ref<FilterState>(createDefaultFilterState("UK"));

// 打开抽屉：activeFilters → draftFilters
const openFilterDrawer = () => {
  draftFilters.value = cloneFilterState(activeFilters.value);
  filterDrawerVisible.value = true;
};

// 确认筛选：draftFilters → activeFilters + 查询
const handleDrawerConfirm = () => {
  activeFilters.value = cloneFilterState(draftFilters.value);
  filterDrawerVisible.value = false;
  pagination.page = 1;
  loadProducts();
};

// 重置：恢复默认
const handleDrawerReset = () => {
  draftFilters.value = createDefaultFilterState(activeFilters.value.marketplace);
};

// 构建 API 参数（单一映射函数）
const buildApiParams = (filters: FilterState) => {
  const params: Record<string, any> = {
    page: pagination.page,
    size: pagination.size,
    marketplace: filters.marketplace || undefined,
    sellerName: filters.sellerName || undefined,
    category: filters.category.length > 0 ? filters.category.join(",") : undefined,
    sortBy: filters.sortBy || "score",
    sortOrder: filters.sortOrder || "desc",
    // 区间筛选
    ...buildRangeParams(filters.range),
  };
  // 移除空值
  return Object.fromEntries(
    Object.entries(params).filter(([_, v]) => v !== undefined && v !== null && v !== "")
  );
};
```

## 八、总结

### 8.1 当前系统核心问题

1. **筛选入口分散**：SelectionQueryForm、unified-filter-bar、FilterDrawer 三处都有筛选能力
2. **排序逻辑重复**：排序出现在 3 个地方，字段列表不一致
3. **状态管理复杂**：draft/committed/rangeFilter 三套状态，同步逻辑容易出错
4. **视觉风格不统一**：部分组件用项目变量，部分用硬编码颜色
5. **SelectionQueryForm 过于臃肿**：1266 行，承担搜索+筛选双重职责

### 8.2 重构目标

1. **筛选入口收敛**：站点/大类高频维度留主栏；区间/维度类低频筛选集中在"更多筛选"抽屉
2. **排序唯一**：只在 FilterDrawer 顶部出现一次
3. **状态简化**：用 `activeFilters` + `draftFilters` 替代三套状态
4. **风格统一**：所有组件使用 Amber Classic 风格变量
5. **组件职责清晰**：SearchBar 负责搜索，FilterDrawer 负责筛选

### 8.3 预期收益

| 指标 | 重构前 | 重构后 |
|------|--------|--------|
| 筛选入口数量 | 3 处分散重复 | 主栏(站点/大类) + 抽屉(区间/维度) 各司其职 |
| 排序出现位置 | 3 处 | 1 处 |
| 状态对象数量 | 3 套 | 2 套（active + draft） |
| SelectionQueryForm 行数 | 1266 行 | ~400 行（仅搜索） |
| 字段映射表 | 2 个 | 0 个（字段名统一） |
| 时效筛选 | 数据时效 + 入库批次（重合） | 仅入库批次 |
| 用户困惑度 | 高 | 低 |
