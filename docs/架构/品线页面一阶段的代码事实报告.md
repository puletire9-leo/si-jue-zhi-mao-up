一、功能定位

  品线页面（frontend/src/modules/product-line-selection/，菜单「品线选品」）是一个"左树 +
  右商品网格"的选品工作台。一阶段做的事：以郑总店铺商品为参考标准，给选品（竞品）的品线打"郑总"标签。

  核心机制一句话：郑总标记不落库、不在前端算，而是在查询品线树时由 Java 后端实时比对算出来，前端只透传展示。

  二、数据源：两张独立的表

  ┌───────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐  
  │          表           │                                      角色                                       │  
  ├───────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤  
  │ competitor_products   │ 选品/竞品（要被打标的对象）                                                     │  
  ├───────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤  
  │ deng_zong_shop        │ 郑总店铺商品快照（参考标准，约 29 店 ~6991 商品，按 marketplace + batch_date    │  
  │                       │ 标识）                                                                          │  
  ├───────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤  
  │ deng_zong_shop_seller │ 郑总店铺名单全集（完整性判定用）                                                │  
  └───────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘  

  注意命名：代码里表名/实体是 deng_zong_shop（邓总/DengZong），但业务语义和前端 UI
  全称"郑总"。前后端命名不一致，是个遗留隐患，但同指一个对象。

  三、郑总标记判定逻辑（最关键）

  入口 GET /api/v1/product-line/tree（ProductLineController.java:92-121），流程：

  1. 取竞品按 bsr_id + node_id 分组计数（countByNodeId，只看 filter_mode='MODE1'）
  2. 取郑总最新批次 zhengBatchDate（只按 batch_date 解析，与竞品 month 解耦）
  3. 算郑总各小类商品数 zhengCounts：key = "bsrId_nodeId"（先按 asin 用 ROW_NUMBER 去重再 COUNT）
  4. ProductLineTreeService.buildTree(...) 打标 + 排序

  判定规则（ProductLineTreeService.java:13,52-53）：

  ▎ 某竞品小类，若郑总店铺在同一个 bsr_id + node_id 组合下拥有 ≥ 3 个（MIN_ZENG=3）商品，则该小类
  ▎ isZheng=true。品线（L1）级别则是"任一子类满足即标记"。

  匹配键是亚马逊大类节点 + 小类节点 ID 组合，不是 seller_name 或文本匹配。seller_name
  在打标流程里不参与逐品判定，只用于聚合统计、完整性名单、同步抓取。

  排序：郑总盘子里的 bsr_id 按其商品数降序优先排前，小类按"郑总数降序 → 竞品数降序"。

  四、前端展示（纯透传）

  - L1 行徽标「郑总店铺」：ProductLineTree.vue:33
  - L2 小类标签「郑总」：index.vue:239

  五、还有一条并行路径（品线指导意见）

  除了打标树，后端还有一套"郑总品线聚合 → 外部 Agent 分析 → 回写"的链路：
  - GET /aggregated-data 从 deng_zong_shop 两级聚合（小类 <10 商品跳过）
  - POST /analysis-results 接收 Agent 算出的 archetype / 机会分 / go-no-go，存 product_line_guidance 表        
  - GET /guidance 查询

  这套目前 Java 侧只是"出聚合数据 + 收结果"，真正的解读计算（archetype/opportunityScore 等）由外部 Agent       
  完成，不在 sjzm-product 模块内。前端品线选品 store 也还没调用 guidance 相关接口。
