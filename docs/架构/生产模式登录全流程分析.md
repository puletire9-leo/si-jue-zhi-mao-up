  逐步数据流（13 步）

  ① 用户输入凭证

  - 文件: frontend/src/views/Login/index.vue
  - 用户填用户名+密码 → 点击"登录" → 表单校验 → 调用 userStore.login(username, password)

  ② Pinia Store 发起 API 请求

  - 文件: frontend/src/stores/user.ts (行 59-87)
  - 调用 userApi.login({ username, password })

  ③ API 函数构造 HTTP 请求

  - 文件: frontend/src/api/user.ts (行 12-17)
  - POST /api/v1/auth/login，请求体 { username, password }

  ④ Axios 请求拦截器

  - 文件: frontend/src/utils/request.ts (行 124-171)
  - 设置 45s 超时、日志记录（此时尚无 token，不附加 Authorization）

  ⑤ Nginx 反向代理路由

  - 文件: frontend/nginx.prod.conf (行 17-24)
  - 匹配 /api/v1/auth → 直连 prod-java-user:8001

  ⑥ Spring Security 放行

  - 文件: java-backend/sjzm-user/.../config/SecurityConfig.java
  - /api/v1/auth/login 在 permitAll() 列表中，无需认证

  ⑦ JwtAuthenticationFilter 跳过

  - 文件: java-backend/sjzm-common/.../security/JwtAuthenticationFilter.java
  - 路径在 PUBLIC_PATHS 中，直接放行

  ⑧ AuthController 接收请求

  - 文件: java-backend/sjzm-user/.../controller/AuthController.java
  - POST /api/v1/auth/login → login(LoginRequest) → 调用 authService.login()

  ⑨ AuthServiceImpl 核心业务逻辑

  - 文件: java-backend/sjzm-user/.../service/impl/AuthServiceImpl.java (行 35-72)
  - 查数据库 → 验密码（BCrypt）→ 验状态 → 生成双 Token → 更新 lastLoginAt

  ⑩ JwtUtil 生成 Token

  - 文件: java-backend/sjzm-common/.../security/JwtUtil.java
  - Access Token: 含 {userId, username, role, type:"access"}，7 天过期
  - Refresh Token: 含 {type:"refresh"}，30 天过期

  ⑪ 响应一路返回

  - AuthController 包装 Result.success("登录成功", LoginResponse)
  - 经 Nginx → 浏览器

  ⑫ 前端 Store 处理响应

  - 文件: frontend/src/stores/user.ts (行 64-86)
  - 提取 accessToken / refreshToken / userInfo → 存入 localStorage

  ⑬ 跳转 Dashboard

  - 文件: frontend/src/views/Login/index.vue (行 214-216)
  - ElMessage.success('登录成功') → router.push('/dashboard')

  路由守卫验证

  - 文件: frontend/src/router/index.ts (行 201-251)
  - beforeEach 检查 localStorage 有 token → 恢复 userInfo → 权限检查 → 放行

  ---
  关键发现

  1. Gateway 在生产中被绕过 — Nginx 直接把 /api/v1/auth 路由到 sjzm-user:8001，Gateway 虽在运行但不处理认证请求。JWT     
  验证由各服务自己的 JwtAuthenticationFilter 完成。
  2. Token 黑名单仅存内存 — AuthServiceImpl 用 ConcurrentHashMap 做黑名单，代码注释写明"生产环境应使用
  Redis"但未实现。服务重启即清空。且 JwtAuthenticationFilter 并未查询黑名单，意味着 logout
  实际上是无效的——真正的登出机制仅靠前端清除 localStorage。
  3. Python 后端认证已废弃 — backend/app/api/v1/auth.py 标注"待废弃"，但代码仍在，且其 JWT 使用 verify_exp:
  False（永不过期），存在安全隐患。
  4. Access Token 7 天过期，Refresh Token 30 天过期 — 前端 store 中 initializeAuth() 明确注释"token
  无期限有效"，不做自动续期，因为过期时间足够长。
