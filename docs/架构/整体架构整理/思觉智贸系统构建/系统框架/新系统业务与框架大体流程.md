## 一、业务详细流程

### 核心理念
**所有数据采集和分析最终汇总到运营做SKU决策，同时各部门也从数据中心获取所需数据**

**系统定位：**
- 运营是SKU决策的核心角色
- 但数据不只为运营服务，各部门都需要使用
- 美工需要看竞品图片、设计趋势
- 采购需要看市场数据、销量预估
- 财务需要看成本结构、利润分析
- **各部门都是数据的使用者，从数据中心各取所需**

### 第1步：数据采集与初筛

#### 1.1 自动数据采集（刘淼系统）
**触发方式：**
- 定时自动触发（如每日凌晨）
- 开发人员手动触发

**采集流程：**
```
1. 八爪鱼云采集
   ├─ 自动爬取亚马逊榜单ASIN（新品榜/热卖榜/飙升榜等）
   ├─ 配置采集规则（类目/市场/排名范围）
   ├─ 去重去黑名单
   └─ 获得原始ASIN列表

2. 卖家精灵API批量查询
   ├─ 输入：ASIN列表
   ├─ 调用卖家精灵API获取商品详情
   │   ├─ 基础信息：标题/品牌/类目/上架日期
   │   ├─ 价格信息：当前价格/历史价格/促销
   │   ├─ 销量信息：月销量/评论数/评分
   │   ├─ 排名信息：BSR排名/小类排名
   │   └─ 竞争信息：卖家数量/FBA比例
   └─ 输出：完整商品数据

3. 系统自动初筛
   ├─ 价格筛选（如：10-50美元）
   ├─ 评论筛选（如：评论数 > 100）
   ├─ 评分筛选（如：评分 > 4.0）
   ├─ 销量筛选（如：月销量 > 500）
   ├─ 竞争度筛选（如：卖家数 < 20）
   └─ 黑名单过滤（已确认不做的品类/品牌）
```

**输出结果：**
- 候选品池（通过初筛的商品列表）
- 每个商品包含：基础信息 + 市场数据 + 初筛得分

#### 1.2 开发人员手工补充（刘淼系统 + 新系统）
**场景：** 开发人员根据市场洞察或经验，手动添加候选品

**操作流程：**
```
1. 开发人员发现潜力商品
   ├─ 通过市场调研
   ├─ 通过竞品分析
   └─ 通过数据分析发现机会

2. 在刘淼系统手动录入
   ├─ 输入ASIN或商品链接
   ├─ 系统自动调用卖家精灵API获取数据
   ├─ 开发人员补充备注（为什么选这个品）
   └─ 标记来源：手工添加

3. 也可直接在新系统录入
   ├─ 新系统提供"手工添加候选品"入口
   ├─ 开发人员填写基础信息
   ├─ 系统对接卖家精灵API自动补全数据
   └─ 直接进入候选品池
```

**关键特性：**
- 支持两种录入方式（刘淼系统 / 新系统）
- 自动调用API补全数据，减少手工输入
- 保留开发人员的备注和判断依据


#### 2.2 市场数据获取与分析（新系统核心功能）

**功能1：竞品深度分析**
```
自动获取竞品数据：
├─ 输入：候选品的 competitor_asins
├─ 调用卖家精灵API批量查询竞品详情
├─ 分析维度：
│   ├─ 价格分布（最低/平均/最高）
│   ├─ 销量分布（头部/中部/尾部）
│   ├─ 评分分布（4星以下/4-4.5/4.5以上）
│   ├─ 上架时长分布（新品/成熟品）
│   └─ Listing质量（标题/五点/图片完整度）
└─ 输出：竞品分析报告
```

**功能2：市场容量评估**
```
计算市场容量：
├─ 竞品总销量（所有竞品月销量加总）
├─ 市场集中度（头部前3名占比）
├─ 新品机会（近6个月新品数量和表现）
└─ 输出：市场容量得分（高/中/低）
```

**功能3：利润预估**
```
自动计算预估利润：
├─ 建议售价（基于竞品价格分布）
├─ 成本估算
│   ├─ 产品成本（根据类目和材质经验值）
│   ├─ 物流成本（根据重量体积估算）
│   ├─ FBA费用（亚马逊标准费率）
│   └─ 广告成本（类目平均ACOS）
├─ 利润计算
│   └─ 毛利率 = (售价 - 成本) / 售价
└─ 输出：预估利润 + 毛利率
```

**功能4：竞争难度评分**
```
综合评估竞争难度：
├─ 卖家数量（越多越难）
├─ FBA比例（越高越难）
├─ 头部销量占比（越集中越难）
├─ 平均评论数（越多越难）
├─ 品牌集中度（大品牌多则难）
└─ 输出：竞争难度得分（1-100）
```

**功能5：趋势分析**
```
历史趋势分析（如果有历史数据）：
├─ 价格趋势（上涨/下跌/稳定）
├─ 销量趋势（增长/下滑/稳定）
├─ 竞品数量趋势（增加/减少）
└─ 输出：趋势判断（上升期/成熟期/衰退期）
```

---

#### 2.3 综合评分与标签

**多维度评分：**
```
系统自动计算：
├─ 市场机会得分（0-100）
│   ├─ 市场容量：30%
│   ├─ 竞争难度：30%（越低越好）
│   ├─ 利润空间：25%
│   └─ 趋势判断：15%
│
└─ 推荐等级
    ├─ S级（90-100）：强烈推荐
    ├─ A级（80-89）：推荐
    ├─ B级（70-79）：可考虑
    ├─ C级（60-69）：谨慎
    └─ D级（<60）：不推荐
```

**自动打标签：**
```
根据特征自动添加标签：
├─ 蓝海品（竞争低+利润高）
├─ 快周转品（销量高+价格低）
├─ 高利润品（毛利率>40%）
├─ 新品机会（近期上架+销量增长快）
├─ 季节性品（根据历史数据判断）
└─ 风险品（竞争激烈/利润低/趋势下滑）
```

### 第3步：运营SKU决策 ⭐（核心）

#### 3.1 运营工作台界面

**筛选与排序：**
```
运营可以按需筛选：
├─ 按推荐等级（S/A/B/C/D）
├─ 按市场（US/UK/DE等）
├─ 按类目
├─ 按价格区间
├─ 按利润率
├─ 按竞争难度
├─ 按标签（蓝海品/高利润品等）
└─ 按来源（自动采集/手工添加）

可以按多种维度排序：
├─ 综合得分（默认）
├─ 预估利润
├─ 月销量
├─ 竞争难度
└─ 添加时间
```

---

#### 3.2 运营决策流程

**查看候选品详情：**
```
运营点击候选品卡片：
├─ 展开完整的决策辅助信息
├─ 查看竞品ASIN详情（点击跳转亚马逊）
├─ 查看竞品图片和Listing
├─ 查看市场分析图表
└─ 查看历史趋势（如有）
```

**决策操作：**
```
运营做出决策：
├─ ✅ 确认开品
│   ├─ 选择理由（多选）
│   │   ├─ 利润空间大
│   │   ├─ 竞争适中
│   │   ├─ 市场容量足够
│   │   ├─ 有差异化机会
│   │   └─ 其他（填写）
│   ├─ 设置优先级（高/中/低）
│   ├─ 预计月销量目标
│   └─ 备注说明
│
├─ ❌ 拒绝
│   ├─ 选择原因（多选）
│   │   ├─ 利润太低
│   │   ├─ 竞争太激烈
│   │   ├─ 市场容量小
│   │   ├─ 有侵权风险
│   │   ├─ 不符合公司策略
│   │   └─ 其他（填写）
│   └─ 备注说明
│
└─ ⏸️ 待定
    ├─ 需要进一步调研
    ├─ 等待市场变化
    └─ 暂时观望
```

---

#### 3.3 决策后的自动流转

**确认开品后系统自动：**
```
1. 更新SKU状态：候选品 → 已确认
2. 生成SKU编码（按规则自动生成）
3. 创建SKU基础档案
4. 触发后续流程：
   ├─ 自动创建Listing撰写任务
   ├─ 预生成采购计划（待补充细节）
   └─ 发送通知（可选）
5. 记录决策日志：
   ├─ 决策人
   ├─ 决策时间
   ├─ 决策理由
   └─ 预期目标
```

## 二、现有3个系统职责

### 系统定位说明
**新系统是数据中心型平台，各部门并行协作：**

#### 核心定位
**数据中心型协作平台 - 各部门并行工作，从数据中心各取所需**

#### 架构理念
```
           ┌─────────────────┐
           │   数据中心层     │
           │  (统一数据存储)  │
           └────────┬─────────┘
                    │
        ┌───────────┼───────────┬───────────┐
        ↓           ↓           ↓           ↓
    ┌───────┐  ┌───────┐  ┌───────┐  ┌───────┐
    │ 运营  │  │ 美工  │  │ 采购  │  │ 财务  │
    │ 板块  │  │ 板块  │  │ 板块  │  │ 板块  │
    └───────┘  └───────┘  └───────┘  └───────┘
       ↕          ↕          ↕          ↕
    各自访问   各自访问   各自访问   各自访问
    所需数据   所需数据   所需数据   所需数据

特点：
- 不是线性流水线（运营决策 → 分配任务 → 执行）
- 而是并行协作（各部门从数据中心获取数据，独立工作）
- 轻量化板块，少一块不影响其他板块
```

#### 7大核心板块与数据使用

**1. 数据汇聚与管理板块**
- 接收刘淼系统推送的候选品数据
- 接收刘颖豪系统推送的设计稿
- 接收领星ERP推送的销售数据
- 统一数据存储与权限管理
- **所有板块都从这里获取数据**

**2. 运营决策板块 ⭐（决策核心）**
使用数据：
- 候选品基础信息
- 市场分析数据
- 竞品对比数据
- 利润预估数据

主要功能：
- 查看候选品列表
- 多维度筛选与排序
- 市场分析与决策辅助
- SKU决策（确认开品/拒绝/待定）
- 决策记录与追踪

**是决策者，但不是唯一的数据使用者**

**3. Listing管理板块**
使用数据：
- 候选品信息
- 竞品Listing
- 关键词数据
- 市场趋势

主要功能：
- Listing撰写（AI辅助 + 人工编辑）
- 版本管理
- 审核流程
- 合规检查

使用者：运营和Listing撰写人员

**4. 美工协作板块**
使用数据：
- 候选品图片
- 竞品图片
- 市场设计趋势
- SKU产品信息

主要功能：
- 接收美工系统推送的设计稿
- 设计稿预览与审核
- 与SKU关联管理
- 提供设计参考素材

**美工参考数据做设计，不只是被动接收任务**

**5. 采购管理板块**
使用数据：
- 市场容量数据
- 销量预估数据
- 成本结构数据
- 历史采购数据

主要功能：
- 采购计划创建（基于数据预估）
- 批次管理
- 供应商管理
- 采购订单跟踪
- 入库登记

**采购基于数据制定计划，不只是执行运营指令**

主要功能：

**整合各部门成果，协调发布流程**
