# 思觉智贸运营协作系统 - 整体框架构建需求

## 一、系统定位

### 核心理念
**插件化板块架构** - 各板块平行独立，数据互联互通，可持续扩展

**设计原则：**
- 各板块保持独立性，可独立迭代升级
- 数据层打通串联，板块间无缝协作
- 支持动态新增板块，持续拓展延伸
- 平行网状结构，非线性流程，各部门按需使用

## 五、详细业务流程

### 阶段1：选品（开发部门使用选品系统）
**使用系统：** 选品系统（刘淼开发）  
**业务用户：** 开发部门选品人员

**流程：**
1. 八爪鱼自动爬取亚马逊榜单ASIN
2. 通过卖家精灵API快速获取商品数据
3. 多维度筛选（价格/评论/销量/竞争度）
4. 人工复核，确定要开的品
5. **写入"开发运营共享表"**（数据交接点）

**输出数据：**
- SKU编码
- 产品名称/分类/市场
- 竞品ASIN列表（含价格/评分/销量/图片）
- 产品信息（尺寸/材质/重量/特性）
- 目标关键词
- 开发备注

---

### 阶段2：任务分发（运营部门使用任务分发平台）
**使用系统：** 任务分发平台（赵燎开发）  
**业务用户：** 运营部门人员

**流程：**
1. 从共享表接收开发部门推送的SKU
2. 运营再过一遍，确认需要做的SKU
3. 建立**采购计划批次号**
4. 创建Listing撰写任务（AI辅助）
5. 创建美工作图任务，分配给美工部门
6. 创建采购任务，分配给采购部门

**输出：**
- 确认的SKU列表
- 批次号
- Listing文案（标题/五点/描述/关键词）
- 任务单（分配给美工/采购）

---

### 阶段3：制作图片（美工部门使用作图平台）
**使用系统：** 作图平台（刘颖豪开发）  
**业务用户：** 美工部门人员

**流程：**
1. 从任务列表接收美工任务
2. 查看产品信息与参考竞品图
3. 设计主图/附图/A+图片
4. 精铺和精品都使用同一套作图平台
5. 提交审核

**输出：**
- 主图（1000x1000px，白底）
- 附图6张（1000x1000px）
- A+内容图片
- 品牌故事图片（可选）

---

### 阶段4：采购入库（采购部门使用采购管理模块）
**使用系统：** 采购管理模块（待开发）  
**业务用户：** 采购部门人员

**流程：**
1. 接收采购任务
2. 根据批次号创建采购计划
3. 联系供应商报价
4. 下单采购
5. 跟踪物流
6. 登记入库

**输出：**
- 采购订单
- 入库单
- 成本数据

---

### 阶段5：上架发布（运营部门）
**使用系统：** 运营协作系统 + 领星ERP  
**业务用户：** 运营部门人员

**流程：**
1. 确认Listing文案已审核通过
2. 确认美工图片已审核通过
3. 确认采购已入库
4. 完成ASIN页面组装
5. **通过领星平台上架至亚马逊**
6. 运营发货至亚马逊FBA仓库

**输出：**
- 上架完成的ASIN
- FBA发货记录

---

### 阶段6：数据回流（自动同步）
**数据源：** 领星ERP  
**接收系统：** 选品系统 + 运营协作系统

**流程：**
1. 亚马逊售卖数据实时返回领星ERP
2. 系统从领星API获取数据
3. 数据同步至各系统

**数据内容：**
- 销量/订单数
- 收入/利润
- 广告花费/ACOS
- 库存状态
- 客户评论/评分

---

### 阶段7：数据分析与决策调整
**使用系统：** 选品系统 + 运营协作系统  
**业务用户：** 开发部门 + 运营部门 + 财务部门

#### 开发部门看数据
**用途：** 继续开品调整
- 哪些品卖得好 → 继续开类似品
- 哪些品滞销 → 调整选品策略
- 市场趋势变化 → 更新筛选规则

#### 运营部门看数据
**用途：** SKU策略调整
- 价格调整
- 广告投放优化
- 库存补货
- 促销活动

#### 财务部门看数据
**用途：** 生成日报
- 每日收入/支出/利润
- SKU级成本核算
- 资金占用分析
- 财务预警

```
POST /api/v1/sku/sync
Authorization: Bearer {token}
```

## 十、开发协作机制

### 模块独立开发
- **刘淼**：维护选品系统，提供数据推送API
- **赵燎**：开发任务分发平台，负责任务流转逻辑

- **其他开发人员**：开发采购/发布/财务模块

### 接口约定
- 各模块通过统一的数据接口通信
- 接口定义提前约定，双方并行开发
- 接口版本化管理，向后兼容

### 数据隔离
- 每个模块有独立的数据表
- 通过接口同步数据，不直接跨库访问
- 共享数据通过中间表传递

## 十二、关键设计原则

1. **模块独立开发** - 刘淼/赵燎/刘颖豪可并行开发，互不阻塞
2. **接口松耦合** - 通过API通信，不直接依赖对方数据库
3. **业务角色清晰** - 开发部门用选品系统，运营/美工用协作系统
4. **数据单向流动** - 选品系统 → 协作系统 → 销售数据 → 选品系统
5. **可扩展架构** - 未来可继续新增模块（客服/广告/BI等）
