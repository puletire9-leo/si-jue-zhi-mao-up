数据中心 · 全平台统一数据底座

市场信息在这里沉淀，其他业务板块通过统一数据服务读取。

① 市场信息获取通过八爪鱼、卖家精灵及人工补充获得 SKU、竞品、价格、销量和类目信息。
→
② 写入数据中心完成清洗、字段统一、去重、版本记录和 SKU 主数据归档，形成唯一可信数据源。
→
③ 各业务板块统一读取业务页面不再分别向外部系统取数，而是读取数据中心的标准数据。
运营工作台Listing美工工作台采购图片管理用户权限
数据规则：市场信息获取是市场数据的写入入口；数据中心负责存储和统一；其他板块以读取为主，业务处理结果再按权限回写。

总体原则
开发端不重复建设，优先复用已经实现的能力

继续沿用赵燎现有的开发对接流程，可在页面和协作方式上优化，但总体流程不做大改。系统建设重点放在开发向运营、采购和美工输出标准信息，而不是重做开发工具。

出开发需要输出
跨部门信息交付
给运营
竞品链接与市场数据

开发提交竞品链接并触发市场数据拉取；新增运营查看页面，统一承载 SKU 市场信息。

给采购
微定制产品定稿图片

打通开发系统定稿图片 API，在新系统建立图片管理。开发、采购、美工及后续 1688 供应商可直接搜索和查看，减少采购每天下载定稿的工作。

给美工
标题、产品图片等设计输入

将产品标题、原始图片、SKU 信息和设计要求形成标准任务输入，供美工工作台直接读取。

入开发需要输入
数据与日常任务来源
领星经营数据API 已打通

读取产品详情、采购计划等现有 API 数据，在数据中心建立自己的分析模型和开发看板。

每日拓品任务持续建设

承接店铺跟踪、老品拓展和其他拓品方式，形成每天可执行、可跟踪的开发任务。

竞品店铺 30 天内选品

结合备货数量推测真实销量；在卖家精灵销量更新不及时的情况下，用备货数量作为更及时的判断依据。

领星优质老品拓品

通过算法识别表现好的历史产品，再据此寻找可扩展的新产品方向。
