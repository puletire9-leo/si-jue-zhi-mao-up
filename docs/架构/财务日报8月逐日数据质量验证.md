## 四、实际算法错误：断货状态机不等价于案例公式

案例工作簿公式：

```excel
IF(AND(FBA=0, SUMIFS(截至当天销量, ASIN, 当前ASIN)>0), 1, 0)
```

业务含义：只要 ASIN 历史上出过单，今天 FBA 为 0，就进入断货候选，然后再过滤淘汰/待淘汰、侵权下架和季节性。

当前 Java 算法：

```text
FBA=0 AND（上一日已经断货 OR 今天销量>0）
```

两者不等价。产品历史出过单、昨天有库存、今天无库存且今天没出单时，案例公式判定断货，当前状态机漏算。

使用案例 08-01 结果作为初始状态，按 UK ASIN 连续回放后的漏算数量：

| 日期 | 当前状态机漏掉的 UK 断货 ASIN |
|---|---:|
| 08-01 | 0（初始化日） |
| 08-02 | 1 |
| 08-03 | 14 |
| 08-04 | 20 |
| 08-05 | 28 |
| 08-06 | 34 |
| 08-07 | 45 |
| 08-08 | 57 |
| 08-09 | 63 |

真实反例 `B0H1BFVQFP`：

- 7 月销量 7。
- 08-01 销量 2、FBA 3，因此当天不是断货。
- 08-02 销量 0、FBA 0。
- 案例公式：历史销量大于 0，判定断货。
- 当前状态机：昨天不是断货、今天没销量，错误判定为非断货。

当前单元测试只覆盖“上一日已断货”和“当天新出单”两种情况，没有覆盖“历史出过单 → 恢复库存 → 再次断货且当天无销量”的回归场景。

## 五、历史元数据没有冻结，导致状态指标无法逐日复原

用案例目录当前保存的标签和创建时间回放历史日期，仍会出现：

- 08-01 案例淘汰 SKU 2,220，当前明细标签重算为 2,263。
- 08-02 案例淘汰 SKU 2,220，当前明细标签重算为 2,287。
- 08-03 案例 SKU 总量 7,078，当前创建时间重算为 7,276。
- 08-04 案例 SKU 总量 7,222，当前创建时间重算为 7,305。

说明标签、创建时间、负责人、开发人均会变化。用“当前统一表元数据”回算过去日期会污染历史结果。

生产链路会保存本次计算实际使用的状态快照用于审计，但下一日报不再继承上一日的标签、创建时间和人员。每次计算始终使用当日事实和当前统一表。若后续需要精确回归历史时点，至少需要另行按日期保存：

- `ever_sold` / 历史是否出过单；
- 标签；
- 创建时间；
- 负责人；
- 开发人；
- 当日站点范围和维度配置版本。

## 七、结论与修复方向

本次逐日案例回放已经确认四类问题：

1. **确定的算法错误**：断货只继承“上一日断货”，会漏掉重新断货的历史有销量 ASIN；08-09 UK 样本已累计漏 63 个。
2. **口径冲突**：旧案例合并 UK+DE 并显示 GBP，当前业务要求只取 UK；两者总数不能直接对齐。
3. **人员版本差异**：案例开发人名单为 7 人；生产名单允许第 8 人夏浩宇，但采用动态输出，没有数据时不会产生空行。
4. **历史元数据/源时点不一致**：标签、创建时间、人员归属和广告指标没有与标准答案同步冻结。

建议修复顺序：

1. 把断货依据改为持久化 `ever_sold`，候选公式恢复为 `FBA=0 AND (历史已出单 OR 当日销量>0)`；不能只保存上一日 `out_of_stock`。
2. 增加 UK-only 案例基线，不再拿旧 UK+DE 案例总额验收当前 UK-only 生产结果。
3. 给维度名单增加生效日期/版本，历史回归用 7 开发人结构，新生产继续用 8 开发人结构。
4. 建立同批冻结的“ASIN 输入 + 17/16 行期望输出”回归夹具，再把 08-01—08-09 做成参数化自动测试。

## 八、2026-08-19 算法修复与双口径落地

已实现并发布两套显式计算口径：

- `LEGACY_CASE`：UK+DE 明细按 ASIN 合并，币种显示 GBP，开发人使用案例中的 7 人名单，运营/开发维度按案例实际出现情况输出；只用于案例回归，不请求领星、不写 RDS、不投递飞书。
- `PRODUCTION_UK`：输入严格限定统一表 UK ASIN，历史销量也严格限定 UK，币种固定 GBP；基础 4 行固定，运营/开发按当天实际存在情况动态输出。

两套口径共享同一个已经修正的断货核心公式：

```text
FBA=0 AND（目标日前历史曾出单 OR 当日销量>0）
```

历史出单集合改为直接读取 RDS：完整周表 `lingxing_sku_weekly_performance` 与目标日前日事实表
`lingxing_product_performance_daily`。生产查询带 `marketplace=UK`，旧案例查询可合并 UK/DE，避免
德国销量污染生产英国断货状态。

真实案例逐行验证：案例明细中 08-07—08-09 保存了断货公式缓存，共 21,918 行；修复公式逐行差异为 0。
08-01—08-06 的明细没有保存该公式缓存，不能把空缓存当作标准答案。用公式重算后与最终汇总仍有
22—70 个历史差异，08-07—08-09 各差 1 个；这些差异对应前文确认的标签/源文件冻结时点不同，
不是断货候选公式差异。
