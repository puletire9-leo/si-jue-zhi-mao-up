## 三、调用链路

```text
领星自动化请求注册表（每日 02:30 排期，错开运营物流 02:10）
  ↓ 生成
lingxing_request_task（优先级 90，FINANCE_REPORT 槽位）
  ↓ 单线程 FIFO 执行，账号级串行门禁
LingxingTaskHandlerRegistry 路由
  ↓
FinanceDailyReportLingxingTaskHandler
  ↓
AutomationCenterService.trigger("FINANCE_DAILY_REPORT")
  ↓
FinanceDailyReportJob.execute()
  ↓
LingxingListingSyncService.refreshTargetListings()
  ├─ 读取统一表目标 ASIN 与实际店铺 SID
  ├─ 分页拉取最新 Listing
  ├─ 保留历史行，禁止清空 lingxing_listing
  └─ 通过 RdsBatchWriteService 分批 upsert，并记录拉取/写入耗时
  ↓
LingxingFinanceDailyReportService.run(reportDate)
  ├─ 拉领星单日 asinList
  ├─ 按 lingxing_product_unified_marketplace 过滤 UK/DE ASIN
  ├─ 领星统一换算 GBP 后按来源站点落 RDS 日事实表
  ├─ 跨站点按 ASIN 合并并继承 ALL 状态快照
  ├─ 工作簿公式加工
  └─ 仅生成 ALL/GBP 5 维度动态行
  ↓
按 5 维度幂等写入飞书 5 张表
  ├─ 通过 automation_record_binding 记录绑定
  ├─ 批量新增/更新（每批最多 200 条）
  └─ 业务键：reportDate|marketplace|dimension|dimensionValue
  ↓
返回 AutomationRun（审计：总数/成功/失败/跳过 + 阶段耗时）
```

### 4.3 手动触发验证（8 月 12 日报表）

财务日报支持阶段化执行，以下参数可独立组合：

- `pullFromLingxing`：是否调用领星；为 `false` 时直接读取 RDS 目标日期日事实。
- `refreshListing`：是否先刷新 Listing；默认跟随 `pullFromLingxing`。历史重算必须显式为 `false`，复用 RDS 已有 Listing。
- `persistFacts`：领星拉取后是否幂等写入 RDS；默认跟随 `pullFromLingxing`。
- `persistStatusSnapshot`：是否在日报确认完成后保存本次状态审计快照；默认 `false`，补数和调试阶段不冻结。
- `allowRepull`：仅用于显式诊断；默认 `false`。目标日期已有事实时默认在请求领星前拒绝。
- `publishToFeishu`：是否投递飞书；为 `false` 时只计算并把 ALL/GBP 动态行结果写入运行审计。

常用组合：

- 完整流程：`pullFromLingxing=true, refreshListing=true, persistFacts=true, publishToFeishu=true`。
- 拉取、落库、计算但不投递：前三项为 `true`，`publishToFeishu=false`。
- 复用 RDS 重新投递：`pullFromLingxing=false, refreshListing=false, persistFacts=false, publishToFeishu=true`。
- 仅复用 RDS 计算：上述四项均为 `false`；不会重复请求产品表现或 Listing。

## 五、默认停用原因

- **安全第一**：新任务默认停用，避免未验证的代码自动跑领星请求
- **验证通过再启用**：手动触发 → 核对飞书结果 → 确认阶段耗时 → 再开定时
- **与运营物流一致**：运营物流任务也是先停用、验证后启用

## 六、排期设计

| 项 | 值 | 说明 |
|---|---|---|
| schedule_type | DAILY | 每日执行 |
| run_time | 02:30:00 | 错开运营物流（02:10） |
| timezone | Asia/Shanghai | 中国时区 |
| priority | 90 | 低于运营物流（100），确保运营物流先执行 |
| slot_group | FINANCE_REPORT | 独立槽位组 |
| minimum_gap_seconds | 60 | 最小间隔 60 秒 |

## 七、注意事项

1. **领星请求中心单线程**：所有注册项生成的任务进入同一 `lingxing_request_task` 队列，由单线程 FIFO 执行，自动串行，无需担心并发冲突。

2. **reportDate 默认昨天**：如果 `parameters.reportDate` 为 null，`FinanceDailyReportJob` 会默认使用 `LocalDate.now().minusDays(1)`。

3. **事实不可变 + 投递幂等**：目标日期已有 RDS 日事实时拒绝重复拉取和原地覆盖；飞书通过 `automation_record_binding` 记录业务键到 record_id 的绑定。

4. **Listing 非破坏刷新**：财务完整流程只 upsert 本次返回的 Listing，不执行清表；周链路原有覆盖入口保持不变。`open_date` 是财务 SKU 总数与上架时间分组的日期事实。

5. **终态不再更新**：`automation_record_binding.terminal=1` 的记录不再参与常规刷新（当前财务日报所有记录都是非终态，因为每日可能有历史修正）。

6. **飞书应用权限**：新应用 `cli_a94659ed3b79dbd4` 已在运营物流场景验证通过，具备 `bitable:app` / `base:record:create` 权限。

## 八、故障排查

### 8.1 启动失败

- 检查 `SchemaGuard`：`automation_job` / `lingxing_automation_request_registry` 表是否存在
- 检查实体扫描：`LingxingAutomationRequestRegistry` / `FinanceDailyReportConfig` bean 加载

### 8.2 任务未生成

- 检查注册项 `enabled=1` 且 `deleted=0`
- 检查 `next_run_at` 是否已更新到未来时间
- 查看 `LingxingAutomationRequestScheduler` 日志

### 8.3 任务执行失败

- 查看 `automation_run` 表的 `error_message` 和 `result_json`
- 查看 `lingxing_request_task` 表的 `error` 字段
- 检查领星账号限流状态
- 检查飞书应用 token 是否过期

### 8.4 飞书写入失败

- 检查 App Token 和 Table ID 配置
- 检查飞书应用是否被授权访问目标 Base
- 检查字段名映射（特别是"开发/非标品/上架时间"三张表的内部命名）
