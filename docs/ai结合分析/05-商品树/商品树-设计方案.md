# 亚马逊商品树 — 逻辑设计方案 v2

> **定位**：全新独立页面，多维树形浏览 `competitor_products`。  
> **唯一数据源**：`competitor_products`（`selection_products` 已废弃，`final_drafts` 不上树）

---

## 一、页面是什么

一个**独立的新页面**（路由 `/product-tree`），不在现有 AllSelection 页面内嵌入。

核心价值：用**树形结构**替代当前的"Tab 切换 + 搜索框"模式，让用户通过**展开 → 下钻 → 定位**的方式浏览所有竞品数据。

---

## 三、四个维度的树逻辑

每个维度是**同一批数据**（`competitor_products` 同站点同月份）的**不同切面**。切换维度 = 换一种方式浏览同一批产品。

### 维度 1: 分类树（最深，支持多层下钻）

**数据锚点**：`node_label_path` 字段（冒号分隔，如 `Home & Garden:Kitchen & Dining:Small Appliances`）

**展开逻辑**：
```
第 1 层: 提取 node_label_path 的第 1 段 → L1 分类列表
         每个 L1 后面显示产品数
         
点击 L1 → 第 2 层: 在 L1 范围内，提取第 2 段 → L2 子分类列表

点击 L2 → 第 3 层: 在 L1:L2 范围内，提取第 3 段 → L3 子分类列表

...以此类推，直到该分类下所有产品的 node_label_path 没有更深层级
→ 此时节点变成"产品节点"，点击直接加载产品列表
```

**关键规则**：
- 层级**动态深度**（2~4层，取决于实际数据）
- 判断是否有子层级的方法：检查是否存在 `node_label_path LIKE '当前路径:%'` 且段数更多的记录
- 每个节点旁边显示该分类下的**产品数**（COUNT）

**节点点击 → 产品查询条件**：
```
WHERE marketplace = 'UK' 
  AND month = '202605'
  AND node_label_path LIKE 'Home & Garden:Kitchen & Dining:%'
```

### 维度 2: 来源树（扁平 + 店铺下钻）

**数据锚点**：`source` 字段 + `seller_name` 字段

**展开逻辑**：
```
第 1 层: source 去重 + COUNT
         ├── 新品榜 (200)        ← source = '新品榜'
         ├── 竞品店铺 (80)       ← source = '竞品店铺'
         └── 郑总店铺 (50)       ← source = '郑总店铺'

点击来源 → 第 2 层: 该来源下的 seller_name 去重 + COUNT
         ├── 卖家 A (30)
         ├── 卖家 B (25)
         └── 卖家 C (20)
```

**节点点击 → 产品查询条件**：
```
-- 第 1 层（来源）
WHERE marketplace = 'UK' AND month = '202605' AND source = '新品榜'

-- 第 2 层（来源 + 卖家）
WHERE marketplace = 'UK' AND month = '202605' AND source = '新品榜' AND seller_name = '卖家A'
```

### 维度 3: 排名树（扁平）

**数据锚点**：`bsr` 字段（Best Seller Rank，整数，越小越好）

**展开逻辑**：
```
固定分层，不展开：
  ├── BSR Top 100     (bsr ≤ 100)
  ├── BSR Top 500     (100 < bsr ≤ 500)
  ├── BSR Top 1000    (500 < bsr ≤ 1000)
  ├── BSR Top 5000    (1000 < bsr ≤ 5000)
  └── BSR 5000+       (bsr > 5000 或 NULL)
```

**节点点击 → 产品查询条件**：
```
WHERE marketplace = 'UK' AND month = '202605' AND bsr > 100 AND bsr <= 500
```

### 维度 4: 评分树（扁平）

**数据锚点**：`grade` 字段（S/A/B/C/D，由 ScoringEngine 计算写入）

**展开逻辑**：
```
固定分层，不展开：
  ├── S 级 (≥90分)
  ├── A 级 (80-89分)
  ├── B 级 (65-79分)
  ├── C 级 (50-64分)
  └── D 级 (<50分)
```

**节点点击 → 产品查询条件**：
```
WHERE marketplace = 'UK' AND month = '202605' AND grade = 'S'
```

## 四、全局控制器的逻辑

### 站点选择器
- 可选值：UK / DE / US（从 `SELECT DISTINCT marketplace FROM competitor_products` 获取）
- 切换站点 → 整棵树刷新（重新加载维度根节点）

### 月份选择器
- 可选值：从 `SELECT DISTINCT month FROM competitor_products WHERE marketplace = ?` 获取
- 默认值：`MAX(month)`（最新月份）
- 切换月份 → 整棵树刷新
- **作用**：`competitor_products` 的唯一键是 `(marketplace, asin, month)`，同一 ASIN 在不同月份有独立记录。月份选择器控制看哪个月的数据快照。

---

## 五、产品浏览器的逻辑

### 树节点点击 → 产品加载

**核心逻辑**：树节点 = 一组筛选条件。点击节点 → 把条件传给产品列表 API → 右侧显示。

```
树节点状态                     →  传给 API 的参数
─────────────────────────────────────────────────
marketplace = UK, month = 202605  →  marketplace, month（始终携带）
分类: Home & Kitchen > Kitchen    →  node_label_path_prefix = "Home & Kitchen:Kitchen:%"
来源: 新品榜                       →  source = "新品榜"
排名: BSR Top 500                 →  bsr_min = 100, bsr_max = 500
评分: S 级                        →  grade = "S"
```

### 二次筛选（在树筛选之上叠加）

产品列表加载后，右栏顶部还有**筛选栏**，可以在树节点筛选的基础上进一步缩小范围：

| 筛选项 | 对应字段 | 说明 |
|---|---|---|
| 筛选模式 | `filter_mode` | MODE1（模式一通过）/ MODE2（模式二通过）/ FAIL |
| 品牌 | `brand LIKE` | 模糊匹配 |
| 店铺名 | `seller_name LIKE` | 模糊匹配 |
| ASIN | `asin =` | 精确查找 |
| 变体合并 | `parent_asin` 去重 | 同父 ASIN 只展示 BSR 最优的那条 |

**筛选逻辑是 AND 关系**：树条件 AND 二次筛选条件，同时满足才展示。

### 产品展示

- 复用现有的 `UniversalCard` 卡片组件（已有完善的字段展示逻辑）
- 卡片网格布局，分页 60/100/200/500 条每页
- 排序可选：BSR 升序 / 评分降序 / 价格升降序 / 上架天数升序

## 六、维度切换的逻辑

| 行为 | 说明 |
|---|---|
| 切换维度 | 清空当前树选择，右侧产品列表清空 |
| 保留全局控制 | 站点和月份不变 |
| 维度间独立 | 每个维度的树状态独立维护（可选：记忆上次展开的节点） |

**不会交叉维度**：树同一时刻只在一个维度下浏览。如果需要"Home & Kitchen + S 级"这种组合，用户应该：
1. 在分类树选中 "Home & Kitchen"
2. 在右侧二次筛选栏选择 grade = S

## 七、树的加载策略

### 首次加载（页面打开时）

```
1. 获取站点列表 → SELECT DISTINCT marketplace
2. 获取月份列表 → SELECT DISTINCT month WHERE marketplace = 默认值
3. 获取默认维度的第 1 层分支 → 聚合 SQL（见下方）
```

**各维度的第 1 层加载 SQL 逻辑**：

| 维度 | 聚合 SQL 逻辑 |
|---|---|
| 分类 | `SELECT SUBSTRING_INDEX(node_label_path, ':', 1) AS l1, COUNT(*) FROM competitor_products WHERE marketplace=? AND month=? GROUP BY l1` |
| 来源 | `SELECT source, COUNT(*) FROM competitor_products WHERE marketplace=? AND month=? GROUP BY source` |
| 排名 | 5 个固定桶的 COUNT，一次查询用 CASE WHEN 分桶 |
| 评分 | `SELECT grade, COUNT(*) FROM competitor_products WHERE marketplace=? AND month=? GROUP BY grade` |

### 懒加载（展开节点时）

**仅分类维度需要懒加载**（其他维度是扁平的）：

```
展开 L1 "Home & Kitchen" → 
  SELECT 第2段分类名, COUNT(*) 
  FROM competitor_products 
  WHERE marketplace=? AND month=? 
    AND node_label_path LIKE 'Home & Kitchen:%'
  GROUP BY 第2段
```

**判断是否还有子层级**：
```
该分类下的产品中，是否存在 node_label_path 段数 > 当前层级数的记录
→ 如果有，显示展开箭头（▶）
→ 如果没有，显示产品图标（📦），点击直接加载产品
```

```

"Home & Kitchen"          selected_path=L1             SQL + COUNT

"Kitchen & Dining"
```

## 九、节点计数逻辑

每个树节点旁边显示的数字 = **该节点下满足条件的产品总数**。

**计数规则**：
- 分类节点：`COUNT(*) WHERE node_label_path LIKE '该路径%'`
- 来源节点：`COUNT(*) WHERE source = '该来源'`
- 排名节点：`COUNT(*) WHERE bsr BETWEEN min AND max`
- 评分节点：`COUNT(*) WHERE grade = '该等级'`
- **所有计数都限定 marketplace + month**

**变体去重（可选）**：
- 如果用户开启"变体合并"，计数改为 `COUNT(DISTINCT COALESCE(NULLIF(parent_asin,''), asin))`
- 即同一 parent_asin 下的多个变体只算 1 个

## 十、与现有系统的关系

| 现有页面 | 商品树页面 | 关系 |
|---|---|---|
| AllSelection（总选品管理） | 商品树 | **互补**：AllSelection 适合搜索驱动的场景，商品树适合浏览驱动的场景 |
| 新品榜/竞品店铺/郑总店铺上新 | 来源维度 | **替代浏览方式**：Tab 切换变为树节点选择 |
| ScoringConfigPanel | 评分维度 | **可视化**：评分结果变成可浏览的树分支 |
| FilterPresetSelector | 二次筛选栏 | **功能保留**：筛选预设可在产品面板中使用 |
| UniversalCard | UniversalCard | **完全复用**：卡片组件不变 |

## 十一、范围之外（v1 不做）

- AI 推荐分支（数据源不存在）
- 终稿池（业务语义不同）
- 跨站点对比（同一棵树里混合 UK+DE）
- 树节点拖拽/编辑
- 历史月份快照对比（两个月份的数据并排看）
- 移动端适配
