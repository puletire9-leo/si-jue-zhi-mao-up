# 亚马逊商品树 — 设计方案

> 树状结构组织所有亚马逊商品，**国家 → 多维度 → 树节点就是商品**。
> 取代/补充当前的扁平产品列表（AllSelection 页面）。

## 一、设计目标

1. **一棵树看完全部产品**：从国家下钻到具体商品，多维度浏览
2. **覆盖全流程**：竞品池 / 选品池 / 终稿池 都在树上
3. **多维度切片**：分类、来源、排名、评分四个维度可切换
4. **懒加载**：树可能很大（300+ 产品），按需加载子节点
5. **AI 推荐可视**：来源树的"AI 推荐"分支直接展示

## 二、树结构

```
[国家] UK / DE / US
│
├── ① 竞品池 (300+ 个产品)
│   ├── 维度 1: 分类树 (按 node_label_path L1/L2/L3)
│   │   ├── Home & Kitchen (X)
│   │   │   ├── Kitchen & Dining (Y)
│   │   │   │   ├── Small Appliances (Z)
│   │   │   │   │   ├── 产品 B0XXX (score=92, S)
│   │   │   │   │   └── 产品 B0YYY
│   │   │   │   └── Cookware (W)
│   │   │   └── Dining Room
│   │   └── Pet Supplies
│   │
│   ├── 维度 2: 来源树
│   │   ├── 新品榜 (new)
│   │   ├── 竞品店铺 (reference)
│   │   ├── 整店导入 (zheng)
│   │   └── AI 推荐 (ai_recommend)        ← ai_recommend_log
│   │
│   ├── 维度 3: 排名树
│   │   ├── BSR Top 100
│   │   ├── BSR Top 500
│   │   └── BSR Top 1000+
│   │
│   └── 维度 4: 评分树
│       ├── S 级 (≥90)
│       ├── A 级 (80-89)
│       ├── B 级 (65-79)
│       ├── C 级 (50-64)
│       └── D 级 (<50)
│
├── ② 选品池 (30-80 个产品)
│   └── 同样的 4 个维度
│
└── ③ 终稿池 (5-15 个产品)
    └── 同样的 4 个维度
```

**深度**：4-5 层（国家 → 池 → 维度 → 分支 → 产品）

## 三、3 个实现方案

### 方案 A：物化树表（推荐）⭐

**核心**：单张 `product_tree_nodes` 表，自引用 `parent_id`，定期重建

**优点**：
- 简单，单表 CRUD
- MySQL 8.0 递归 CTE 性能足够（4-5 层）
- 节点 = 目录（不存产品），`product_count` 缓存统计
- 重建快（< 1 秒）

**缺点**：
- 需重建逻辑（增量更新复杂，先用全量重建）

**数据量预估**：
```
单国树目录节点数：
  3 pool × 4 dim × 平均 10 分支 = 120 节点
  + 3 国家根 = 3
  ≈ 130 节点/国
重建耗时: < 500ms
```

### 方案 B：闭包表（最灵活）

**核心**：节点表 + 闭包表 `product_tree_closure (ancestor, descendant, depth)`

**优点**：
- 子孙查询极快（一次 JOIN）
- 节点移动只改闭包表，节点表不动

**缺点**：
- 双表维护，逻辑复杂
- 重建或修改时要重算闭包
- 对当前需求**杀鸡用牛刀**

### 方案 C：实时 SQL 聚合（无新表）

**核心**：不存树，查询时用 `GROUP BY` + 递归 CTE 拼装

**优点**：
- 始终新鲜（数据变更立刻反映）
- 无同步问题

**缺点**：
- 每次展开节点都跑 SQL
- 多维度切换要重新聚合，性能差
- 前端树交互体验差（每次展开都 loading）

## 四、推荐方案 A 的详细设计

### 4.1 数据模型

```sql
CREATE TABLE product_tree_nodes (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  parent_id BIGINT NULL,
  marketplace VARCHAR(10) NOT NULL,        -- UK/DE/US
  pool VARCHAR(20) NOT NULL,                -- competitor/selection/final_draft
  dimension VARCHAR(20) NULL,               -- category/source/ranking/grade
  node_type VARCHAR(20) NOT NULL,           -- country/pool/dim/branch
  node_name VARCHAR(255) NOT NULL,
  ref_key VARCHAR(200),                     -- 维度值，如 "Home & Kitchen"、"new"、"S"
  product_count INT DEFAULT 0,              -- 该节点下产品数（缓存）
  sort_order INT DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_parent (parent_id),
  INDEX idx_marketplace (marketplace),
  INDEX idx_pool_dim (marketplace, pool, dimension, parent_id)
);
```

> **关键决策**：产品级节点**不存到 product_tree_nodes**。
> - 300+ 产品会爆炸
> - 产品的真实数据在 `competitor_products` / `selection_products`
> - 树的"产品层"用 `ref_key` 标记（如分类路径），点击时 SQL 查产品

### 4.2 节点示例数据

```sql
-- 国家根
(1, NULL, 'UK', '',           '',         'country', '英国',       NULL,    360);
-- 池节点
(2, 1,   'UK', 'competitor',  '',         'pool',    '竞品池',     NULL,    300);
-- 维度节点
(3, 2,   'UK', 'competitor',  'category', 'dim',     '分类树',     NULL,    300);
(4, 2,   'UK', 'competitor',  'source',   'dim',     '来源树',     NULL,    300);
-- 分支节点
(10, 3,  'UK', 'competitor',  'category', 'branch',  'Home & Kitchen', 'Home & Kitchen', 45);
(11, 3,  'UK', 'competitor',  'category', 'branch',  'Pet Supplies',   'Pet Supplies',   30);
(20, 4,  'UK', 'competitor',  'source',   'branch',  '新品榜',     'new',         200);
(21, 4,  'UK', 'competitor',  'source',   'branch',  'AI 推荐',     'ai_recommend',  30);
```

### 4.3 重建逻辑

```python
def build_product_tree(marketplace: str):
    """重建单国树，< 1 秒完成"""
    # 1. 清空该国旧树
    db.execute("DELETE FROM product_tree_nodes WHERE marketplace = ?", marketplace)
    
    # 2. 国家根
    root_id = insert(marketplace=marketplace, node_type='country', 
                     node_name=f'{country_name(marketplace)}', product_count=total_count)
    
    # 3. 3 个池
    for pool in ['competitor', 'selection', 'final_draft']:
        pool_id = insert(parent_id=root_id, pool=pool, node_type='pool',
                         node_name=pool_display_name(pool), product_count=pool_count)
        
        # 4. 4 个维度
        for dim in ['category', 'source', 'ranking', 'grade']:
            dim_id = insert(parent_id=pool_id, dimension=dim, node_type='dim',
                            node_name=dim_display_name(dim))
            
            # 5. 该维度的分支（聚合 SQL 一次）
            if dim == 'category':
                rows = sql(f"""
                    SELECT SUBSTRING_INDEX(node_label_path, ':', 1) AS l1,
                           COUNT(*) AS cnt
                    FROM {pool_table(pool)}
                    WHERE marketplace = ? AND filter_mode IN ('MODE1','MODE2')
                    GROUP BY l1
                """, marketplace)
                for l1, cnt in rows:
                    insert(parent_id=dim_id, dimension=dim, node_type='branch',
                           node_name=l1, ref_key=l1, product_count=cnt)
            # 类似处理 source/ranking/grade
```

### 4.4 API 设计

```python
# 1. 获取根节点
GET /api/v1/product-tree/roots
→ [{"id": 1, "marketplace": "UK", "name": "英国", "product_count": 360}, ...]

# 2. 懒加载子节点
GET /api/v1/product-tree/children/{node_id}
→ [{"id": 2, "name": "竞品池", "type": "pool", "has_children": true}, ...]

# 3. 获取产品列表（叶子层）
GET /api/v1/product-tree/products
  ?marketplace=UK
  &pool=competitor
  &dimension=category
  &ref_path=Home & Kitchen
  &page=1&size=20
→ {list: [产品详情], total: 45, page: 1, size: 20}

# 4. 重建树
POST /api/v1/product-tree/rebuild
  body: {"marketplace": "UK"}
→ {status: "ok", node_count: 130, duration_ms: 350}
```

## 六、关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 单表 vs 闭包表 | **单表** | 树浅（4-5 层），简单优先 |
| 物化 vs 实时聚合 | **物化** | 响应快，前端体验好 |
| 产品存树 vs 不存 | **不存** | 避免节点爆炸，用真实表 |
| 重建 vs 增量 | **全量重建** | 数据量小（< 1s），逻辑简单 |
| 跨服务调用 | **HTTP POST** | 简单可靠，不引入 MQ |
| 维度选择 | **4 个**（分类/来源/排名/评分）| 覆盖主要浏览场景 |
