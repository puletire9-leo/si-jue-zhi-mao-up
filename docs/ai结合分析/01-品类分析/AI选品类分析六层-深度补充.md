## 第1层：品类画像 — 不只是聚合数字

### 现状问题

简单的 COUNT/AVG/SUM 只能描述品类的"平均状态"。但品类内部的**分布形态**比平均值重要得多。

### 补充：分布形态分析

一个品类均价£15，可能是两种完全不同的市场：

- **A型**：所有产品都在£12-18之间 → 成熟标准化市场，价格已收敛
- **B型**：一半产品£5-8，一半产品£25-35 → 两极分化，中间有空白

**均价一样，但策略完全不同。**

需要增加的分布指标：

| 指标 | 计算方式 | 含义 |
|------|---------|------|
| **价格变异系数** | stddev(price) / avg(price) | >0.4说明价格分散，市场未成熟 |
| **销量基尼系数** | 前20%产品的销量占比 | >0.8说明头部通吃，<0.5说明均匀分布 |
| **BSR中位数 vs 均值** | median(bsr) / avg(bsr) | 偏差大说明有极端值拉偏 |
| **评论集中度** | 前3个产品的评论占品类总评论的比例 | >0.5说明评论壁垒集中在头部 |

### 补充：品类层级下钻

`node_label_path` 有三层：`一级:二级:三级`

当前方案按一二级分析，但有些品类需要**三级下钻**：

```
Home & Kitchen > Kitchen & Dining > Small Appliances     (20个产品)
Home & Kitchen > Kitchen & Dining > Cutlery              (8个产品)
Home & Kitchen > Kitchen & Dining > Bakeware             (5个产品)
```

二级"Kitchen & Dining"有33个产品，看起来不错。但下钻到三级发现：
- Small Appliances有20个 → 可能是主流
- Cutlery只有8个 → 可能太小众
- Bakeware只有5个 → 不值得单独分析

**策略：先按一二级聚合，当二级品类产品数>15时，自动下钻到三级。**

### 补充：品类"有效产品数"

不是所有通过筛选的产品都有分析价值。需要过滤掉：

- **空壳记录**：有asin但无title的记录（追踪记录）
- **极端异常值**：价格<£1（可能是配件/附属品，不是主产品）
- **超级变体**：一个父ASIN下有50+变体（实际只是1个产品的颜色/尺寸变化）

品类画像应该基于**去重后的独立有效产品数**，不是原始行数。

现有SQL里已经有 `groupByParent` 的逻辑（每父ASIN取BSR最低的前3个），品类分析应该复用这个去重逻辑。

## 第2层：品类指标 — 从静态到动态

### 现有7个指标的局限

都是**横截面指标**——只看当前这批数据，没有时间维度。

### 补充：纵向对比指标（需要至少2个月数据）

当系统积累2个月以上数据后，可以计算：

| 动态指标 | 计算 | 含义 |
|---------|------|------|
| **品类热度变化** | 本月通过品数 / 上月通过品数 | >1.5 = 品类升温，<0.5 = 品类降温 |
| **价格趋势** | 本月均价 vs 上月均价 | 均价下降 = 可能正在打价格战 |
| **卖家流动率** | 本月新出现的卖家 / 总卖家 | >0.5 = 大量新卖家涌入（机会or红海？） |
| **新品存活率** | 上月新品中本月仍在售的比例 | >0.6 = 新品能活下来 |
| **评分升级率** | 上月C/D级产品中本月升到A/B的比例 | 说明品类内产品迭代活跃 |

**动态指标的价值远大于静态指标。**

一个品类静态看可能很普通（均价低、评论多），但如果"本月新品数量暴增 + 价格开始上涨" → 说明品类正在转折，是进入的好时机。

### 补充：品类指标的"组合判定"

单个指标可能有误判。真正有价值的判断需要**多指标交叉**：

```
经典好品类模式:
  品牌集中度 > 0.8 (分散)
  + CN比 < 0.4 (不内卷)
  + 评论壁垒 < 80 (低门槛)
  + 市场活跃度 > 0.2 (多产品能卖)
  + Listing运营 < 0.4 (对手弱)
  → 推荐

经典陷阱品类模式:
  品牌集中度 > 0.8 (看起来分散)
  + CN比 > 0.6 (但是很内卷)
  + 均价 < £8 (低价品类)
  + 价格带宽比 < 0.5 (价格趋同)
  → 不推荐（看似有机会实际是红海）

虚假繁荣模式:
  市场活跃度 > 0.4 (很多产品卖得好)
  + 评论壁垒 > 300 (但评论都很多)
  + 品类新鲜度 < 0.2 (全是老品)
  + Listing运营 > 0.7 (对手都很专业)
  → 不推荐（市场大但你进不去）
```

这些模式判定可以用Python规则引擎做（if-else），不需要LLM。**预筛一遍，LLM只看规则引擎不确定的品类。**

### 补充：品类指标的可信度标记

当品类内产品数太少（3-5个），统计指标的可信度很低：
- 3个产品都是CN卖家 → CN比100%，但不代表品类特征
- 均价基于4个产品 → 可能被一个极端值拉偏

需要加一个**可信度标记**：
```python
if product_count < 5:
    confidence = "低（样本不足）"
elif product_count < 10:
    confidence = "中"
else:
    confidence = "高"
```

LLM在分析时应该参考这个可信度，低可信度的品类给更保守的评级。

## 第3层：价格带地图 — 找的不只是空白

### 补充：价格带"需求密度"

空白带不一定是机会。可能是**这个价格带没有需求**。

判断方法：看品类整体的价格-销量分布曲线

```
理想的价格带机会：
  供给少（产品数少） + 需求大（平均销量高）
  → 真正的空白带

危险的价格带：
  供给少（产品数少） + 需求也少（平均销量低）
  → 不是空白，是没需求

拥挤但有机会的价格带：
  供给多（产品数多） + 需求也大（平均销量高）
  → 市场大，虽然有竞争但容量够
```

### 补充：价格带与Listing质量的关系

不只是看"这个价格带有几个产品"，还要看**这个价格带的产品运营水平**：

```
价格带 £15-20:
  产品数: 5个
  平均销量: 72
  有A+的产品: 0个      ← 全部没有A+
  有视频的: 0个        ← 全部没有视频
  平均评论: 31
  
→ 这个价格带不仅供给少，而且现有卖家运营水平极差
→ 如果进入，做好Listing就能碾压
```

vs

```
价格带 £15-20:
  产品数: 5个
  平均销量: 72
  有A+的产品: 4个      ← 大部分有A+
  有视频的: 3个
  平均评论: 180
  
→ 虽然也是5个产品，但对手很强
→ 进入需要更多投入
```

### 补充：价格带的"甜蜜价格"识别

每个品类都有一个"甜蜜价格"——消费者决策最快的价格区间。

**判定方法**：平均销量最高 + 产品数适中的价格带

```
Kitchen Gadgets 品类:
  £5-10:   12个产品, 平均销量 23  → 太便宜，利润低
  £10-15:  18个产品, 平均销量 45  → 竞争最激烈
  £15-20:  5个产品,  平均销量 89  → ★ 甜蜜价格 ★
  £20-30:  8个产品,  平均销量 34  → 需求下降
  £30-50:  3个产品,  平均销量 12  → 太小众
```

甜蜜价格 = 供给少 + 需求高 + 在品类的"正常消费价格"范围内。

### 补充：跨品类价格带对比

同一价格带在不同品类意味着完全不同的东西：

- £15-20 在 Kitchen Gadgets → 中档价位，品质消费者
- £15-20 在 Phone Accessories → 高档价位，可能是配件套装
- £15-20 在 Pet Supplies → 中高档，愿意为宠物花钱的主人

**LLM需要理解价格带在不同品类中的"语义"。**

## 第4层：卖家力量分析 — 从"谁在卖"到"怎么卖"

### 补充：卖家画像分类

品类内的卖家不是同质的，可以分为：

| 卖家类型 | 特征 | 威胁等级 |
|---------|------|---------|
| **品类专家** | 在此品类有5+产品，其他品类很少 | 高 — 深耕供应链 |
| **杂货铺** | 在很多品类各有几个产品 | 中 — 不专注，可能退出 |
| **品牌卖家** | 有品牌名、有A+、有视频 | 高 — 有品牌护城河 |
| **白牌铺货** | 无品牌、无A+、多SKU | 低 — 容易超越 |
| **本地小店** | seller_nation=UK/DE，1-2个产品 | 低 — 运营水平有限 |

**品类内卖家类型的分布，比单纯的"集中度"更能说明问题。**

```
品类A: 15个卖家，12个是白牌铺货 + 3个本地小店
→ 几乎没有专业竞争，进入门槛极低

品类B: 15个卖家，5个品类专家 + 8个品牌卖家 + 2个杂货铺
→ 头部都是专业选手，进入需要差异化策略
```

### 补充：卖家"跨品类足迹"

一个卖家如果在你关注的品类有3个产品，同时在另外5个品类各有2个产品 → 这是一个有供应链深度的卖家。

```sql
-- 查看品类内Top卖家在其他品类的布局
SELECT seller_name, 
       COUNT(DISTINCT SUBSTRING_INDEX(node_label_path, ':', 1)) AS category_spread,
       GROUP_CONCAT(DISTINCT SUBSTRING_INDEX(node_label_path, ':', 1)) AS categories
FROM competitor_products
WHERE seller_name IN (品类内Top卖家列表)
  AND filter_mode IN ('MODE1','MODE2')
GROUP BY seller_name
```

**价值**：如果品类内的头部卖家都是"跨品类大卖家"，说明这个品类吸引了专业选手。如果头部卖家只在品类内有产品、其他地方看不到 → 说明是品类内的小玩家，威胁有限。

### 补充：卖家国籍与运营水平的交叉

不只看"CN卖家占比"，要看**CN卖家 vs 本地卖家的运营水平差异**：

```
Pet Supplies 品类:
  CN卖家(10个):  平均评论 45, A+占比 20%, 视频占比 10%
  本地卖家(8个): 平均评论 120, A+占比 75%, 视频占比 50%
  
→ CN卖家运营水平明显低于本地卖家
→ 说明CN卖家靠价格/铺货竞争，还没开始做品牌
→ 如果以CN身份进入但做品牌化运营，有差异化空间
```

### 补充：卖家"进入/退出"信号

如果品类内有产品的listing_days很短（<30天），说明**最近有新卖家进入**。
如果有产品的rating_delta大幅为负，说明**现有卖家可能在遇到问题**。

这些信号可以帮助判断：品类是处于"新卖家不断涌入"的阶段还是"格局稳定"的阶段。

## 第5层：风险评估 — 从标签到量化

### 补充：风险不只看品类名，还要看数据模式

有些风险不是品类名能看出来的：

**风险信号1：评论异常**
```
品类内平均rating 4.5，但有个别产品rating 3.2且评论数很多
→ 说明消费者对这类产品有特定不满
→ 如果你能解决这个不满，就是机会
→ 如果不能，这就是品类固有的质量风险
```

**风险信号2：变体爆炸**
```
某品类内3个父ASIN总共有120个变体
→ 说明头部卖家在用"变体墙"策略（占满所有颜色/尺寸/组合）
→ 新品进入很难获得展示位
→ 这是结构性进入壁垒
```

**风险信号3：价格断崖**
```
品类内价格分布:
  60%产品在£5-8
  35%产品在£25-35
  5%在£10-20
  
→ 明显的两极分化，中间几乎不存在
→ 说明消费者只认"便宜款"或"品质款"
→ 中间价位是死亡区间，不要进
```

**风险信号4：单卖家品类**
```
某品类45个产品中30个来自同一卖家
→ 这个品类可能是某个卖家"做出来"的
→ 一旦你进入，对方有充分的动机和能力打压你
```

### 补充：风险等级矩阵

不是所有风险都一样严重，需要分级：

```
致命风险（直接排除）:
  - 品类名明确涉及IP（Disney/Marvel/NFL等）
  - 品类需要强制认证且成本>£5000（医疗器械、儿童安全座椅）
  - 亚马逊自营已是品类Top3

高风险（需充分准备）:
  - CN比>70%（必然价格战）
  - 品类头部3个卖家占>60%市场
  - 品类平均rating<3.8（说明品类有质量通病）

中风险（需注意）:
  - 季节性强（年销量波动>3x）
  - 品类退货率历史偏高
  - 物流限制（液体/电池/超大件）

低风险（留意即可）:
  - 品类较新，数据样本不足
  - 品类均价较低（利润空间有限）
  - 品类增长放缓
```

### 补充：风险的时间维度

风险不是静态的：

- **圣诞品类**：7-9月备货是机会，10-12月进入已经晚了
- **新法规影响**：欧盟新电子产品法规生效前3个月，相关品类风险上升
- **亚马逊政策变化**：FBA费用调整后，低利润品类风险增加

这些LLM可以从日期和品类特征推断。

## 第6层：跨品类关联 — 从发现到行动

### 补充：卖家重叠度分析

**最硬的跨品类信号是卖家重叠**——不是AI猜的，是数据实证的。

```sql
-- 计算任意两个品类之间的卖家重叠度
SELECT 
  a.category_l1 AS cat_a,
  b.category_l1 AS cat_b,
  COUNT(DISTINCT a.seller_name) AS shared_sellers,
  -- Jaccard相似度
  COUNT(DISTINCT a.seller_name) / 
    (SELECT COUNT(DISTINCT seller_name) FROM 
     (SELECT seller_name FROM cat_a_sellers 
      UNION 
      SELECT seller_name FROM cat_b_sellers) t
    ) AS jaccard_similarity
FROM category_a_sellers a
JOIN category_b_sellers b ON a.seller_name = b.seller_name
GROUP BY cat_a, cat_b
HAVING shared_sellers >= 3  -- 至少3个共同卖家才算有意义的重叠
```

**卖家重叠度高意味着：**
- 供应链可能共享（同一批供应商/工厂）
- 运营经验可复用（同一批人在做）
- 如果其中一个品类你已经在做，另一个品类扩展成本低

### 补充：品类"生态位"分析

每个品类在消费者购买行为中有"生态位"：

```
核心品类：消费者主动搜索的（如"air fryer"）
  → 流量大，竞争激烈
  
配件品类：买了核心产品后顺带买的（如"air fryer liner"）
  → 流量依赖核心品类，但竞争小，利润率高
  
耗材品类：需要持续购买的（如"coffee pods""water filter"）
  → 复购率高，长期价值大
  
季节品类：特定时间才买的（如"christmas lights"）
  → 季节性波动，需要精准的库存管理
  
趋势品类：社交媒体带火的（如"fidget spinner"类）
  → 爆发力强但生命周期短
```

**LLM可以从品类名+数据模式判断生态位类型。**

不同生态位的选品策略不同：
- 核心品类 → 需要差异化产品+品牌投入
- 配件品类 → 跟进核心品类的热销品，做配件
- 耗材品类 → 关注复购率和利润率
- 趋势品类 → 快速进入快速退出，不做品牌

### 补充：品类组合推荐

最终给用户的不是"一个好品类"，而是**一组互补的品类组合**：

```
推荐组合A："小家电生态"
  主攻：Small Appliances（核心品类）
  配件：Appliance Accessories（配件品类）
  耗材：Replacement Filters/Parts（耗材品类）
  
  理由：三个品类共享供应链，卖家重叠度40%
  策略：先做核心品打品牌，再用配件/耗材做复购

推荐组合B："宠物生活"
  主攻：Pet Feeding（核心品类）
  扩展：Pet Grooming + Pet Travel（互补品类）
  
  理由：宠物主人是高复购群体，跨品类购买率高
  策略：一个品类验证后快速扩展到其他
```

## 层与层之间的数据流

六层不是独立的，数据在层与层之间流动：

```
第1层（品类画像）
  ↓ 原始聚合数据
第2层（品类指标）
  ↓ 7+N个量化指标
  ↓
  ├→ 第3层（价格带）—— 按品类分组后再按价格带细分
  ├→ 第4层（卖家力量）—— 按品类分组后再按卖家细分
  └→ 第5层（风险评估）—— 品类指标 + 品类名 → 风险标签
           ↓
第6层（跨品类关联）—— 汇总所有品类的指标+风险+卖家数据 → 全局视角
           ↓
最终输出：品类评级 + 机会产品 + 品类组合推荐
```

### 每一层的输入/输出契约

| 层 | 输入 | 输出 | 依赖 |
|----|------|------|------|
| 1 | 筛选后的产品列表 | 品类聚合数据(30-50行) | 无 |
| 2 | 品类聚合数据 | 品类指标矩阵(30×N) | 层1 |
| 3 | 品类内产品明细 | 价格带地图(JSON) | 层1 |
| 4 | 品类内卖家明细 | 卖家格局(JSON) | 层1 |
| 5 | 品类名+指标+价格带+卖家 | 风险标签+风险等级 | 层1-4 |
| 6 | 所有品类的全量数据 | 关联图谱+品类组合 | 层1-5 |

**第5层和第6层需要前4层的全部数据作为输入。** 这就是为什么LLM调用放在第5层之后——此时数据已经充分加工，LLM只需要做判断。

---

## 边界情况处理

### 情况1：品类产品数太少（<3个）

不纳入品类分析。但这些产品可以单独列为"小众品类"列表，用户自行判断。

### 情况2：一个三级品类横跨多个二级品类

`node_label_path` 有时会有多值（产品属于多个子类目）。取主类目（第一个）。

### 情况3：品类名不一致

卖家精灵返回的 `node_label_path` 可能在不同月份有微小差异（如 "Home & Kitchen" vs "Home and Kitchen"）。需要做品类名标准化：

```python
CATEGORY_NORMALIZE = {
    "Home and Kitchen": "Home & Kitchen",
    "Health & Personal Care": "Health & Personal Care",
    "Sports & Outdoors": "Sports and Outdoors",
    # ... 常见变体映射
}
```

### 情况4：数据月份缺失

如果某个月没有导入数据，品类画像只基于有数据的月份。动态指标标记为"数据不足"。

### 情况5：FBM产品占比极高

如果一个品类FBM占比>80%，这本身就是一个信号：
- 可能这个品类不适合FBA（超大件/危险品）
- 也可能说明FBA卖家还没进入 → 巨大机会
- 需要LLM结合品类特征判断是哪种情况
