# 权限修改导致的连锁问题：多问题叠加排查

**日期**: 2026-05-29
**严重程度**: 高（开发环境和生产环境同时无法使用）
**影响范围**: 所有用户，所有环境

---

## 现象

用户报告：仓库角色访问微定制页面显示"您无此权限"。

修改代码后问题不但没解决，反而引发更多问题：
- 生产环境页面空白
- 开发环境页面空白
- admin/12456 登录失败（401）
- 浏览器报 MIME 类型错误

---

## 问题链路（5 个问题叠加）

```
用户报告：仓库角色没有微定制权限
  ↓
我修改 user.ts，添加 final-draft:view
  ↓
用户测试：无效
  ↓
我排查：发现生产环境没重新构建
  ↓
尝试 npm run build → OOM（内存不足）
  ↓
用 --minify false 成功构建
  ↓
用户测试：admin/12456 登录失败（401）
  ↓
发现：数据库密码哈希损坏
  ↓
重置密码后：页面空白 + "您无此权限"
  ↓
发现：浏览器缓存了旧 JS 文件
  ↓
清理旧文件 + 重建 → 问题解决
```

## 5 个问题详解

### 问题 1：权限修改未生效

**现象**: 修改了 `user.ts` 中"仓库"角色的权限，但用户仍看到"您无此权限"

**根因**: 生产环境需要重新构建前端，但构建 OOM

**修复**: 用 `--minify false` 跳过压缩，成功构建

```powershell
cd frontend
$env:NODE_OPTIONS="--max-old-space-size=2048"
npx vite build --mode production --minify false
```

---

### 问题 2：前端读错登录响应字段

**现象**: 登录成功后 userInfo 为 null，导致权限检查失败

**根因**: Java 后端返回 `userInfo`，前端读 `user`，字段名不匹配

```typescript
// 后端返回
{
  "code": 200,
  "data": {
    "accessToken": "...",
    "userInfo": { "role": "admin", ... }  // ← 字段名是 userInfo
  }
}

// 前端原本读法
setUserInfo(loginData?.user || null)  // ← 读 user，是 undefined！
```

**修复**: 兼容两种字段名

```typescript
setUserInfo(loginData?.userInfo || loginData?.user || null)
```

---

### 问题 3：数据库密码哈希损坏

**现象**: admin/12456 登录返回 401

**根因**: 生产数据库的 admin 密码哈希与 123456 不匹配

```powershell
# 验证方法
$body = '{"username":"admin","password":"123456"}'
Invoke-RestMethod -Uri "http://localhost:9003/api/v1/auth/login" -Method Post -ContentType "application/json" -Body $body
# 返回 code=401
```

**修复**: 重置所有用户密码为 123456

```powershell
# 生成新的密码哈希
$hash = python -c "import bcrypt; print(bcrypt.hashpw(b'123456', bcrypt.gensalt()).decode())"

# 更新生产数据库
docker exec prod-mysql mysql -usijue -psijue123456 sijuelishi -e "UPDATE users SET password = '$hash' WHERE status = 1"

# 更新开发数据库
docker exec dev-mysql mysql -usijue -psijue123456 sijuelishi_dev -e "UPDATE users SET password = '$hash' WHERE status = 1"
```

---

### 问题 4：浏览器缓存旧 JS 文件

**现象**: 重新构建后用户仍看到旧页面

**根因**: nginx 配置了 1 年的静态文件缓存

```nginx
# nginx.prod.conf
location ~* \.(?:ico|css|js|gif|jpe?g|png|svg|woff2?|ttf|eot)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

浏览器缓存了旧的 JS 文件（如 `index-DExB0VdV.js`），即使文件内容已更新，浏览器仍使用缓存版本。

**修复**: 清理旧文件 + 重建

```powershell
# 清理旧的构建产物
cmd /c "rmdir /s /q E:\项目\si-jue-zhi-mao-up\static\vue-dist\js"
cmd /c "rmdir /s /q E:\项目\si-jue-zhi-mao-up\static\vue-dist\css"
cmd /c "del /q E:\项目\si-jue-zhi-mao-up\static\vue-dist\index.html"

# 重新构建
cd frontend
$env:NODE_OPTIONS="--max-old-space-size=2048"
npx vite build --mode production --minify false

# 重启 nginx
docker restart prod-frontend
```

---

### 问题 5：构建 OOM

**现象**: `npm run build` 报 JavaScript heap out of memory

**根因**: 系统内存不足（Docker 容器占用 ~7GB），terser 压缩是内存密集型操作

**修复**: 用 `--minify false` 跳过压缩

```powershell
$env:NODE_OPTIONS="--max-old-space-size=2048"
npx vite build --mode production --minify false
```

产物未压缩但功能一致，nginx gzip 传输不受影响。

## 为什么排查这么久

### 1. 症状相同，根因不同

"您无此权限"可以由以下任何原因导致：
- 登录失败（token 无效）
- userInfo 为空（字段名错误）
- 权限检查失败（角色不匹配）
- 老代码在跑（没重新构建）
- 浏览器缓存（旧 JS 被缓存）

**教训**: 遇到"无权限"先验证登录，再逐步排查。

### 2. 没有先验证最基本的事实

应该先问：**用户能不能登录成功？** 如果登录就失败了，后面所有权限检查都没意义。

```powershell
# 正确排查顺序
1. 验证登录 → curl 测试 API
2. 验证 token → 检查 localStorage
3. 验证 userInfo → 检查返回的 role 字段
4. 验证 hasPermission → 检查角色映射
5. 验证构建 → 检查生产 JS 是否包含修改
6. 验证缓存 → 检查浏览器加载的 JS hash
```

### 3. 修改太多，没有隔离验证

同时改了 `user.ts`（权限）、`competitor.ts`（normalizeProduct）、`UniversalCard/index.vue`（点击日志）、`AllSelection/index.vue`（数据处理），导致无法判断哪个修改引起了问题。

**教训**: 每次只改一个功能，验证通过后再改下一个。

## 正确的排查流程

```
遇到 "您无此权限"
  ↓
1. 先验证登录是否成功
   curl -X POST http://localhost:9000/api/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"123456"}'
  ↓
2. 如果登录失败 → 检查密码哈希
   docker exec prod-mysql mysql -usijue -psijue123456 sijuelishi \
     -e "SELECT username, password FROM users WHERE username='admin'"
  ↓
3. 如果登录成功但页面空白 → 检查浏览器控制台
   - 看 console.log 输出
   - 看 Network 请求
   - 看是否有 MIME 类型错误
  ↓
4. 如果有 MIME 错误 → 检查 JS 文件是否存在
   curl -I http://localhost:5173/js/index-xxx.js
  ↓
5. 如果 JS 文件存在但不生效 → 清理缓存
   - 清理浏览器缓存
   - 清理 nginx 缓存
   - 重新构建前端
```

## 预防措施

### 1. 登录响应字段统一

后端返回 `userInfo`，前端读 `userInfo`，不要依赖 fallback。

```typescript
// 正确写法
setUserInfo(loginData?.userInfo || null)

// 依赖 fallback 的写法容易出错
setUserInfo(loginData?.userInfo || loginData?.user || null)
```

### 2. 构建产物清理

每次构建前清理旧文件，避免 hash 冲突。

```powershell
# 在 build 脚本中加入清理步骤
Remove-Item -Recurse -Force static/vue-dist/*
npm run build
```

### 3. nginx 缓存配置优化

HTML 文件不缓存，静态文件用 hash 命名。

```nginx
# HTML 不缓存
location / {
    try_files $uri $uri/ /index.html;
    add_header Cache-Control "no-cache, no-store, must-revalidate";
}

# 静态文件长期缓存（Vite 生成的文件名带 hash）
location ~* \.(?:css|js|gif|jpe?g|png|svg|woff2?|ttf|eot)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

### 4. 权限修改验证流程

修改权限后必须验证：
1. 源码已修改
2. 生产环境已重新构建
3. 浏览器已加载新 JS
4. 用户已重新登录（清除旧 userInfo）
