## 2026-06-05 编辑定稿保存修改要求导致图片加载失败

**现象**：图定稿管理中，编辑定稿时只填写"修改要求"保存后，定稿图片加载失败。

**根因**：`frontend/src/views/FinalDraft/components/DraftDialog.vue`

`handleSubmit()` 每次保存都会调用 `handleImageUpload()` + `handleReferenceImageUpload()`，然后把 `formData.images` / `formData.reference_images` 写进 API 请求——即使用户没动图片。

`handleImageUpload()` 从 fileList 的代理 URL 反向重建 COS URL，依赖代理 URL 里有 `object_key` 参数。如果代理 URL 是 fallback 格式（`?url=`），`objectKey` 为空，代理 URL 就直接当图片 URL 存进数据库，导致图片无法加载。

另外，即使 URL 重建正确，无差别发送 images 字段也会触发后端的图片新旧比对和 COS 删除逻辑，增加了误删风险。

**修复**：
1. 编辑前保存原始图片 URL 快照
2. 提交时判断图片是否真实变更（数量变化 / 有新增 blob 文件）
3. 未变更 → 不调用上传、不发 images/reference_images 到后端

```typescript
// 判断图片是否被用户修改
const imagesCountChanged = fileList.value.length !== originalImages.value.length
const refImagesCountChanged = referenceFileList.value.length !== originalReferenceImages.value.length
const hasNewUploads = fileList.value.some(f => f.url && f.url.startsWith('blob:'))
  || referenceFileList.value.some(f => f.url && f.url.startsWith('blob:'))
const imagesModified = imagesCountChanged || refImagesCountChanged || hasNewUploads
```

## 2026-06-05 prod-celery-download 容器一直 unhealthy

**现象**：`prod-celery-download` 容器 health check 持续失败，日志 `No nodes replied within time constraint`。

**根因**：`docker-compose.prod-simple.yml` 健康检查用 `CMD` 数组形式，`$HOSTNAME` 不会被 shell 展开，传给 celery 的是字面字符串。

**修复**：`CMD` 改为 `CMD-SHELL`，让 shell 展开变量。
```yaml
test: ["CMD-SHELL", "celery -A app.tasks.celery_app inspect ping -d celery@$$HOSTNAME"]
```

## 2026-06-05 选品店铺接口 500（selection_products 不存在）

**现象**：`/api/v1/selection/stores` 返回 500，日志 `Table 'sijuelishi.selection_products' doesn't exist`。

**根因**：Python 后端镜像未重建，容器里跑的是旧代码，还在查已废弃的 `selection_products` 表。新代码已改为查 `competitor_products`。

**修复**：重建 Python backend 镜像并重启容器。
```powershell
docker build -t sjzm-python-base -f backend/Dockerfile.base backend
docker compose -f docker-compose.prod-simple.yml build --no-cache backend
docker compose -f docker-compose.prod-simple.yml up -d backend
```
