# 卖家精灵 API 问题与解答

> 高频调用口径、请求次数统计、店铺是否查询变体、市场编码等细节，统一补充记录在
> [调用口径与踩坑记录.md](调用口径与踩坑记录.md)。新增卖家精灵接口能力前，先核对这份记录。
> 统一口径：卖家精灵这里说“使用次数”；当前每月 20000 次，一次 HTTP 请求算 1 次。
> 请求实况、暂停、停止、失败重试的统一计划见：[卖家精灵请求中心实施计划.md](卖家精灵请求中心实施计划.md)。

## 1. API 单次最多 40 个 ASIN

`competitor-lookup` 接口单次请求最多传入 40 个 ASIN，超过会返回 `ERROR_PARAM: asin数量不能超过40`。

Java 代码中 `BATCH_SIZE = 40` 已正确匹配此限制。

## 2. API 只返回有 units（月销量）数据的 ASIN

**问题**：传入 40 个 ASIN，只返回 24 条，为什么少了？

**原因**：卖家精灵 API 只返回有月销量数据的 ASIN。没有销量数据的 ASIN 不会出现在响应中。

**测试验证（2026-05-21）**：
- 测试条件：仅 `marketplace: UK`，40 个 ASIN，无其他参数
- 返回结果：24 条（15 个请求的 ASIN + 9 个变体子 ASIN）
- 25 个请求的 ASIN 无数据，62.5% 无数据率
- 所有 24 条返回均有 `units` 值，哪怕 `units=0` 也被返回
- `amzUnit`（子体近30日销量）在所有测试中均为空

**结论**：返回数量少不是参数问题，是这批 ASIN 在 UK 市场确实只有这么多销量数据。与卖家精灵网站上的结果差异可能是网站统计口径不同或展示的是不同数据。

## 3. `nearly` 参数不支持

`competitor-lookup` 接口不支持 `nearly` 参数，传入会返回 `ERROR_PARAM`。

时间筛选应通过 `month` 参数（格式 `yyyyMM`）实现。如果不传 `month`，API 返回该 ASIN 所有历史数据。

## 4. `variation` 参数

- `variation=N`：含变体（子 ASIN 也会返回）
- `variation=Y`：不含变体（仅返回请求的 ASIN）
- 不传：默认等同 `N`（含变体）

### 4.1 店铺/统计类默认口径

后续凡是为了店铺筛选、店铺画像、店铺销量分级、店铺品级统计而调用卖家精灵 API，默认使用：

```json
{
  "variation": "Y"
}
```

原因：

- 亚马逊店铺页面显示的总商品数，是不含变体的父体商品数量。
- 店铺分析要对齐亚马逊店铺页口径，看的是独立商品/父体商品数量，而不是颜色、尺寸、套装等子变体数量。
- `variation=N` 会把子 ASIN 一起返回，容易把同一父体商品重复计入，污染店铺规模、销量分布和方法卡命中统计。

只有在专门研究变体策略、子 ASIN 表现、颜色/尺寸/套装结构时，才使用 `variation=N`。

## 5. `month` 参数

- 格式：`yyyyMM`，如 `202605`
- 不传：返回该 ASIN 所有时间的数据
- 注意：传 `month` 会显著减少返回数量（仅该月数据），如果需要全量数据则不传此参数
