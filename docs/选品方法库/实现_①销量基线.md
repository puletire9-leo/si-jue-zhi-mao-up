## 一句话结论

后端现有 `CategoryBaselineService.computeBaseline()` **口径错了,不能直接用**。错在两点:① 用 `node_label_path` 第2级当品类主键 → 德语/英语类目名跨国对不齐 → 无法支撑跨国套利;② 不分 BSR 桶 → 头部爆款和长尾揉成一个中位数 → 数字没有指导意义。

**解法:新建一张 `category_bsr_baseline` 表,按 `bsr_id`(跨国统一)+ BSR分桶 存销量分位。**

## 锁定的口径规格

| 项 | 规格 | 理由 |
|----|------|------|
| 品类主键 | **`bsr_id`**(kitchen/fashion/automotive...) | 跨国统一,语言无关。node_id 绑国家,node_label_path 是本地语言 |
| 切片维度 | **marketplace × bsr_id × bsr_bucket** | 跨国对比的最小单元 |
| BSR分桶 | `<5k / 5k-20k / 20k-50k / 50k-150k / >150k` | 对齐新品标准量级;每桶内销量量级一致 |
| 分位 | units 的 **P25 / P50 / P75** | P50中位抗极值;P25/P75给分散度 |
| 辅助 | price_avg、样本数 n | 价格带参考 + 可信度判断 |
| 最小样本 | 每桶 **n≥30** 才可信 | <30 标记"低可信",不参与推荐(UK kitchen <5k 桶空、fashion小桶噪声大) |
| 数据切片 | `month`(如 202606) | 对接"数据地基每月刷新" |
| 数据过滤 | **不要** `filter_mode != FAIL` | 老引擎依赖这个,但 filter_mode 正被改作 mo1/mo2 方法溯源,不能再依赖 |

## 建表 DDL(明天直接用)

```sql
CREATE TABLE category_bsr_baseline (
  id BIGINT NOT NULL AUTO_INCREMENT,
  marketplace VARCHAR(10) NOT NULL COMMENT '站点 UK/DE/US',
  bsr_id VARCHAR(100) NOT NULL COMMENT '大类slug(跨国统一)',
  bsr_bucket VARCHAR(16) NOT NULL COMMENT 'BSR分桶:lt5k/5k20k/20k50k/50k150k/gt150k',
  baseline_month VARCHAR(6) NOT NULL COMMENT '基线月份 如202606',
  sample_size INT NOT NULL DEFAULT 0 COMMENT '样本数',
  units_p25 INT DEFAULT NULL COMMENT '销量P25',
  units_p50 INT DEFAULT NULL COMMENT '销量中位数',
  units_p75 INT DEFAULT NULL COMMENT '销量P75',
  price_avg DECIMAL(10,2) DEFAULT NULL COMMENT '均价',
  confidence VARCHAR(8) DEFAULT NULL COMMENT '可信度 high/mid/low(按样本数)',
  computed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_slice (marketplace, bsr_id, bsr_bucket, baseline_month),
  KEY idx_lookup (marketplace, bsr_id, baseline_month)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='品类BSR分桶销量基线(①线)';
```

## 计算逻辑(SQL,已验证可跑)

明天可选两种实现:**(A)** 写进 Java Service 用 stream 算分位;**(B)** 直接 SQL `INSERT...SELECT` 灌表(更快,适合"每月刷新"定时任务)。推荐 B,逻辑就是这条已验证的 SQL:

```sql
WITH ranked AS (
  SELECT bsr_id, marketplace, units, price,
    CASE WHEN bsr<5000 THEN 'lt5k' WHEN bsr<20000 THEN '5k20k'
         WHEN bsr<50000 THEN '20k50k' WHEN bsr<150000 THEN '50k150k'
         ELSE 'gt150k' END AS bucket,
    PERCENT_RANK() OVER (
      PARTITION BY bsr_id, marketplace,
        CASE WHEN bsr<5000 THEN 1 WHEN bsr<20000 THEN 2 WHEN bsr<50000 THEN 3
             WHEN bsr<150000 THEN 4 ELSE 5 END
      ORDER BY units
    ) AS pr
  FROM competitor_products
  WHERE month=? AND bsr_id IS NOT NULL AND bsr_id<>'' AND bsr IS NOT NULL AND units IS NOT NULL
)
SELECT marketplace, bsr_id, bucket, COUNT(*) AS n,
  MAX(CASE WHEN pr<=0.25 THEN units END) AS p25,
  MAX(CASE WHEN pr<=0.50 THEN units END) AS p50,
  MAX(CASE WHEN pr<=0.75 THEN units END) AS p75,
  ROUND(AVG(price),2) AS price_avg
FROM ranked GROUP BY marketplace, bsr_id, bucket;
```

⚠️ 注意:`MAX(CASE WHEN pr<=0.5...)` 这种取分位法**不能用 GROUP_CONCAT 字符串拼**(H0踩过坑,group_concat_max_len 截断导致中位数算成0)。必须用窗口函数 PERCENT_RANK。

## 补充:小类基线表 DDL(H4新增,2026-06-23)

> 大类基线(上面)定位不了你的猎场(赢家在大类中后段)。**真正定位机会的是小类基线**。
> 只给③线圈定的小类 + 样本≥30 建基线。

```sql
CREATE TABLE subcategory_baseline (
  id BIGINT NOT NULL AUTO_INCREMENT,
  marketplace VARCHAR(10) NOT NULL COMMENT '站点 UK/DE/US',
  bsr_id VARCHAR(100) DEFAULT NULL COMMENT '大类slug',
  sub_category VARCHAR(200) NOT NULL COMMENT '小类(node_label_path末级)',
  baseline_month VARCHAR(6) NOT NULL COMMENT '基线月份',
  sample_size INT NOT NULL DEFAULT 0 COMMENT '样本数',
  units_p50 INT DEFAULT NULL COMMENT '销量中位数',
  units_p75 INT DEFAULT NULL COMMENT '销量P75(头部线)',
  units_p90 INT DEFAULT NULL COMMENT '销量P90(爆款线)',
  price_p50 DECIMAL(10,2) DEFAULT NULL COMMENT '价格中位数',
  confidence VARCHAR(8) DEFAULT NULL COMMENT '可信度 high/mid/low',
  computed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_slice (marketplace, sub_category, baseline_month),
  KEY idx_lookup (marketplace, bsr_id, baseline_month)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='小类销量基线(③线猎场专用)';
```

计算SQL(同大类基线,分位换P50/P75/P90,分组键改小类):

```sql
WITH ranked AS (
  SELECT marketplace,
    SUBSTRING_INDEX(node_label_path,':',-1) AS sub_cat,
    units, price,
    PERCENT_RANK() OVER (PARTITION BY marketplace,
      SUBSTRING_INDEX(node_label_path,':',-1) ORDER BY units) AS pr
  FROM competitor_products
  WHERE month=? AND node_label_path IS NOT NULL
    AND units IS NOT NULL
)
SELECT marketplace, sub_cat, COUNT(*) AS n,
  MAX(CASE WHEN pr<=0.50 THEN units END) AS p50,
  MAX(CASE WHEN pr<=0.75 THEN units END) AS p75,
  MAX(CASE WHEN pr<=0.90 THEN units END) AS p90,
  ROUND(AVG(price),2) AS price_p50
FROM ranked GROUP BY marketplace, sub_cat HAVING n>=30;
```

只灌③线圈定的小类(赢家集中的那批):
```
Sun Catchers / Tote Bag / Figure / Cosmetic Bag / Drawstring Bag /
Keychain / Bracelet / Water Bottle / Cap / Cake Topper / Ornament
```
