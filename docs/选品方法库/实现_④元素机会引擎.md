# ④ 元素机会引擎 · 实现定稿

> 方法①的落地引擎。两条路径互相补充:**已知元素去市场找补位** + **市场反向发现新元素**。
> 核心原则:**载体是通货(完整覆盖),元素是变量(动态发现,用户验证后入库)**。
> 定稿库(final_drafts)只读参考,本引擎建独立表。

---

## 两条路径(用户定调 2026-06-23)

```
路径1(正向):已知好卖的元素 → 去市场找
  我们验证过的元素(③线赢家 + final_drafts高频)
        ↓ 三语锚点词搜三国 competitor_products 标题
  看这些元素出现在哪些载体上 → 新载体=补位推荐⭐
  看这些元素的销量/BSR趋势 → 热起来=快跟进

路径2(反向):市场好卖的元素 → 反馈回来
  先匹配载体锚点(完整的55载体库,三语)
        ↓ 提取所有元素候选
  统计每个元素:跨载体数 / 总销量 / BSR分布 / 三国覆盖
        ↓
  热门元素(跨载体多+销量高) → 推荐⭐
  冷门元素(有销量但跨载体少) → 也推荐⭐(蓝海)
        ↓
  你人工反馈:这个好卖 → 入库到已验证元素库 → 下次路径1就能找到它
```

**两条路径不是先后,是并行跑,互相喂养。** 你验证了一个新元素,下次路径1立刻覆盖它。

## 建表(三张独立表)

### 1. 载体词典 `element_carrier_dict`(基础设施,完整覆盖)

从 final_drafts 复制所有载体,配三语锚点(见 [[补充/载体元素三语映射表]] 载体部分)。

```sql
CREATE TABLE element_carrier_dict (
  id BIGINT NOT NULL AUTO_INCREMENT,
  carrier_cn VARCHAR(100) NOT NULL COMMENT '中文载体名',
  carrier_en VARCHAR(300) NOT NULL COMMENT '英文锚点(/分隔多词)',
  carrier_de VARCHAR(300) DEFAULT NULL COMMENT '德文锚点(/分隔多词)',
  carrier_type VARCHAR(20) DEFAULT 'CUSTOM' COMMENT 'STD=标品载体/CUSTOM=非标品载体',
  is_active TINYINT DEFAULT 1 COMMENT '是否启用(低频载体标0,等确认)',
  source VARCHAR(50) DEFAULT 'final_drafts' COMMENT '来源',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_cn (carrier_cn)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='载体三语词典(完整,所有非标品载体锚点)';
```

**种子**:从 final_drafts 提取全部 DISTINCT carrier(~55个),配三语→来源 [[补充/载体元素三语映射表]]。载体会持续补(市场出现新载体时人工加)。

### 2. 已验证元素库 `element_library`(只收好卖的,不收全量)

```sql
CREATE TABLE element_library (
  id BIGINT NOT NULL AUTO_INCREMENT,
  element_cn VARCHAR(100) NOT NULL COMMENT '中文元素名',
  element_en VARCHAR(300) NOT NULL COMMENT '英文锚点(/分隔同义词)',
  element_de VARCHAR(300) DEFAULT NULL COMMENT '德文变体(/分隔)',
  element_category VARCHAR(50) DEFAULT NULL COMMENT '分类:动物/植物/节日/赛事/IP/抽象/文字',
  cross_carrier_count INT DEFAULT 0 COMMENT '已验证跨载体数',
  total_drafts INT DEFAULT 0 COMMENT 'final_drafts定稿次数(参考)',
  is_proven TINYINT DEFAULT 0 COMMENT '③线591赢家出现过=1',
  is_curated TINYINT DEFAULT 0 COMMENT '你人工确认好卖=1',
  market_total_units INT DEFAULT 0 COMMENT '市场总销量(自动更新)',
  market_seen_nations VARCHAR(50) DEFAULT NULL COMMENT '出现国家:UK,DE,US(自动更新)',
  source VARCHAR(50) DEFAULT 'final_drafts' COMMENT '来源:final_drafts/591/market_discovered/manual',
  first_seen_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_cn (element_cn),
  KEY idx_proven (is_proven),
  KEY idx_curated (is_curated)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='已验证好卖元素库(非全量,只收验证过的)';
```

**种子(只入库被验证过或高频的,不是全部426个)**:

| 优先级 | 来源 | 数量 | 例子 |
|--------|------|------|------|
| 🥇 必入 | ③线591赢家出现过的元素 | ~30 | 高地牛/蝴蝶结/卡皮巴拉/足球/F1/天使/豹纹/猫头鹰 |
| 🥈 必入 | final_drafts≥6次高频 | ~43 | 伦敦/黑猫/长颈鹿/独角兽/腊肠狗/世界杯... |
| 🥉 待入 | 你人工标记好卖的 | 持续 | 市场新发现的元素,你反馈后入库 |
| ❌ 不入 | final_drafts孤立实验(1次) | 261 | 这些是设计草稿,不是验证过的好卖元素 |

⚠️ **不把426全灌进元素库**——映射表也不需要列全部元素。只有验证过的才进库,其余靠路径2动态发现。

### 3. 元素发现结果表 `element_discovery`

```sql
CREATE TABLE element_discovery (
  id BIGINT NOT NULL AUTO_INCREMENT,
  asin VARCHAR(20) NOT NULL,
  marketplace VARCHAR(10) NOT NULL,
  discovery_month VARCHAR(6) NOT NULL,
  discovery_path VARCHAR(8) NOT NULL COMMENT 'PATH1=已知元素补位/PATH2=市场反向发现',
  extracted_element_en VARCHAR(200) DEFAULT NULL COMMENT '提取到的英文元素词',
  element_cn VARCHAR(100) DEFAULT NULL COMMENT '匹配到的中文元素(PATH1有值,PATH2先空)',
  carrier_cn VARCHAR(100) DEFAULT NULL COMMENT '匹配到的载体(中文)',
  carrier_en VARCHAR(100) DEFAULT NULL COMMENT '匹配到的载体(锚点词)',
  element_in_lib TINYINT DEFAULT 0 COMMENT '元素是否在已验证库',
  carrier_in_lib TINYINT DEFAULT 0 COMMENT '载体是否在库',
  confidence VARCHAR(8) DEFAULT NULL COMMENT '提取可信度HIGH/MID/LOW',
  title_raw VARCHAR(1000) DEFAULT NULL COMMENT '原始标题',
  units INT DEFAULT NULL,
  bsr INT DEFAULT NULL,
  price DECIMAL(10,2) DEFAULT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_discovery (asin, marketplace, discovery_month, discovery_path),
  KEY idx_path (discovery_path),
  KEY idx_element (extracted_element_en(64))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='元素发现结果(每日跑)';
```

## 路径1:已知元素补位(正向)

**逻辑**:用已验证元素的三语锚点词,去三国标题里搜索 → 看这些元素出现在哪些载体上 → 我们没做的载体=补位推荐。

```
输入: element_library 中 is_proven=1 OR is_curated=1 的元素
      例: 卡皮巴拉 → element_en="Capybara" element_de="Capybara/Wasserschwein"

搜索: competitor_products 三国新品 title LIKE '%Capybara%'
      英+美用英文,德用英文+德文都搜

匹配: 对搜索结果,再用载体锚点词定位每条标题的载体
      例: "Capybara Drawstring Bag for Kids..." → 载体=束口袋
          "Capybara Water Bottle..." → 载体=水杯

对比: 这个元素×载体组合,我们在 final_drafts 里有吗?
      有 → 已知组合,不推
      没有 → 补位推荐⭐

叠加: 查①线小类基线(这品在小类里卖得动吗?)
      查②线标准(BSR+销量是否达标?)
      达标 → 强推;不达标 → 弱推(观察)
```

**输出示例**:
> ⭐ 补位:卡皮巴拉(已验证) × 束口袋 — 市场上UK出现4个品,月销20-35单,售价£5.98-7.98。我们没做过卡皮巴拉束口袋。
> ⭐ 补位:卡皮巴拉 × 水杯 — 市场上DE出现3个品,月销15+。

## 路径2:市场反向发现(反向)

**逻辑**:先匹配载体锚点 → 从标题提取元素 → 按"跨载体/热度/销量"给元素排名 → 热门的和冷门但卖得动的都推荐 → 你人工标记入库。

```
输入: competitor_products 本月新品(title非空)
      载体锚点词库(55载体三语)

Step 1 — 载体锚点匹配: 每条标题找载体词(三语,最长匹配优先)
       匹配到 → 确定载体,进入Step 2
       未匹配 → 可能是标品/未覆盖载体,BROKEN挂起

Step 2 — 元素提取: 载体词向前取1-5词 → 剥工艺/材质/品牌 → 元素候选
       详见 [[补充/标题匹配说明]]

Step 3 — 元素聚合统计:
       按元素候选词 GROUP BY:
         element_en (英文原词)
         cross_carrier_count (跨了多少载体)
         total_products (总品数)
         total_units (总销量)
         avg_bsr (平均BSR)
         nations (出现国家:UK,DE,US)
         carriers_list (载体列表)
         price_range (价格带)

Step 4 — 元素排名:
       热门元素 = 跨载体≥3 + 总销量高 + 三国都出现 → 已验证的爆款元素⭐
       冷门元素 = 有销量(>10) + 跨载体少(1-2) + 特定国家 → 蓝海机会⭐
       噪音    = 销量<5 + 品数<3 → 过滤

Step 5 — 对照:
       热门元素在 element_library 里吗?
         在 → 不推(路径1已经覆盖)
         不在 → 推荐给你,等人工判断

Step 6 — 你的反馈循环:
       你看到推荐 → 判断"这个元素好卖"
         → 入库 element_library(is_curated=1)
         → 补充中文名+德文变体
         → 下次路径1自动覆盖这个元素
```

**输出示例**:
> 🔥 热门新元素发现:
> - **Leopard Print Cherry(豹纹樱桃)**:跨5种载体,UK+DE共68品,总月销1200+。我们库里没有——值得看。
> - **Axolotl(蝾螈)**:跨4种载体,DE主战场,总月销800+。新兴IP元素。
>
> 🥶 冷门但有销量:
> - **Tree of Life(生命树)**:只出现在挂牌+帆布袋,UK月销45单,德几乎不出现。小众但持续有量。
> - **Retirement Gifts(退休)**:只在马克杯+挂牌,UK特定人群,单小众高。

## 每日运行流程(两条路径可并行)

```
凌晨(数据刷新后):
  1. 先跑路径1: element_library 已验证元素 × 三国新品 → discovery(PATH1) → 补位推荐
  2. 同时跑路径2: 55载体锚点全扫 → 提取元素 → 聚合排名 → discovery(PATH2) → 元素排名推荐
  3. 两类推荐合并 → 按优先级排列:
     路径1补位(确定性最高) > 路径2热门(市场验证) > 路径2冷门(蓝海)
```

## 两条路径的关系(互相喂养,闭环)

```
路径2发现新元素 → 你人工确认好卖 → 入库 element_library
                                       ↓
                              下次路径1会自动覆盖它
                              在所有三国标题里找到它的新载体
                                       ↓
                              你又看到补位推荐 → 又确认
                                       ↓
                              元素库不断扩充,越来越准
```

**这就是"市场是变化的,我们也要灵活变化"的落地。** 载体库是稳定的基础设施(55种载体,偶尔加),元素库是活的(市场反哺,你人工验证)。
