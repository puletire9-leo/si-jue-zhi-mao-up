# M02 · 郑总同行品线跟随法

> 方法卡片归属 L3 前端消费层。它不是品线分析本体，也不是入库自动标签，而是一张可开关的“同行候选商品方法卡”。

---

## 身份

`id: M02` · `状态: active` · `消费页面: 品线选品`

一句话：用 `deng_zong_shop` 最新批次里的郑总同行店铺盘子，筛出一批“同行已经验证过”的候选商品，前端点击方法卡即可展示。

## 何时用

- 想快速看郑总同行当前重点铺在哪些商品 / 大类 / 小类。
- 想在品线页里直接拉出同行盘子的候选商品，优先看已经有人验证过的方向。
- 想判断“这是没人做的机会，还是同行已经扎堆的红海”。

## 输入

- `deng_zong_shop`
- `marketplace`
- 最新 `batch_date`
- `bsr_id`
- `node_id`

## SOP

1. 进入品线选品页。
2. 打开“更多筛选”。
3. 在“业务方法卡”里应用 `M02 郑总同行品线跟随法`。
4. 系统调用方法卡接口，按当前 L1 / L2 节点返回郑总同行候选商品。
5. 退出方法后，商品区回到通用竞品全量视角。

## 判定标准

- 数据源：`deng_zong_shop` 最新 `batch_date`。
- 范围：支持按 `marketplace / bsr_id / node_id / batch_date` 收窄。
- 去重：同一 ASIN 取最新记录，避免重复污染。
- 排序：优先月销量高、BSR 更靠前的商品。

## 产出

- 与 M01 一致的 `MethodCardProductResponse` 商品列表。
- `methodId=M02`、`methodName`、`hitReasons`。
- `ruleSnapshot.batchDate` 标明使用的郑总证据批次。

## 当前系统落地

- 后端接口：`GET /api/v1/method-cards/M02/products?marketplace=UK&bsrId=...&nodeId=...`
- 品线树保持通用容器，不再用 `methodId=M02` 改树排序或打方法命中。
- 前端入口：品线选品页 → 更多筛选 → 业务方法卡 → M02。

## 边界

- 品线选品页是通用容器，不应默认带“郑总”标签。
- M02 只是一个可开关的方法卡片，主产出是候选商品列表。
- `deng_zong_shop` 是 M02 的证据源，不是所有品线分析的默认模型。
