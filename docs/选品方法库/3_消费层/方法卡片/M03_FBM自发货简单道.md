# 🃏 M03 · FBM 自发货简单道

---

## 〔身份〕
`id: method-fbm-simple` · `状态: active` · `精度层级: 单段 90 天(不分账龄段) — FBM 专属通道`

**一句话**:FBM 自发货品不走 M01 的分档 + BSR 逻辑,只用"90 天销量单一门槛"快速过筛,是自发货打法的候选池。

## 〔何时用〕
- ✅ 只想看 FBM(自发货)品,过滤掉 FBA
- ✅ 需要"简单粗暴"的一档筛选,不想被账龄分段和 BSR 代理绕
- ❌ 找主流 FBA 铺量新品 → 走 [[M01_新品榜加速法]](分档 + BSR)
- ❌ 找"小而无人抢 + 有价差"的冷门 → 走 [[M02_价格洼地法]]

## 〔输入〕
八爪鱼新品榜导出(UK / DE / US),同 M01 数据源,但必须含 `fulfillment` 字段(用于隔离 FBM)。
关键字段:上架天数、预估销量、价格、`fulfillment`(必须 = `FBM`)。

> 数据源沿用 `competitor_products_clean`,不新建表。M03 是**同源不同筛**,不是不同数据。

## 〔SOP 步骤〕
1. **fulfillment = 'FBM' 硬门槛** → 2. **上架 < 90 天** → 3. **90 天销量按站点门槛** → 4. 通过的直接进候选,平铺给前端

**跟 M01 的关键差异**:
- 不看 BSR(自发货逻辑,BSR 代理不适用)
- 不分账龄段(90 天单一门槛,不做 30/60/90 分档)
- 不做价格带过滤(FBM 打法价格灵活,用户可后期补)
- 不做重量门槛(FBM 自发货不受 300g 物流成本约束)

## 〔判定标准〕 ← 核心

**硬门槛(必须同时满足):**
- `fulfillment = 'FBM'`(M03 身份定义,非 FBM 一律不出现在候选)
- 上架 < 90 天

**达标逻辑(单段 90 天销量):**

| 国家 | 90 天销量门槛 |
|------|---------------|
| 🇬🇧 英国 | ≥ 5 |
| 🇩🇪 德国 | ≥ 10 |
| 🇺🇸 美国 | ≥ 20 |

> 无价格带、无重量上限、无 BSR 代理 —— **只看 fulfillment=FBM + 上架天数 + 销量**这三条。极简是设计意图。

**↓ 编译成当前接口参数:**
硬门槛走顶层筛选参数:`fulfillment='FBM'`、`listingDaysMax=90`。
达标逻辑走单条 `qualifyRules`:`{listingDays: 90, units: <站点门槛>}`。

> 计划新增独立方法卡接口:`GET /api/v1/method-cards/M03/products`。接口直接消费 `competitor_products_clean`,返回候选商品、`hitReasons` 和 `ruleSnapshot`;前端在全部选品页"筛选方法 / M03 FBM 自发货简单道"中点击展示。

## 〔产出〕
候选清单 + 每个候选的"90 天销量命中"标注 + 一组可一键回灌的 filterRules。

## 〔依据 / 为什么〕 ← 最重的一格
- **为什么和 M01 分卡而不是加个开关**:M01 是"分档 + BSR 代理"的复合逻辑,FBM 完全不适用(BSR 是 FBA 排名系统的产物,自发货基本不进主榜)。加开关会污染 M01 的判定路径 —— 上一版尝试过,失败了。**独立卡片 = 独立心智模型**。
- **为什么单段不分档**:FBM 自发货体量本身小,分 30/60/90 反而误杀早期爬量的品。单段 90 天是对"自发货节奏慢"的让步。
- **为什么门槛比 M01 低那么多**:FBA 主流通道流量大,门槛可以高;FBM 是长尾通道,能过 5/10/20 已经是能盈利的品。数据感来自用户口述业务经验。
- **为什么不设价格带 / 重量**:M01 的价格带是要过滤"打广告不划算"的两端,FBM 打法逻辑不同 —— 自发货可以做贵重小件、可以做超轻件。**不预设约束,让用户在筛选面板自己叠加**。
