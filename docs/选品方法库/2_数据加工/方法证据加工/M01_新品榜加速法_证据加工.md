# M01 · 新品榜加速法 · 证据加工

> 归属：L2 选品证据层。
> 用途：说明 M01 方法卡片背后的数据怎么从干净数据加工出来。L3 方法卡片负责前端怎么展示，本文负责后端/数据侧怎么取数、过滤、打命中原因。

---

## 一句话

从 `competitor_products_clean` 读取去变体污染后的新品榜数据，按 M01 的价格、重量、上架天数、销量分段和 BSR 代理规则筛出候选，再把候选和命中原因暴露给 L3 前端方法卡片。

---

## 所在链路

```text
L1 数据底座层
competitor_products_clean
  ↓
L2 选品证据层
方法证据加工 / M01 新品榜加速法证据
  ↓
L3 前端组合层
方法卡片 / M01 新品榜加速法
  ↓
前端公用筛选页
筛选方法 → M01 → 点击展示候选
```

---

## 输入数据

| 输入 | 口径 |
|------|------|
| 主表 | `competitor_products_clean` |
| 来源 | 新品榜数据，`source` 需能识别新品榜 |
| 站点 | 先支持 `UK` / `DE`，`US` 只做参考雷达 |
| 批次 | 默认最新批次；也允许指定 `month` / `createdWeek` |
| 去重 | 沿用 clean 表的父 ASIN 代表品口径，避免变体污染 |

---

## 硬门槛

硬门槛必须同时满足：

| 字段 | UK | DE |
|------|----|----|
| 价格 | `4.99 <= price <= 17.99` | `5.99 <= price <= 18.99` |
| 重量 | `weight_g < 300` | `weight_g < 300` |
| 上架天数 | `listing_days < 90` | `listing_days < 90` |

---

## 达标逻辑

硬门槛通过后，满足“销量分段”或“BSR 代理”任一即可入选。

### UK

| 命中路径 | 条件 |
|----------|------|
| `SALES_30D_PASS` | `listing_days <= 30 AND units >= 2` |
| `SALES_60D_PASS` | `listing_days <= 60 AND units >= 10` |
| `SALES_90D_PASS` | `listing_days <= 90 AND units >= 30` |
| `BSR_PASS` | `bsr > 0 AND bsr < 20000` |

### DE

| 命中路径 | 条件 |
|----------|------|
| `SALES_30D_PASS` | `listing_days <= 30 AND units >= 4` |
| `SALES_60D_PASS` | `listing_days <= 60 AND units >= 20` |
| `SALES_90D_PASS` | `listing_days <= 90 AND units >= 50` |
| `BSR_PASS` | `bsr > 0 AND bsr < 25000` |

---

## 输出字段

| 字段 | 说明 |
|------|------|
| `methodId` | 固定 `M01` |
| `methodName` | 固定 `新品榜加速法` |
| `asin` / `parentAsin` | 商品标识与去重依据 |
| `title` / `imageUrl` | 前端列表展示 |
| `marketplace` | 站点 |
| `price` / `units` / `bsr` / `listingDays` / `weightG` | 命中判断核心字段 |
| `hitReasons` | 命中路径数组，如 `["SALES_60D_PASS", "BSR_PASS"]` |
| `ruleSnapshot` | 本次使用的 M01 阈值快照 |
| `source` / `month` / `createdWeek` | 数据来源与批次 |

---

## 建议接口

```http
GET /api/v1/method-cards/M01/products
```

建议参数：

| 参数 | 说明 |
|------|------|
| `marketplace` | `UK` / `DE` |
| `month` | 可选，指定数据月份 |
| `createdWeek` | 可选，指定导入周批次 |
| `bsrId` | 可选，限定大类 |
| `nodeId` | 可选，限定小类 |
| `page` / `size` | 分页 |

---

## 和 L3 方法卡片的边界

本文只回答：

- 数据从哪里来
- 怎么筛
- 为什么命中
- 接口返回什么

L3 的 [[../../3_消费层/方法卡片/M01_新品榜加速法]] 负责回答：

- 前端怎么介绍这个方法
- 用户什么时候点它
- 点击后怎么展示候选
- 怎么复盘这个方法是否有效
