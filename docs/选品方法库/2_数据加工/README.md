# L2 · analysis-baseline 数据分析基线层

> 目录名仍是 `2_数据加工`，但更准确的职责名是 **analysis-baseline 数据分析基线层**。
> 它在 L1 干净数据上产出可组合的决策证据：商品基础特征、市场销量基线、错位机会、自有战绩、元素机会、新品分级、店铺画像证据、商品族证据。

---

## 这一层负责什么

把 L1 的干净数据加工成"能被 L3 方法卡片、店铺定位、前端页面组合使用"的证据产物：

1. **商品基础特征** — 上架天数、重量克数、销量 A/B/C/D、类目拆解、链接等
2. **销量证据** — 大类/小类/账龄的销量、价格、BSR 分布
3. **方向证据** — 本土 vs CN 的错位机会、可行动小类方向
4. **真值证据** — 自有战绩库、赢家标签、green/eliminated 回测样本
5. **内容证据** — 标题里的元素+载体候选
6. **店铺画像证据** — 店铺 A/B/C/D、ABC 稳定盘、D 测品池、基线相似
7. **商品族证据** — 同 ASIN / 同父体 / 标题相似 / 多店出现 / 爆款种子验证

`listing_days`、`weight_g`、`sales_tier` 这类字段描述商品本身，供本层证据和 L3 方法卡片复用；它们不直接代表某张方法卡命中。

2026-07-07 追加：店铺画像证据可以反哺单品选品。比如某个爆款种子 ASIN 30 天销量 50+，并且同款/相似款在多家优质画像店铺中出现，那么新出现的相似 ASIN 即使刚上架 2 天、暂时没有销量，也可以被视为“商品族已验证”的候选。这个判断属于 L2 证据加工：把店铺画像、商品族相似、多店出现证据加工成 L3 方法卡可消费的事实。

## 方法卡片归属说明

方法卡片直接对接前端筛货、展示和复盘，语义上属于 [[../3_消费层/README]]。

L2 只负责给方法卡片提供证据产物：

| 证据产物 | 给方法卡片什么 |
|------|--------|
| 商品基础特征 | 上架账龄、重量克数、销量 A/B/C/D/UNKNOWN 分级等可复用字段 |
| 店铺画像证据 | 店铺 ABC 稳定盘、D 测品池、基线相似、方法卡命中摘要 |
| 商品族/标题相似证据 | 同款/相似款、标题核心词、元素载体、跨店出现次数 |
| ①销量基线 | 大类/小类销量参照 |
| ②错位机会 | 小类方向机会 |
| ③自有战绩 | 赢家真值和复盘标签 |
| ④元素机会预览 | 元素/载体候选 |
| M04 新品分级 | 新品 S/A/B/C/D 分层 |
| 方法证据加工 | 某张方法卡片对应的候选集、命中原因、接口口径 |

## analysis-baseline → L3 的契约

L3 任何视图、方法卡片、接口都必须：

1. **只组合 analysis-baseline 证据产物** — 不直接 FROM `competitor_products_clean`
2. **不做新的底层统计** — 想新统计就建到 analysis-baseline
3. **方法卡片是 L3 镜头** — 不要把方法卡片变成"入库时自动打的死标签"
