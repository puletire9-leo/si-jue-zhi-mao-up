## 🔴 H4 最重要发现:真实赢家不在大类头部

用591个真实赢家做假回测(他们赢时的大类BSR分布):

| 大类BSR段 | 赢家数 |
|-----------|--------|
| <5k | **0** ← 一个都没有 |
| 5k-20k | 21 |
| 20k-50k | 89 |
| 50k-150k | **164** |
| >150k | **157** |

**你赢的品,431/591(73%)大类BSR在5万名之后,零个在头部1万。**

★ 这推翻了①线隐含假设"大类BSR越靠前越该做"。真相:
**你不抢大类头部,你在大类中后段做小类里的爆款。** 一个品大类排15万,但在小类(如 Sun Catchers)里是前列。

**实证**:Sun Catchers UK 148个样本,bsr_min=14476、max=266840 — 整个小类没一个进大类前1万,但你在这小类里赢了。

## 三线主从关系重构(从"平等投票"改为"③线指挥")

### ❌ 原模型(已废弃)
①大类销量高 + ②聪明卖家多 + ③像赢家 → 三票平等加权
问题:①②高度共线(都偏大类头部),且大类BSR根本不是你的猎场。

### ✅ 新模型:③线是大脑,①②是手

```
        ③线(tier1真值)= 大脑,定方向
        "我赢过哪些小类型?Sun Catcher/Tote Bag/Figure/Cosmetic Bag..."
                          ↓ 圈定猎场(小类白名单 + 元素载体库)
        ┌─────────────────┴─────────────────┐
        ↓                                   ↓
    ①线(在小类内看销量)              ②线(看小类有没有被CN卷)
    "这个小类的头部能卖多少?           "这小类是本土在做(错位机会)
     候选品在小类里排第几?"             还是CN已扎堆(红海)?"
        └─────────────────┬─────────────────┘
                          ↓
              候选品 = ③圈的类型 ∩ ①小类有量 ∩ ②未被卷
```

**关键变化:①线的基线单位从"大类BSR桶"改为"小类"。** 大类桶定位不了你的机会,小类才行。

## ①线口径再修正(基于H4发现)

H1定的"大类bsr_id分桶"**仍然有用**(给市场全局视角、跨国对比),但**不够定位机会**。要补一层:

| 层级 | 单位 | 用途 |
|------|------|------|
| 大类基线(H1已设计) | marketplace×bsr_id×BSR桶 | 市场全局、跨国对比、卖精校准 |
| **小类基线(H4新增)** | marketplace×小类(node末级) | **真正定位机会**:这小类头部卖多少 |

小类基线只给**③线圈定的、且样本≥30的小类**建(小类逐个毕业)。
小类基线也要用分位数(P50/P75/P90),因为小类内长尾多、均值被拉低(Sun Catchers avg=9,但头部几十单)。要对标的是**小类头部**,不是平均。

## 回测模型(怎么验证"80%成功率")

③线有 is_green(正样本)/ is_eliminated(负样本)标签,这是回测的金标准:

```
回测流程:
1. 取③线全部591赢家 + 标签(green=成功, eliminated=失败)
2. 对每个品,跑新模型三线打分:
   - ③型匹配:它的小类/元素载体在不在"赢家类型库"
   - ①小类位置:它在所属小类的销量分位(P75以上=有量)
   - ②错位度:它所属小类的 heat_signal(GREEN/RED)
3. 看模型高分品 vs 真实green品的重合度
4. 重合度高 → 模型成立;低 → 调权重/阈值
```

⚠️ **诚实**:591样本里green只11+、eliminated 50+,样本偏少,回测只能给**方向性信号**,不能给精确的"80%"。"80%成功率"是目标,不是现在能验证出的数字。**先让回测能跑、能区分green/eliminated,数字以后随数据积累逼近。**

## ①②共线问题的解法

实测:郑总扎堆的大类(outdoors/garden/kitchen)= ①线销量厚的大类。两线在大类层面共线。

**解法:让两线在不同层级工作,消除共线:**
- ①线回答"量"(小类头部能卖多少)
- ②线回答"竞争结构"(这小类是不是本土专属空白)
- 两者在**小类层面**看的是不同维度(销量 vs 卖家构成),不再共线。

## 合成打分(第一版,先定性)

```
候选品 score:
  base = 0
  IF 小类/元素载体 ∈ ③赢家类型库:  base += 40   (③线:你能做)
  IF 候选品在所属小类销量分位 ≥ P75: base += 30   (①线:小类里有量)
  IF 所属小类 heat_signal = GREEN:   base += 30   (②线:错位机会)
  IF 所属小类 heat_signal = RED:     base -= 20   (②线:CN红海扣分)
  IF 退款率 > 20%(同类):            base -= 15   (③线教训:高退款kill)

  score ≥ 70 → 强推荐
  score 40-69 → 观察
  score < 40 → 不推荐
```

权重(40/30/30)是拍的,**回测后用真实green/eliminated校准**。先能跑,再精确。
