## 一句话结论

后端原 `CategoryBaselineService.computeBaseline()` 口径错了。**①线现在的口径是：大类按 `bsr_id × bsr_bucket` 切，小类按 `bsr_id × Amazon leaf` 切，两条线都按 `marketplace × month` 切片**。同名 leaf 在不同大类下永远是独立的两行。

## 锁定的口径规格

### 大类基线 `category_bsr_baseline`

| 项 | 规格 | 理由 |
|----|------|------|
| 切片维度 | **marketplace × bsr_id × bsr_bucket × month** | 跨国对比的最小单元 |
| 品类主键 | **`bsr_id`**(kitchen/fashion/automotive...) | 跨国统一,语言无关 |
| BSR分桶 | `<5k / 5k-20k / 20k-50k / 50k-150k / >150k` | 对齐新品标准量级 |
| 分位 | units 的 **P25 / P50 / P75** | P50中位抗极值;P25/P75给分散度 |
| 最小样本 | 每桶 **n≥30** 才可信 | <30 标记"低可信",不参与推荐 |
| 唯一键 | `(marketplace, bsr_id, bsr_bucket, baseline_month)` | |

### 小类基线 `subcategory_baseline`（H5 收紧）

| 项 | 规格 | 理由 |
|----|------|------|
| 切片维度 | **marketplace × bsr_id × Amazon leaf × month** | 大类 + 末级小类 + 国家 + 月份 四元粒度 |
| Sub_category 来源 | `TRIM(SUBSTRING_INDEX(node_label_path, ':', -1))` 末级 | 不做 alias / canonical 合并 |
| Bsr_id 来源 | `competitor_products.bsr_id` 直接保留 | 同 leaf 在两个 bsr_id 下要分两行 |
| 分位 | units 的 **P50 / P75 / P90** + price P50 | 头部线 P75、爆款线 P90 |
| 最小样本 | **n≥30** | HAVING COUNT(*) >= 30 |
| 唯一键 | **`(marketplace, bsr_id, sub_category, baseline_month)`** | H5 收紧（之前是三列） |

## 计算逻辑（小类基线 SQL，已落地）

```sql
WITH filtered AS (
  SELECT cp.marketplace, cp.bsr_id,
         TRIM(SUBSTRING_INDEX(cp.node_label_path, ':', -1)) AS sub_category,
         cp.units, cp.price
  FROM competitor_products cp
  WHERE cp.month = ?
    AND cp.bsr_id IS NOT NULL AND cp.bsr_id != ''
    AND cp.node_label_path IS NOT NULL
    AND TRIM(SUBSTRING_INDEX(cp.node_label_path, ':', -1)) != ''
    AND LOWER(TRIM(SUBSTRING_INDEX(cp.node_label_path, ':', -1))) != 'null'
    AND cp.units IS NOT NULL
    -- AND cp.marketplace = ?  可选
),
units_ranked AS (
  SELECT marketplace, bsr_id, sub_category, units,
         PERCENT_RANK() OVER (
           PARTITION BY marketplace, bsr_id, sub_category
           ORDER BY units
         ) AS units_pr
  FROM filtered
),
units_agg AS (
  SELECT marketplace, bsr_id, sub_category,
         COUNT(*) AS sample_size,
         MAX(CASE WHEN units_pr <= 0.50 THEN units END) AS p50,
         MAX(CASE WHEN units_pr <= 0.75 THEN units END) AS p75,
         MAX(CASE WHEN units_pr <= 0.90 THEN units END) AS p90
  FROM units_ranked
  GROUP BY marketplace, bsr_id, sub_category
  HAVING COUNT(*) >= 30
)
SELECT marketplace, bsr_id, sub_category, sample_size, p50, p75, p90
FROM units_agg;
```

⚠️ 注意:
1. `MAX(CASE WHEN pr<=0.5...)` 这种取分位法**不能用 GROUP_CONCAT 字符串拼**(H0踩过坑,group_concat_max_len 截断导致中位数算成0)。必须用窗口函数 PERCENT_RANK。
2. 跨表字符串 join 时，geji 环境下 `utf8mb4_0900_ai_ci` / `utf8mb4_unicode_ci` 混用会报错。Mapper SQL 已对所有跨 CTE 的字符串 JOIN 加 `COLLATE utf8mb4_unicode_ci`。
3. **删除了 dominant_bsr CTE**：之前用它给每个 (marketplace, sub_category) 挂一个 bsr_id 标签做 LEFT JOIN，现在 bsr_id 直接进 PARTITION/GROUP BY，分组主键自带，不需要再"挂标签"。

## 计算逻辑(SQL,已验证可跑)

明天可选两种实现:**(A)** 写进 Java Service 用 stream 算分位;**(B)** 直接 SQL `INSERT...SELECT` 灌表(更快,适合"每月刷新"定时任务)。推荐 B,逻辑就是这条已验证的 SQL:

```sql
WITH ranked AS (
  SELECT bsr_id, marketplace, units, price,
    CASE WHEN bsr<5000 THEN 'lt5k' WHEN bsr<20000 THEN '5k20k'
         WHEN bsr<50000 THEN '20k50k' WHEN bsr<150000 THEN '50k150k'
         ELSE 'gt150k' END AS bucket,
    PERCENT_RANK() OVER (
      PARTITION BY bsr_id, marketplace,
        CASE WHEN bsr<5000 THEN 1 WHEN bsr<20000 THEN 2 WHEN bsr<50000 THEN 3
             WHEN bsr<150000 THEN 4 ELSE 5 END
      ORDER BY units
    ) AS pr
  FROM competitor_products
  WHERE month=? AND bsr_id IS NOT NULL AND bsr_id<>'' AND bsr IS NOT NULL AND units IS NOT NULL
)
SELECT marketplace, bsr_id, bucket, COUNT(*) AS n,
  MAX(CASE WHEN pr<=0.25 THEN units END) AS p25,
  MAX(CASE WHEN pr<=0.50 THEN units END) AS p50,
  MAX(CASE WHEN pr<=0.75 THEN units END) AS p75,
  ROUND(AVG(price),2) AS price_avg
FROM ranked GROUP BY marketplace, bsr_id, bucket;
```

⚠️ 注意:`MAX(CASE WHEN pr<=0.5...)` 这种取分位法**不能用 GROUP_CONCAT 字符串拼**(H0踩过坑,group_concat_max_len 截断导致中位数算成0)。必须用窗口函数 PERCENT_RANK。

```sql
  bsr_id VARCHAR(100) DEFAULT NULL COMMENT '大类slug',
  canonical_key VARCHAR(100) DEFAULT NULL COMMENT '保留字段，不再承担 alias 合并',
  sub_category VARCHAR(200) NOT NULL COMMENT '亚马逊末级小类',
  baseline_month VARCHAR(6) NOT NULL COMMENT '基线月份',
  sample_size INT NOT NULL DEFAULT 0 COMMENT '样本数',
  units_p50 INT DEFAULT NULL COMMENT '销量中位数',
  units_p75 INT DEFAULT NULL COMMENT '销量P75(头部线)',
  units_p90 INT DEFAULT NULL COMMENT '销量P90(爆款线)',
  price_p50 DECIMAL(10,2) DEFAULT NULL COMMENT '价格中位数',
  confidence VARCHAR(8) DEFAULT NULL COMMENT '可信度 high/mid/low',
  computed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_slice (marketplace, sub_category, baseline_month),
  KEY idx_lookup (marketplace, bsr_id, baseline_month),
  KEY idx_sub_lookup (marketplace, sub_category, baseline_month),
  KEY idx_canonical_lookup (marketplace, canonical_key, baseline_month)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='亚马逊原生小类销量基线(①线)';
```

计算SQL(同大类基线,分位换P50/P75/P90,分组键改亚马逊末级小类):

```sql
WITH filtered AS (
  SELECT marketplace,
    bsr_id,
    TRIM(SUBSTRING_INDEX(node_label_path,':',-1)) AS sub_cat,
    units,
    price
  FROM competitor_products
  WHERE month=? AND node_label_path IS NOT NULL
    AND TRIM(SUBSTRING_INDEX(node_label_path,':',-1)) != ''
    AND LOWER(TRIM(SUBSTRING_INDEX(node_label_path,':',-1))) != 'null'
    AND units IS NOT NULL
),
ranked AS (
  SELECT marketplace,
    bsr_id,
    sub_cat,
    units,
    price,
    PERCENT_RANK() OVER (PARTITION BY marketplace, sub_cat ORDER BY units) AS pr,
    PERCENT_RANK() OVER (PARTITION BY marketplace, sub_cat ORDER BY price) AS price_pr
  FROM filtered
)
SELECT marketplace, sub_cat, COUNT(*) AS n,
  MAX(CASE WHEN pr<=0.50 THEN units END) AS p50,
  MAX(CASE WHEN pr<=0.75 THEN units END) AS p75,
  MAX(CASE WHEN pr<=0.90 THEN units END) AS p90,
  MAX(CASE WHEN price_pr<=0.50 THEN price END) AS price_p50
FROM ranked GROUP BY marketplace, sub_cat HAVING n>=30;
```

当前口径不再只灌 ③线圈定小类，而是：

- **所有亚马逊原生末级小类**
- 只要在该市场该月份 **样本量 >= 30**
- 就建立一套 ①线小类销量基线
