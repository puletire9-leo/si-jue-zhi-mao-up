# 小类方向层与标题载体层分离说明

> 这份补充是给当前开发纠偏用的。结论先说:
> **小类只看方向,载体只看标题。**

---

## 1. 为什么要分两层

当前选品模型里有两个完全不同的问题:

1. **方向问题**
   - 这个商品属于哪片市场?
   - 它和我们真实战绩覆盖的是不是同一个需求切片?
   - 这层看的是大类/小类/BSR/市场容量

2. **商品结构问题**
   - 这条 listing 具体卖的是什么载体?
   - 这个载体上承载的元素是什么?
   - 这层看的是标题里的锚点词和标题结构

这两个问题不能混成一个字段解决。

---

## 2. 正确口径

### 2.1 小类层

- 大类/小类只用于**方向判断**
- 用途:
  - ①线销量基线: 识别哪片市场卖得动
  - ②线错位机会: 识别本土/中国卖家在哪些方向扎堆
  - ③线辅助画像: 看赢家分布在哪些市场切片
- 这层回答的是:
  - "这个东西在哪片市场里卖"
  - 不是 "这个商品载体是什么"

### 2.2 标题层

- 载体必须从**商品标题**提取
- 规则: 先找载体锚点,再向左提元素
- 这层回答的是:
  - "这是 Suncatcher / Tote Bag / Cosmetic Bag / Mug 里的哪一个"
  - "它前面的核心元素是什么"

### 2.3 载体准入

载体也不是市场里出现什么就全放进来,要分三层:

1. `final_drafts` 载体
   - 代表我们明确能做
2. `product_performance_actual` 载体
   - 代表我们真实赚过钱
3. 市场新载体
   - 可以进候选池
   - 但只有在销量/BSR 达标后,才值得进入下一步人工审核

---

## 3. 对当前实现的直接纠偏

当前 dev 实现里, `subcategory_alias_map` 曾被用来做:

- 赢家小类种子
- 竞品末级小类种子
- 再加上一层 `carrier_hint -> canonical_key`

这会把两件事揉在一起:

- 小类方向对齐
- 载体归一

这是**过渡实现**,不是最终口径。

当前已经修正为:

- **①线小类基线直接按亚马逊原生末级小类统计**
- 不再依赖 `subcategory_alias_map` 才能生成 baseline
- `subcategory_alias_map` 即使保留,也只应该服务别的方向层/分析层

后续应拆成:

### A. 小类方向对齐层

- 只处理:
  - 赢家小类名
  - 竞品末级小类名
  - 两边是不是同一片方向
- 不负责定义具体载体

### B. 标题提取层

- 只处理:
  - 标题里的 carrier
  - 标题里的 element
  - carrier 是否在可做库/已验证库
- 这层才是 ④线元素机会引擎和商品级分析的基础

---

## 4. 这对后续开发意味着什么

下一步代码不要再沿着"从小类推载体"继续加深,而是按下面顺序做:

1. 保留 `subcategory_alias_map`
   - 但把它视为**方向层**
2. 抽出共享的标题解析服务
   - 让 `product_performance_actual` 导入和后续 ④线共用一套 carrier / element 提取逻辑
3. 建立载体来源分层
   - can-do: `final_drafts`
   - proven: `product_performance_actual`
   - candidate: 市场新增且销量/BSR 达标
4. 再决定 ①/②/④ 怎么合成
   - ①/② 看方向
   - ④ 看标题拆解出的元素/载体

---

## 5. 一句话版本

**小类告诉我们去哪里看,标题告诉我们具体卖什么。**
