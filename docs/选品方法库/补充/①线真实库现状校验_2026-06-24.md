### 5.2.1 后续纠偏说明

上面的实测结果只说明:

- 这套过渡实现**在技术上能跑通**
- 不代表它已经是最终业务口径

最新纠偏后,需要明确区分:

- `subcategory_alias_map` = 小类方向对齐层
- 标题解析 = 商品级载体提取层

也就是说:

- `Garden Sun Catchers -> sun_catcher` 这类结果,可以继续作为**当前实现现状**
- 但不能再把它理解成"载体来自小类"
- 真正的 `carrier` 仍应以标题锚点匹配为准

补充:

- **2026-06-24 之后的代码已继续纠偏**
- 现在 `winner` 侧的 canonical 应回到"赢家原始小类 = 方向种子"
- `carrier_hint` 只保留为上下文提示,不再作为自动 canonical 的事实来源

可正常查询的真实例子：

- `UK + Garden Sun Catchers`
  - `canonicalKey = sun_catcher`
  - `subCategory = Sun Catcher`
  - `resolvedBy = CARRIER`
  - `sampleSize = 257`
  - `p50 = 1`
  - `p75 = 3`
  - `p90 = 4`
  - `priceP50 = 9.99`

批量审核工具已用真实库临时数据验证：

- `APPROVE` 可批量把 pending alias 绑定到指定 canonical
- `REJECT` 会把 alias 置为 `REJECTED`
- `sample_count / latest_month` 会被保留
- 之后再次 `bootstrap` 不会把人工 `REJECTED` 冲回 `PENDING`

### 5.3 暴露出的真实缺口

小类接口已经通，alias layer 也已经把第一层错位补上，但**还没有到“可大规模自动信任”**，根因不是 SQL 坏了，而是：

- ③线赢家小类名
- `competitor_products.node_label_path` 末级小类名

两边存在明显**别名/叫法不一致**。

典型例子：

- ③线：`Garden Sun Catchers`
- 竞品库末级：`Glass Art & Suncatchers`

所以这次实现验证了文档里原本就记过的那个缺口：

- **确实需要单独做“小类名别名表/对齐层”**
- 而且这层不能只靠 runtime fuzzy match，必须有**可回看、可人工审核、可复用给②线**的映射表

当前状态可以定义为：

- **大类基线：可用**
- **小类基线：机制已通，alias layer 已落地，但当前这版仍带过渡性的 carrier canonical 痕迹，后续要回到“方向层”定位**
- **下一阶段瓶颈：1121 条 pending competitor alias 的人工审核，以及 191 条 pending winner alias 的 carrier 补齐**
