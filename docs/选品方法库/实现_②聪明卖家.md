## 一句话本质

②线之前"卡壳"的真因:`smart_density` 方向想反了。原设计"聪明卖家扎堆=机会",但 `deng_zong_shop` 是29家**中国同行**,他们扎堆=时间差关闭=红海。

**正确信号 = 错位:本土优质卖家在做(验证了需求)+ 中国卖家还没发现(你还有时间差)。**

---

## 三层卖家模型(必须分三层,不能揉成一个密度)

```
某小类里的卖家 → ┌ 郑总系(29家CN同行,seller_id JOIN deng_zong_shop)
                ├ 其他CN(seller_nation=CN/HK,但非郑总系)
                └ 非CN优质(seller_nation=US/DE/GB/PL...本土卖家)
```

**为什么三层**:实测发现"郑总系=0"不够。`Squeeze Toys` 郑总没进,但其他CN已83家 → 是CN红海不是机会。真金是三层都稀疏、唯独本土在闷声赚的小类。

## 量化公式(已验证,2026-06-23)

### dislocation_score(错位分,0~1)

```
对每个 marketplace × sub_category(小类,node_label_path末级):
  total         = dengzong + other_cn + non_cn   (排除null_nation)
  non_cn_share  = non_cn / MAX(total, 1)
  
  dislocation_score = non_cn_share × LN(avg_units + 1) / LN(MAX(avg_units_overall) + 1)
    — 前半段(non_cn_share):本土密度,越高越"错位"
    — 后半段(LN销量):有肉才是机会,对数防止300单和3单差100倍线性拉爆
    — 分母归一化到0~1
```

### heat_signal

| 条件 | 信号 | 含义 |
|------|------|------|
| total_sellers < 3 | **COLD** | 没人气,需求未验证 |
| non_cn_share > 0.30 AND dz_share = 0 | **GREEN** | ⭐错位机会 |
| dz_share > 0.20 | **RED** | 郑总系扎堆,红海躲开 |
| dz_share 0.01~0.20 | **YELLOW** | 有郑总但不多,观察 |
| dz_share > 0 AND non_cn_share < 0.15 | **RED** | CN专供,本土没空间 |
| 其他 | **COLD** | 不够明确 |

### 关键常量(初始值,回测后调)

| 常量 | 值 | 含义 |
|------|-----|------|
| GREEN_NON_CN_MIN | 0.30 | 非CN占比>30%才算"本土在做" |
| RED_DZ_MAX | 0.20 | 郑总占比>20%就是红海 |
| YELLOW_DZ_HIGH | 0.20 | 郑总占比上限 |
| YELLOW_DZ_LOW | 0.01 | 郑总占比下限 |
| COLD_MIN_SELLERS | 3 | 总卖家<3→太冷 |
| null_nation | **排除** | 7万行无国籍,不作任何一方统计(已知偏差) |

**为什么用占比不用绝对数**:UK outdoors 大盘500个品、某小类可能只有20个品。绝对卖家数在不同小类间不可比,占比才是"卷不卷"的真正信号。

## ⚠️ 错位机会 ≠ 你能做的机会(必须过③线筛子)

实测金子 Soils/Ants/Moths 是**功能性/难做品**(液体、化学、重货),不符合你"轻小+非标+元素载体"打法。

**所以②线必须和③线联动:**
```
②线错位清单(本土在做、CN没发现)
        ∩  (交集)
③线产品能力筛子(你真实赢过的小类型:Suncatcher/Tote Bag/Figure/Cap...轻小非标)
        ↓
= 你能做的错位机会(真正可行动的②线推荐)
```

单独的②线错位清单只是"市场空白",叠加③线才变成"你的空白"。

## 已验证的技术事实(踩坑记录)

- **匹配率86%**:29家郑总卖家,25家能用 `seller_id` 在 competitor_products 匹配上。
- ⚠️ **collation坑(必记)**:`competitor_products.seller_id`=utf8mb4_0900_ai_ci,`deng_zong_shop.seller_id`=utf8mb4_unicode_ci。直接JOIN报 "Illegal mix of collations"。**所有跨表JOIN必须 `c.seller_id = d.seller_id COLLATE utf8mb4_unicode_ci`**。
- 小类粒度:用 `SUBSTRING_INDEX(node_label_path,':',-1)` 取末级当小类。
- seller_nation 取值:CN/HK(中国)、US/DE/GB/PL/VN/NL/IT/IN(本土及其他)、NULL(7万行无国籍,占比大,排除)。
- **占比计算**: `total = dz+other_cn+non_cn`,**不含null_nation**(否则占比被稀释失真)。

## 建表 `category_dislocation`

```sql
CREATE TABLE category_dislocation (
  id BIGINT NOT NULL AUTO_INCREMENT,
  marketplace VARCHAR(10) NOT NULL,
  bsr_id VARCHAR(100) DEFAULT NULL COMMENT '大类slug',
  sub_category VARCHAR(200) NOT NULL COMMENT '小类(node_label_path末级)',
  baseline_month VARCHAR(6) NOT NULL,
  dengzong_count INT DEFAULT 0 COMMENT '郑总系卖家数',
  other_cn_count INT DEFAULT 0 COMMENT '其他CN卖家数',
  non_cn_count INT DEFAULT 0 COMMENT '非CN本土卖家数',
  total_sellers INT DEFAULT 0,
  product_count INT DEFAULT 0,
  avg_units DECIMAL(10,2) DEFAULT NULL,
  dz_share DECIMAL(8,4) DEFAULT NULL COMMENT '郑总占比',
  non_cn_share DECIMAL(8,4) DEFAULT NULL COMMENT '本土占比',
  dislocation_score DECIMAL(8,4) DEFAULT NULL COMMENT '错位分(0~1)',
  heat_signal VARCHAR(8) DEFAULT NULL COMMENT 'RED/GREEN/YELLOW/COLD',
  computed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_slice (marketplace, sub_category, baseline_month),
  KEY idx_signal (marketplace, heat_signal)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='小类错位机会(②线)';
```

DDL 更新(vs 初版):新增 `dz_share/non_cn_share` 两列存占比,`avg_units` 改为 DECIMAL。
