# Docker 生产部署流程

## 日常更新（仅变更服务）

### 只改 Java

```powershell
# 1. 编译 JAR（在 java-backend 目录）
docker run --rm -v "$($pwd):/app" -v "$env:TEMP\m2:/root/.m2" -w /app `
    maven:3.9-eclipse-temurin-21 mvn package -DskipTests -T 4

# 2. 重命名为 app.jar（Dockerfile.prod 要求）
Copy-Item sjzm-product/target/sjzm-product-1.0.0-SNAPSHOT.jar sjzm-product/target/app.jar -Force
Copy-Item sjzm-gateway/target/sjzm-gateway-1.0.0-SNAPSHOT.jar sjzm-gateway/target/app.jar -Force
Copy-Item sjzm-user/target/sjzm-user-1.0.0-SNAPSHOT.jar sjzm-user/target/app.jar -Force

# 3. 重建镜像 + 重启（回到项目根目录）
cd ..
docker compose -f docker-compose.prod-simple.yml build --no-cache java-product gateway java-user
docker compose -f docker-compose.prod-simple.yml up -d java-product gateway java-user
```

> 改到哪个模块就 rebuild 哪个，不需要全部重建。

### 只改前端

```powershell
# 1. 构建（跳过压缩避免 OOM）
cd frontend
npx vite build --mode production --minify false

# 2. 重建镜像 + 重启
cd ..
docker compose -f docker-compose.prod-simple.yml build --no-cache frontend
docker compose -f docker-compose.prod-simple.yml up -d frontend
```

### 只改 Python

```powershell
docker compose -f docker-compose.prod-simple.yml build --no-cache backend celery-download
docker compose -f docker-compose.prod-simple.yml up -d backend celery-download
```

### 多服务同时改

```powershell
docker compose -f docker-compose.prod-simple.yml build --no-cache java-product gateway frontend
docker compose -f docker-compose.prod-simple.yml up -d java-product gateway frontend
```

## 首次部署

### 1. Python 基础镜像（仅首次 / 依赖变更）

```powershell
docker build -t sjzm-python-base -f backend/Dockerfile.base backend
```

### 2. Java JAR

```powershell
cd java-backend
docker run --rm -v "$($pwd):/app" -v "$env:TEMP\m2:/root/.m2" -w /app `
    maven:3.9-eclipse-temurin-21 mvn package -DskipTests -T 4
Copy-Item sjzm-product/target/sjzm-product-1.0.0-SNAPSHOT.jar sjzm-product/target/app.jar -Force
Copy-Item sjzm-gateway/target/sjzm-gateway-1.0.0-SNAPSHOT.jar sjzm-gateway/target/app.jar -Force
Copy-Item sjzm-user/target/sjzm-user-1.0.0-SNAPSHOT.jar sjzm-user/target/app.jar -Force
```

### 3. 前端 dist

```powershell
cd ..\frontend
npx vite build --mode production --minify false
```

### 4. 构建所有镜像

```powershell
cd ..
docker compose -f docker-compose.prod-simple.yml build
```

### 5. 启动

```powershell
docker compose -f docker-compose.prod-simple.yml -p sijuelishi-prod up -d
```

### 6. 验证

```powershell
docker ps --format "table {{.Names}}\t{{.Status}}"
```

## 经验规则

### 铁律

| # | 规则 | 原因 |
|---|------|------|
| 1 | **禁止 `mvn clean`** | 会删除 `target/app.jar`，导致 Dockerfile COPY 失败 |
| 2 | **禁止 `docker compose down`** | 会销毁容器和数据卷，生产只用 restart/start/stop |
| 3 | **前端构建必须在宿主机** | Docker Desktop 内存不够，Vite 构建会 OOM 崩溃 |
| 4 | **COS_BUCKET 不用宿主机 .env** | 宿主机 .env 带 `-dev` 后缀，生产 bucket 是 `sijuelishi-1328246743` |
| 5 | **push 前确认在 master** | `git branch --show-current` 先看一眼 |

### Java 构建

- `mvn package` 不用 `mvn install`，后者写 `~/.m2` 但生产不需要
- `-T 4` 4 线程并行编译，快一半时间
- Maven 容器用完就删（`--rm`），不占空间
- JAR 名带版本号（`sjzm-product-1.0.0-SNAPSHOT.jar`），Dockerfile 要求 `app.jar`，所以 Copy-Item 改名

### 前端构建

- 正常 `npm run build` 会 OOM → 用 `--minify false`
- 跳过压缩：JS 不混淆但功能一样，内网管理后台影响可忽略
- 输出到 `../static/vue-dist/`，Dockerfile 从项目根 COPY

### 镜像重建

- `--no-cache` 确保新 JAR/dist 被 COPY 进去（Docker 可能缓存旧层）
- 共用 `Dockerfile.prod` 的 Java 服务（user/product/gateway）可以一起 build，只产生一个 `prod-java` 镜像
- 改 Python 依赖必须重建设 `sjzm-python-base` 基础镜像

## 常用命令

```powershell
# 查看所有容器状态
docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"

# 查看容器日志（最近 50 行）
docker logs prod-gateway --tail 50

# 查看日志（带时间过滤）
docker logs prod-backend --since 5m

# 搜索日志中的错误
docker logs prod-java-product --tail 100 2>&1 | Select-String "ERROR|Exception"

# 重启单个容器
docker compose -f docker-compose.prod-simple.yml restart gateway

# 停止所有容器
docker compose -f docker-compose.prod-simple.yml stop

# 启动所有容器
docker compose -f docker-compose.prod-simple.yml start

# 查看镜像列表
docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}\t{{.CreatedAt}}"

# 清理构建缓存
docker builder prune -f
```
