## 这份草案解决什么问题

现有文档已经不足以回答“某个前端请求现在到底打到哪个后端”。

当前仓库同时存在：

1. 文档路由表
2. Vite 开发代理规则
3. Java Controller 实现
4. Python FastAPI Router 实现
5. Selection Agent 独立服务

这 5 份信息并不完全一致。本草案只描述“当前代码事实”，不描述理想架构。

## 已确认的不对齐点

下面这些问题不是“文档描述不准”，而是“前端调用和后端实现当前就不完全一致”。

### A. 前端存在调用，但当前未见后端对应实现

| 前端路径 | 前端文件 | 当前情况 |
|---|---|---|
| `/api/v1/logs` | `logs.ts` | Python `logs.py` 未见总列表入口 |
| `/api/v1/logs/{id}` | `logs.ts` | Python `logs.py` 未见该详情入口 |
| `/api/v1/logs/export` | `logs.ts` | Python `logs.py` 未见该导出入口 |
| `/api/v1/material-library/batch-update` | `materialLibrary.ts` | Python `material_library.py` 未见该路由 |
| `/api/v1/carrier-library/batch-update` | `carrierLibrary.ts` | Python `carrier_library.py` 未见该路由 |

### B. 前端路径和后端路径命名不一致

| 前端路径 | 当前后端实现 | 问题 |
|---|---|---|
| `/api/v1/images/search-similar` | `/api/v1/images/search-by-image` | 同一功能两套命名 |
| `/api/v1/final-drafts/download-zip` | Python 有 `/download-zip`，另有 `/download-zip-file` | 需要统一下载入口语义 |

### C. 前端自己存在双套语义

| 领域 | 现状 | 风险 |
|---|---|---|
| 定稿 API | `finalDraft.ts` 偏 `sku/identifier`，`finalDrafts.ts` 偏 `id` | 调用方容易混用，回收站恢复/详情接口尤其危险 |
| 文件链接 API | `fileLink.ts` 与 `resourceCollection.ts` 均在封装 `file-links` | 容易出现重复演化 |
| 选品/评分 | `selection.ts` 同文件内同时调用 Python `/selection/*` 与 Java `/scoring/*` | 文件归属看起来单一，实际是跨后端文件 |
| 品线 API | `product-line.ts` 既打 Java，又打 Selection Agent | 没有显式注释时很难判断归属 |

## 当前规范执行面的主要问题

### 1. 文档事实源不唯一

当前至少有 4 份“看起来像事实源”的材料：

1. `docs/api/README.md`
2. `frontend/AGENTS.md`
3. `docs/development/standards.md`
4. `frontend/vite.config.js`

其中真正决定开发态请求去向的是 `frontend/vite.config.js`，但其他文档并没有稳定跟它同步。

### 2. 一个前端 API 文件里混多个后端

当前最典型的是：

- `selection.ts`
- `systemConfig.ts`
- `product-line.ts`

这类文件如果不加“归属注释”和“迁移状态标记”，后续维护很容易误判。

### 3. 路由迁移缺少台账

素材库、载体库、选品、定稿都处在“Python 实现仍在、Java 接管部分能力、前端路径未完全切换”的中间态。

目前缺少一份统一的迁移台账来回答：

- 哪些接口仍由 Python 提供
- 哪些接口已切到 Java
- 哪些只是代理改了，前端封装还没改
- 哪些旧路径还在兼容期

### 4. 自动化规则没有完全接上

当前仓库有前端 ESLint、Prettier、Vitest、`vue-tsc`，但规范守门还不完整：

- ESLint 版本是 9.x，但仓库主要配置还是 `.eslintrc.cjs`
- TypeScript 配置目前较宽松，`strict`、`noImplicitAny` 等未收紧
- CI 里没有形成“前端 lint + Java 检查 + Python lint/test”的统一入口

## 建议后续新增的最小规则

1. 新增前端 API 前，先确定它走 `Java`、`Python`、还是 `Selection Agent`。
2. 只有当 `vite.config.js`、前端封装、后端实现三者一致时，接口才算“完成接入”。
3. 迁移中的接口必须在代码注释或文档里标记“当前拥有者”和“目标拥有者”。
4. 任何代理特例路径都必须在对应后端里存在真实实现，禁止只配代理不补接口。
