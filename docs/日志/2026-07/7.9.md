## 店铺三维画像模型定稿

在销量分级加入上架时间后，继续讨论确认：店铺画像不能停留在单维 A/B/C/D，也不应该只做二维“销量 × 时间”。正式模型升级为三维：

```text
销量层：A / B / C / D / UNKNOWN
时间层：新品 / 成长期 / 成熟品 / 老品 / 未知
注意与倾向层：好品倾向 / 普通 / 需复核 / 强注意 / 未知
```

三维分别回答：

- 销量层：卖得动吗？
- 时间层：是最近卖动的吗？
- 注意与倾向层：我们能不能学习复制？

关键口径：

- A/B/C/D 继续作为销量层保留，不再单独代表店铺好坏。
- 上架时间用于区分“新 A / 老 A”“新 D / 老 D”“新品 B/C / 老长尾 B/C”。
- 注意与倾向层不是“违禁/拒绝”判断，只是分析、筛选和前端解释标签。
- `ATTENTION_STRONG` 表示强注意，需要人工重点看；不代表系统拒绝。
- `GOOD_TENDENCY` 表示接近轻小、主题化、可组合、可定制的验证好品线。

三维组合解释：

- A + 新品 + 好品倾向：最近打出的强爆品，代表当前选品能力。
- A + 老品 + 好品倾向：历史利润锚点，可学习类目样貌，但不是最新机会。
- B/C + 新品 + 好品倾向：最值得挖的起量方向，可能比老 A 更重要。
- D + 新品 + 好品倾向：正常测品池，适合观察后续转化。
- A/B/C + 新品 + 强注意：有市场信号，但涉及合规、责任、体积或履约注意，需要人工判断。
- D + 老品 + 普通/强注意：低价值沉淀，通常不是优先学习对象。

## 时间层桶口径冲突拍板

发现一处必须先统一的口径冲突：文档里的 `ageBucket` 是互斥时间层，但现有 `insight` SQL 里的 `new30Count / new90Count / new180Count / old180Count` 是累计窗口。

最终拍板：

- 三维画像时间层使用互斥 `ageBucket`：
  - `NEW <= 90`
  - `GROWING = 91-180`
  - `MATURE = 181-365`
  - `OLD > 365`
  - `UNKNOWN = listing_days 为空`
- 三维矩阵、店铺类型、商品筛选都必须使用互斥 `ageBucket`。
- `new30Count / new90Count / new180Count / old180Count` 保留为运营观察窗口和兼容字段，不能相加，也不能用于三维矩阵。
- `old180Count` 只是 180 天以上沉淀窗口，包含成熟品和老品，不能叫“老品数”。

## 领星广告指标口径沉淀（2026-07-09）

新增说明文件：

```text
产品数据/领星数据api/领星广告指标与利润判断说明_2026-07-09.md
```

核心口径：

- `ACOS = 广告花费 / 广告销售额`，用于判断广告订单本身投放效率。
- `TACOS = 广告花费 / 总销售额`，用于判断广告费吃掉整体 SKU 生意多少。
- `ACOAS = 广告花费 / 净销售额`，用于更保守地判断广告费压力。
- 如果基础利润率约 20%，利润风险优先看 `ACOAS > 20%`；没有净销售额时用 `TACOS > 20%` 替代。
- `ACOS` 不用于直接判断 SKU 整体是否赚钱，只用于广告投放效率。

## 精铺备货量口径修正（2026-07-09）

复盘“备首批备货数量与出单率关系”模型时确认一条硬规则：首批备货数量 Q1 必须是精确字段，不能用产品表现库存快照倒推。

当前领星产品表现数据可以支持：

- `volume`：出单量/销量。
- `afn_fulfillable_quantity`：FBA 可售库存快照，用于判断当周是否在售。
- `available_inventory.available_inventory`：可用库存总计快照。
- `stock_up_num`、`reserved_customerorders`、`reserved_fc_processing`、`reserved_fc_transfers`：在途/预留/调仓状态快照。

当前不能支持：

- 精确首批备货数量 Q1。
- 精确第二批备货数量 Q2。
- 按批次区分“这一批备了多少、何时入仓、何时卖完”。

原因：这些字段是查询时点/时间窗返回的库存状态，已经被销量、预留、调仓、补货、入库共同影响。5 月数据中 `afn_fulfillable_quantity` 最大值超过 300，而精铺首批通常不可能超过 50，进一步证明它不是 Q1。

下一步如要严肃计算备货量与出单率关系，必须找到或新增领星采购单、备货单、入仓单、shipment 或仓库库存流水数据源。拿到精确 Q1/Q2 前，只能用现有周/月表做在售、出单、断货、广告、利润表现诊断，不能输出 Q1 盈亏模型结论。
