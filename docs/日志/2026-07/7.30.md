## ⑤ listing 覆盖同步（新增）

### 需求
统一表 `listing_open_date`（真实上架日）此前全空——每周流程只到统一表，没拉 listing。补一步：用刚重建的统一表目标 ASIN 去拉 listing，**覆盖式**（要最新数据）。

### 取数方式（两次纠偏后定稿）
接口 `/erp/sc/data/mws/listing` 是 sid 维度、sid 必填。

- **先想按 sid 循环**：18 家逐个拉——被否，请求数几十次。
- **再对照文档**（`产品数据/领星数据api/查询亚马逊Listing.md`）：sid 支持逗号分隔多店一次查（示例 `"sid":"1,16"`）。改成 **18 家 sid 合并成一个逗号串全局分页**（实测 17 页），请求数 = 总行数/1000。
- `search_field=asin` 不用：`search_value` 上限仅 10 个，6994 ASIN 要 ~700 批，最差。
- **不传任何时间参数** → 拉「所有时间」的当前全量 listing 快照；每周 truncate 后重拉最新。

目标店铺 sid 由 `LingxingListingMapper.selectTargetSids()` 在周表与统一表**刚重建之后**实时算：`周表 sid+asin ∩ 统一表目标 ASIN` 去重。新增店铺打了目标标签自动纳入，非固定清单（实测某周 18 家，仅当次观测值）。

### 踩坑：唯一键大小写陷阱（3 次构建才定位）
一次性落库反复报 `Duplicate entry '13549-YBUK-CeramicPendant-12p-2560259-TR' for key uk_sid_seller_sku`。

- 先加 `HashSet` 去重 seller_sku → 仍报错。
- 改 `Map<sid+seller_sku>` 去重 + 一次性 saveBatch → 仍报错，且去重后累计 7607 > 目标预期。
- 查库发现真凶：库里存的是 `...12P...`（大写），崩溃插入的是 `...12p...`（小写）。**领星同店返回仅大小写不同的 seller_sku**，MySQL 唯一键 `utf8mb4_general_ci`（大小写/尾空格不敏感）视为同一键，而 Java Map 精确区分 → 两条都保留 → 落库撞唯一键。
- 修复：Map 去重 key 用 `seller_sku.trim().toLowerCase(Locale.ROOT)` 归一化对齐 collation，`putIfAbsent` 保留先出现的。

### 落库方式
Map 收集全部页去重后**一次性 saveBatch**（truncate 后空表 + Map 已去重 = 纯 INSERT 不撞键），避免跨多次 saveBatch 调用的 batch executor 语句累积问题。

## ⑥ 回填 open_date（新增）
`LingxingListingMapper.backfillUnifiedOpenDate()`：listing 落库后单独一条精准 UPDATE，按 asin 取 `MIN(open_date)` 回填统一表 `listing_open_date`，只更新这一列，不重算整表（省 30s）。
