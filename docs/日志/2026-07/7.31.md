## 二、踩坑记录（血泪）

### 坑1：TACOS 计算口径
TACOS = SUM(广告费 spend) / SUM(销售额 amount)，**近3月加总再除**，不是逐周算再平均。按 ASIN 聚合。

### 坑2：INSERT/SELECT 列顺序错位
XML 的 SELECT 把 `tacos` 放到了 `volume/profit` 前面，与 INSERT 列顺序不匹配 → tacos 列写进了 actual_price 的值（15.92 当成 TACOS）。修复：SELECT 顺序对齐 INSERT。

### 坑3：Docker 镜像不更新（最大的坑，追了 1 小时）
改完 XML，`docker compose build` + `docker restart` 后，jar 里仍是**旧版 XML**。逐层排查：
- source MD5 = target/classes MD5 = 正确的新版 → **Maven 编译没问题**
- 容器镜像 ID ≠ 最新镜像 ID（build 出的新镜像 17:33，容器还在用更早的）
- **根因：`docker restart` 只是重启旧容器，用的是旧镜像。build 后必须 `docker compose up -d` 重建容器才能挂载新镜像。**
- 之前误用 `--no-cache` + `builder prune` 都没用，因为问题不在 build 而在容器没换镜像。

### 坑4：实际利润率算错（口径用错表）
初版用 `lingxing_profit_asin`（财务表）算利润率 → 预估27%对实际2.7%，差10倍。
查证：某 ASIN 财务表只有 15.99，而周表 gross_profit 有 189.74。财务表口径偏窄不完整。
修复：改用**周表 gross_profit**，实际利润率 = SUM(周表gross_profit)/SUM(amount)。预估27%对实际32%，量级一致。

### 坑5：dev_profit_rate 未 ×100
库里存小数（0.27），Excel 里直接显示 0.27 而非 27%。修复：导出时 ×100。

### 坑6：亚马逊 FBA 费大面积空（7月表 244/423 空）
`lingxing_listing_fba_fee` 只有 309 行——之前只为3月对比的307个msku拉过getPrices。
7月新表 423 个 ASIN 大部分没拉过 → 亚马逊费空。
修复：新增按月补拉端点（下），拉 444 个 sid+msku，7月覆盖 **423/423 = 100%**。
