# 8.5 工作日志

## 精铺·新品榜初筛规则改造：已采过新品放行重取 + 取消价格/评论筛选

用户诉求演进了三版，最终口径：**已被采过（在 skip_asins）的 ASIN，只要主表当前上架 < 30 天就放行，重新走卖家精灵获取；不看销量；初筛不再做价格/评论筛选。**

### 演进过程（每版都线上实测）
1. **v1**：上架<30天且无销量→放行（AND 无销量）。
2. **v2**：阈值 30→60。
3. **v3（最终）**：阈值改回 **30 天**，**销量条件去掉**，只看上架时间。且**取消初筛的价格/评论筛选**（全部留给卖家精灵后的 MODE1/MODE2 精筛）。

> 取代了之前那套「API已请求<90天 + 系统导入超1月」时间闸——旧的 BlacklistSplit/created_at/导入超一月逻辑整个删除。

### 关键实现
| 文件 | 改动 |
|------|------|
| `CompetitorProductMapper.java/.xml` | 新增 `selectYoungAsinsInList(marketplace, asins, maxListingDays)`：`GROUP BY asin HAVING MIN(listing_days) < #{maxListingDays}`（只看上架天数，用主表实时值） |
| `AsinImportService.java` | 常量 `NEW_PRODUCT_REFETCH_MAX_LISTING_DAYS=30`。`filterRows` 签名改 `(rows, blockedAsins, refetchAsins, mainTableAsins, marketplace)`，`blockedAsins = skipAsins - refetchAsins`。**删除价格/评论筛选整段**（PRICE_FAIL/REVIEW_FAIL 桶保留但恒 0）。判定顺序：ASIN格式→文件内去重→已采过黑名单(非重取候选)→新品重取放行→主表已有(SKIP_MAIN)→PASS |
| `AsinImportStreamingTest.java` | 场景改：young→PASS、非young→SKIP_BLACKLIST、价格/评论不再淘汰全 PASS |

### 防无限重取
上架天数取**主表实时值**（每次采集刷新），非 skip_asins 冻结快照。满 30 天自动移出候选、天然收敛。无时间闸，每次八爪鱼重爬都重新判定。

## 八爪鱼自动采集：导入任务 暂停 / 继续 / 重新获取 + 修「完成」恒为 0

用户报：八爪鱼导入中断不能续、不能暂停、不能重新获取；而且「完成」一直是 0。**前几次我只在错的地方（配置抽屉映射行）找落点、按钮编辑没落地、前端也没重构建 → 用户看不到任何变化。** 这次彻底梳理机制后落到正确位置。

### 诊断（线上数据 + 代码确认）
- `task_status` 分布：READY 64 / ERROR 1，零 DONE/RUNNING/PAUSED。
- **完成恒为 0** = 指标 bug：导入初筛终态是 `READY`（待人工请求卖家精灵），本链路从不写 `DONE`；overview 的 doneCount 只数 DONE。
- **暂停/继续/重新获取按钮根本不存在**，且导入(drain)阶段 `cancelled=null` 没接协作取消。
- 三个采集入口（导入DB/一键全导/启动云端）**全汇聚到同一条** `collectAndScreen → fetchBatchDataStreaming`（offset 整页分页）路径，每次生成一行 AsinImportTask。→ 操作落点是**历史任务表每一行（按 taskId）**，不是配置抽屉映射行。

### Part A — 修完成语义
`BazhuayuController.overview` 把 `READY` 计入 weekDoneCount/lifetimeDoneCount（READY+DONE）。仅改聚合，不动数据。实测本周完成 0→16。

### Part B — 暂停/继续/重新获取（榜单初筛 batch 路径）
| 文件 | 改动 |
|------|------|
| `BazhuayuImportControlService`（新） | 进程内 `ConcurrentHashMap<taskId, PAUSE>` 协作信号，仿 runStateService |
| `asin_import_tasks` + Entity | 加可空列 `resume_offset`（断点：已处理云端原始行 offset）。迁移 `sql/add_asin_import_resume_offset.sql`，已应用生产库 |
| `BazhuayuClient.fetchBatchDataStreaming` | 重载加 `startOffset/alreadyProcessed/cancelled`；每翻页前查暂停信号，停在整页边界；暂停时跳过"不完整批次"完整性校验 |
| `AsinImportService` | `pauseStreamingTask`(落 ctx计数+nextOffset,置 PAUSED)、`beginResumeStreamingTask`(PAUSED→RUNNING,已存计数 seed 回 ctx) |
| `BazhuayuScheduledService` | `collectAndScreen` 加 seedCtx/startOffset 续跑分支 + 暂停收口；新增 `pauseImportTask/resumeImportTask/refetchImportTask` |
| `BazhuayuController` | 新增 `POST /import-task/{id}/{pause,resume,refetch}` |
| `bazhuayu-auto/index.vue` + `bazhuayu.ts` | 操作列按状态加按钮：RUNNING/DRAINING→暂停；PAUSED/INTERRUPTED/ERROR→继续；READY/DONE/PAUSED/INTERRUPTED/ERROR→重新获取。已关联卖家精灵的不显示 |

### 断点能续的数学保证
`fetchBatchDataStreaming` 整页不截断（只有收口末页才截断），所以 `下一offset = startOffset + 本轮已处理行数` 精确无漂移。已导行 offset 跳过不重拉、alreadyProcessed 参与 targetRows 判定不重复写明细、raw/skip 唯一键幂等。

### 边界
- 只覆盖**榜单初筛(initialFilter=true)的 batch 路径**（用户实际用的导入DB/一键全导）。精品直入(premium)路径的续跑/重取挡掉（提示不支持），写另一套表、断点语义不同，需单独设计。
- 「启动云端」一条龙的运行态仍挂旧 `runStateService` 6 槽位 + `stopCloudCollect`（停的是云端采集本身），与导入暂停是两套语义，未动。

### 线上实测（全链路真跑）
- refetch 294 → 删旧、新建 300 RUNNING 重拉 US 批次(243k) ✅
- 300 跑到 total=6185 时 pause → **PAUSED + resume_offset=7000**（7页整页断点）✅
- resume → startOffset=7000 续跑，total 6185→16547 **累加不重来** ✅
- 守卫：对 READY 点暂停/继续 → 清晰 400（`IllegalStateException` 被全局处理器吞成 500，改用 `IllegalArgumentException` 让消息透出）✅
- 前端按钮 Playwright 实测渲染正确、本周完成显示 16 ✅

### 部署

## 八爪鱼控制台：通过 / 未通过原因拆细（含义明确化）

用户反馈原来的「未通过原因」只有 `重复` 和 `已采过/黑名单` 两个模糊标签，尤其"已采过/黑名单"把两种完全不同的情况混一坨；顺带把「通过」也拆开（新品重取会重复烧卖家精灵 API，值得单独盯）。

### 未通过原因 → 4 类明确标签
- 价格不符 / 评论超标 / 文件内重复
- **主表已有**（SKIP_MAIN：competitor_products 已入库，去重）
- **已采过淘汰**（SKIP_BLACKLIST：skip_asins 命中且非新品重取候选，如上架≥30天）

> 后端 ctx 本来就分 `skipMain`/`skipBlacklist`，但 `finishStreamingTask` 写库时 `skip_count = skipMain + skipBlacklist` 合并成一列 → 前端只能显示一个模糊标签。这次分列持久化。

### 通过原因 → 新增列，拆 2 类
- **新品重取**（`_passKind=REFETCH`，蓝色芯片提示会重复消耗 API）：已采过但主表<30天重新放行
- **全新通过**（`_passKind=NEW`，绿色）：从没见过的 ASIN

### 实现（分列持久化，全落库点覆盖）
| 文件 | 改动 |
|------|------|
| `AsinImportTask` + 迁移 | 加 4 列 `skip_main_count`/`skip_blacklist_count`/`pass_refetch_count`/`pass_new_count`（`sql/add_asin_import_skip_split_counts.sql` + `add_asin_import_pass_split_counts.sql`，已应用生产库） |
| `AsinImportService` | `filterRows` 给每个 PASS 行打 `_passKind`(REFETCH/NEW)；ctx 加 `passRefetch`/`passNew` 计数；**所有落库点**（finish/fail/pause/flush + 文件路径 filterRowsAndCreateTask）+ resume seed 分列读写。flushProgress 也写分列，RUNNING 中实时可见 |
| `BazhuayuController.taskToMap` | 暴露 4 个拆分字段（旧数据为 null，前端回退） |
| `bazhuayu.ts` + `index.vue` | 类型加 4 字段；`failureBreakdown` 拆主表已有/已采过淘汰；新增 `passBreakdown`（新品重取/全新通过）；表格新增「通过原因」列（量级 与 未通过原因 之间）；详情抽屉同步拆分；新增 `.reason-chip.ok`(绿)/`.refetch`(主色) 样式。null 分列回退显示合并值 |

### 实测
- 文件上传 2 个 ASIN（B01J4L6SLU young-skip + B0ZID88NEW 全新）→ 任务 pass_count=2、**pass_refetch_count=1 + pass_new_count=1** ✅
- Playwright 确认「通过原因」列已在表头正确渲染（量级/通过原因/未通过原因 并列）✅
- 现有 READY 历史任务(300/301)分列显示 0（旧代码跑完，符合预期），下次真实八爪鱼导入填充。
