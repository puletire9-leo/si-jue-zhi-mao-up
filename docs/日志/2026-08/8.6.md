### 有无相似商品 = listing 活跃度信号（四象限分析）

决定「有没有相似商品」的核心是 **listing 是否有用户浏览行为数据积累**，不是销量高低、不是上架长短。

| 象限 | 有相似商品 | 无相似商品 | 判断 |
|------|-----------|-----------|------|
| ①有销量+新品 | 5/5 | 0 | 有销量必有浏览 |
| ②有销量+老品 | 3/5 | 2（全是停售/死链接）| 「无」=死了 |
| ③没销量+新品 | **1/5**（B0H3Z8J9RK）| 4（刚上架）| **有相似=有浏览量没转化** |
| ④没销量+老品 | 3/5 | 2（死listing）| 有=还活着有人看 |

**可直接用的判断规则**：
> 新品 + 0 销量 + 有相似商品 = 有浏览量没转化（值得跟进）
> 新品 + 0 销量 + 无相似商品 = 基本没人看
> 老品 + 无相似商品 = 停售/死链接（该清理）
> ⚠️ 不能单独用「有无相似商品」判断新老，必须叠加销量+上架时间。

## 后续执行：缺失 ASIN 补数、Browse Node 方法二链接与爬取深度分级

> 本节记录 8.6 下午继续执行的结果，并修正前文“只看数据源覆盖率”的局限。当前目标不是再次判断开发找到的商品质量，而是从 7、8 月已经认可的开品竞品反推：团队怎样持续取得同类竞品 ASIN，并生成可供八爪鱼采集的类目搜索入口。

### 一、口径修正

1. `7月8月竞品ASIN.txt` 中 1792 行包含 1 行无效值 `1441341439`，有效 ASIN 为 1791 个。
2. 同一 ASIN 可能同时出现在 UK/DE/US 链接中，因此按原始 Amazon 域名恢复国家后是 **1807 个“站点-ASIN”**，不能跨站点合并请求或复用 Node ID。
3. “任意表命中 ASIN”只证明数据库见过该商品，**不代表记录含数字 `node_id`**。
4. 方法二链接使用的是数字 Browse Node：`node_id`；`bsr_id` 是 `kitchen`、`home-garden`、`toys` 等大类代码，不能直接替换到 `rh=n:`。
5. 方法二固定格式：

```text
US https://www.amazon.com/s?rh=n:{node_id}&fs=true
UK https://www.amazon.co.uk/s?rh=n:{node_id}&fs=true
DE https://www.amazon.de/s?rh=n:{node_id}&fs=true
```

### 六、当前结论与下一步实验

当前分级只是**第一轮爬取预算**，不是最终停止规则。Node 整体平均销量不能回答“第 10 页以后还有没有有效商品”，必须等八爪鱼回传结果后按页码验证：

```text
1-10页商品 → 卖家精灵补数 → 有销量率/平均销量
11-20页商品 → 卖家精灵补数 → 有销量率/平均销量
21-30页商品 → 卖家精灵补数 → 有销量率/平均销量
```
