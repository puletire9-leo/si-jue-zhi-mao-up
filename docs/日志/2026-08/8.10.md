## 一、开发功能：竞品店铺页面化

### 方法一：新品爆款

目标：把竞品店铺做成可查看、筛选和持续跟踪的页面，帮助开发发现有真实出单信号的新品。

业务规则：

```text
竞品店铺页面化
    -> 筛选上架 30 天以内的新品
    -> 持续跟踪库存变化
    -> 根据库存减少量反推销量
    -> 日均销量底线 >= 0.5 单
    -> 达到底线后标记为“推荐”
```

页面需要支持：

- 查看竞品店铺及店铺内产品；
- 筛选上架 30 天以内的新品；
- 查看产品库存跟踪记录；
- 根据有效观察天数和库存减少量计算反推日均销量；
- 对日均达到 0.5 单底线的产品展示“推荐”结果；
- 保留竞品 ASIN、产品链接和店铺来源，支持开发复核。

最低数据字段：

| 字段 | 用途 |
|------|------|
| 竞品店铺 | 机会来源 |
| 竞品 ASIN / 产品链接 | 唯一对象与复核入口 |
| 产品上架日 | 判断是否在 30 天窗口内 |
| 首次跟踪时间、库存 | 建立观察起点 |
| 最新跟踪时间、库存 | 建立观察终点 |
| 有效观察天数 | 统一销量计算周期 |
| 库存减少量 | 反推销量基础 |
| 反推日均销量 | `库存减少量 / 有效观察天数` |
| 推荐结果 | 日均销量达到 0.5 单时标记推荐 |

注意：库存减少可能受到补货、调拨、取消订单或同步延迟影响。今天的功能先按库存变化提供反推和推荐信号，不在本页面内讨论整体模型准确率。

## 二、运营功能一：发货及本地仓到货查看

目标：运营通过表格直接确认产品是否发货、是否到达本地仓，不再依赖人工逐单询问。

页面或表格至少展示：

| 字段 | 用途 |
|------|------|
| SKU / 产品 | 跟踪对象 |
| 采购完成时间 | 供应链起点 |
| 发货状态 | 未发货 / 已发货 |
| 发货时间 | 判断是否及时发出 |
| 本地仓状态 | 未到仓 / 已到仓 |
| 本地仓到货时间 | 判断运输进度 |
| 异常备注 | 延误、缺货、数量差异等 |
