## 精品统一选品页

- 在“店铺选品”下新增“精品”菜单，页面复用统一选品框架。
- 精品列表固定读取 `premium_products` 原始表，不进入新品榜初筛、评分或 clean 层。
- 默认站点为 UK，首次进入、重置和切换站点时自动选择该站点最新入库周；默认不应用 M01。
- 支持标题/ASIN/卖家/类目、周批次、价格、销量、上架天数、BSR、重量、配送、变体及排序筛选。
- M01/M03 可由用户手动叠加到精品表；M02 不支持，且方法卡不会切换数据源。
- 接入精品类目、卖家、变体详情、选择模式、人工好品/差品库及“下载全部 CSV”，CSV 导出 `premium_products` 完整数据库字段。

## 精品八爪鱼导入与云采集批次修复

- 修复 UK/DE 精品云端任务有 1000+ 条，但“导入DB”生成 0 条任务的问题。
- 原因是精品导入错误使用 `/data/notexported`，数据一旦在八爪鱼侧标记为已导出，该接口便返回 0；云端数量来自 `/data/all`，两者口径不同。
- 打开配置页会自动刷新 `statuses/v2`，并明显展示最新批次号（`yyyyMMdd-HHmmss`）、开始/结束时间、本批次数量和状态；云端限流时回退上次缓存，仍保留手动刷新按钮。
- “导入DB”固定携带页面显示的批次元数据，后端在提交和真正执行前都会复核批次未变化且为 Finished，避免页面显示批次 A、实际导入批次 B。
- 系统自身启动的批次使用真实 `lotNo` 调 `/data/lotno/all` 精确读取；网页手动启动且开放接口不返回 `lotNo` 时回退 `/data/all` 当前快照，并在 `total` 超过本批次数量时拒绝导入，防止历史累积混入。
- `/data/all` 分页响应同时兼容分页对象位于根节点和 `data` 节点两种结构；精铺无人值守增量仍继续使用 `/data/notexported`。
- 修复部署后浏览器继续运行旧前端的问题：Nginx 对 SPA 入口和 history fallback 禁止缓存，hash 静态资源仍长期缓存；旧页面未携带批次参数时，后端兼容锁定当前最新 Finished 批次，避免直接返回 400。

## 精品缺图与跨任务重复请求修复

- 生产库核查确认缺图不是图片代理故障，而是八爪鱼空壳记录未被卖家精灵返回：DE 987 条中补全 597 条，UK 993 条中补全 55 条，US 1087 条中补全 864 条。
- 请求中心过去按返回/写入数判断成功，未对比本批实际请求 ASIN 数，导致卖家精灵部分返回时仍显示 `SUCCESS`；现按请求数计算未返回数量，子项和任务标记 `PARTIAL_SUCCESS`。
- 精品任务再次发起请求前，按同站点 ASIN 跳过已有 `sellersprite_raw_json` 的商品；不同站点继续独立请求，避免跨任务重复扣费但不混淆各站点价格、销量和 BSR。
- 精品列表返回精确 `enriched` 状态；只有八爪鱼原始数据的卡片显示“待卖家精灵补全”灰色占位，不再显示红色问号。
- 发现 UK 历史数据中有 987 条实际来源为 DE 八爪鱼任务，且与 DE ASIN 完全重合；当前新链路已按 `function + marketplace + taskId` 三项校验阻止继续错站导入，历史数据等待人工确认后再清理。
- 精品尚未正式使用，确认物理清理历史垃圾：删除无卖家精灵响应的空壳，以及站点/映射/任务不一致的错站数据。页面、批次、类目、卖家、变体与 CSV 以后统一只查询 `sellersprite_raw_json` 非空记录；新导入空壳仅留给请求中心，不再展示。
- 修复精品及统一选品“上架时间”排序：前端传 `listingDate`，旧 Java 白名单没有该分支而错误回退为销量排序；现映射到 `available_date`，空日期固定置后，同日用 ASIN 稳定排序。

## 统一选品商品详情优化

- 选品详情保留居中宽弹窗，重构为“左侧商品图 + 右侧8项核心决策指标 + 分类页签 + 固定操作区”。
- 页签包含概览、市场竞争、规格物流、卖家内容、变体和数据来源；只有多变体时显示变体页签，技术字段放入低频折叠区。
- 修复站点币种硬编码：UK/DE/US 分别显示英镑/欧元/美元，卡片和详情共用规则；卖家精灵 `-1` 价格哨兵值显示为 `—`。
- 修复 `units/salesVolume` 映射、数字 `0` 被当成空值、文本 `null` 直接显示、BSR被缩写为“万”、主图 `cover` 裁切、子变体打开父 ASIN 等数据与交互问题。
- Java 详情 DTO 补齐包装尺寸/重量、LQS、更新时间；精品补齐八爪鱼任务、映射和运行批次元数据。

## 新品榜 M01 大类榜单修复

- 根因是分类下拉仍调用 Python 旧接口，统计整张 `competitor_products`，没有站点、clean 表、M01 规则和最新周批次口径；商品列表则调用 Java M01 接口，导致分类展示、数量和筛选三者彼此不一致。
- 新增 M01 同口径分类统计接口，分类统计和商品分页复用 `MethodCardMapper.M01Where`，统一站点、来源、周批次、BSR/node 和 M01 阈值。
- M01 商品查询正式支持一级分类多选；分类数组改用 POST JSON 传输，修复 `Arts, Crafts & Sewing` 等名称自带逗号时被错误拆分为多个分类的问题。
- 前端按当前 M01 查询计划加载分类，主动排除当前分类自身以保持完整榜单；站点/筛选切换增加请求序号，防止旧响应覆盖新结果。
- 生产实测：US `Arts, Crafts & Sewing` 榜单数量与筛选后商品总数均为 97；UK `Automotive` 页面显示 76，选择后商品总数为 76。

## 店铺选品分类数量修复

- 根因是店铺分类下拉只按 marketplace 聚合全量 `shop_products`，而商品列表已经叠加 M01/M03、批次和其他筛选；因此截图中分类显示 1033，实际 M01 命中只有 3。
- 店铺商品分页与分类聚合改为共用唯一筛选构造器，分类统计保留站点、方法卡、批次和全部区间条件，仅排除当前 category 自身。
- 分类值继续使用完整 `node_label_path`；商品分类筛选从模糊 LIKE 改为完整路径精确 IN，避免相似父子路径导致统计数和分页总数再次漂移。
- 前端分类接口改为 POST 当前 `shop_products` 查询计划，并沿用分类请求序号防止快速切换时旧结果覆盖。
- 生产实测：US + M01 下 `Sports & Outdoors:Fan Shop:Patio, Lawn & Garden:Outdoor Flags` 分类榜单数量为 3，选择后商品总数同为 3。

## 新品榜 M01 销量上限阈值

- M01 阈值编辑器新增“销量上限”，默认 UK/DE 为 200、US 为 500，并按站点持久化到 `api_config`。
- M01 商品列表和大类榜单统一在数据库分页/统计前排除已知销量超过上限的商品；销量为空的数据仍可按 BSR 兜底规则判定。
- 店铺选品 `shop_products` 与精品 `premium_products` 叠加 M01 时同步应用销量上限，避免只在新品榜数据源生效。
- 接口规则快照、方法卡说明和 Java 单品判定同步包含 `salesMax`，避免页面展示与实际查询口径不一致。
