### 一、代码分两块

**1. `产品数据/领星数据api/`（Python 蓝本 + 官方文档）**
- `lingxing_api.py`：换 token、签名（MD5→大写→AES-ECB→Base64）的参考实现，Java 版移植蓝本。

- 此目录仅蓝本与文档，业务代码在 Java。

**2. Java `sjzm-product/modules/lingxing/`（真正的实现）**

已打通 4 数据域 + 本地产品写回，全部落库：

| 数据域 | 领星接口 | 落库表 | 幂等键 |
|--------|---------|--------|--------|
| 店铺列表（sid 来源） | `GET /erp/sc/data/seller/lists` | `lingxing_seller` | sid |
| 本地产品（拉取） | `productList` | `lingxing_local_product` | lingxing_id |
| 本地产品（写回） | `product/set` + `uploadPictures` | 同上 | 透传领星 body |
| 产品表现 | `asinList`（≤92天） | `lingxing_product_performance` | 维度组合键 |
| 利润统计-ASIN | `profit/statistics/.../asin/list`（≤7天） | `lingxing_profit_asin` | asin\|sid\|dataDate\|currency |

- 签名/token 在 `LingxingClient.java`：过期前 60s 自动刷新，refresh 失败重换，签名与 Python 字节级一致。
- 控制器 `LingxingController.java`：`/api/v1/modules/lingxing/*`（ping / credentials / call + 4 数据域各自 sync + list）。
- 前端 4 个即插即用模块页：`frontend/src/modules/lingxing-{sellers,products,performance,profit}/`，menuGroup「领星」。
- 落库范式：结构化业务列 + `raw_json` 整包留底，组合业务键手动幂等 upsert（张总蓝本）。

## 店铺分析下一阶段：方法卡命中找店铺 + 店铺数据分表（2026-07-08，计划）

### 一、当前判断

数据基础和店铺画像辅助层已经基本闭合：

- `competitor_products_clean` 已经服务新品榜方法卡筛选。
- 郑总 UK/DE clean no variants 数据已导入系统。
- `shop-profile` 店铺画像、快照、基线、定位已跑通。
- A/B/C/D 销量分级、父体口径、郑总精铺结构画像已经验证。

但最终目标不是“画像好看”，而是：

```text
找到我们需要盯的店铺。
```

因此下一阶段主线回到：

```text
新品方法卡命中商品 -> 按店铺聚合 -> 找到高价值店铺 -> 再抓店铺全集 -> 用画像解释和跟踪。
```

### 二、三条数据线确定

#### 1. 新品榜数据：`competitor_products` / `competitor_products_clean`

定位：

```text
专门承接八爪鱼新品榜数据 + ASIN 卖家精灵补数。
```

口径：

- 可以含变体。
- 后续走 `competitor_products_clean` 去变体。
- M01/M03 等新品榜方法卡优先读 clean 表。
- `m01_active` 只是 M01 当前命中的性能标记，不再扩散成一堆 `mxx_active`。

要看的文件：

- `java-backend/sjzm-product/src/main/resources/mapper/MethodCardMapper.xml`
- `java-backend/sjzm-product/src/main/resources/mapper/CompetitorProductsCleanMapper.xml`
- `java-backend/sjzm-product/src/main/resources/mapper/ShopMethodRankMapper.xml`
- `java-backend/sjzm-product/src/main/java/com/sjzm/product/modules/shoprating/service/ShopMethodRankService.java`
- `java-backend/sql/add_m01_active_flag.sql`
- `java-backend/sql/backfill_m01_active.sql`

#### 2. 店铺观察池：`shop_watchlist`

定位：

```text
记录哪些店铺值得抓，以及为什么值得抓。
```

来源可以是：

- `METHOD_CARD`：如 M01 新品命中多。
- `BASELINE`：如郑总相似、自有优质店相似。
- `MANUAL`：人工加入。
- `CATEGORY`：类目专项观察。

建议字段：

```text
marketplace
seller_name
seller_id
source_type
source_code
reason
hit_count
top_category
status
last_fetch_run_id
created_at / updated_at
```

这张表回答：

```text
这家店为什么进入观察池？
它是因为哪张方法卡、哪个基线、哪个人工判断进来的？
```

#### 3. 店铺全集数据：`shop_products`

定位：

```text
专门承接卖家精灵“店铺名查询”返回的店铺商品全集。
```

关键原则：

```text
字段能力基本复制 competitor_products。
```

不是轻量表。因为店铺画像、店铺商品明细、方法卡解释、店铺上新流都需要和新品榜商品类似的完整字段能力。

建表思路：

```sql
CREATE TABLE shop_products LIKE competitor_products;
```

然后补店铺抓取专用字段：

```text
source_run_id
fetch_source
fetch_reason
watchlist_id
variation_mode
raw_json
first_seen_at
last_seen_at
```

口径：

- 卖家精灵店铺名查询固定 `variation=Y`。
- 即不含变体，直接对齐亚马逊店铺页面父体商品数量。
- 不再做 `shop_products_clean`。
- 但仍需要基础标准化：数值字段、`sales_tier`、`age_bucket/listing_days`、末级类目、`raw_json` 留底。

### 三、后续实现顺序

1. 新增 SQL：`shop_watchlist`、`shop_products`。
2. `shop_products` 先用 `CREATE TABLE LIKE competitor_products` 保证字段不缩水，再补店铺专用字段。
3. 卖家精灵店铺名抓取服务改为写入 `shop_products`，固定 `variation=Y`。
4. 方法卡店铺排名结果写入或同步到 `shop_watchlist`，记录进入原因。
5. 店铺画像 `shop-profile` 后续从 `shop_products` 读取，而不是混读新品榜表。
6. 单店详情展示：
   - 店铺为什么进观察池。
   - 该店命中的方法卡商品。
   - 店铺全集 A/B/C/D 分布。
   - A/ABC/D 类目结构。
   - 后续新增 ASIN 上新流。
