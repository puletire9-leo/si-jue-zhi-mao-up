# 2026-07-12

## 领星历史 SKU 生命周期数据恢复方案

### 一、已确认的问题

当前 `lingxing_target_sku_pool` 只有 `2026-W29` 一次快照：

```text
active rows = 6,560
UK = 5,913
DE = 647
```

这个数量只能作为 W29 当前同步覆盖基线，不能作为 2026 年 1~6 月历史 Cohort 的 SKU 池。

原因：

```text
- 每月、每周都有新增 SKU；
- 失败 SKU 会停售、淘汰或离开标签；
- 后期新增 SKU 不应被放入早期月份；
- 使用当前池回看历史会漏掉失败样本，产生幸存者偏差。
```

完整模型需要的不是当前 6,560 个 SKU，而是：

```text
历史期间在 UK/DE 店铺实际出现过的 listing / store-sku 全集。
```

### 二、当前数据现状

```text
采购 order_time：2026-01-17 ~ 2026-07-01
周表现 week_start：2026-04-01 ~ 2026-07-01
```

当前周表现从 2026-04 开始，4~7 月数据于 2026-07-09 一次性回补。

因此：

```text
first_active_week = 2026-04-01
```

的对象存在左截断，不能直接判定为 4 月第一周首次上架；它可能在 3 月或更早已在售。

正式首次上架周口径保持：

```text
首次上架周
= marketplace + sid + sku 首次观察到
  afn_fulfillable_quantity > 0 的 week_start。
```

只有补齐更早的周表现后，才能确认该口径。

### 三、商品主数据不能代替历史事实

当前 `lingxing_local_product` 来自：

```http
POST /erp/sc/routing/data/local_inventory/productList
```

同步模式是全量拉取当前产品后，按 `lingxing_id` 原地 upsert：

```text
- lx_create_time：领星本地产品创建时间；
- global_tags：当前产品标签；
- status：当前产品状态；
- raw_json：当前接口响应。
```

它不能回答：

```text
- 某 SKU 历史上在哪个亚马逊店铺上架；
- 哪周首次 FBA 可售；
- 历史新增、断货、恢复、停售或淘汰；
- 历史期间是否属于 6 个目标标签。
```

### 四、新建：领星商品月份实际数据快照表

不能复用现有：

```text
lingxing_sku_monthly_performance
```

因为该表是从周表聚合的派生结果，不是领星接口按月返回的实际响应，且没有逐行原始 `raw_json`。

需新增独立月度实际快照表，保留领星产品表现接口对每个月的实际返回。

数据源和请求口径：

```text
POST /bd/productPerformance/openApi/asinList
summary_field = msku
is_recently_enum = false
start_date / end_date = 目标月份完整范围
不传 search_value
不使用当前 W29 的 6,560 SKU 作为过滤条件
```

月度快照至少保留：

```text
period_month
marketplace
sid
store_name
sku
msku
asin
parent_asin
listing_status
is_delete
price
volume
amount
gross_profit
spend
库存相关字段
currency_code
raw_json
source_run_id
请求参数、页码、响应归档路径、同步时间
```

物理事实应优先保留 listing 粒度：

```text
period_month + marketplace + sid + sku + msku
```

同一个 store-sku 存在多个 msku 时，先保留明细，后续再聚合。

### 五、月度回补执行策略

目标是先恢复每月历史 SKU/listing 宇宙，再做周级完整生命周期回补。

回补月份：

```text
2026-01
2026-02
2026-03
2026-04
2026-05
2026-06
```

每个月的顺序：

```text
1. 先请求 UK 全部范围店铺；
2. UK 全部分页完成、落库、验收通过；
3. 再请求 DE 全部范围店铺；
4. DE 全部分页完成、落库、验收通过；
5. 月度 UK/DE 数据分别保存，不混合币种、库存和利润。
```

接口 `sid` 支持一次传多个店铺，技术上 UK/DE 可合并请求；但实际数据中 msku 存在跨国家、跨店铺复用，且顶层金额、毛利、广告和库存字段可能具有跨店聚合风险。

因此月度实际事实按 UK 后 DE 执行与保存，保证：

```text
marketplace + sid + sku + msku
```

归属清晰。

### 六、第一轮：2026-01 月快照试跑

试跑范围：

```text
UK 全部范围店铺
完成并验收后
DE 全部范围店铺
```

验收项：

```text
- 请求 sid 数、实际返回 sid 数；
- 分页数、请求失败数、重试结果；
- 原始响应行数；
- 展开后的 listing 行数；
- 去重后的 marketplace + sid + sku + msku 数；
- 去重后的 marketplace + sid + sku 数；
- 有销量 / 零销量行数；
- 有库存 / 零库存 / 库存未知行数；
- 同 store-sku 多 msku 数；
- 与当前 W29 池的交集和差集；
- source_run_id、请求参数、原始归档路径、同步时间。
```

月度“未出现”只标记：

```text
MONTHLY_NOT_OBSERVED
```

不能直接判定为淘汰。淘汰需要结合后续月份的销量、库存、listing 状态、采购批次和标签事实判断。

### 七、月度快照完成后的下一步

```text
1. 完成 2026-01 ~ 2026-06 历史月度快照；
2. 计算每月历史 listing/store-sku 并集、每月新增和未观察对象；
3. 找回当前 W29 池之外的历史 SKU；
4. 将采购 Q1 与月度实际表现关联，核验 Q1=10/15/20/30 的有效样本；
5. 从月度历史全集筛选需精确分析的对象；
6. 对筛选对象按周回补更早表现，确认首次 FBA 可售、断货、补货和完整生命周期；
7. 最后建立 Q1 首批量—出单—风险平衡模型，以及滚动 Cohort 利润转正模型。
```

### 八、当前已知限制

```text
- 历史标签未必能通过当前产品表现接口回放，不能把 W29 当前标签反标为历史标签；
- 采购子项 sid 大量为空，需要后续通过 marketplace + sku 唯一店铺、msku/fnsku 等映射归属；
- 月度表现用于恢复历史 SKU 集合和验证数据路径，不能替代精确周级首次上架/断货判断；
- 6 月数据存在回写延迟，先保存、标记成熟度，不用于最终模型参数结论。
```

## 月度 Cohort 模型首次测试

已使用 2025-04 至 2026-06 的 15 份领星月度导出完成团队 SKU 月度 Cohort 测试，产物位于：

```text
产品数据/领星数据api/领星25年到26年6月所有数据，以每月数据/
  历史SKU上架基础数据_2025-04至2026-06/04_月度模型测试/
```

测试对象与口径：

```text
对象粒度 = marketplace + store + SKU
团队已观察 FBA 可售对象 = 5,183
2025-04 首月左截断对象 = 21（不进入转化率）
R1 月度代理 = 首次 FBA 可售后的首个完整自然月销量 > 0
R2 月度代理 = R1 已出单，第二个完整自然月销量 > 0
```

截至 2026-06 的成熟 cohort 结果：

| 指标 | 数量 | 比率 |
|---|---:|---:|
| 非左截断 cohort 对象 | 5,162 | - |
| 首个完整月可观察 | 4,282 | - |
| R1 首个完整月有出单 | 3,580 | 83.61% |
| 两个完整月可观察 | 3,609 | - |
| R1 出单后第二月持续出单 | 2,331 / 3,003 | 77.62% |
| 两个月持续出单占成熟 cohort | 2,331 / 3,609 | 64.59% |

此轮只验证上架后月度出单和持续性，不将库存快照当作 Q1，不将结算毛利润称为真实净利润。采购 `quantity_real` 虽已存在，但月度导出尚缺可直接对应的店铺 `sid`，完成映射前不能输出严格的 Q1/Q2 批次盈亏结论。
