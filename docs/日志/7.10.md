# 2026-07-10

## 领星采购接口补齐备货量来源

新增并阅读采购接口文档：

- `产品数据/领星数据api/文档/采购/查询采购计划列表.md`
- `产品数据/领星数据api/文档/采购/查询采购单列表.md`

结论：

- 采购计划接口 `/erp/sc/routing/data/local_inventory/getPurchasePlans` 能提供计划采购量 `quantity_plan`、采购计划号 `plan_sn`、采购计划批次号 `ppg_sn`、SKU、店铺 `sid`、仓库 `wid`、预计到货时间等字段。
- 采购单接口 `/erp/sc/routing/data/local_inventory/purchaseOrderList` 能提供采购单、采购单子项、实际采购量 `item_list.quantity_real`、到货入库量 `item_list.quantity_entry`、待到货量 `item_list.quantity_receive`、状态、到货状态、关联采购计划等字段。
- 精铺模型中的 Q1/Q2 备货量可以优先从采购单子项 `quantity_real` 建立精确批次口径。
- `quantity_entry` 用于校验实际到货入库，不能和 `quantity_real` 混成同一个指标。
- 采购计划的 `quantity_plan` 只能代表计划，不是最终实际备货量。

模型口径更新：

```text
Q1 = SKU 首个有效采购单子项的 item_list.quantity_real
Q1_entry = 同一批次 item_list.quantity_entry
Q2 = Q1 后下一次有效采购单子项的 item_list.quantity_real
```

有效采购单建议过滤：

```text
status = 9：完成
status_shipped = 3：全部到货
status_shipped = 2：部分到货，只能按 quantity_entry 计算已到货部分
status IN (-1, 124)：作废，不进入模型
item_list.is_delete = 1：删除子项，不进入模型
```

后续数据层建议新增：

```text
lingxing_purchase_plan
lingxing_purchase_order
lingxing_purchase_order_item
```

采购接口负责回答“备了多少、哪一批、什么时候采购/到货”；产品表现接口继续负责回答“什么时候 FBA 可售、什么时候出单、什么时候断货”。

## 前端 Docker 端口修复

Docker 启动前端时报：

```text
ports are not available: exposing port TCP 0.0.0.0:5175
bind: An attempt was made to access a socket in a way forbidden by its access permissions
```

排查结果：

- `netstat :5175` 未发现占用进程。
- Windows TCP excluded port range 包含 `5141-5240`，`5175` 正好在保留段内。

修复：

- `docker-compose.dev.yml` 前端宿主机端口改为 `6175:5175`。
- `config/public/dev.env` 的 `FRONTEND_PORT` 改为 `6175`。
- `config/ports.json` dev frontend 改为 `6175`。
- CORS 增加 `localhost:6175` 和 `127.0.0.1:6175`。

当前前端访问地址：

```text
http://localhost:6175/
```
