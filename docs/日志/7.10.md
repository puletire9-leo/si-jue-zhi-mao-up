## 领星采购接口补齐备货量来源

新增并阅读采购接口文档：

- `产品数据/领星数据api/文档/采购/查询采购计划列表.md`
- `产品数据/领星数据api/文档/采购/查询采购单列表.md`

结论：

- 采购计划接口 `/erp/sc/routing/data/local_inventory/getPurchasePlans` 能提供计划采购量 `quantity_plan`、采购计划号 `plan_sn`、采购计划批次号 `ppg_sn`、SKU、店铺 `sid`、仓库 `wid`、预计到货时间等字段。
- 采购单接口 `/erp/sc/routing/data/local_inventory/purchaseOrderList` 能提供采购单、采购单子项、实际采购量 `item_list.quantity_real`、到货入库量 `item_list.quantity_entry`、待到货量 `item_list.quantity_receive`、状态、到货状态、关联采购计划等字段。
- 精铺模型中的 Q1/Q2 备货量可以优先从采购单子项 `quantity_real` 建立精确批次口径。
- `quantity_entry` 用于校验实际到货入库，不能和 `quantity_real` 混成同一个指标。
- 采购计划的 `quantity_plan` 只能代表计划，不是最终实际备货量。

模型口径更新：

```text
Q1 = SKU 首个有效采购单子项的 item_list.quantity_real
Q1_entry = 同一批次 item_list.quantity_entry
Q2 = Q1 后下一次有效采购单子项的 item_list.quantity_real
```

有效采购单建议过滤：

```text
status = 9：完成
status_shipped = 3：全部到货
status_shipped = 2：部分到货，只能按 quantity_entry 计算已到货部分
status IN (-1, 124)：作废，不进入模型
item_list.is_delete = 1：删除子项，不进入模型
```

后续数据层建议新增：

```text
lingxing_purchase_plan
lingxing_purchase_order
lingxing_purchase_order_item
```

采购接口负责回答“备了多少、哪一批、什么时候采购/到货”；产品表现接口继续负责回答“什么时候 FBA 可售、什么时候出单、什么时候断货”。

## 统一店铺选品前端：讨论结论（本次新增，优先级最高）

原始需求：把选品中心「竞品店铺选品」的具体商品数据，移动到店铺总览，并改为读取店铺详情数据源，
打通「总览 → 分析 → 店铺详情 → 店铺商品数据详情」，点店铺直接跳到对应店看数据。

### 摸清实际代码后的关键结论

1. **旧「竞品店铺」(reference tab) 不是真正的按店下钻。**
   - 它读 `competitor_products_clean`，走 `POST /api/v1/competitor/products`，`source="竞品店铺"` 做 LIKE 过滤。
   - 它的「卖家」筛选器错接了郑总店铺卖家列表（`getDengZongShopSellers` → `deng_zong_shop`），
     选竞品店时用的是另一套店名。本质是一个松散的商品大池，不是「选一家店看它全部商品」。
2. **用户真正想要的「按店看商品」，新模块昨天已做出来了：**
   `shop-collection-shops` 的「商品数据」Tab，走 `GET /shop-collection/{marketplace}/{sellerName}/products`
   直接按店读 `shop_products`，三维筛选齐全。所以这不是「从零搬迁」，而是「切分定位 + 补差距」。
3. **两个数据源本质不同：**
   - `competitor_products_clean`：商品为中心、多店混池、来源零散、不保证抓全 → 适合当线索/历史。
   - `shop_products`：店铺为中心、整店某时点完整快照、请求中心抓全集 → 「研究某家店」天然归它。
4. **「换数据源」的真实含义不是拷数据，而是把值得研究的竞品店路由进
   「候选池 → 请求中心抓全集 → shop_products」这条管线。数据是抓出来的，不是搬出来的。**

### 三个已拍板决策

- **未抓全集的竞品店（两者都要）**：`商品数据` Tab 默认走 `shop_products`；无快照时降级读
  `competitor_products_clean` 显示该店零散商品 + 醒目标注「非全集，历史竞品数据」+ 一键「抓全集」按钮
  （加入候选池 / 创建请求中心任务）。
- **字段差距（补齐核心字段）**：
  - brand / rating / ratings / fulfillment —— **`ShopProfileProduct` 已带、SQL 已 select，只差前端加列**，零后端成本。
  - grade / score 选品评级 —— `shop_products` 没有，是竞品/选品体系特有，是否给店铺全集也算评级留待单独讨论。
- **旧入口（保留为历史池）**：`reference-products` 维持改名「历史竞品商品池」+ 降级提示，作为历史导入/线索留存，
  不再作为「研究某个店」的入口。不下线菜单。
