## AI 选品载体同步：三国一次·增量·合并一个批次

### 背景

7.27 上线 ai_selection 表 + 载体（nonstandard_carrier）+ 全量捞取（/harvest）。7.28 发现两个体验/正确性问题：
1. 载体同步是**单站点**下拉，要三国得切三次点三次；且旧串行版本每国生成独立批次，切国家就换批次。
2. 每次全量重灌（跨批次不去重），产生大量重复批次。

用户明确诉求：**点一次 = 三国一起请求，相对历史增量去重，只灌新增，合并成「一个」批次**。

### 数据库 DDL

**文件**: `java-backend/sql/alter_ai_selection_uk_marketplace.sql`
- 唯一键 `uk_batch_asin (batch_id, asin)` → `uk_batch_asin_mp (batch_id, asin, marketplace)`。
  根因：ASIN 会跨站点重复（同 asin 在 US/UK 都有，实测 4118 行 distinct(asin+mp)=2054），
  不含 marketplace 会让三国合批时第二国的同 asin 被 INSERT IGNORE 丢掉。新键是旧键超集，ALTER 安全。
- 加 `idx_carrier_mp_asin (carrier, marketplace, asin)`：增量去重 NOT EXISTS 走此索引。
- 已备份 ai_selection（`backups/ai_selection/`）后执行，验证键切换成功。
- `create_ai_selection_table.sql` 同步更新唯一键定义。

### Java 后端

| 文件 | 改动 |
|------|------|
| `dto/AiSelectionHarvestRequest.java` | `marketplace` (String) → `marketplaces` (List<String>) |
| `controller/AiSelectionController.java` | harvest 传 list |
| `service/AiSelectionService.java` | `harvestByCarrier(carrierKey, List<String>, userId)`：**一个 batchId 贯穿三国**，遍历每站点 × shop/clean 双通道全写同一批次；batchLabel 形如 `挂牌 · UK/DE/US · 增量 2026-07-28` |
| `mapper/AiSelectionMapper.xml` | harvest 加 `incrementalNotExists`：`NOT EXISTS(SELECT 1 FROM ai_selection e WHERE e.carrier=? AND e.marketplace=s.marketplace AND e.asin=s.asin)`，相对该载体历史（跨所有批次）只灌新增。同事务内 clean 见 shop 刚插入行，跨通道/跨站点天然不重 |

### 前端

- `api/ai-selection-pool.ts`：`harvest(carrierKey, marketplaces[])`
- `views/AllSelection/index.vue`：`carrierSyncMarketplaces` 多选默认三国全选；`handleCarrierSync` 一次请求带三国数组，文案改「增量同步·合并一个批次」，提示新增 N 条
- `components/RangeFilterPanel/index.vue`：批次下拉每项加删除垃圾桶（仅 `ai_selection_batch` 场景 `canDeleteBatch` 守卫），调 `deleteBatch` + emit `batch-deleted` 让父组件刷新

### 验证

- guapai 清空旧的 5 个单国批次后重跑三国同步 → **一个批次** `batch_e9fa…`，countries=DE/UK/US，共 2054 行（UK749/DE752/US553）。
- 三国 batches 接口都返回同一个 batchId、同一 label（切国家不换批次）。
- 增量验证：删 UK 2 个 asin 再同步 → 精准只回灌那 2 条进一个新批次；无缺口时新增 0、空批次不落地。

## AI 选品捞取质量：检索词加「排除词」通道

### 问题

德国站 752 条里 **516 条（69%）** 是 `fensterdeko`（窗户装饰大类词）子串误捞的窗帘杆/窗帘轨道；
另有珠子/水晶串原料（类目为珠饰制作而非 suncatcher）混入 DE51/US39/UK7。用户确认：删 fensterdeko、珠子原料算污染要排除。

### 关键设计：排除词只作用标题通道，类目通道豁免

实测发现走**类目通道**进来的真品（如「Sonnenfänger Kristall mit Holzperlen」带木珠的成品）标题也含 Perlen，
一刀切 `NOT LIKE perlen` 会误删 48 条真品。故双通道 WHERE 重构为：

```
AND ( 类目命中(node_label_path LIKE 类目词)          -- 真品，无条件保留
      OR ( 标题命中(title LIKE 标题词) AND title NOT LIKE 每个排除词 ) )
```

### 改动

- **DDL** `java-backend/sql/add_carrier_exclude_keywords.sql`：`nonstandard_carrier` 加 `exclude_keywords` TEXT 列；
  guapai 删 fensterdeko、填初始排除词（gardinenstang/curtain rod/octagon bead/perlen zum auffädeln 等，不含单独 perlen/beads 以免误伤成品）。
- **坑**：`Get-Content | docker exec -i mysql` 管道会把 UTF-8 德语变音字符 ä 写成字面 `?`（HEX 验证 663F 而非 66C3A4），
  导致 sonnenfänger 匹配不到。改用 `docker cp` 文件进容器再 `source` 修复。
- 后端：`NonstandardCarrier` 加 excludeKeywords；Service 读取传给 mapper；两 mapper 方法签名加 excludeKeywords。
- 前端：`nonstandard-carrier.ts` 类型 + 载体编辑表单加「排除词」textarea + 表格加排除词列。

### 验证

- 重跑后 DE 752 → 456（去掉 296 条污染）。9 个明确错误 asin 清掉 7 个。
- 剩 2 个（B0GX2668HM 鸡笼网木框套件、B0GZT2VVGV 240颗替换珠）是被亚马逊**误归到 suncatcher 类目**的原料套件，
  走类目通道豁免进来。用户裁决：可接受，不管（主要污染已清）。
- 带 Perlen 的真品（B0GK8TQKHC 等类目通道）确认仍在库，豁免生效。

### 第三轮：类目通道去豁免 + 统一硬筛选

用户纠偏：「类目豁免是懒政，Sonnenfänger 类目里 Bastelset/Perlen/Sticker 满地跑，两条通道都筛选，聪明点。」

**SQL 改法** (`AiSelectionMapper.xml` dualChannelWhere)：去掉类目通道无条件保留逻辑，改为 `(标题命中 OR 类目命中) AND NOT 任一排除词`——所有行统一过筛。

**排除词进化**（从防御性"只排标题通道"→"全通道统一形态过滤"）：
- 原词保留：gardinenstang/curtain rod/octagon bead/perlen zum auffädeln 等
- 加形态词：bastelset/diy set/perlen set/ersatzperlen/sticker/aufkleber/anti collision
- 加棱镜词：glass prism/crystal pendant/crystals sun/prism sun/kristall prism/lamp repair/chandelier prism/icicle/teardrop bead/wind chime bead

**关键设计**：不排 `perlen`/`beads`（会误伤成品挂牌），只排 `perlen set`/`perlen zum auffädeln`/`teardrop bead` 等**精确组合**。不排 `crystal`/`kristall`（玻璃挂牌也算），只排 `crystal pendant`/`glass prism`/`kristall prism` 等**棱镜形态**。

**收敛效果**：DE 752→346 / UK 749→691 / US 553→494，三轮净减 523 条（25%）。8 个用户标注的错误 asin 全部清零；真品（热气球、圆盘花卉、猫 suncatcher、带 Perlen 成品）全部保留。一个批次。

## 挂牌召回率修复：亚克力与玻璃载体已可用

### 问题复核

对 `shop_products + competitor_products_clean` 做独立宽口径召回审计后，发现统一硬排除仍会误杀完整成品：

- `DIY set / Bastelset` 会误杀亚克力拼图挂牌；
- `crystal pendant / prism` 会误杀主体完整、仅附带水晶吊坠的挂牌；
- `Stained Glass ... Window Hanging`、`Acrylic ... Puzzle ... Hanging` 等插词标题无法被固定短语命中；
- `Glass Art & Suncatchers`、`Stained Glass Panels` 等玻璃类目未完整覆盖。

用户确认范围扩展为：亚克力成品挂牌 + 可按原材质生产的玻璃/彩绘玻璃成品窗挂；珠子、贴纸、链条、颜料、空白框、玻璃片等原料和配件继续排除。

### 三层载体规则

`AiSelectionMapper.xml` 的两个来源通道统一执行：

```text
(标题命中 OR 类目命中)
AND 未命中硬排除词
AND (未命中条件排除词 OR 命中成品保护词)
```

- 硬排除词：明确原料/配件，成品保护词不能覆盖；
- 条件排除词：`DIY set / Bastelset / crystal pendant / prism` 等，通常排除；
- 成品保护词：`acrylic puzzle / stained glass window hanging` 等完整形态，只覆盖条件排除。
- 标题词支持 SQL LIKE 的 `%` 有序插词，例如 `stained glass%window hanging`、`acrylic%puzzle%hanging`，不增加裸 `window hanging` 宽词。
