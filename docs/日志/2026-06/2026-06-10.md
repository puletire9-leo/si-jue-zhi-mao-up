### DeepSeek API 接入

- 模型: `deepseek-v4-flash`，OpenAI 兼容协议
- **关键坑**: DeepSeek V4 默认启用 reasoning，所有 output token 被内部推理吃掉（finish_reason=length, content=0）
- **修复**: `extra_body={"thinking": {"type": "disabled"}}`
- **第二个坑**: 输出 40 个产品的 JSON 需 ~15K+ tokens，初始 max_tokens=8192 截断
- **修复**: `max_tokens=32768`

### 关键修复

- `available_date` 解析: deng_zong_shop 存的是毫秒时间戳（13位），需先判断 `>1_000_000_000_000`
- AI 返回 element（单数）而非 elements（复数）→ parser 全面兼容单复数/字符串/对象
- browser_tool/terminal_tool/gateway 模块级 import → try/except 守卫

## 二、架构决策记录

1. **版本模型**: `reference_data_versions` 表驱动，数据导入时 `bump_data_version()` 原子升级，AI 分析批次的版本号对齐数据版本
2. **JSON 双路径**: `{bsrId}/{nodeName}.json`（人读） + `{bsrId}/by_node_id/{nodeId}.json`（机器查）
3. **并发策略**: ThreadPoolExecutor（非 asyncio），每线程独立 DB 连接，pymysql 天然线程隔离
4. **API 归属**: 模型数据由 Python 直接服务（数据就近），竞品搜索由 Java 扩展（已有框架）
5. **前端 API 代理**: `/selection-api` → selection-agent-v2:8011（Vite 代理已有），Gateway 层新增路由 `/api/v1/product-line/model/**` → selection-agent-v2:8011
6. **DeepSeek thinking=disabled**: 关闭 reasoning 模式，否则所有 output token 被内部推理消耗
7. **ON DUPLICATE KEY UPDATE**: `product_line_elements` 表加 `UNIQUE KEY uk_batch_asin` 防重跑重复
