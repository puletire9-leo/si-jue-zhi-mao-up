# 日志说明

> 本文件说明 `docs/日志/` 的目录结构、命名规范、写作规范与各月工作主线。日志索引见 [目录.md](目录.md)。

---

## 一、目录结构

```
docs/日志/
├── 目录.md            ← 全部日志索引（按月份分组 + 一句话主题）
├── 说明.md            ← 本文件
├── 敏感品清单.md       ← 非日志：敏感品（带电/带磁/带液体/真羽毛真干花）清单
├── 月计划.md           ← 非日志：月度计划草稿
├── 主线任务/          ← 跨日期的重点任务跟踪（重要度高于每日日志）
│   └── 优化模型.md     ← 优化模型主线：开发（自动化选品）+ 运营（运营看板）
├── 2026-06/           ← 6 月日志（5 篇）
├── 2026-07/           ← 7 月日志（24 篇）
└── 2026-08/           ← 8 月日志（11 篇）
```

**归档规则**：每日日志按月份移入对应 `2026-MM/` 子目录；非日志文件（清单、计划等）保留在根目录；跨日期的重点任务放入 `主线任务/`，每项任务一个 md。

## 二、命名规范

| 格式 | 示例 | 说明 |
|------|------|------|
| `M.D.md`（主流） | `7.31.md`、`8.6.md` | 自 7 月起使用的简写格式，今日日志沿用（`8.10.md`） |
| `YYYY-MM-DD.md` | `2026-06-10.md` | 6 月早期使用的完整日期格式（历史遗留，不新增） |
| `M.D.local-pre-pull.md` | `7.16.local-pre-pull.md` | 「拉取前本地备份」类日志，与同日 `.md` 并存 |

> 建议：新日志统一用 `M.D.md`；若当天有 pre-pull 备份日志，同日主日志仍为 `M.D.md`。

## 三、写作规范

- **标题**：首行 `# M.D`（如 `# 8.6`），无需重复写年份。
- **结构**：一个主题一个 `##` 大标题；大日志可再分 `###` / 表格 / 代码块。
- **内容**：记录当天核心工作、涉及模块与数据表、改动文件、线上实测结果、踩坑教训（"坑"单独列出并写根因+修复）。
- **结尾**：待办事项用 `- [ ]` 列表；关键产出记录文件路径。
- **语言**：中文；表格对齐；长日志（如 7.8/7.9）按子主题分区便于检索。

## 五、维护提示

1. **新增日志**：当天新建 `docs/日志/2026-MM/M.D.md`，按上面规范填写。
2. **归档**：每月底确认当月日志都在 `2026-MM/` 下（现有文件已归档）。
3. **更新索引**：新增日志后同步在 `目录.md` 对应月份表里加一行。
4. **非日志文件**：清单/计划类文件不要放进月份子目录。
5. **主线任务**：跨日期重点任务建在 `主线任务/`，进展同步更新对应任务 md 与「更新记录」表；新的主线任务在 `目录.md` 的「主线任务」区登记。
