# 8.3

## 修复领星 refresh token 失效导致同步卡死（+ 拉齐7月完整数据 + 月度明细表）

### 事故现象
触发每周同步后，`lingxing_data_sync_run` 长时间 RUNNING，fetched/upserted 全 0，不推进。
日志反复刷：`领星 API 临时失败: 领星 API 错误 [2001009] refresh token is invalid，第N次重试，等待…ms`。

### 根因（LingxingClient token 管理 bug）
领星 token 机制：appId+secret 换 access_token + refresh_token；access_token 到期用 refresh_token 续约，**refresh_token 2小时有效且一次性**。

- access_token 过期 → `ensureToken()` 调 `refreshAccessToken()` 续约
- 但 refresh_token 也已失效（过期/用尽）→ 领星返回 **2001009**
- `isTokenInvalidCode()` **只认 2001001/2001002/2001005，没有 2001009**
- 于是 2001009 走 `sendWithRetry` 的通用 catch 分支，被当"临时失败"重试 8 次（30/60/…/240s，累计约20分钟），每次都失败（refresh_token 不会自己恢复）
- 8次耗尽才抛异常，`ensureToken` 才 fallback 到 `getAccessToken()`——但此时任务早已被人为超时/重启，留下僵死 RUNNING 记录

### 修复（LingxingClient.java 两处）
1. `isTokenInvalidCode()` 增加 `2001009`：refresh_token 失效码归为 token 失效类，抛 `TokenInvalidException` 快速处理，不进无限重试
2. `ensureToken()` 续约失败时先 `refreshToken = ""` 作废失效 token，再 `getAccessToken()` 换全新 token——避免下次还拿失效 refresh_token 续约
