## 领星按所需 SKU 池拉一周数据测试（2026-07-09）

测试目标：

- `snapshot_week=2026-W29`
- 所需 SKU 池基线：`lingxing_target_sku_pool` active 6,560 行
- 时间窗：`2026-04-01 ~ 2026-04-07`
- 旧请求方式：按 `sid` 分组，每 50 个 `local_sku` 一批，`summary_field=sku`，`search_field=local_sku`，`is_recently_enum=false`

测试前估算：

| 项 | 数量 |
|----|-----:|
| 所需 SKU 行 | 6,560 |
| 店铺数 | 16 |
| 旧 SKU 搜索批次 | 139 |
| 文档口径最低耗时 | 约 3 分钟 |
| 保守预估 | 约 10-15 分钟 |

实际结果：

- HTTP 客户端 60 分钟超时。
- 已落 `lingxing_product_performance` 部分数据：552 行。
- 已覆盖店铺：`sid=4299` 2 行、`sid=13239` 550 行。
- 周规范表未生成，因为全量批次没有跑完。
- `lingxing_data_sync_run` 已标记失败：`sku-weekly-target-20260709081531`。

原因：

- 领星产品表现接口实际限流比文档单店铺 1 秒更严。
- 连续命中 `103 请勿频繁请求`，自动重试等待为 30s、60s、90s、120s 递增。
- 按实际 60 分钟 552 行估算，6,560 行全量一周会到 10-12 小时级别，不能用前端/HTTP 同步请求直接跑。

结论：

- 按 SKU 获取周数据的参数口径正确，接口能返回并落库。
- 但按 6,560 个目标 SKU 拆 50 个一批是错误主链路，会把 16 个有用店铺拆成 139 次请求，浪费接口额度。
- 新主链路改为：从 `lingxing_target_sku_pool` 反查实际包含目标 SKU 的店铺，当前 2026-W29 为 UK 13 个、DE 3 个，合计 16 个店铺；按这些店铺全量拉 `summary_field=sku` 周表现，不再传 `search_value`。
- 周表落库后再用 `snapshot_week + marketplace + sid + sku` 标记 `is_target_sku`，不能只按 `marketplace + sku`，避免同 SKU 跨店铺误标。
- `search_field=local_sku/search_value` 只保留给精确验证和小样本 smoke test，不作为全量周数据更新方式。
- 后续如果 16 个店铺全量同步仍超过前端 HTTP 时间，再改后台可续跑任务；但任务粒度应是“目标店铺”，不是“50 个 SKU”。

## 领星广告指标口径沉淀（2026-07-09）

新增说明文件：

```text
产品数据/领星数据api/领星广告指标与利润判断说明_2026-07-09.md
```

核心口径：

- `ACOS = 广告花费 / 广告销售额`，用于判断广告订单本身投放效率。
- `TACOS = 广告花费 / 总销售额`，用于判断广告费吃掉整体 SKU 生意多少。
- `ACOAS = 广告花费 / 净销售额`，用于更保守地判断广告费压力。
- 如果基础利润率约 20%，利润风险优先看 `ACOAS > 20%`；没有净销售额时用 `TACOS > 20%` 替代。
- `ACOS` 不用于直接判断 SKU 整体是否赚钱，只用于广告投放效率。

## 精铺备货量口径修正（2026-07-09）

复盘“备首批备货数量与出单率关系”模型时确认一条硬规则：首批备货数量 Q1 必须是精确字段，不能用产品表现库存快照倒推。

当前领星产品表现数据可以支持：

- `volume`：出单量/销量。
- `afn_fulfillable_quantity`：FBA 可售库存快照，用于判断当周是否在售。
- `available_inventory.available_inventory`：可用库存总计快照。
- `stock_up_num`、`reserved_customerorders`、`reserved_fc_processing`、`reserved_fc_transfers`：在途/预留/调仓状态快照。

当前不能支持：

- 精确首批备货数量 Q1。
- 精确第二批备货数量 Q2。
- 按批次区分“这一批备了多少、何时入仓、何时卖完”。

原因：这些字段是查询时点/时间窗返回的库存状态，已经被销量、预留、调仓、补货、入库共同影响。5 月数据中 `afn_fulfillable_quantity` 最大值超过 300，而精铺首批通常不可能超过 50，进一步证明它不是 Q1。

下一步如要严肃计算备货量与出单率关系，必须找到或新增领星采购单、备货单、入仓单、shipment 或仓库库存流水数据源。拿到精确 Q1/Q2 前，只能用现有周/月表做在售、出单、断货、广告、利润表现诊断，不能输出 Q1 盈亏模型结论。
