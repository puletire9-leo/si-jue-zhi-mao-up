## 需求

初筛流程中，`skip_asins` 标记为已采过（`filter_reasons='API已请求'` 或 `'初筛PASS'`）的 ASIN 原本一律拦截（SKIP_BLACKLIST）。
现增加放行规则：**其它筛选（价格/评论）都通过后，若该 ASIN 在主表 `competitor_products.listing_days < 90`，则放行进 PASS，允许重复调用卖家精灵获取最新数据。**

## 判定顺序（新）

```
ASIN格式 → 文件内去重 → 硬性黑名单(历史淘汰) → 价格 → 评论 → 已采过放行判断 → 主表已有(SKIP_MAIN) → PASS
```

- 硬性黑名单 = `skip_asins` 中 `filter_reasons` 非 `API已请求`/`初筛PASS` 的记录（价格/评论/精筛淘汰等）
- 已采过放行：`listingDays < 90` → PASS；`listingDays == null` 或 `>= 90` → SKIP_BLACKLIST（保守拦截）
- SKIP_MAIN 语义不变（主表已有仍拦截）

## 第三版规则（2026-08-05，取代前两版时间闸）

用户决策：**旧的「API已请求 + 上架<90天 + 系统导入超1月」时间闸不要了**。改为更简单直接的新品重取规则试验：

**新规则**：凡命中 `skip_asins`（不再区分 `filter_reasons`）的 ASIN，若主表 `competitor_products` **当前** `listing_days < 30` **且当前仍无销量**（`MAX(units)` 为空或 ≤0），价格/评论通过后放行进 PASS，重新调用卖家精灵。否则 skip 命中即归 SKIP_BLACKLIST。

### 判定顺序（新）
```
ASIN格式 → 文件内去重 → 已采过黑名单(非新品重取候选) → 价格 → 评论 → 新品重取放行判断 → 主表已有(SKIP_MAIN) → PASS
```

### 关键实现
| 文件 | 改动 |
|------|------|
| `CompetitorProductMapper.java/.xml` | 新增 `selectYoungNoSalesAsinsInList(marketplace, asins, maxListingDays)`：`GROUP BY asin HAVING MIN(listing_days)<max AND (MAX(units) IS NULL OR MAX(units)<=0)` |
| `AsinImportService.java` | 常量 `NEW_PRODUCT_REFETCH_MAX_LISTING_DAYS=30`（取代 `API_REQUESTED_REFETCH_MAX_LISTING_DAYS=90`）。`batchQueryExistingBlacklist`/`BlacklistSplit`/`parseCreatedAt`/`isApiRequestedReason`/`batchQueryListingDays` 全部删除，改为 `batchQueryExistingSkipAsins`（全量 skip 命中）+ `batchQueryYoungNoSalesRefetch`（主表 young-no-sales 子集）。`filterRows` 签名改 `(rows, blockedAsins, refetchAsins, mainTableAsins, marketplace)`，`blockedAsins = skipAsins - refetchAsins`。两条入口同步。 |
| `AsinImportStreamingTest.java` | 4 个旧时间闸场景替换为 3 个：young-no-sales→PASS、非候选→SKIP_BLACKLIST、候选但价格淘汰→PRICE_FAIL |

### 关键设计（防无限重取）
上架天数/销量取**主表实时值**（每次采集刷新），非 `skip_asins` 冻结快照。ASIN 一旦满 30 天或拿到销量，`selectYoungNoSalesAsinsInList` 不再返回它 → 落 blockedAsins → SKIP_BLACKLIST，天然收敛。**无时间闸**：每次八爪鱼重爬都重新判定，符合用户「每次重爬都放行」诉求。
