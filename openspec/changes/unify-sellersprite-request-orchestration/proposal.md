## Why

卖家精灵调用目前分散在 ASIN 批量导入、通用竞品查询、店铺全集、邓总店铺和卖家名导入等多条链路中。2026-07-13 的 UK 任务已证明：网络连接超时会触发局部熔断，但旧执行器仍继续将后续未发出的批次标记失败，既丢失真实原因，也无法安全恢复。

现在需要把所有卖家精灵调用统一到请求中心，并把限流、超时、重试、熔断、错误审计和暂停恢复收敛为同一套基础能力，避免不同页面和任务类型出现不同的故障语义。

## What Changes

- 新增唯一的卖家精灵执行网关，统一管理 HTTP 客户端、认证、请求超时、限流、调用审计、错误分类、有限重试和熔断。
- 扩展卖家精灵请求中心，使 ASIN、店铺全集、候选池、精品复抓、邓总店铺和卖家名批量导入都以可跟踪任务方式执行。
- 为请求运行和子项新增重试等待、系统暂停、失败分类、尝试次数、下次重试时间和原始错误摘要，支持在网络故障或熔断时安全暂停而非批量误标失败。
- 将现有同步直连入口迁移为“创建请求中心任务并返回 runId”；旧入口在兼容期内只做代理或返回迁移提示。**BREAKING**：原先同步等待卖家精灵结果的接口将改为异步任务语义。
- 将停机恢复、手动暂停、停止、重试和使用次数统计统一到请求中心；未实际发出的请求不得标记为 API 失败或计入使用次数。
- 增加卖家精灵运行健康与熔断状态的可视化，帮助操作员区分网络、鉴权、额度、参数和上游业务错误。
- 请求中心支持按任务创建月份筛选，并展示所选月份（默认本月）全部任务累计的卖家精灵请求次数。
- 将精确店名 `Amazon` 设为全局禁止抓取名称，避免通用名称触发海量模糊匹配和无效扣费。
- 为所有店铺名称分页抓取增加单店 10 次请求硬上限，超限时保留已抓结果并继续下一个店铺。

## Capabilities

### New Capabilities

- `sellersprite-execution-gateway`: 提供唯一的卖家精灵调用通道，以及统一的限流、超时、熔断、重试、错误分类和调用审计。
- `sellersprite-request-orchestration`: 将所有卖家精灵业务入口编排为可暂停、恢复、停止、重试和追踪的请求中心任务。

### Modified Capabilities

无。

## Impact

- Java 后端：`SellerspriteApiService`、`ApiRateLimitService`、`AsinImportService`、`CompetitorService`、`DengZongShopService`、`ShopProductSyncService`、候选池、精品池与请求中心模块。
- 前端：ASIN 导入、八爪鱼自动采集、请求中心、候选池、精品池、邓总店铺分析、全部选品和相关 API 客户端。
- 数据库：扩展 `sellersprite_request_run`、`sellersprite_request_item` 和调用审计表，新增迁移并由 SchemaGuard 校验。
- API：现有同步卖家精灵入口迁移为异步 run 创建接口；需保留短期兼容策略并更新网关/nginx 路由与部署预检。
