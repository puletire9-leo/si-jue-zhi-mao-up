## Context

人工选品库已经通过 `developer_selection_library` 保存开发人员的好品/差品商品快照，并复用统一筛选抽屉与分页 CSV 导出。当前页面固定显示复选框且卡片尺寸固定，数据库也没有批次归属。此次变更同时涉及数据库迁移、Java 权限校验与 Vue 交互，需要保持普通开发数据隔离和管理员跨开发查看能力。

## Goals / Non-Goals

**Goals:**

- 好品与差品各自维护、筛选和操作批次。
- 每个批次归属一个开发人员，每个商品最多归属一个同库批次。
- 复用新品榜的选择模式与卡片缩放交互。
- 保持已有筛选、分页、好差品转换、移出和全量 CSV 导出行为。
- 数据库迁移可在已有生产表上重复执行。

**Non-Goals:**

- 不实现自动分类、经验规则、批次统计报表或批次删除/重命名管理页面。
- 不允许一个商品同时属于多个批次。
- 不把好品批次与差品批次合并共享。

## Decisions

1. 新增 `developer_selection_batch` 表，而不是把批次名称直接写入商品表。批次实体保存 `user_id`、`developer_name`、`bucket`、`batch_name` 和 `batch_date`，便于权限校验、标签列表和后续扩展；商品表仅增加可空 `batch_id`。
2. 批次名称在同一开发人员、同一好/差品库中唯一。好品和差品可使用相同名称，符合“两套独立分类”的要求。
3. 批量归类在 Service 层先读取全部商品与批次，统一校验操作者权限、商品所有者、商品 bucket 和批次 bucket，再更新 `batch_id`，避免越权或跨库归类。
4. 好差品转换及重复加入导致 bucket 变化时清空 `batch_id`，防止旧库批次残留。
5. 列表返回商品时补充 `batchName`，筛选条件使用 `batchId` 或 `unassigned=true`；CSV 复用列表查询，因此自然包含当前批次筛选结果和批次字段。
6. 前端只在选择模式显示复选状态，并复用新品榜“点击整张卡片切换、全选当前页”的操作模型。详情和按钮点击阻止冒泡。
7. 卡片缩放复用新品榜基于 CSS transform、测量基础高度和 `ResizeObserver` 的实现，使用独立 localStorage key，避免两个页面相互覆盖偏好。
8. 管理员默认开发人通过有效用户记录的 `developer/full_name/username` 匹配“刘淼”，不硬编码用户 ID；后端在管理员未传目标用户时同样执行该默认解析，确保旧前端或其他入口不会把商品写回系统管理员名下。

## Risks / Trade-offs

- [批次被逻辑删除后商品仍持有 batch_id] → 当前版本不提供删除批次入口；查询展示通过批次表映射，未来删除能力必须先解除商品归属。
- [管理员查看全部开发时同名批次产生歧义] → 批次标签和 API 都携带开发人员信息；管理员必须先选开发后才能新建批次，筛选具体批次使用唯一 ID。
- [批量更新部分成功] → Service 使用事务，并在更新前完成全量校验。
- [缩放后的动态高度抖动] → 沿用新品榜已验证的基础高度缓存与 ResizeObserver 逻辑。

## Migration Plan

1. 在四套 schema 文件中新增批次表和 `batch_id`，迁移脚本使用 `information_schema` 守卫保证幂等。
2. 在临时库连续执行迁移两次，确认首次创建和重复执行均成功。
3. 构建并验证 Java、前端后，先执行生产数据库迁移，再重建产品服务与前端。
4. 冒烟验证普通开发、管理员、好品/差品独立批次、转换清空和筛选导出。
5. 回滚应用时旧版本会忽略新增表和列；数据库结构保留，避免破坏已归类数据。

## Open Questions

无。批次删除、重命名和统计能力留待后续需求。
