- **分层架构**：采用 API (`api/v1`) -> Service (`services`) -> Model/Schema (`models`/`schemas`) 的经典三层结构。
- **双数据源策略**：产品基础信息（SKU、名称等）存储于 MySQL，通过 `ProductService` 和 `ProductRecycleService` 管理；海量销售数据存储在 Parquet 文件中，通过 `ProductDataService` 集成 `Polars` 进行高性能分析，`ProductSalesService` 则直接使用 `DuckDB` 查询 Parquet。
- **状态管理**：产品删除采用软删除机制（`status='deleted'`），由 `ProductRecycleService` 负责恢复或永久清理。
- **依赖注入**：API 层通过 FastAPI 的 `Depends` 获取服务实例，服务实例初始化时注入 MySQL 和 Redis 连接。
