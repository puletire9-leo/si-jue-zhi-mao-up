## 二、P0 — 色彩系统统一

### 问题

设计文档中出现 **两套完全不同且冲突的主色调**：

| 来源 | 主色 | 备注 |
|------|------|------|
| 文档4 Agent对话 | `#409EFF` (Element Plus 默认蓝) | — |
| 文档5 系统方案 | `#409EFF` 为主 + `#b45309` 为品牌色 | 双重角色 |
| 文档1 分析页 | 未涉及品牌色 | — |
| 文档3 基础设计 | 未明确 | — |
| 当前前端 | `#b45309` (Amber Classic) | 已实施 |

**问题分析**：`#409EFF`（冷蓝）和 `#b45309`（暖琥珀）在色轮上完全不同象限（蓝 vs 橙），同时作为主色会导致视觉分裂。文档5 将两者都列为系统级颜色但未说明各自的适用场景。

### 方案

// ============================================

$primary-light: #d97706;
$primary-dark: #92400e;

// 中性色
$bg-color: #ffffff;
$bg-hover: #f5f0eb;
$bg-body: #f5f0eb;
$border-color: #e5e1da;
$border-hover: #d6cfc6;

// 文字颜色
$text-primary: #1a1a1a;
$text-secondary: #6b7280;
$text-tertiary: #9ca3af;

// 语义色
$success-color: #059669;
$warning-color: #b45309;
$danger-color: #dc2626;
$info-color: #b45309;

// 等级色（店铺评级）
$grade-s: #b45309;    // 金色 → 改为琥珀主色
$grade-a: #059669;    // 绿色
$grade-b: #0891b2;    // 青色
$grade-c: #ca8a04;    // 黄色
$grade-d: #ea580c;    // 橙色
$grade-e: #dc2626;    // 红色

// 健康度色
$health-healthy: #059669;    // 健康=绿
$health-stable: #0891b2;    // 稳定=青
$health-declining: #ca8a04; // 衰退=黄

// 标记色
$mark-potential: #0891b2;  // 潜在=青

$mark-abandon: #dc2626;    // 放弃=红

✅ 建议分层：

    ├── product-line-selection/
    │   └── components/    ← 仅模块私有组件
    │       ├── ProductLineTree.vue
    │       ├── ProductLineModel.vue

## 五、P1 — 交互模式优化

### 问题：弹窗过度堆叠

文档2 在品线选品单页面可能同时出现 **7 层弹窗/抽屉**：

1. `ShareDialog` — 分享弹窗
2. `ExportDialog` — 导出弹窗
3. `FilterPresetSaveDialog` — 保存预设弹窗
4. `AddToSelectionDialog` — 加入选品弹窗
5. `CompareDrawer` — 对比抽屉 (50vh)
6. `FeedbackForm` — 反馈表单
7. `ElementTrendDetail` — 趋势详情弹窗

### 优化方案

| 当前 | 优化后 | 理由 |
|------|--------|------|
| CompareDrawer 底部弹出 | 竞品表格内联展开对比行 | 减少层级，保留上下文 |
| FilterPresetSaveDialog | 内联输入 + toast 确认 | 保存预设是高频操作，弹窗打断流程 |
| ShareDialog | 点击后直接复制链接 + toast "已复制" | 分享 90% 场景是复制链接 |
| FeedbackForm | 保留弹窗（低频） | — |
| ExportDialog | 保留弹窗（需配置选项） | — |
| AddToSelectionDialog | 保留弹窗（需选列表） | — |

**优化后最大弹窗叠加层数：4 → 2**

## 七、P1 — 三栏布局空间分配

### 问题

品线选品页三栏布局在当前设计中的空间分配不合理：

```
品线树 (320px, 可拖拽)
    ↓ 拖拽边界未定义（最小 200px？最大 500px？）
品线模型 (flex: 1)
    ↓ 模型卡片 + 底部操作栏，内容密集
竞品结果 (初始折叠, 展开 40vh)
    ↓ 40vh → 432px @1080p = 表头 + 3 行数据就满了
```

### 优化方案

```
桌面端 (≥1280px):
┌───────────┬────────────────────┬──────────────────────┐
│ 品线树    │ 品线模型            │   竞品结果（展开时）   │
│ 280px     │ flex: 1 (约 40%)   │   flex: 1 (约 35%)   │
│ min:200px │ min: 360px         │   min: 480px          │
│ max:400px │ 收到 40% 后停止扩大  │   收到 35% 后停止扩大  │
└───────────┴────────────────────┴──────────────────────┘

竞品结果展开时：
- 品线模型自动从 100% 宽度收缩到 55%
- 竞品表格从 0 扩展到 45%
- 过渡动画 300ms ease
- 折叠按钮放在分隔线上方
```

### 实现

```scss
.selection-layout {
  display: flex;
  height: calc(100vh - 108px); // 减去 topNav(64px) + tagsBar(44px)

  &__tree {
    width: 280px;
    min-width: 200px;
    max-width: 400px;
    resize: horizontal;
    overflow: auto;
    border-right: 1px solid $border-color;
  }

  &__model {
    flex: 1;
    min-width: 360px;
    overflow-y: auto;
    transition: flex 0.3s ease;

    .has-results & {
      flex: 0 0 55%; // 收缩给表格留空间
    }
  }

  &__results {
    flex: 0;
    min-width: 0;
    overflow: hidden;
    transition: flex 0.3s ease;

    &--open {
      flex: 1;
      min-width: 480px;
      border-left: 1px solid $border-color;
    }
  }
}
```

## 九、P2 — URL 状态序列化统一

### 问题

文档5 和文档2 对同一功能（分享/跳转时的 URL 参数）使用了两种不同的编码方案：

| 来源 | 方案 | 示例 |
|------|------|------|
| 文档5 页面跳转 | 短参数名 | `?m=US&b=123&n=456` |
| 文档2 分享功能 | LZ-String + Base64 JSON | `?state=N4Ig...` |

### 统一方案

```typescript
// ============================================
// URL 状态序列化 — 统一规范
// ============================================

// 简单状态（≤3 个参数）：直接 URL query
// 适合：页面间跳转，携带基本上下文
// /product-line-selection?marketplace=US&batchId=123&nodeId=456

// 复杂状态（>3 个参数或含筛选条件数组）：LZ-String 压缩
// 适合：分享链接、书签保存
// /product-line-selection?state=lz-compressed-base64

// 实现
import { compressToEncodedURIComponent, decompressFromEncodedURIComponent } from 'lz-string'

// 编码
function encodeState(state: SelectionState): string {
  const json = JSON.stringify(state)
  return compressToEncodedURIComponent(json)
}

// 解码
function decodeState(encoded: string): SelectionState | null {
  try {
    const json = decompressFromEncodedURIComponent(encoded)
    return json ? JSON.parse(json) : null
  } catch {
    return null
  }
}

// 判断阈值：参数数量 > 3 时自动使用压缩
function shouldCompress(params: Record<string, unknown>): boolean {
  return Object.keys(params).length > 3
}
```
