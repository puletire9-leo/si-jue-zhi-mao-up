# 02 · 三层证据链

> 回答"这个候选团队熟不熟、像哪种手法、有多大概率能做起来"。**基于三层证据，不做销量预测，不替代人工看图定审美。**

## 结构

```
L1 开品层  →  L2 上架层  →  L3 经营层
   ↓             ↓            ↓
团队开过   →   真上架了   →  真赚了钱
5,312 SKU    65.2% 进 L2    3,698 挂 L3
             51.5% 有 FBA   12% 留存盈利
```

**三层必须同时通过才算好方向。任一层触红线即打红旗。**

| 层 | 回答什么 | 硬红线 | 详见 |
|---|---|---|---|
| L1 开品层 | 团队怎么开的 | P1-P3（+非标 P10/P11） | [03 手法](03_八大开发手法.md) / [04 红线](04_硬红线P1-P11.md) |
| L2 上架层 | 开的品有多少真上了 FBA | P4-P6 | [04 红线](04_硬红线P1-P11.md) |
| L3 经营层 | 上架后真赚钱了吗 | P7-P9 | [11 经营真相](11_经营真相与教训.md) |

## 数据边界与来源

| 层 | 数据源 | 规模 |
|---|---|---|
| L1 开品事实 | 理实产品对接表(2026-01~06 共 40 张) + 领星本地产品表 `lingxing_local_product` | 5,312 SKU |
| L2 上架事实 | 领星模型/基础统一表/`ASIN_FBA可售优先*.csv` | 6,617 ASIN |
| L3 经营事实 | 领星模型/ASIN月度经营模型/`{GBP,EUR}/*.xlsx` | 5,786 GBP + 607 EUR ASIN |
| 图片 | `lingxing_local_product.pic_url` | 99.6% 有图 |
| 找品候选源 | `competitor_products_clean`(m01_active=1) + 竞品店铺表 | M01 新品榜达标品 |

**三层贯通主表**：`第二版/理实开品经验/data/sku_full_lifecycle.csv`（5,703 行 × 40 列，含 Amazon item_name / tacos / 最新月销量）。
字段涵盖 L1(SKU/开发/供应商/开品理由/售价/采购价/手法/主题/图URL) → L2(ASIN/基准店铺/FBA首现月/Listing标签) → L3(币种/累计销量/结算利润/结算销售额/当前标签)。

## 三个必须记住的口径陷阱

1. **账面 ≠ 结算**：L1 的利润率是账面预估，L3 是真实结算。S04 老品季节化 L1 报 27.20%，L3 实际只有 4.6%，差 22pp。**判断赚不赚钱只认 L3。**
2. **FBA 首现月 ≠ 真实首销月**（R-FBA可售月-01）。累计利润会掩盖 launch 期亏损（R-月度视角-01）——必须看月度轨迹，不能只看累计数字。
3. **"留存且盈利"是粗标签**，会把"盈利明星"和"边缘留存"混为一谈。必须用 P11 单单毛利 + 最新月销量 + tacos 重新分类（见 [04 红线 R-销量口径-01](04_硬红线P1-P11.md)）。

## 每月增量入库流程（数据怎么更新）

脚本在 `第二版/理实开品经验/scripts/`：
1. `python ingest_month.py <目录> --month YYYY-MM` — L1 层入库
2. `python link_layers.py` — 贯通三层证据链
3. `python enrich_amazon_data.py` — 补 Amazon item_name / tacos / 最新月销量等 8 列

供应商分片：≥3 SKU 独立目录，<3 归入 `_tail/`。深审档案沉淀到 `data/审计档案/<SKU>.md`。
