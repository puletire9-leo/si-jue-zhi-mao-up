# 开发循环流程 · 双向飞轮

> 一句话：开品不是一次性找货，而是 **市场发现 ⇄ 自身复盘** 两条线咬合的循环。
> 两条线共享同一个判断内核（元素池/载体库/方法卡/红线/E02），靠三个咬合点闭环，靠经营数据回流自转。
>
> 关系澄清（纠正旧版 `01总纲` 的"A/B 二选一、A 太局限"说法）：
> A 不是降级选项，而是**从经营结果反向提炼模式**的内循环；B 是从市场原始数据发现新方向的外循环。两条腿缺一不可。

---

## 一、两条线的定位

| | 线1 · 内循环（自身复盘拓品） | 线2 · 外循环（市场扫描发现） |
|---|---|---|
| 旧称 | A 模式（升级版，不再是找竞品变体） | B 模式（主攻） |
| 数据源 | 领星 L2 上架 + L3 经营 + `sku_full_lifecycle.csv` | 新品榜 `competitor_products_clean` + `shop_products` 20万 |
| 本质 | 从"我们已经赚到钱的品"反推能拓什么 | 问市场"哪些类目/元素在冒新品且在涨" |
| 优点 | 低风险、复用现成产线、有 L3 真实盈利背书 | 上限高、能发现没碰过的新方向 |
| 风险 | 被自己锚死（靠"提炼模式"而非"找变体"来破解） | 未验证、需逐品校验 |

---

## 二、领星线不只找爆款（你纠正的重点）

领星是 L3 经营真相层，"卖得好"有梯度，爆款太少但**六类都不放过**：

| 形态 | 例子 | 拓法 |
|---|---|---|
| 盈利明星 | 02 跨站复制 17.3% | 元素×载体重组、跨站照搬 |
| 现金牛标品 | 圣经笔记本 TACOS<1% 自然流量 | 换新款式 / 性价比 |
| 爬升中新品 | 水桶接头 0→84 | 加码、盯利润（带尺寸件高退款正常） |
| 季节性走量 | S04 季节化、德国毕业季 | 提前布明年、跨季节复制 |
| 低竞争长尾 | 干净小类目持续出单 | 复制"干净池子"模式（月销小≠差） |
| 边缘留存(薄利) | 头枕套贴 P1 下限 | 优化或换角度，别硬拓 |

### 三个咬合点（循环能转起来的关键，旧版缺的就是这个）

1. **线1 → 线2**：线1从成功 SKU 提炼出"知更鸟×花园地插盈利"→ 转成线2的找品画像，去 `shop_products` 找该元素还在哪些新载体上爬升。
2. **线2 → 线1**：线2扫出市场热点 → 用线1的元素池/载体库打标，命中的直接喂现成产线（强化）。
3. **开品 → 领星 → 线1**：新品上架后经营数据回流领星，成为线1下一轮"分层筛卖得好"的输入。**这一步让飞轮自转。**

## 四、结合系统：已实现 vs 缺口

| 环节 | 系统现状 | 缺口 |
|---|---|---|
| 线2·L0 合池 | 新品榜✅、shop_products✅(20万) | ❌ 两源未合并去重、shop 未接品线分析 |
| 线2·L1 方法卡 | ✅ M01 打标 + M03/ShopScreeningService 实时筛 | — |
| 线2·L2 分桶 | ✅ 品线页两级桶，算好 unitsGrowthRate | ❌ 热点排序加权公式未定 |
| 线2·L3-L5 | — | ❌ 全人工，无"命中现有方向"自动打标 |
| **线1 全线** | 领星模型✅、`sku_full_lifecycle.csv`✅ | ❌❌ **无系统入口**，现全是离线 csv 分析——最大空白 |
| 共享内核 | 方法卡/红线在代码里 | ❌ 元素池/载体库仍是 md，未进系统供两线调用 |

**最扎眼的缺口**：线1（领星复盘拓品）完全没有系统承载，品线选品页只服务线2。飞轮现在"一条腿半自动（线2）+ 一条腿离线纯人工（线1）"，转不顺。

---

## 四之补 · 本阶段架构决定：AI 分析在系统外，系统只负责呈现结果

> 上面的"缺口表"是**终态视角**（理想上什么都进系统）。但**当前阶段先明确分工，不急着把 AI 搬进系统**：

| | 归属 | 说明 |
|---|---|---|
| **AI 分析（黑箱漏斗）** | **系统外（场外）** | 领星定锚 → 赛道卡 → L0-L5 → E02 → 强化/拓展打标，全部在场外用 AI+人工跑完。系统内**没有也暂不需要 AI Agent**。 |
| **系统** | **只负责呈现结果** | 场外产出的干净候选（ASIN 清单）导入系统，用现成选品框架呈现、复审、导出、接回飞轮。 |

**落地入口 = AI 选品页 `/ai-selection`**（复用 AllSelection 框架 + `ai_selection` 表）：
- 场外漏斗产出 ASIN 清单 → 人工粘贴导入（`/import`）→ 按 ASIN 回 `shop_products`（优先）/`competitor_products_clean`（兜底）补全整行 → 落成一个 batch。
- 因此"离线 csv 分析"在本阶段**不是要消灭的空白，而是有意为之的分工**：AI 留在场外灵活迭代，系统只做承载与呈现。**先这样结合跑，验证方法论能不能用，再决定要不要把哪一段分析做进系统。**

> 与"缺口表"的关系：缺口表描述的是**将来可能补的方向**（如把 E02/红线/打标也做进系统）；本节描述的是**现在就这么干**。不冲突——先呈现结果跑通，再谈自动化。
