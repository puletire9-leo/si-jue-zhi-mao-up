# 00 · 微定制 · 载体×元素矩阵索引

> **这是微定制细分赛道的导航入口。**
> 核心思路见 [前言](../前言.md)：不指望 AI 一次找全，而是把找品拆成一条条聚焦的细分赛道，一个个找。
> 微定制的本质（见 [经验总结 E01](../../经验总结/07_非标看图深审法.md)）：**竞品是元素验证器**，团队把已验证的元素 copy 微改，搬到自己擅长的载体上。所以每条赛道 = 一个「载体 × 元素」交叉点。
> 载体×元素是**多对多的网**（同载体配多元素、同元素上多载体），文件树是一维的，塞不下二维网，所以二维关系交给下面这张矩阵表，文件夹保持扁平。

## 一、命名规范（四维，标题即索引）

每张赛道卡文件名固定四维，用 `×` 连接：

```
载体 × 元素 × 时间 × 人群 .md
例：铁皮画×花卉×春季×全年龄.md
```

## 三、怎么读这张表（找品时）

1. **手里有一个已验证好卖的元素**（从新品榜/竞品来）→ 找该元素所在**列**，看团队还有哪些载体能接（`·` 和 `待验证` 都是机会位）。
2. **想给某个主力载体扩款**（如铁皮画产线要新 SKU）→ 找该载体所在**行**，看还能叠哪些正盈利元素。
3. **亏损元素要加权、不是回避**：`蝴蝶`(T4) / `花卉·粉色系`(T6) 是 [05 主题池](../../经验总结/05_主题元素池.md) 里的亏损主题，仍可建卡、仍可开，但每个候选要额外靠价格/空白优势把它抬成谨慎可开，优势顶不上就暂缓该候选、换角度再找，不是否掉整个元素或载体。完全不做的品（合规/敏感类）见团队既有的敏感品/拒绝清单，不在本索引重复。
4. 选定一个交叉点 → 打开对应赛道卡 → 按卡里的「数据库查法」去 `competitor_products_clean` 跑候选。

## 四、怎么加新卡

1. **四维齐全**：文件名必须 `载体×元素×时间×人群.md`，四维都从上面词表取值。
2. **词表没有就先补词**：新载体查 [08 载体库](../../经验总结/08_载体库.md) 确认团队能定制，新元素查 [05 主题池](../../经验总结/05_主题元素池.md) 确认已验证（首次出现的元素需 3+ SKU 才入池），补进本文件第一节词表后再建卡。
3. **建卡后回填矩阵**：在第二节主矩阵表对应格子填链接 + 机会★ + (时间·人群)。
4. **卡是方法模板不是候选清单**：卡里写"怎么找"，具体候选是拿卡去数据库跑出来的产物，不写死在卡里。
5. **卡的固定结构**（6 段）：交叉点定义 / 为什么成立 / 数据库查法 / 分流+红线 / E02 优势理由 / 候选卡格式+避坑。
