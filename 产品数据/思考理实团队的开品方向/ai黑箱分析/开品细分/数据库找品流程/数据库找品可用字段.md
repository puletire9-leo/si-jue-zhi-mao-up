# 数据库找品可用字段

> 目的：搞清楚数据池里**哪些字段能撑起找品**，怎么结构化打通。这是找品的"零件表"，
> 找品流程（见 `数据库流程.md`）就是把这些字段按顺序组装起来。
>
> 两个池子（字段几乎同构）：
> - **新品榜** `competitor_products_clean`（clean 表，`m01_active=1` 为有效行，约 6 千行/UK+DE+US）
> - **店铺选品** `shop_products`（大头，UK 16.6万 / US 7.2万 / DE 1.3万，`units_gr` 覆盖约 44%）
>
> ⚠️ `m01_active` 只在 clean 表有意义；`shop_products` 里该列全为 0，别拿它筛店铺选品。

---

## 一、按"能回答什么找品问题"分组

找品要回答 5 个问题，每个问题对应一组字段。

### 组 1 · 新度（这是不是新品、新到什么程度）
| 字段 | 类型 | 说明 |
|---|---|---|
| `listing_days` | int | 上架天数。**<30 天=新品榜强验证候选**，上百上千只算"需求存在" |
| `m04_age_bucket` / `m04_tier` | varchar | 已算好的新老品分层（clean 表有值，shop 表待确认覆盖率） |
| `new_release` | varchar | 亚马逊 New Release 标记 |
| `available_date` | bigint | 上架时间戳 |
| `first_seen_at` / `last_seen_at` | datetime | 我们首次/最近抓到它的时间 |

### 组 2 · 销量爬升（新品是在涨还是死的）★B 模式核心
| 字段 | 类型 | 说明 |
|---|---|---|
| `units_gr` | decimal | **销量环比增长率**。找"又新、销量在涨"的品的核心信号；覆盖约 44% |
| `units` | int | 月销量 |
| `sales_tier` | varchar | 销量档（UK 分布：D 最多→C→A→B，UNKNOWN 少量）。粗筛用 |
| `revenue` / `amz_sales` | decimal | 销售额 |
| `bsr` / `bsr_cr` / `bsr_cv` | int/decimal | 排名及变化率，趋势佐证 |
| `rating_delta` | int | 新评论涌入（新品起量的侧证） |

### 组 3 · 元素/品类（这是什么方向、什么元素）★聚合降维靠它
| 字段 | 类型 | 说明 |
|---|---|---|
| `node_label_path` | varchar | **类目面包屑**，`:` 分隔、3-5 层（如 `DIY & Tools:Power, Garden & Hand Tools:Hand Tools:Punches`）。**聚合降维的主键** |
| `node_id_path` / `node_id` | - | 类目 ID 路径 |
| `title` | varchar(1000) | 标题，抽元素词/功能词的来源（标品抽功能、微定制抽元素） |
| `brand` | varchar | 品牌。白牌/无品牌 = 好切入信号 |

### 组 4 · 竞争验证（池子挤不挤、验证够不够）
| 字段 | 类型 | 说明 |
|---|---|---|
| `sellers` | int | 跟卖数，越多越红海 |
| `seller_nation` | varchar | 卖家国别。**中国卖家扎堆 = 红海预警** |
| `ratings` / `rating` / `ratings_rate` | int/decimal | 评论数/星级/评论增速。验证需求真实度 |
| `lqs` | decimal | Listing 质量分 |
| `best_seller` / `amazon_choice` | varchar | 平台背书标记 |

### 组 5 · 能否落地（我们开得了吗、利润够吗）
| 字段 | 类型 | 说明 |
|---|---|---|
| `price` / `prime_price` | decimal | 售价，对 **P1 区间**（UK £4.99-19.99 等） |
| `profit` / `fba` / `delivery_price` | decimal | 利润/FBA 费，对 **P3 利润率 ≥20%** |
| `variations` | int | **款式数/件数**。数量装/多款式判定；⚠️ 有时是 listing 变体非真实件数，需详情页核 |
| `weight` / `weight_g` / `dimension` / `pkg_dimensions` | varchar/decimal | 重量尺寸。空运成本 + 载体匹配 + **标品"带尺寸功能件"识别** |
| `fulfillment` | varchar | FBA/FBM |

## 二、字段 → 找品诉求映射（你要的三件事）

你要"新品上得多、又新销量在涨、元素还不错"的品，恰好是组1+组2+组3 三个字段撑起来的：

| 你的诉求 | 主字段 | 怎么用 |
|---|---|---|
| 新品上得多 | `listing_days` + `node_label_path` | 按类目聚合，数 `listing_days<X` 的新品数量，多的类目=新品在涌入 |
| 又新、销量在涨 | `units_gr` + `listing_days` | 新且 `units_gr` 高 = 正在爬升 |
| 元素还不错 | `title` + `node_label_path` | 从标题抽元素/功能，对现有元素池 T1-T6 / 载体库打标 |
| 能落地 | `price`+`profit`+`variations`+`dimension` | P1/P3 红线 + 载体/件数校验 |

## 三、已加工层（省事，别重复造轮子）
| 字段 | 说明 |
|---|---|
| `m01_active`（仅 clean） | **M01 新品加速方法卡的打标结果**（1/0），导入时打、每日摘超期标。找新品直接取 `=1` |
| `m04_age_bucket/tier/units_pct/bsr_pct` | 新老品分层 + 分位数（已算好，M04 卡产出，仅供基线服务读） |
| `score` / `grade` | 老的通用评分引擎产出（Python scoring_engine），与方法卡是两套体系 |
| `week_tag` / `is_current` / `batch_code` | 周批次，取最新批用 `is_current=1` |
| `raw_json` | 原始全字段兜底（shop 表有） |

> **重点**：筛选和分桶系统已实现，别自己写——
> - 筛选 = 方法卡 M01 / M03 / M02。**M01/M03 对新品榜和店铺选品两个源都能筛**：新品榜读打标列 `m01_active`，店铺选品由 `ShopScreeningService` 实时套 `M01Rule` 阈值算（支持 `m01Only`/`m01HitCount`/FBM 过滤）。
> - 分桶 = 品线分析页面按 `bsr_id → node_id` 两级类目桶，每桶已算 `unitsGrowthRate` 等。
> - 目标：品线选品页升级为统一市场选品入口（两源合并、同 ASIN 按最新导入时间去重、源标签暂不分）。
> - 详见 `数据库流程.md` 的"〇、系统现有能力"与"★ 目标形态"。
