# 第一层：团队开品分析

> 本层只回答“开发创建了什么、创建了多少”。暂时不使用销量和利润评价产品。

## 一、正式口径

- 数据源：MySQL `lingxing_local_product`。
- 团队范围：八位指定开发人。
- 时间范围：`lx_create_time >= 2025-04-01` 且 `< 2026-07-01`。
- 计数单位：去重 SKU。
- 组合产品：`is_combo=1` 的组合主 SKU 按一个产品计算，不展开辅助 SKU。
- 当前共 10,303 个开品 SKU，其中组合主 SKU 291 个。

这里的“开品”表示领星本地产品被创建，不代表运营已经选择，更不代表亚马逊已经上架。

## 四、这一层应当怎样继续细分

每个开品 SKU 后续至少需要以下标签：

| 维度 | 示例 | 用途 |
|---|---|---|
| 商品形态 | 单件、套装、多件包、组合产品 | 验证“套装/组合是否更容易上架和盈利”。 |
| 体积与重量 | 轻小、普通、大件、重货 | 验证物流和仓储对上架率、利润的影响。 |
| 功能风险 | 普通消费品、带电、化学、功效、安全责任 | 验证旧垃圾规则中的风险方向。 |
| 主题属性 | 动物、礼品、派对、节日、兴趣、DIY | 找出团队真正擅长的主题。 |
| 定制空间 | 可印花、可包装、可改数量、无差异化 | 判断是否具备团队的设计和组合优势。 |
| 价格带 | 低客单、中客单、高客单 | 验证 £4–£15 主力价格带。 |
| IP 风险 | 通用、可改写擦边、强 IP/真人 | 区分可运营方向和不可控风险。 |

## 五、当前数据问题

团队本地产品记录中的 `category_name` 基本为空，因此现在不能可信地按数据库类目比较开品方向。商品名称仍然完整，后续应以“本地产品名 + 亚马逊标题”生成统一方向标签。

在方向标签建立以前，本层只下三个结论：

1. 团队在 15 个月内创建了 10,303 个 SKU，开品规模很大。
2. 2026-03 后开品量显著加速，必须结合第二层检查运营承接率。
3. 评价开发人不能只看数量，必须追踪同一开品批次最终有多少进入 FBA、多少产生利润。
