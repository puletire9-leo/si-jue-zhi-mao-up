# 思考理实团队的开品方向：第一版总纲

> 数据观察范围：2025-04 至 2026-06。  
> 更新时间：2026-07-15。  
> 团队范围：蒋舒、陈杨、宋凤莉、刘淼、龙梦临、周沁仪、张子轩、黄雨珊。  
> 本文是总入口，具体证据和细分结论放在三份分层文档中。

## 一、这次不再从“哪个 ASIN 像垃圾”开始

旧版《垃圾 ASIN 分析》主要根据标题、风险和商品形态判断“什么不要”。这套经验仍有价值，但它只是一组方向假设，不能直接证明团队真实的开品质量。

现在数据已经能够把团队产品拆成三个连续层级：

1. 团队开品层：开发实际创建了多少 SKU、由谁创建、创建在哪个月。
2. 运营上架转化层：这些 SKU 中多少进入 Listing/ASIN 基础池，多少出现明确 FBA 可售证据。
3. 上架后经营表现层：上架 ASIN 的销量、利润、留存、淘汰和当前出单能力。

三层必须连起来看：

```text
开发开品 SKU
  ↓ 运营选择、建 Listing、备货和上架
进入上架基础表的 SKU / ASIN
  ↓ 上架后的销售与财务验证
留存、淘汰、盈利、亏损、持续出单
```

## 二、当前三层总览

| 层级 | 当前可确认的主要数量 | 说明 |
|---|---:|---|
| 团队开品 | 10,303 个 SKU | 本地产品表中八位开发人于 2025-04 至 2026-06 创建的去重 SKU；其中组合主 SKU 291 个，主 SKU 按一个产品计数。 |
| 进入统一上架基础表 | 5,709 个 SKU | 占全部开品 SKU 的 55.41%；共关联 6,378 个 ASIN。 |
| 明确观察到 FBA 可售 | 4,693 个 SKU | 占全部开品 SKU 的 45.55%；关联 5,160 个有 FBA 证据的 ASIN。 |
| 仅创建时间兜底 | 1,016 个 SKU | 已进入 ASIN 基础表，但在月表未观察到 FBA 可售；其中 820 个来自 2026-05、2026-06 新近开品，不能过早判定。 |
| 未进入统一上架基础表 | 4,594 个 SKU | 可能是运营未选、未建 Listing、未上架、标签范围外或编码映射缺失，不能直接等同于“垃圾产品”。 |
| GBP 经营模型 | 5,786 个 ASIN | 截至 2026-06 累计结算利润 GBP 71,012.30，标签留存率 62.58%。 |
| EUR 经营模型 | 607 个 ASIN | 主要集中在 2026-04 至 2026-06，累计结算利润 EUR -1,386.74，样本尚年轻。 |

SKU 与 ASIN 不是同一单位：一个 SKU 可能关联多个 ASIN，所以不能把三层数量直接相减。

## 三、第一版最重要的发现

### 1. 最大损耗首先发生在“开品到真正 FBA 上架”之间

为避免 2026-05、2026-06 尚未完成上架的产品干扰，先只看创建时间不晚于 2026-04 的成熟开品：

| 指标 | 数量 | 占成熟开品 |
|---|---:|---:|
| 成熟开品 SKU | 7,836 | 100.00% |
| 进入上架基础表 | 4,156 | 53.04% |
| 有明确 FBA 可售证据 | 3,960 | 50.54% |
| 未进入上架基础表 | 3,680 | 46.96% |

这说明团队方向分析不能只盯上架后的利润。接近一半成熟开品没有进入当前统一上架事实，必须进一步区分是开发方向问题、运营选择问题、执行问题还是数据映射问题。

### 2. 留存率高不等于开品方向好

GBP 数据中，蒋舒的标签留存率只有 46.25%，但累计结算利润和利润率最高；周沁仪、龙梦临的留存率较高，但利润接近持平或为负。

所以以后不能用“留存 ASIN 多”直接评价方向，至少要同时看：

- FBA 上架转化率；
- 上架后的出单率；
- 盈利 ASIN 比例；
- 留存 ASIN 利润率；
- 淘汰损失；
- 成熟批次的持续盈利能力。

### 3. 2026-05、2026-06 不能和老批次直接比较

这两个月共创建 2,467 个 SKU，其中 820 个只使用创建时间兜底。尤其 2026-06 的产品通常要到 7 月甚至 8 月才有较完整的 FBA 和销售结果。

因此：

- 2026-05、2026-06 可以看执行进度；
- 暂时不能用淘汰率、利润率或 FBA 转化率评价最终开品质量；
- 开发人横向比较应优先使用创建时间不晚于 2026-04 的成熟批次。

### 4. 旧“垃圾 ASIN”规则需要进入数据验证阶段

旧分析提出了“轻小、低客单、可组合、可定制、低责任风险”等好品方向，也提出化学品、充电器、安全责任件、大件重货等风险方向。

当前事实表已经具备验证条件，但本地产品的 `category_name` 在团队数据中基本为空，不能直接按数据库类目得出方向结论。下一步应使用商品名称和亚马逊标题建立统一的中文方向标签，再分别计算每个标签的：

```text
开品数 → FBA上架率 → 有销量率 → 留存率 → 盈利率 → 累计利润
```

只有同时通过这条链路的方向，才能进入正式的“团队好品方向”。

## 五、第一版后的正确推进顺序

1. 锁定三层事实表和成熟期规则，不再变更分母。
2. 给 10,303 个开品 SKU 和对应 ASIN 建立统一“产品方向标签”。
3. 先看方向标签的 FBA 上架转化，找出大量开但运营不上的方向。
4. 再看已上架方向的利润、留存、出单和淘汰损失。
5. 最后按开发人、开品月份、产品方向三维交叉，形成真正可执行的开品白名单、复核清单和拒绝清单。
