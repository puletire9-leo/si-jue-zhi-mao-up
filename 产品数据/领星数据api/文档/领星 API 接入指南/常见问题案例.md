# 常见问题案例

---

### 1. 获取 access_token 时报 RSA 解密错误

```json
{
    "code": "0001001",
    "msg": "rsa private decrypt error",
    "data": null
}
```

**原因**：appSecret 中可能有特殊字符，在传输中会转义，因此 appSecret 用 Rsa 解密时报错。

**解决方法**：appSecret 利用 `urlencode.encode()` 进行转义后传输。

---

### 2. 生成签名不正确

```json
{
    "code": "2001006",
    "msg": " api sign not correct",
    "data": {
        "throwable": " api sign not correct",
        "throwTime": "2022-01-20 15:37:55"
    }
}
```

**原因**：生成的签名不正确。

**解决方法**：
1. 检查参与生成签名的参数是否正确
2. 当参数的值为空时，不需要把该参数代入计算签名
3. 参与签名的时间戳长度取 10 位
4. 检查签名是否进行了 `URLEncoder.encode()` 进行 URL 字符转义
5. POST 请求 URL 上只能带 `appId`、`token`、`timestamp`、`sign`（转义后的值）这四个参数，其他业务请求参数放在 body 里
6. 传入 body 参数若为数组、List 等集合类型时，需要将其先转为 String 类型后再进行传入从而生成 sign；在生成 sign 之后，需要重新将数组、List 集合本身再次进行覆盖（参考官方 SDK 中的写法）
7. 使用 Python 调用接口时，为了防止大写 `False`/`True` 导致签名错误，Boolean 字段统一用字符串 `'true'` 或 `'false'`

---

### 3. 频繁出现 access_token 过期

```json
{
    "code": "2001005",
    "msg": " access token not match"
}
```

**解决方法**：检查自己本地是否存在别的应用一直在重复请求导致 access_token 频繁变换。

---

### 4. IP 被限制访问

```json
{
    "code": "3001002",
    "msg": "ip not permit, please add ip to white list first."
}
```

**原因**：应用所在服务器的 IP 不在白名单中。

**解决方法**：IP 未加入白名单，确认发起 IP 地址后在 **设置 > 业务配置 > 全局 > 开放接口** 自行增加即可。

---

### 5. 服务器返回 400

```json
{
    "code": 400,
    "message": "服务不存在",
    "error_details": [],
    "request_id": "903BFE57-E7B3-81C2-4E4A-29EDA32C3B59",
    "response_time": "2021-12-27 16:21:14",
    "data": [],
    "total": 0
}
```

**原因**：请求 URL 路径不正确。

**解决方法**：检查 URL 地址是否正确。

---

### 6. 服务器返回 405

```
Response error, status code: 405, body:
<html>
<head><title>405 Not Allowed</title></head>
<body><center><h1>405 Not Allowed</h1></center><hr><center>nginx</center></body>
</html>
```

**原因**：请求 URL 路径不正确。

**解决方法**：检查 URL 地址是否正确。

---

### 7. 服务器返回 500

```json
{
    "code": "500",
    "msg": "404 NOT_FOUND",
    "data": {
        "throwable": "404 NOT_FOUND",
        "throwTime": "2021-12-27 16:22:09"
    }
}
```

**原因**：请求 URL 路径不正确。

**解决方法**：检查请求地址是否正确，注意 Domain 与 API Path 的拼接中不要有多余的 `/`（反斜杠）。

---

### 8. 公共请求参数不完整

```json
{
    "code": "3001001",
    "msg": "missing query param(access_token,sign,timestamp,app_key)"
}
```

**原因**：公共请求参数不完整。

**解决方法**：在 Query Params 参数中，需要传入包括 `access_token`、`app_key`、`sign`、`timestamp` 四个公共请求参数。

---

### 9. 参数不合法

```json
{
    "code": "102",
    "msg": "参数不合法"
}
```

**原因**：数组、List 集合在生成 sign 过程中会将其数据类型转为 string 类型后传入 body 参数当中，而转义后的数据不符合接口文档传入参数类型的规范。

**解决方法**：在生成 sign 之后，添加一段代码将 body 参数中对应的值重新以本身数组或 List 集合类型进行覆盖即可。

---

### 10. 限流拦截

```json
{
    "code": 103,
    "message": "请求过于频繁,请稍后再试 [C0C1B855-48A2-6BB6-5636-5AC80042386C]",
    "error_details": [],
    "request_id": "4B750B70-2026-FE98-B88F-400B91D3F1E4"
}
```

**原因**：请求速率过高导致被限流拦截。

**解决方法**：根据限流规则去设计发送请求的频率，防止被系统拦截。

---

### 11. appId 被禁用

```json
{
    "code": "401",
    "msg": "授权被禁用，请检查授权状态",
    "data": null
}
```

**解决方法**：请求接口的 appId 被禁用了，请联系 ERP 超级管理员在 **设置 > 全局 > 开放接口** 页面，为该 appId 解除禁用。

---

### 12. appId 已经失效

```json
{
    "code": "403",
    "msg": "授权失效，请更新授权有效期",
    "data": null
}
```

**解决方法**：请求接口的 appId 过期了，请联系 ERP 超级管理员在 **设置 > 全局 > 开放接口** 页面，为该 appId 更新授权有效期。

---

### 13. appId 没有接口权限

```json
{
    "msg": "授权失效，请更新授权有效期或检查权限",
    "code": "403",
    "data": null
}
```

**解决方法**：appId 账号没有其请求接口的权限，请联系 ERP 超级管理员在 **设置 > 全局 > 开放接口** 页面，为该 appId 授权接口。
