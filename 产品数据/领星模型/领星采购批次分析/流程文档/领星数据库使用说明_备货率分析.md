# 领星数据库使用说明（备货率分析）

> 备货率分析涉及的领星表结构、字段说明、查询逻辑

**最后更新**: 2026-08-12  
**数据库**: `sijuelishi` (MySQL 127.0.0.1:3310)  
**适用场景**: 采购备货分析、利润归属、问题SKU识别

---

## 一、核心表结构

### 1.1 采购计划表 `lingxing_purchase_plan`

**用途**: 采购批次的决策记录（PPG批次号）

**关键字段**:
| 字段 | 类型 | 说明 | 示例 | 备注 |
|------|------|------|------|------|
| `plan_sn` | varchar | 采购计划编号 | PP260423142 | 一个PPG可能包含多个plan |
| `ppg_sn` | varchar | **批次号（关键）** | PPG260423020 | 补货决策单位，按此统计批次数 |
| `sku` | varchar | 产品SKU | 2551413 | 对应`lingxing_local_product.sku` |
| `creator_real_name` | varchar | **创建人** | 李杉/余江燕 | 用于判断国家（余江燕=DE，其他=UK） |
| `create_time` | datetime | **批次创建时间** | 2026-04-23 18:00:26 | 批次边界，用于利润归属分段 |
| `quantity_plan` | int | 计划采购数量 | 10 | 同ppg_sn多个plan需SUM |
| `status` | int | 状态码 | -2 | **-2=已完成**, -3=已作废, 124=已作废, 2=待采购, 121=待审批 |
| `status_text` | varchar | 状态文本 | 已完成 | 可读性好 |
| `is_combo` | tinyint | 是否组合品 | 1/0 | 1=组合，算入分母但标记 |
| `is_aux` | tinyint | 是否辅料 | 1/0 | 1=辅料，**排除**分母 |

**索引**:
```sql
CREATE INDEX idx_sku ON lingxing_purchase_plan(sku);
CREATE INDEX idx_ppg_sn ON lingxing_purchase_plan(ppg_sn);
CREATE INDEX idx_status ON lingxing_purchase_plan(status);
```

**常用查询**:
```sql
-- 查询某SKU的所有批次（已完成）
SELECT ppg_sn, creator_real_name, DATE(create_time) AS ppg_date,
       SUM(quantity_plan) AS qty
FROM lingxing_purchase_plan
WHERE sku = '2551413' AND status = -2
GROUP BY ppg_sn, creator_real_name, DATE(create_time)
ORDER BY create_time;

-- 统计某批SKU的批次数
SELECT sku, COUNT(DISTINCT ppg_sn) AS batch_count
FROM lingxing_purchase_plan
WHERE sku IN ('2551413','2551298',...)
  AND status = -2
GROUP BY sku;
```

**数据质量问题**:
- `create_time` 个别NULL → 已过滤
- `ppg_sn` 个别NULL → 已过滤
- `status=-2` 占大多数（16195/16670），其他状态少量

### 1.2 采购单表 `lingxing_purchase_order` + `lingxing_purchase_order_item`

**用途**: 采购执行记录（PO订单号），**已弃用做批次统计**

**关键字段**（order表）:
| 字段 | 类型 | 说明 | 问题 |
|------|------|------|------|
| `order_sn` | varchar | 采购单号 | PO260508033 |
| `order_time` | datetime | 下单时间 | **部分NULL** |
| `status` | int | 状态 | -1=已作废, 124=已作废, 9=已完成, 2=待到货 |

**关键字段**（order_item表）:
| 字段 | 类型 | 说明 |
|------|------|------|
| `order_sn` | varchar | 关联采购单 |
| `sku` | varchar | SKU |
| `plan_sn` | varchar | 关联采购计划 |
| `quantity_real` | int | 实际采购数量 |
| `quantity_entry` | int | 入库数量 |
| `is_delete` | tinyint | 是否删除 |

**为什么弃用**:
1. 一个PPG可能对应多个PO，或多个PPG合并成一个PO
2. `order_time` 有NULL值，无法准确排序
3. PO是执行层（王亚成操作），PPG是决策层（李杉/余江燕创建）

### 1.4 Listing表 `lingxing_listing`

**用途**: SKU → ASIN映射（连接本地SKU和亚马逊ASIN）

**关键字段**:
| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `local_sku` | varchar | **本地SKU** | 2551413 |
| `asin` | varchar | **亚马逊ASIN** | B0H1BMSQQR |
| `marketplace` | varchar | **市场** | 英国/德国/美国/... |
| `listing_status` | int | 上架状态 | 1=正常, 0=下架 |

**一对多关系**: 一个local_sku可能有多个ASIN（UK一个、DE一个、US一个）

**常用查询**:
```sql
-- 查询某SKU的所有ASIN
SELECT marketplace, asin, listing_status
FROM lingxing_listing
WHERE local_sku = '2551413';

-- 批量SKU → ASIN映射（用于周表关联）
SELECT local_sku, marketplace, asin
FROM lingxing_listing
WHERE local_sku IN (清单SKU);
```

**marketplace值**:
- `英国` → UK
- `德国` → DE
- `美国` → US
- `法国` → FR
- `意大利` → IT
- `西班牙` → ES
- `日本` → JP

---

### 1.5 周表 `lingxing_sku_weekly_performance`

**用途**: 每周销售数据（按ASIN汇总）

**关键字段**:
| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `asin` | varchar | **ASIN** | B0H1BMSQQR |
| `week_start` | date | **周起始日** | 2026-07-06 |
| `week_end` | date | 周结束日 | 2026-07-12 |
| `volume` | int | **销量** | 4 |
| `amount` | decimal(18,4) | **销售额** | 26.64 |
| `gross_profit` | decimal(18,4) | **毛利** | 0.35 |
| `currency_code` | varchar | 币种 | GBP/EUR/USD |

**注意事项**:
1. **按ASIN存储**，不是local_sku → 需通过`lingxing_listing`映射
2. **币种各国不同**：UK=GBP, DE=EUR, US=USD，**不做汇率转换**
3. **week_start是归属依据**：按此判断销售落在Q1/Q2/Q3哪个批次周期
4. 历史数据完整（从2025-04开始），但很多周销量为0

**常用查询**:
```sql
-- 查询某SKU的所有周表数据（通过listing映射）
SELECT l.marketplace, w.week_start, w.volume, w.amount, w.gross_profit
FROM lingxing_listing l
JOIN lingxing_sku_weekly_performance w ON w.asin = l.asin
WHERE l.local_sku = '2551413'
ORDER BY w.week_start;

-- 批量SKU的周表数据（用于利润归属）
SELECT l.local_sku, l.marketplace, w.week_start,
       w.volume, w.amount, w.gross_profit
FROM lingxing_listing l
JOIN lingxing_sku_weekly_performance w ON w.asin = l.asin
WHERE l.local_sku IN (清单SKU);
```

## 二、数据口径说明

### 2.1 批次定义

**批次单位**: PPG（`lingxing_purchase_plan.ppg_sn`）

**批次统计**:
```sql
-- 某SKU的批次数 = 去重ppg_sn的数量
SELECT COUNT(DISTINCT ppg_sn)
FROM lingxing_purchase_plan
WHERE sku = '2551413' AND status = -2;
```

**同日多批处理**:
```python
# 同SKU同国同日多个PPG合并为1批
sku_country_date_ppg[sku][country][DATE(create_time)].append(ppg_sn)
```

### 2.2 国家归属

**规则**:
```python
if creator_real_name == "余江燕":
    country = "DE"
else:
    country = "UK"
```

**原因**: 余江燕负责德国市场，其他采购人（李杉/唐若/张亚芳/罗伟豪）负责英国市场

**多国SKU处理**: 一个SKU可能既有UK批次也有DE批次 → 拆成两条独立记录

### 2.3 批次周期边界

**边界时间**: PPG创建时间（`create_time`）

**周期划分**（同SKU同国内部）:
```
Q1周期 = [首批create_time, 二批create_time)
Q2周期 = [二批create_time, 三批create_time)
Q3周期 = [三批create_time, ∞)
```

**示例**:
```
SKU 2551413 UK侧：
- PPG260423020: 2026-04-23 → Q1周期起点
- PPG260615006: 2026-06-15 → Q2周期起点
- PPG260617029: 2026-06-17 → Q3周期起点

周表某行week_start=2026-07-06 → 落在Q3周期（≥06-17）
```

### 2.4 利润归属

**归属逻辑**:
```python
for week_row in 周表:
    week_start = week_row['week_start']
    sku = week_row['local_sku']
    country = "UK" if marketplace=="英国" else "DE"
    
    # 找该SKU在该国的批次列表（按create_time排序）
    batches = sku_country_batches[sku][country]
    
    # 判断week_start >= 哪个批次的create_time
    batch_idx = 0
    for i, batch in enumerate(batches, 1):
        if week_start >= batch.create_time:
            batch_idx = i
        else:
            break
    
    # 累加毛利到该批次
    agg[sku][country][batch_idx].gross_profit += week_row['gross_profit']
```

### 2.5 状态过滤

**采购计划status**:
| 值 | 含义 | 是否统计 |
|-----|------|---------|
| -2 | 已完成 | ✓ 统计 |
| -3 | 已作废 | ✗ 过滤 |
| 124 | 已作废 | ✗ 过滤 |
| 2 | 待采购 | ✗ 过滤 |
| 121 | 待审批 | ✗ 过滤 |
| 122 | 已驳回 | ✗ 过滤 |

**只统计已完成**（`status=-2`），因为：
- 待采购/待审批还未执行，不算真实批次
- 已驳回/已作废是取消的计划，不算

## 三、常用SQL查询模板

### 3.1 批次统计

**某批SKU的批次数和采购量**:
```sql
SELECT sku,
       COUNT(DISTINCT ppg_sn) AS batch_count,
       SUM(quantity_plan) AS total_purchase
FROM lingxing_purchase_plan
WHERE sku IN (%s, %s, ...)  -- 用pymysql参数化
  AND status = -2
  AND ppg_sn IS NOT NULL
  AND create_time IS NOT NULL
GROUP BY sku;
```

**某SKU的批次明细**:
```sql
SELECT ppg_sn, creator_real_name, 
       DATE(create_time) AS ppg_date,
       SUM(quantity_plan) AS qty,
       status_text
FROM lingxing_purchase_plan
WHERE sku = '2551413'
  AND status = -2
GROUP BY ppg_sn, creator_real_name, DATE(create_time), status_text
ORDER BY create_time;
```

### 3.2 利润查询

**某批SKU的周表数据**:
```sql
SELECT l.local_sku, l.marketplace, 
       w.week_start, w.week_end,
       w.volume, w.amount, w.gross_profit, w.currency_code
FROM lingxing_listing l
JOIN lingxing_sku_weekly_performance w ON w.asin = l.asin
WHERE l.local_sku IN (%s, %s, ...)
ORDER BY l.local_sku, w.week_start;
```

**某SKU某周的毛利**:
```sql
SELECT week_start, week_end, volume, gross_profit
FROM lingxing_sku_weekly_performance
WHERE asin = 'B0H1BMSQQR'
  AND week_start = '2026-07-06';
```

### 3.3 组合品/辅料标记

**查询组合品**:
```sql
SELECT DISTINCT sku
FROM lingxing_purchase_plan
WHERE sku IN (清单SKU)
  AND is_combo = 1;
```

**查询辅料**:
```sql
SELECT DISTINCT sku
FROM lingxing_purchase_plan
WHERE sku IN (清单SKU)
  AND is_aux = 1;
```

**处理逻辑**:
- 组合品：算入"主SKU"分母，但标记为"组合"类型（蓝色填充）
- 辅料：**排除**分母（不算主SKU），灰色填充

### 3.4 ASIN映射检查

**某SKU有哪些ASIN**:
```sql
SELECT marketplace, asin, listing_status
FROM lingxing_listing
WHERE local_sku = '2551413';
```

**反查ASIN对应哪个SKU**:
```sql
SELECT local_sku, marketplace
FROM lingxing_listing
WHERE asin = 'B0H1BMSQQR';
```

**无ASIN的SKU**（可能未上架或映射缺失）:
```sql
SELECT sku
FROM lingxing_local_product
WHERE sku IN (清单SKU)
  AND sku NOT IN (
      SELECT DISTINCT local_sku 
      FROM lingxing_listing
  );
```

## 六、性能优化

### 6.1 索引建议

```sql
-- 采购计划表
CREATE INDEX idx_sku_status ON lingxing_purchase_plan(sku, status);
CREATE INDEX idx_ppg_sn ON lingxing_purchase_plan(ppg_sn);
CREATE INDEX idx_create_time ON lingxing_purchase_plan(create_time);

-- Listing表
CREATE INDEX idx_local_sku ON lingxing_listing(local_sku);
CREATE INDEX idx_asin ON lingxing_listing(asin);

-- 周表
CREATE INDEX idx_asin_week ON lingxing_sku_weekly_performance(asin, week_start);
```

### 6.2 查询优化

**避免**:
```sql
-- ✗ 逐个SKU查询（N次查询）
for sku in all_skus:
    SELECT ... WHERE sku = sku
```

**推荐**:
```sql
-- ✓ 批量查询（1次查询）
SELECT ... WHERE sku IN (all_skus)
```

**分批处理**（SKU数量>5000时）:
```python
# 每批1000个SKU
batch_size = 1000
for i in range(0, len(all_skus), batch_size):
    batch = all_skus[i:i+batch_size]
    placeholders = ",".join(["%s"] * len(batch))
    sql = f"SELECT ... WHERE sku IN ({placeholders})"
    results = q(sql, batch)
```

## 七、常见问题排查

### 问题1: SKU显示0批次但有销量

**原因**: 采购计划status不是-2（可能是待采购/已驳回）

**排查**:
```sql
SELECT plan_sn, ppg_sn, status, status_text
FROM lingxing_purchase_plan
WHERE sku = '2551413';
```

**解决**: 确保查询条件包含`status=-2`

---

### 问题2: 批次数不对（比实际多或少）

**原因1**: 同一天多个PPG被算成多批

**解决**: 按`DATE(create_time)`去重

**原因2**: 用了PO而非PPG统计

**解决**: 改用`ppg_sn`

**排查**:
```sql
-- 查看该SKU的所有PPG和日期
SELECT ppg_sn, DATE(create_time), COUNT(*)
FROM lingxing_purchase_plan
WHERE sku = '2551413' AND status=-2
GROUP BY ppg_sn, DATE(create_time)
ORDER BY create_time;
```

---

### 问题3: 毛利和手算不一致

**原因1**: 周表包含多个ASIN（UK+DE）

**排查**:
```sql
SELECT l.marketplace, COUNT(DISTINCT l.asin)
FROM lingxing_listing l
WHERE l.local_sku = '2551413'
GROUP BY l.marketplace;
```

**原因2**: 周表有延迟/缺失周

**排查**:
```sql
-- 检查某段时间的周表连续性
SELECT week_start, week_end
FROM lingxing_sku_weekly_performance
WHERE asin = 'B0H1BMSQQR'
  AND week_start BETWEEN '2026-06-01' AND '2026-08-01'
ORDER BY week_start;
```

**原因3**: 币种未转换（UK=GBP, DE=EUR）

**解决**: 分国展示，不做汇率转换

---

### 问题4: 有销量但Excel里不显示

**原因1**: 该SKU无采购记录，被`批次数>=1`过滤掉了

**排查**:
```sql
SELECT COUNT(*) FROM lingxing_purchase_plan
WHERE sku = '2551469' AND status=-2;
-- 返回0说明无采购计划
```

**原因2**: listing映射缺失

**排查**:
```sql
SELECT * FROM lingxing_listing WHERE local_sku = '2551469';
-- 返回空说明未上架或映射缺失
```

## 九、表关系图

```
lingxing_local_product (SKU基本信息)
    sku (PK)
    ↓
lingxing_purchase_plan (采购计划/PPG批次)

lingxing_local_product
    sku (PK)
    ↓
```

**数据流**:
```

```

## 十、字段命名规范

### 领星表字段风格

- **下划线命名**: `create_time`, `quantity_plan`, `creator_real_name`
- **时间字段**: 多数为`datetime`类型，少数为`date`
- **状态字段**: `status`（int）+ `status_text`（varchar）双字段
- **数量字段**: `quantity_*`（int）
- **金额字段**: `amount`, `gross_profit`（decimal(18,4)）

### Python代码命名

- **变量**: 下划线命名 `sku_batch_count`, `all_skus`
- **字典key**: 字符串 `{"sku": "2551413", "batch_count": 3}`
- **函数**: 下划线命名 `def q(sql, args):`
