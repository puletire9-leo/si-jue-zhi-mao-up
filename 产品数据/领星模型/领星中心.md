# 领星中心

> 最后更新：2026-07-17
> 本文件是领星相关所有代码、数据、模型的唯一入口。新增功能从这里找位置。

## 领星 API 关键规则

- **只有限流，没有配额上限** —— 可以放心多调，不用担心 API quota
- **单店铺请求：1 秒间隔**
- **多店铺请求（sid 数组 > 1）：10 秒间隔**
- **令牌桶容量 1** —— 紧凑请求会累积等待
- **单次 sid 数组上限 200** —— UK/DE 各 115 个正好塞得下
- **`is_recently_enum: false` 必须传** —— 默认 true 只返回活跃 ASIN，会漏淘汰品

## 一、数据获取层 (Java 后端)

### 数据同步服务（清理后的真实状态）

| Service | 写入表 | 触发端点 |
|---------|--------|----------|
| `LingxingLocalProductSyncService` | `lingxing_local_product` | POST /local-products/sync |
| `LingxingSellerSyncService` | `lingxing_seller` | POST /sellers/sync |
| `LingxingProfitAsinSyncService` | `lingxing_profit_asin` | POST /profit-asin/sync |
| `LingxingPurchaseDataLayerService` | `lingxing_purchase_plan/order/item` | POST /purchase/plans/sync 和 /purchase/orders/sync |

### Mapper（数据写入映射）

| Mapper | 操作的表 |
|--------|----------|
| `LingxingLocalProductMapper` | lingxing_local_product |
| `LingxingSellerMapper` | lingxing_seller |
| `LingxingProfitAsinMapper` | lingxing_profit_asin（已删 raw_json 列） |
| `LingxingPurchaseDataLayerMapper` | purchase_plan / order / order_item |
| `LingxingSkuDataLayerMapper` | lingxing_data_sync_run（只保留 begin/finish 方法） |

### 通用透传端点（推荐周同步用）

| 端点 | 用途 |
|------|------|
| `POST /call` | 通用透传领星 API — 传 path + body，返回原始响应 |

**周同步不再依赖专用 SyncService**，用 `/call` 直接透传 `productPerformance/openApi/asinList`，

### 新增数据流程

新增一个月数据（如 2026-07）：
1. Java 端同步该月的 profit_asin / sku_weekly
2. 领星导出该月 Excel → Python 脚本追加到 `lingxing_asin_monthly_performance`
3. 如有新 ASIN 进入团队 → 更新 `lingxing_asin_baseline`

### 5.4 基准表维护边界

基准表是公共事实源，但允许通过独立维护入口进行受控人工纠错。这不违反
“模型程序只读”的规则：前端基准表及其后端维护 API 属于独立维护程序，模型一、模型二
仍不得回写 baseline。人工修正只开放白名单字段，并由前后端共同校验：

- 开发人必须来自当前团队固定名单；
- 起算月必须符合 `YYYY-MM`；
- 分析状态必须来自固定枚举；
- 标签和起算依据需要去空白、限制长度；
- 更新请求不得覆盖首现库存、创建时间等只读事实字段。

## 九、新增功能指南

### 想加新数据源

1. Java 端写一个新 SyncService（参考 `LingxingProfitAsinSyncService`）
2. 加 Controller 端点触发同步
3. 建新表 → 只存基准 ASIN 相关数据
4. 更新本文件

### 想加新模型

1. 在 `scripts/lingxing_daily/` 新建 `build_xxx.py`
2. 通过 `lingxing_base_access.py` 读取 DB（不直接写 SQL 连接）
3. 输出放 `产品数据/领星模型/新模型名/`
4. 更新本文件的依赖关系图

### 想新增月份数据

1. 领星导出新月份 Excel → 运行导入脚本追加 `lingxing_asin_monthly_performance`
2. Java 端同步新月份的 profit_asin / sku_weekly
3. 运行 `weekly_asin_sync.py` → 自动发现新 ASIN 并加入 baseline

### 每周例行同步（自动发现新上架 ASIN）

```bash
# 方式1: 从 DB 已有周数据中识别（Java 端先同步 sku_weekly 后执行）
python scripts/lingxing_daily/weekly_asin_sync.py

# 方式2: 直接调 Java 后端 API 拉取最新一周
python scripts/lingxing_daily/weekly_asin_sync.py --api

# 方式3: 指定日期范围
python scripts/lingxing_daily/weekly_asin_sync.py --start 2026-07-14 --end 2026-07-20
```

逻辑：
- 筛选标签含 6 个团队标签之一的 ASIN
- 和 baseline 比对：已有 → 更新标签；新增 → 自动加入 baseline
- 上架时间判定：FBA-可售 > 0 → 起算月 = 本周所在月；否则创建时间兜底
