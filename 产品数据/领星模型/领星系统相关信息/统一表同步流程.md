# 领星产品统一表 —— 同步流程

> 生成时间：2026-07-30
> 事实来源：直接阅读实现代码 + 生产实测。
> 目标：把领星「产品表现」按周同步落库，加工成一张 **ASIN 维度产品统一表** `lingxing_product_unified`，只保留目标标签的 ASIN。

---

## 一句话

**店铺列表 → 产品表现(多店批量) → 周表 → 统一表(仅目标标签)**，一条链路自动跑完，统一表自包含所有字段，不依赖 CSV/baseline 历史表。

---

## 一、完整链路（4 步，一次调用跑完）

```
① 刷新店铺列表         /erp/sc/data/seller/lists（GET，一次性全量 1497 家）
        │  取 UK(mid=4)/DE(mid=5) 在售店铺 → 约 228 家
        ▼
② 产品表现多店批量拉    /bd/productPerformance/openApi/asinList（POST, summary_field=msku）
        │  分批 ≤200 sid/批，批间 10s；落 lingxing_product_performance（raw_json 含 price_list/tag_set）
        ▼
③ 加工进周表           从 raw_json 展开 price_list[*]/tag_set[*]，限 mid IN(4,5)
        │  落 lingxing_sku_weekly_performance（SKU×店铺×周 一行，SHA256 幂等）
        ▼
④ 重算统一表           只留 6 个目标标签 ASIN，按 asin 聚合 + 首现从周表算
           落 lingxing_product_unified（每 ASIN 一行，truncate 后重建）
```

**统一触发入口**：`POST /api/v1/modules/lingxing/scheduled/run-now`
body：`{"startDate":"2026-07-06","endDate":"2026-07-12"}`（一个周窗口）

`LingxingScheduledSyncService.run()` 串起 ①②③④ 全流程。

---

## 二、准入铁律：只允许 6 个目标标签 ASIN

以「该 ASIN 最新一周的 `tag_ids`」为准（周表 tag_ids 逗号分隔，`FIND_IN_SET` 精确匹配 tag_id）：

| 标签 | global_tag_id |
|------|---------------|
| 欧洲精铺2025 | 907563170455592213 |
| 欧洲精铺2025非标品 | 907654877317203632 |
| 欧洲精铺2025淘汰 | 907585631391968576 |
| 欧洲精铺2025待淘汰 | 907585847123066054 |
| 欧洲精铺2025季节性断货 | 907596133278666918 |
| 绿标 | 907657425150046095 |

**明确排除**：侵权下架(907677931879515735)、普通产品、新品、淘汰产品、需确认 等一律不进。

**动态性**（关键）：以最新周标签为准 →
- 旧 ASIN 改成非目标标签 → 自动退出统一表
- 新上架 ASIN 打了目标标签 → 自动进入
- 不是死名单（CSV 是 6 月快照 6617，7 月同步后为 6994，多出的是新上架目标标签 ASIN）

## 三、统一表字段（45 列，自包含）

数据全部从周表算，不依赖 baseline（baseline 仅补 developer 等纯档案字段）。

| 组 | 字段 | 来源 |
|----|------|------|
| 身份 | asin, parent_asin, base_sku, base_msku, base_store, country, developer, title, listing_tags | 周表 + baseline 补档 |
| 起算时间 | model_start_month（可售首现月优先，无则库存首现月）+ model_start_basis | **周表算** |
| FBA库存首现 | fba_inventory_first_month, inventory_first_store/country/sku/qty | **周表按时间序取首次>0** |
| FBA可售首现 | fba_first_available_month + available_first_store/country/sku/qty | **周表按时间序取首次>0** |
| 观测状态 | fba_observation_status | 周表 |
| 真实上架日 | listing_open_date | lingxing_listing.open_date |
| 经营累计 | total_volume/amount/order_items/gross_profit, avg_gross_margin, active_months, first_sale_month, last_sale_month | 周表聚合 |
| 最近周快照 | latest_month, latest_volume/amount/fba_available, latest_avg_star, latest_reviews_count | 周表最新 week_end |
| 元数据 | data_cutoff_month, unified_version, synced_at | — |

## 四、限流规则（领星文档 §附加说明）

- 令牌桶容量 **1**，必须**串行**（上次返回后再下次）
- 单店查询间隔 **1s**；**多店查询间隔 10s**
- 按「账户 + path」维度限流，同账户多 appId 共享
- 客户端已内置 code 3001008/103 自动退避重试

> 注：领星只有**限流**，无"配额"概念（配额是卖家精灵侧）。

## 五、关键实现文件

| 环节 | 文件 |
|------|------|
| 调度编排 | `service/LingxingScheduledSyncService.java` |
| 店铺同步 | `service/LingxingSellerSyncService.java` |
| 产品表现同步 | `service/LingxingProductPerformanceSyncService.java` |

**端点**：
- `POST /scheduled/run-now`（全流程，传 startDate/endDate）
- `POST /product-performance/sync`（单独同步产品表现）
- `POST /sku-weekly/rebuild`（单独加工周表）
- `POST /product-unified/rebuild`（单独重算统一表）
- `GET /product-unified?asin=&developer=`（查询）

## 六、自动调度

- `@Scheduled(cron = "0 30 3 ? * MON")` 每周一 03:30
- 开关 `LINGXING_SCHEDULED_ENABLED`（默认 false，验证后设 true 才自动跑）
- 窗口取「上周一~上周日」完整一周
