# 艾为系统采购发货管理模块 - 前端交互与状态管理分析

## 一、组件化设计模式

### 1. 多弹窗状态管理

艾为系统采用**多弹窗状态分离**模式，每个弹窗独立状态：

```vue
<script setup>
// ① 编辑弹窗状态
const editDialogVisible = ref(false);
const editForm = reactive({
    id: 0,
    plan_sn: "",
    sku: "",
    quantity_plan: 0,
    remark: ""
});

// ② 算法详情弹窗状态
const detailDialogVisible = ref(false);
const detailLoading = ref(false);
const analysisDetail = ref<any>(null);

// ③ 发货日历弹窗状态
const shippingCalendarVisible = ref(false);
const shippingItems = ref<any[]>([]);
const expectedArrivalDate = ref<string | null>(null);
const selectedChannel = ref<string | null>(null);

// ④ 发货成功弹窗状态
const shippingSuccessVisible = ref(false);
const shippingResult = reactive({
    shippingNo: "",
    itemCount: 0,
    channelName: "",
    arrivalDate: ""
});
</script>
```

**借鉴价值**：

1. **状态独立**：每个弹窗的 `visible` 和数据状态分离，互不干扰

2. **命名规范**：
   - `xxxVisible` → 弹窗显示状态
   - `xxxLoading` → 弹窗内加载状态
   - `xxxForm` / `xxxData` → 弹窗业务数据

3. **关闭时重置**：
   ```vue
   const closeEditDialog = () => {
       editDialogVisible.value = false;
       // 重置表单，避免数据残留
       Object.assign(editForm, {
           id: 0,
           plan_sn: "",
           sku: "",
           quantity_plan: 0,
           remark: ""
       });
   };
   ```

**对比我们的系统**：
```vue
<!-- 我们当前的到货看板没有弹窗，所有交互都在主页面 -->
<template>
  <div class="inventory-arrival-dashboard">
    <!-- 筛选区 -->
    <!-- 表格区 -->
    <!-- 分页区 -->
  </div>
</template>
```

**建议**：
- 如果未来加"批次详情查看"/"手动同步确认"等功能，参考这个多弹窗模式
- 每个弹窗独立状态，关闭时重置数据

### 2. 分步式交互流程（Step Wizard）

**发货流程的分步式设计**：

```
Step 1: 选择商品（表格勾选）
   ↓
Step 2: 选择到货日期
   ↓
Step 3: 系统计算可用物流渠道（根据时效自动筛选）
   ↓
Step 4: 选择物流渠道
   ↓
Step 5: 确认摘要并提交
   ↓
Step 6: 显示发货成功结果
```

**关键实现**：

```vue
<!-- Step 1: 显示已选商品 -->
<div class="selected-items-section">
    <div class="section-label">已选商品 ({{ shippingItems.length }}件)</div>
    <div class="selected-items-list">
        <div v-for="item in shippingItems" :key="item.id" class="selected-item">
            <span class="item-sn">{{ item.plan_sn }}</span>
            <span class="item-name">{{ item.product_name }}</span>
            <span class="item-qty">{{ item.quantity_plan }}件</span>
        </div>
    </div>
</div>

<!-- Step 2: 选择日期 -->
<div class="date-section">
    <el-date-picker
        v-model="expectedArrivalDate"
        :disabled-date="disablePastDate"
        @change="calculateAvailableChannels"  <!-- 🔑 日期变化触发渠道计算 -->
    />
</div>

<!-- Step 3: 显示可用渠道（日期选择后才显示） -->
<div v-if="expectedArrivalDate" class="channels-section">
    <div class="channel-list">
        <div
            v-for="channel in logisticsChannels"
            :class="{
                selected: selectedChannel === channel.id,
                disabled: !channel.available  <!-- 🔑 时效不足的渠道置灰 -->
            }"
            @click="channel.available && (selectedChannel = channel.id)"
        >
            <span class="channel-name">{{ channel.name }}</span>
            <span class="channel-days">{{ channel.days }}天到</span>
            <el-tag v-if="channel.available" type="success">可选</el-tag>
            <el-tag v-else type="danger">时效不足</el-tag>
        </div>
    </div>
</div>

<!-- Step 4: 确认摘要（日期和渠道都选了才显示） -->
<div v-if="selectedChannel && expectedArrivalDate" class="summary-section">
    <div class="summary-item">
        <span class="label">发货商品:</span>
        <span class="value">{{ shippingItems.length }}件</span>
    </div>
    <div class="summary-item">
        <span class="label">物流渠道:</span>
        <span class="value">{{ getChannelName(selectedChannel) }}</span>
    </div>
    <div class="summary-item">
        <span class="label">预计到货:</span>
        <span class="value highlight">{{ expectedArrivalDate }}</span>
    </div>
</div>
```

**渠道计算逻辑**：

```typescript
// 根据到货日期计算可用渠道
const calculateAvailableChannels = () => {
    if (!expectedArrivalDate.value) {
        logisticsChannels.value = [];
        return;
    }
    
    const today = new Date();
    today.setHours(0, 0, 0, 0);
    const arrivalDate = new Date(expectedArrivalDate.value);
    
    // 计算距离到货还有几天
    const daysToArrival = Math.ceil(
        (arrivalDate.getTime() - today.getTime()) / (1000 * 60 * 60 * 24)
    );
    
    // 标记每个渠道是否可用（时效是否足够）
    logisticsChannels.value = logisticsChannelsConfig.map((channel) => ({
        ...channel,
        available: daysToArrival >= channel.days  // 🔑 核心逻辑
    }));
    
    // 自动选择第一个可用的渠道
    selectedChannel.value = null;
    const firstAvailable = logisticsChannels.value.find((c) => c.available);
    if (firstAvailable) {
        selectedChannel.value = firstAvailable.id;
    }
};
```

**借鉴价值**：

1. **渐进式展示**：用户完成上一步才显示下一步，避免信息过载
   ```vue
   <div v-if="step1Completed"><!-- Step 2 --></div>
   <div v-if="step1Completed && step2Completed"><!-- Step 3 --></div>
   ```

2. **智能默认选择**：系统自动选第一个可用渠道，减少用户操作

3. **业务规则可视化**：
   - 时效不足的渠道置灰 + 红色tag "时效不足"
   - 用户一眼看出为什么不能选某个渠道

4. **确认摘要**：提交前显示汇总信息，减少错误提交

**对比我们的系统**：
```vue
<!-- 我们当前的筛选是平铺式，所有选项同时显示 -->
<el-row :gutter="12">
    <el-col :span="4">
        <el-select v-model="queryParams.developer" placeholder="开发人" />
    </el-col>
    <el-col :span="4">

    <el-col :span="4">

    </el-col>
    <!-- ... -->
</el-row>
```

**建议**：
- 如果未来有"批量发货创建"功能，参考这个分步式交互
- 关键：每一步完成后，用 `v-if` 控制下一步的显示

## 二、表格交互优化

### 1. 固定列 + 响应式表格高度

```vue
<template>
  <el-table
    ref="tableRef"
    :data="tableData"
    :height="tableHeight"  <!-- 🔑 动态计算高度 -->
  >
    <!-- 固定左侧 -->
    <el-table-column type="selection" width="40" fixed="left" />
    <el-table-column prop="pic_url" label="图片" width="55" fixed="left" />
    <el-table-column prop="plan_sn" label="计划编号" width="120" fixed="left" />
    <el-table-column prop="sku" label="SKU" width="140" fixed="left" />
    
    <!-- 可滚动中间区 -->
    <el-table-column prop="seller_name" label="店铺" width="100" />
    <el-table-column prop="marketplace" label="站点" width="70" />
    <!-- ... 更多字段 ... -->
    
    <!-- 固定右侧 -->
    <el-table-column label="操作" width="80" fixed="right" />
  </el-table>
</template>

<script setup>
const tableHeight = ref(0);

// 动态计算表格高度（适配屏幕）
const calculateTableHeight = () => {
    const windowHeight = window.innerHeight;
    const headerHeight = 60;      // 页面头部
    const filterHeight = 80;      // 筛选区
    const paginationHeight = 50;  // 分页区
    const padding = 40;           // 内边距
    
    tableHeight.value = windowHeight - headerHeight - filterHeight - paginationHeight - padding;
};

onMounted(() => {
    calculateTableHeight();
    window.addEventListener('resize', calculateTableHeight);
});

onUnmounted(() => {
    window.removeEventListener('resize', calculateTableHeight);
});
</script>
```

**借鉴价值**：

1. **固定高度 + 内部滚动**：表格内部滚动而非整个页面滚动

2. **响应式高度**：监听窗口resize，自动调整表格高度

3. **固定列策略**：
   - 左固定：勾选框 + 图片 + 关键字段（SKU/编号）
   - 右固定：操作列
   - 中间滚动：其他字段

**对比我们的系统**：
```vue
<!-- 我们当前没有动态高度和固定列 -->
<el-table :data="groupedData" border stripe>
  <!-- 所有列都可滚动 -->
</el-table>
```

**建议**：
- 加动态高度计算，避免表格太高或太矮
- 左固定：SKU + 批次号，右固定：操作列

### 3. 状态色彩化映射

```typescript
// 状态映射配置
const statusMap: Record<number, { text: string; type: ElTagType }> = {
    2: { text: "待采购", type: "warning" },
    "-2": { text: "已完成", type: "success" },
    121: { text: "待审批", type: "info" },
    122: { text: "已驳回", type: "danger" },
    "-3": { text: "已作废", type: "info" }
};

const getStatusText = (status: number) => {
    return statusMap[status]?.text || "未知状态";
};

const getStatusType = (status: number) => {
    return statusMap[status]?.type || "";
};
```

```vue
<!-- 使用 -->
<el-tag :type="getStatusType(row.status)" size="small">
    {{ getStatusText(row.status) }}
</el-tag>
```

**借鉴价值**：

1. **配置驱动**：状态映射统一管理，避免模板里写一堆 `v-if`

2. **类型安全**：TypeScript `Record<number, {...}>` 明确约束

3. **降级处理**：`|| "未知状态"` / `|| ""` 避免空指针

**对比我们的系统**：

## 三、数据加载与缓存策略

### 1. 智能刷新机制

```typescript
// 分页查询
const loadData = async () => {
    tableLoading.value = true;
    
    try {
        const params = {
            page: pagination.page,
            size: pagination.size,
            status: filterStatus,
            keyword: searchKeyword,
            order: sortInfo.order,
            sort: sortInfo.sort
        };
        
        // 调用智能分页接口（后端自动检测并同步过期数据）
        const res = await request({
            url: '/app/bsr_purchase_plan_lingxing/smartPage',
            method: 'post',
            data: params
        });
        
        tableData.value = res.data.records;
        pagination.total = res.data.total;
        
        // 检查是否有正在刷新的记录
        const refreshingCount = tableData.value.filter(r => r._refreshing).length;
        if (refreshingCount > 0) {
            // 5秒后自动重新查询（获取刷新后的数据）
            setTimeout(() => {
                loadData();
            }, 5000);
        }
        
    } catch (error) {
        ElMessage.error('查询失败');
    } finally {
        tableLoading.value = false;
    }
};
```

```vue
<!-- 表格中显示刷新状态 -->
<el-table-column prop="status" label="状态" width="120">
    <template #default="{ row }">
        <el-tag :type="getStatusType(row.status)">
            {{ getStatusText(row.status) }}
        </el-tag>
        <el-tag v-if="row._refreshing" type="info" size="small" style="margin-left: 4px">
            刷新中
        </el-tag>
    </template>
</el-table-column>
```

**借鉴价值**：

1. **被动刷新变主动**：后端检测过期数据，前端自动轮询更新

2. **非阻塞加载**：第一次查询立即返回旧数据，后台同步新数据

3. **刷新状态提示**：`_refreshing` 标记 + "刷新中" Tag

4. **自动停止轮询**：没有 `_refreshing` 的记录时停止轮询

**对比我们的系统**：
```typescript
// 我们当前手动触发同步，用户需等待几分钟
const handleSync = async () => {
    syncing.value = true;
    const r = await syncInventoryBatch({});  // 阻塞等待
    syncing.value = false;
    ElMessage.success(`同步完成`);
    handleQuery();
};
```

**建议**：
- 加 `synced_at` 字段，查询时检测过期（>5分钟）
- 过期记录后台触发同步，前端5秒后自动刷新
- 显示"正在刷新"提示，避免用户重复点同步

### 2. 悬浮预览的防抖加载

```typescript
// 悬浮查看计划详情（鼠标hover时）
const hoverTimeoutId = ref<number | null>(null);

const handleRowMouseEnter = (row: any) => {
    // 延迟500ms加载，避免鼠标快速划过时频繁请求
    hoverTimeoutId.value = window.setTimeout(() => {
        loadPlanDetails(row.plan_sn);
    }, 500);
};

const handleRowMouseLeave = () => {
    // 鼠标离开时取消加载
    if (hoverTimeoutId.value) {
        clearTimeout(hoverTimeoutId.value);
        hoverTimeoutId.value = null;
    }
};

const loadPlanDetails = async (planSn: string) => {
    try {
        const res = await request({
            url: '/app/bsr_purchase_plan_lingxing/hoverDetails',
            method: 'post',
            data: { plan_sns: [planSn] }
        });
        
        // 显示悬浮卡片

    } catch (error) {
        console.warn('加载悬浮详情失败', error);
        // 降级：不显示悬浮卡片，不影响主功能
    }
};
```

**借鉴价值**：

1. **防抖延迟**：500ms后才加载，避免鼠标快速划过时浪费请求

2. **取消机制**：鼠标离开时取消加载（已发出的请求无法取消，但不显示结果）

3. **静默失败**：悬浮详情加载失败不影响主功能（只是不显示悬浮卡片）

**对比我们的系统**：
```vue

```

**建议**：

## 四、表单校验与错误提示

### 1. 前端校验规则配置化

```typescript
// 采购计划创建表单校验规则
const createFormRules = {
    sku: [
        { required: true, message: '请输入SKU', trigger: 'blur' },
        { min: 3, max: 100, message: 'SKU长度3-100个字符', trigger: 'blur' }
    ],
    quantity_plan: [
        { required: true, message: '请输入采购量', trigger: 'blur' },
        { type: 'number', min: 1, message: '采购量至少为1', trigger: 'blur' }
    ],
    wid: [
        { required: true, message: '请选择仓库', trigger: 'change' }
    ],
    expect_arrive_time: [
        { required: true, message: '请选择期望到货日期', trigger: 'change' },
        { validator: validateFutureDate, trigger: 'change' }
    ]
};

// 自定义校验：日期必须是未来
const validateFutureDate = (rule: any, value: any, callback: any) => {
    if (!value) {
        callback(new Error('请选择日期'));
        return;
    }
    
    const selected = new Date(value);
    const today = new Date();
    today.setHours(0, 0, 0, 0);
    
    if (selected < today) {
        callback(new Error('期望到货日期不能是过去'));
    } else {
        callback();
    }
};
```

**借鉴价值**：

1. **规则集中管理**：所有校验规则在一个对象里，易维护

2. **自定义校验器**：`validator` 函数实现复杂业务规则

3. **触发时机配置**：`trigger: 'blur' / 'change'` 控制何时校验

**对比我们的系统**：
```vue
<!-- 我们当前主要靠后端校验，前端较少 -->
<el-input v-model="queryParams.sku" placeholder="SKU 搜索" />
```

**建议**：
- 表单类操作（创建/编辑）加前端校验规则
- 复杂规则（如日期范围、SKU格式）用自定义validator

### 2. 错误提示的层次化

```typescript
// 三层错误提示
const handleCreatePurchasePlan = async () => {
    try {
        // ① 前端校验
        const valid = await formRef.value?.validate();
        if (!valid) return;  // 校验失败，Element Plus自动显示错误提示
        
        // ② 调用API
        const res = await request({
            url: '/app/bsr_purchase_plan_lingxing/createPurchasePlan',
            method: 'post',
            data: {
                ...createForm,
                return_structured_failure: true  // 🔑 请求结构化失败
            }
        });
        
        // ③ 业务逻辑校验
        if (res.success === false) {
            // 结构化失败：显示详细错误信息
            ElMessageBox.alert(
                `<div>
                    <p><strong>创建失败原因：</strong></p>
                    <p>${res.message}</p>
                    ${res.purchase_remark_sync?.message ? 
                        `<p><strong>备注同步状态：</strong>${res.purchase_remark_sync.message}</p>` 
                        : ''}
                </div>`,
                '创建失败',
                { dangerouslyUseHTMLString: true, type: 'error' }
            );
            return;
        }
        
        // ④ 成功提示
        ElMessage.success('采购计划创建成功');
        dialogVisible.value = false;
        loadData();  // 刷新列表
        
    } catch (error: any) {
        // ⑤ 异常错误
        ElMessage.error(error.message || '网络错误，请稍后重试');
        console.error('创建采购计划失败', error);
    }
};
```

**借鉴价值**：

1. **三层校验**：
   - 前端表单规则（Element Plus自动提示）
   - 业务逻辑校验（结构化失败，MessageBox详细说明）
   - 异常捕获（网络错误，Message简短提示）

2. **结构化失败的优势**：
   ```typescript
   // 后端返回
   {
       success: false,
       message: "采购备注处理失败，未创建采购计划",
       purchase_remark_sync: {
           status: "failed",
           message: "领星API超时"
       }
   }
   
   // 前端可以展示详细信息，而不是简单的"创建失败"
   ```

3. **错误信息分级**：
   - 用户可修复的错误（如必填项）→ 表单提示
   - 业务规则限制（如库存不足）→ MessageBox详细说明
   - 系统异常（如网络错误）→ Message简短提示 + console.error记录

**对比我们的系统**：
```typescript
// 我们当前简单的try-catch
try {
    const data = await listInventoryBatch(queryParams);
    // ...
} catch (e: any) {
    ElMessage.error(e?.message || "查询失败");
}
```

**建议**：
- 表单操作加 Element Plus 的 `rules` 校验
- 业务校验失败用 MessageBox 显示详细原因
- 网络异常用 Message 简短提示
