#### 8. 通用PageQueryBuilder
**位置**：新建 `com.sjzm.common.query.PageQueryBuilder`

**设计**：
```java
public class PageQueryBuilder<T> {
    private LambdaQueryWrapper<T> wrapper;
    
    public PageQueryBuilder<T> fieldEq(String field, Object value) {
        if (value != null) {
            // 根据field反射获取getter，构建eq条件
        }
        return this;
    }
    
    public PageQueryBuilder<T> keyword(String keyword, String... fields) {
        if (keyword != null && keyword.length() > 0) {
            wrapper.and(w -> {
                for (int i = 0; i < fields.length; i++) {
                    if (i == 0) {
                        w.like(fields[i], keyword);
                    } else {
                        w.or().like(fields[i], keyword);
                    }
                }
            });
        }
        return this;
    }
    
    public IPage<T> page(int current, int size) {
        return mapper.selectPage(new Page<>(current, size), wrapper);
    }
}

// 使用
PageQueryBuilder<LingxingInventoryBatchDetail> builder = new PageQueryBuilder<>(batchMapper);
IPage<LingxingInventoryBatchDetail> page = builder
    .fieldEq("developer", developer)
    .fieldEq("dataDate", dataDate)
    .keyword(keyword, "sku", "batchNo")
    .page(current, size);
```

**价值**：
- 减少Controller和Service中的重复分页代码
- keyword统一处理OR条件

#### 9. 智能同步机制
**位置**：`LingxingInventoryBatchService`

**设计**：
```java
// Entity加字段
@Column(comment = "最后同步时间")
private LocalDateTime syncedAt;

// Service智能查询
public Map<String, Object> smartQuery(QueryParams params) {
    // ① 正常分页查询
    IPage<LingxingInventoryBatchDetail> page = batchMapper.selectPage(...);
    
    // ② 检测前10条是否过期（>5分钟未同步）
    LocalDateTime fiveMinutesAgo = LocalDateTime.now().minusMinutes(5);
    List<String> staleDataDates = page.getRecords().stream()
        .limit(10)
        .filter(r -> r.getSyncedAt() == null || r.getSyncedAt().isBefore(fiveMinutesAgo))
        .map(LingxingInventoryBatchDetail::getDataDate)
        .distinct()
        .collect(Collectors.toList());
    
    // ③ 后台异步刷新（CompletableFuture）
    if (!staleDataDates.isEmpty()) {
        CompletableFuture.runAsync(() -> {
            for (String date : staleDataDates) {
                try {
                    syncDaily(date, date, null);
                } catch (Exception e) {
                    log.error("后台同步失败", e);
                }
            }
        });
    }
    
    Map<String, Object> result = new HashMap<>();
    result.put("records", page.getRecords());
    result.put("total", page.getTotal());
    result.put("refreshing", !staleDataDates.isEmpty());  // 前端根据这个字段轮询
    return result;
}
```

**前端配合**：
```typescript
const loadData = async () => {
    const res = await listInventoryBatch(queryParams);
    groupedData.value = groupBySku(res.records);
    total.value = res.total;
    
    // 如果有数据正在刷新，5秒后自动重新查询
    if (res.refreshing) {
        setTimeout(() => loadData(), 5000);
    }
};
```

**价值**：
- 用户无需手动点同步，系统自动检测并刷新
- 非阻塞，第一次查询立即返回

#### 10. 结构化失败响应
**位置**：所有复杂操作接口

**设计**：
```java
// DTO
public class StructuredResult<T> {
    private boolean success;
    private String message;
    private T data;
    private Map<String, Object> metadata;  // 补充信息（如失败原因详情）
}

// Service
public StructuredResult<SyncResult> syncDaily(SyncDailyRequest req) {
    if (req.isReturnStructuredFailure()) {
        try {
            SyncResult result = doSync(req);
            return StructuredResult.success(result);
        } catch (Exception e) {
            return StructuredResult.failure(
                "同步失败: " + e.getMessage(),
                Map.of("error_type", e.getClass().getSimpleName(),
                       "lingxing_response", lastLingxingResponse)
            );
        }
    } else {
        // 传统模式：抛异常
        SyncResult result = doSync(req);
        return StructuredResult.success(result);
    }
}
```

**前端使用**：
```typescript
const result = await syncInventoryBatch({
    ...,
    return_structured_failure: true
});

if (result.success === false) {
    ElMessageBox.alert(
        `<p><strong>同步失败原因：</strong>${result.message}</p>
         ${result.metadata?.error_type ? `<p>错误类型：${result.metadata.error_type}</p>` : ''}`,
        '同步失败',
        { dangerouslyUseHTMLString: true, type: 'error' }
    );
} else {
    ElMessage.success(`同步完成：${result.data.upserted}行`);
}
```

**价值**：
- 前端无需try-catch，可以拿到详细的失败信息
- 适用于长时间操作（用户需要知道哪一步失败了）

#### 15. 多级降级策略
**参考**：`getPlanDetailsForHover()` 的三级降级

**设计**：
```java
public BatchDetailDTO getBatchDetail(Long id) {
    // ① 先查本地缓存（Redis）
    BatchDetailDTO cached = redisTemplate.opsForValue().get("batch:" + id);
    if (cached != null) {
        return cached;
    }
    
    // ② 缓存失效，查领星API（带超时）
    try {
        BatchDetailDTO fresh = lingxingClient.getBatchDetail(id);
        redisTemplate.opsForValue().set("batch:" + id, fresh, 1, TimeUnit.MINUTES);
        return fresh;
    } catch (Exception apiError) {
        log.warn("领星API失败，降级到本地数据库", apiError);
    }
    
    // ③ API失败，降级到本地数据库
    LingxingInventoryBatchDetail local = batchMapper.selectById(id);
    if (local != null) {
        BatchDetailDTO dto = convertToDTO(local);
        dto.setFromLocal(true);  // 标记数据来源
        return dto;
    }
    
    // ④ 本地也没有，返回空
    return null;
}
```

**价值**：
- 多级降级确保服务可用性
- 适合对外部API依赖较强的场景

public Map<String, Object> createBatchShipment(CreateRequest req) {

#### 18. 多弹窗状态分离
**参考**：采购计划管理页面的4个弹窗

```typescript
// composables/useDialogs.ts（提取为可复用hook）
export function useDialogs() {
    const dialogs = reactive({
        edit: { visible: false, data: {} },
        detail: { visible: false, data: null, loading: false },
        confirm: { visible: false, message: '' }
    });
    
    const openDialog = (name: string, data?: any) => {
        dialogs[name].visible = true;
        if (data) dialogs[name].data = data;
    };
    
    const closeDialog = (name: string) => {
        dialogs[name].visible = false;
        // 延迟重置数据，避免关闭动画时数据闪烁
        setTimeout(() => {
            dialogs[name].data = {};
        }, 300);
    };
    
    return { dialogs, openDialog, closeDialog };
}
```

**价值**：
- 多弹窗场景状态管理清晰
- 关闭时自动重置数据，避免残留

## 六、关键收获总结

### 架构设计
- **分层清晰**：Controller只管路由，Service管业务，Repository管SQL
- **职责单一**：每个Service方法只做一件事，复杂流程拆成多个方法
- **配置驱动**：状态映射、校验规则、分页参数都提取为配置

### 数据同步
- **双向同步**：本地→领星（创建）+ 领星→本地（同步）
- **智能刷新**：自动检测过期数据，后台静默同步
- **幂等设计**：clientToken防重复提交

### 错误处理
- **三层校验**：前端表单 + 业务规则 + 异常捕获
- **结构化失败**：详细的失败原因 + 补偿操作状态
- **降级策略**：API失败→本地数据库→空结果

### 用户体验
- **渐进式展示**：分步式交互，完成上一步才显示下一步
- **完整反馈**：操作成功后显示详细结果 + 后续操作引导
- **非阻塞操作**：长时间操作后台执行，前端不阻塞
